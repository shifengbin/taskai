# terminal-output-status-detection Specification

## Purpose

定义终端输出如何驱动临时实时状态，以及用户如何在设置中选择该判定方式，并明确静默计时、自动信号隔离和本机 HTTP 服务的兼容行为。

## Requirements

### Requirement: 可选择终端输出作为状态判定方式

系统 MUST 在“实时状态”的状态管理方式中提供值为 `output-change` 的“根据终端输出变化”选项，并将用户选择持久化。`output-change`、`title-change` 和 `http` MUST 互斥；缺失状态管理方式的既有设置 MUST 默认使用 `title-change`。

#### Scenario: 保存并恢复输出判定方式
- **WHEN** 用户选择“根据终端输出变化”并保存设置后重新打开设置
- **THEN** 系统显示已选择该方式，并将实时状态服务配置为输出判定方式

#### Scenario: 读取未包含方式字段的既有设置
- **WHEN** 系统读取缺失状态管理方式字段的已保存设置
- **THEN** 系统使用“根据终端标题变化”，且不会将其误认为输出判定方式

### Requirement: 终端画面变化驱动活动状态

在 `output-change` 方式下，系统 MUST 将活动终端接收到的 PTY 输出经 xterm 解析后造成的活动终端页实际变化视为活动。活动终端页 MUST 是活动缓冲区从 `baseY` 开始的 `rows` 行，MUST NOT 使用用户当前滚动视口作为比较范围或比较基线。画面比较 MUST 包含字符内容（包括空格等空白单元格）、字符宽度、前景色、背景色和可见文本样式，MUST NOT 包含光标位置、光标形态、闪烁状态或缓冲区内部行号。仅设置后续输出颜色、标题、响铃或不改变活动终端页的控制序列 MUST NOT 触发活动。画面比较 MUST 在同一输出批次（按输出静默期合并写入）解析完成后执行，每个合并批次至多比较一次；同一批次内被改写又在批次末还原为比较基线的瞬时变化 MUST NOT 单独计为一次活动。每次活动 MUST 将对应终端设为工作中，并以最后一次活动为起点计算 1.5 秒静默期。静默期结束时，当前选中的终端 MUST 变为空闲，未选中的终端 MUST 变为未读；错误事件 MUST NOT 触发活动。

#### Scenario: 首次画面变化显示工作中
- **WHEN** 输出判定方式下的活动终端收到输出，且解析后活动终端页中的字符、空白单元格或样式发生变化
- **THEN** 该终端和聚合后的任务实时状态显示为工作中

#### Scenario: 向上滚动时底部画面变化显示工作中
- **WHEN** 用户将终端滚动到历史内容，随后活动终端页因输出而发生字符、空白单元格或样式变化
- **THEN** 系统将该终端视为活动，且状态判定结果与用户停留在终端底部时相同

#### Scenario: 用户滚动不改变状态基线
- **WHEN** 用户仅改变终端滚动位置，或随后输出不改变活动终端页的单元格
- **THEN** 系统不创建活动状态、不重置或推迟静默计时，且用户滚动不会改变后续活动终端页变化的判定基线

#### Scenario: 仅移动光标不触发活动
- **WHEN** 输出判定方式下的终端只收到光标移动、定位、保存或恢复控制序列，且解析后活动终端页不变
- **THEN** 终端和任务实时状态保持不变，且不创建或推迟静默计时

#### Scenario: 仅设置未使用颜色不触发活动
- **WHEN** 输出判定方式下的终端只设置后续输出的颜色或样式，且没有改写活动终端页中的单元格
- **THEN** 终端和任务实时状态保持不变，且不创建或推迟静默计时

#### Scenario: 改写字符颜色触发活动
- **WHEN** 输出判定方式下的终端在已有字符位置写入相同字符但前景色、背景色或可见样式不同
- **THEN** 系统将该终端视为活动

#### Scenario: 空白内容改变触发活动
- **WHEN** 输出判定方式下的终端使用空格或其他空白内容覆盖已有单元格，或改变空白单元格的可见背景或样式
- **THEN** 系统将该终端视为活动

#### Scenario: 同一合并批次内的瞬时改写还原不计为活动
- **WHEN** 某输出批次合并写入的输出在解析完成后，活动终端页与该批次开始前的比较基线完全一致（例如同一批次内某单元格被改写又被还原）
- **THEN** 系统不因该批次创建活动状态或推迟静默计时

#### Scenario: 连续画面变化推迟静默判定
- **WHEN** 终端在首次画面变化后的 1.5 秒内再次发生画面变化
- **THEN** 系统从最新变化重新计算静默期，且终端在最新变化后的 1.5 秒前保持工作中

#### Scenario: 未选中终端停止变化
- **WHEN** 未选中的工作中终端在最后一次画面变化后静默满 1.5 秒
- **THEN** 该终端变为未读，并按既有优先级更新任务实时状态

#### Scenario: 选中终端停止变化
- **WHEN** 当前选中的工作中终端在最后一次画面变化后静默满 1.5 秒
- **THEN** 该终端变为空闲，并按既有优先级更新任务实时状态

### Requirement: 自动状态信号按方式隔离

系统 MUST 只在所选的自动状态管理方式下处理其对应的活动信号。`title-change` MUST 保持仅由实际变化的 OSC 标题触发自动活动；`output-change` MUST 仅由终端画面实际变化触发自动活动；`http` MUST 不因终端输出自动改变状态。方式切换时，系统 MUST 清除旧方式留下的临时自动状态和静默计时器。已启用的本机 HTTP 服务 MUST 继续允许其既有的显式状态更新接口。

#### Scenario: 标题方式忽略普通输出
- **WHEN** 标题变化方式下的终端收到不包含完整且不同 OSC 标题的非空输出
- **THEN** 该输出不会自动将终端标记为工作中

#### Scenario: HTTP 方式忽略终端输出
- **WHEN** HTTP 状态管理方式下的终端收到造成画面变化的输出且没有 HTTP 状态更新
- **THEN** 该输出不会自动改变终端或任务的实时状态

#### Scenario: 切换离开输出判定方式
- **WHEN** 工作中终端的设置从输出判定方式切换为标题变化或 HTTP 方式
- **THEN** 系统清除该终端的自动工作中状态和未到期的静默计时器，后续旧计时器不得再改变状态

### Requirement: 手动关闭已退出终端后清理任务异常状态

系统 MUST 在用户成功关闭一个已经退出的终端后，将该终端从临时实时状态服务中移除，并发布包含更新后任务聚合状态的实时状态事件。若该终端是任务中唯一的异常终端，任务实时状态 MUST 从 `error` 恢复为 `idle`；若任务仍有其他终端，任务实时状态 MUST 继续按照剩余终端的状态优先级聚合。该清理 MUST 不改变持久化任务状态或该终端已经发生的原始退出原因。

#### Scenario: 异常退出后手动关闭唯一终端

- **WHEN** 终端自然退出并被标记为 `error`，且用户随后在任务树中关闭该已退出终端
- **THEN** 系统从实时状态服务移除该终端，发布 `terminalRemoved` 事件，并将任务实时状态更新为 `idle`

#### Scenario: 关闭异常终端后保留其他终端状态

- **WHEN** 任务有一个异常终端和至少一个其他终端，用户关闭该异常终端
- **THEN** 系统移除异常终端，但任务实时状态继续反映剩余终端中优先级最高的状态

#### Scenario: 关闭活动终端保持既有行为

- **WHEN** 用户关闭一个仍处于活动状态的终端
- **THEN** 系统继续发布该终端的正常关闭事件，并且重复的实时状态移除调用不得产生错误或改写原始退出原因

#### Scenario: 关闭失败时保留异常提示

- **WHEN** 关闭终端操作失败
- **THEN** 系统不得移除该终端的实时状态或前端条目，并继续向用户显示关闭错误
