# terminal-output-status-detection Specification

## Purpose

定义终端输出如何驱动临时实时状态，以及用户如何在设置中选择该判定方式，并明确静默计时、自动信号隔离和本机 HTTP 服务的兼容行为。

## Requirements

### Requirement: 可选择终端输出作为状态判定方式

系统 MUST 在“实时状态”的状态管理方式中提供值为 `output-change` 的“根据终端输出变化”选项，并将用户选择持久化。`output-change`、`title-change` 和 `http` MUST 互斥；缺失状态管理方式的既有设置 MUST 默认使用 `title-change`。

#### Scenario: 保存并恢复输出判定方式
- **WHEN** 用户选择“根据终端输出变化”并保存设置后重新打开设置
- **THEN** 系统显示已选择该方式，并将实时状态服务配置为输出判定方式

#### Scenario: 读取未包含方式字段的既有设置
- **WHEN** 系统读取缺失状态管理方式字段的已保存设置
- **THEN** 系统使用“根据终端标题变化”，且不会将其误认为输出判定方式

### Requirement: 非空终端输出驱动活动状态

在 `output-change` 方式下，系统 MUST 将来自活动终端的任意非空 PTY 输出视为活动，包括命令回显、进度刷新、ANSI 控制序列和 OSC 序列。每次活动 MUST 将对应终端设为工作中，并以最后一次活动为起点计算 1.5 秒静默期。静默期结束时，当前选中的终端 MUST 变为空闲，未选中的终端 MUST 变为未读；空输出、用户输入但未产生回显以及错误事件 MUST NOT 触发活动。

#### Scenario: 首次输出显示工作中
- **WHEN** 输出判定方式下的活动终端收到非空输出
- **THEN** 该终端和聚合后的任务实时状态显示为工作中

#### Scenario: 连续输出推迟静默判定
- **WHEN** 终端在首次输出后的 1.5 秒内再次收到非空输出
- **THEN** 系统从最新输出重新计算静默期，且终端在最新输出后的 1.5 秒前保持工作中

#### Scenario: 未选中终端停止输出
- **WHEN** 未选中的工作中终端在最后一次非空输出后静默满 1.5 秒
- **THEN** 该终端变为未读，并按既有优先级更新任务实时状态

#### Scenario: 选中终端停止输出
- **WHEN** 当前选中的工作中终端在最后一次非空输出后静默满 1.5 秒
- **THEN** 该终端变为空闲，并按既有优先级更新任务实时状态

### Requirement: 自动状态信号按方式隔离

系统 MUST 只在所选的自动状态管理方式下处理其对应的活动信号。`title-change` MUST 保持仅由实际变化的 OSC 标题触发自动活动；`output-change` MUST 由非空终端输出触发自动活动；`http` MUST 不因终端输出自动改变状态。方式切换时，系统 MUST 清除旧方式留下的临时自动状态和静默计时器。已启用的本机 HTTP 服务 MUST 继续允许其既有的显式状态更新接口。

#### Scenario: 标题方式忽略普通输出
- **WHEN** 标题变化方式下的终端收到不包含完整且不同 OSC 标题的非空输出
- **THEN** 该输出不会自动将终端标记为工作中

#### Scenario: HTTP 方式忽略终端输出
- **WHEN** HTTP 状态管理方式下的终端收到非空输出且没有 HTTP 状态更新
- **THEN** 该输出不会自动改变终端或任务的实时状态

#### Scenario: 切换离开输出判定方式
- **WHEN** 工作中终端的设置从输出判定方式切换为标题变化或 HTTP 方式
- **THEN** 系统清除该终端的自动工作中状态和未到期的静默计时器，后续旧计时器不得再改变状态

### Requirement: 手动关闭已退出终端后清理任务异常状态

系统 MUST 在用户成功关闭一个已经退出的终端后，将该终端从临时实时状态服务中移除，并发布包含更新后任务聚合状态的实时状态事件。若该终端是任务中唯一的异常终端，任务实时状态 MUST 从 `error` 恢复为 `idle`；若任务仍有其他终端，任务实时状态 MUST 继续按照剩余终端的状态优先级聚合。该清理 MUST 不改变持久化任务状态或该终端已经发生的原始退出原因。

#### Scenario: 异常退出后手动关闭唯一终端

- **WHEN** 终端自然退出并被标记为 `error`，且用户随后在任务树中关闭该已退出终端
- **THEN** 系统从实时状态服务移除该终端，发布 `terminalRemoved` 事件，并将任务实时状态更新为 `idle`

#### Scenario: 关闭异常终端后保留其他终端状态

- **WHEN** 任务有一个异常终端和至少一个其他终端，用户关闭该异常终端
- **THEN** 系统移除异常终端，但任务实时状态继续反映剩余终端中优先级最高的状态

#### Scenario: 关闭活动终端保持既有行为

- **WHEN** 用户关闭一个仍处于活动状态的终端
- **THEN** 系统继续发布该终端的正常关闭事件，并且重复的实时状态移除调用不得产生错误或改写原始退出原因

#### Scenario: 关闭失败时保留异常提示

- **WHEN** 关闭终端操作失败
- **THEN** 系统不得移除该终端的实时状态或前端条目，并继续向用户显示关闭错误
