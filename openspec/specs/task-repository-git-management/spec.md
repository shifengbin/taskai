## Requirements
### Requirement: 发现任务工作目录中的 Git 仓库
系统 MUST 在用户查看任务详情的 Git 标签时，基于该任务保存的工作目录发现其中所有 Git 仓库。系统 MUST 识别普通 Git 仓库和 Git worktree，MUST 使用相对于任务工作目录的稳定路径区分仓库，MUST 跳过 `.git` 元数据目录和符号链接目录，且 MUST 不访问任务工作目录之外的路径。系统 MUST 使用持久化的 Git 最大扫描深度限制目录遍历；任务工作目录为第 1 层，直属子目录为第 2 层。默认最大深度 MUST 为 2，且设置值 MUST 限制在 1–10。任务没有保存工作目录，或保存的工作目录尚未实际创建时，系统 MUST 不显示 Git 标签；任务工作目录存在但未发现仓库时，系统 MUST 展示明确空态。

#### Scenario: 列出多个普通仓库和 worktree
- **WHEN** 用户打开一个任务的 Git 标签，且其工作目录中包含两个普通 Git 仓库和一个 Git worktree
- **THEN** 系统列出这三个仓库，分别显示相对路径和当前分支，且不将 `.git` 元数据目录作为仓库列出

#### Scenario: 默认深度不进入第二层子目录
- **WHEN** Git 最大扫描深度为默认值 2，任务工作目录的直属子目录中还包含一个 Git 仓库
- **THEN** 系统列出任务目录与直属子目录中的仓库，但不进入直属子目录的下一层目录

#### Scenario: 提高深度后发现更深层仓库
- **WHEN** 用户将 Git 最大扫描深度保存为 3，任务工作目录的第二层子目录中包含 Git 仓库
- **THEN** 系统列出该更深层仓库

#### Scenario: 任务没有工作目录
- **WHEN** 用户查看没有保存工作目录，或虽已保存预期路径但工作目录尚未创建的任务详情
- **THEN** 系统不显示 Git 标签，也不请求 Git 仓库列表

#### Scenario: 从 Git 标签切换到没有工作目录的任务
- **WHEN** 用户正在查看某任务的 Git 标签，随后切换到没有保存工作目录或工作目录尚未创建的任务
- **THEN** 系统选中并展示新任务的“项目信息”，且不保留不可见的 Git 标签状态

#### Scenario: 拒绝工作目录外的仓库请求
- **WHEN** 前端请求读取或操作不在该任务工作目录内的仓库路径
- **THEN** 后端拒绝请求且不启动 Git 进程

### Requirement: 每个仓库独立展示 Git 状态和单一主操作
系统 MUST 为每个发现的仓库独立展示当前分支、所选远程和工作区状态，并为该仓库提供恰好一个随 Git 状态变化的主操作按钮。仓库有任何已跟踪或未跟踪改动时按钮 MUST 显示“提交”；工作区干净且所选远程不存在当前本地分支时按钮 MUST 显示“发布分支”；工作区干净且所选远程存在当前分支时按钮 MUST 显示“同步远程”。各仓库的提交信息、加载、操作中和错误状态 MUST 相互隔离。

#### Scenario: 多仓库状态独立
- **WHEN** 用户提交第一个仓库时第二个仓库处于发布分支状态
- **THEN** 第一个仓库刷新为自身的新状态，第二个仓库的按钮和输入状态不变

#### Scenario: 已同步仓库不重复同步
- **WHEN** 仓库工作区干净，当前分支跟踪所选远程的同名分支，且本地、跟踪引用与远程提交均无差异
- **THEN** 系统显示置灰且不可点击的“同步远程”按钮

### Requirement: 按受控流程提交全部改动
系统 MUST 要求用户填写非空提交信息后才允许提交。提交时系统 MUST 在该仓库内依次执行 `git add -A` 和 `git commit -m <提交信息>`，从而包含该仓库的所有已修改、已删除和未跟踪文件。任何步骤失败时系统 MUST 停止后续命令、向用户展示 Git 错误，并重新读取仓库状态。

#### Scenario: 提交全部改动后转为发布分支
- **WHEN** 用户为有改动且远程没有同名分支的仓库填写提交信息并点击“提交”
- **THEN** 系统依次暂存全部改动并创建提交，刷新后该仓库按钮显示“发布分支”

### Requirement: 使用确定的远程选择规则发布和同步分支
系统 MUST 优先选择名为 `origin` 的远程；没有 `origin` 且只有一个远程时 MUST 选择该远程；多个远程且没有 `origin` 时 MUST 拒绝发布或同步并提示用户配置远程；没有远程时 MUST 拒绝发布或同步并提示用户先配置远程。

#### Scenario: 缺少远程配置
- **WHEN** 用户对未配置远程的仓库点击同步操作
- **THEN** 系统不启动网络 Git 命令，并提示用户先配置远程仓库

### Requirement: 发布分支并建立上游关系
系统 MUST 在“发布分支”操作中确认工作区无未提交改动并确认当前本地分支存在。系统 MUST 使用选定远程运行等价于 `git push -u <远程> <当前分支>` 的命令。发布成功后系统 MUST 刷新仓库状态并显示“同步远程”。

#### Scenario: 成功发布新分支
- **WHEN** 用户点击远程不存在同名分支的干净仓库的“发布分支”按钮
- **THEN** 系统向选定远程推送当前分支并建立上游关系

### Requirement: 同步已发布分支
系统 MUST 在“同步远程”操作中确认工作区无未提交改动。当前分支未设置上游但所选远程已有同名分支时，系统 MUST 先获取并建立该同名远程分支的上游关系；随后系统 MUST 先拉取再推送。拉取失败时系统 MUST 不执行推送，且 MUST 将失败原因展示给用户。

#### Scenario: 为已有远程分支建立上游后同步
- **WHEN** 用户点击工作区干净、远程已有同名分支但本地尚未设置上游的仓库的“同步远程”按钮
- **THEN** 系统先建立同名远程分支的上游关系，再执行拉取和推送
