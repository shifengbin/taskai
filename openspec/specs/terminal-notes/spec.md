# terminal-notes Specification

## Purpose

定义在前端运行期间，按终端会话收集鼠标选区备注、查看汇总、复制或发送至关联终端，并清理会话状态的完整行为。

## Requirements

### Requirement: 备注按活动终端会话仅在运行期保存

系统 MUST 仅在前端应用运行期间按任务标识和终端标识的组合维护备注列表。每条备注 MUST 保存创建时的原文选区和用户输入的备注文本，并且不同终端会话的列表 MUST 相互隔离。系统 MUST NOT 将备注内容写入应用数据文件、任务数据、设置或后端持久化状态。

系统 MUST 在终端关闭、终端以会话释放原因退出、所属任务结束或删除、以及前端应用卸载时清除相应会话的备注和“操作后清空”偏好。异常退出但仍保留只读输出快照的终端不得新增或发送备注；其已有备注也不得被迁移到其他终端。该偏好仅在前端应用运行期间按会话保存，缺失时默认为已勾选，应用重启后不得恢复。

#### Scenario: 两个终端的备注相互隔离

- **WHEN** 用户分别在同一任务的终端 A 和终端 B 保存备注
- **THEN** 每个终端标题栏和备注面板仅显示自身的记录，发送 A 的汇总不会读取、发送或清空 B 的记录

#### Scenario: 关闭终端后清除备注

- **WHEN** 一个包含未发送备注的活动终端被关闭
- **THEN** 系统清除该终端的全部备注，之后新建或切换到任意终端均不显示这些记录

#### Scenario: 应用重启不恢复备注

- **WHEN** 用户保存备注后退出并重新打开应用
- **THEN** 系统不恢复退出前任一终端的备注，且持久化数据中不包含备注内容

### Requirement: 鼠标选区提供备注输入入口

系统 MUST 在任何活动终端中响应用户完成的非空 xterm 本地文本选区，不得因终端程序开启鼠标追踪或既有 `disableTaskAIMouseClipboard` 数据而禁用备注。拖拽选择范围、双击选择单词和三击选择整行完成后，系统 MUST 在结束位置附近、终端内容区边界内显示半透明的备注图标按钮；空选区、选区被清除、点击其他位置、切换或关闭终端时，系统 MUST 隐藏该按钮。

点击入口后，系统 MUST 打开备注输入框，显示对应选区原文并提供多行备注输入。系统 MUST 拒绝仅包含空白字符的备注；保存有效内容时将原文和备注追加到当前终端会话列表，取消时不得创建记录。保存或取消后系统 MUST 关闭输入框、隐藏入口并将输入焦点归还给原终端。

#### Scenario: 鼠标框选后添加备注

- **WHEN** 用户在活动终端中鼠标选中 `编译失败`，点击附近的备注按钮，输入 `检查依赖版本` 并保存
- **THEN** 当前终端新增一条原文为 `编译失败`、备注为 `检查依赖版本` 的记录，标题栏数量增加，焦点回到该终端

#### Scenario: 鼠标追踪期间框选后添加备注

- **WHEN** Claude、Codex 或其他终端程序已开启鼠标追踪，用户拖拽选择非空文本
- **THEN** 系统显示备注按钮且不把该拖拽发送给终端程序，用户可以用完整选区原文创建当前终端的备注

#### Scenario: 选择后移动鼠标仍可添加备注

- **WHEN** Claude、Codex 或其他终端程序启用了无按键鼠标移动追踪，用户完成非空选择后移动鼠标
- **THEN** 原选区和备注按钮保持可见，打开输入框时仍使用选择完成时的完整原文

#### Scenario: 双击单词后添加备注

- **WHEN** 用户在活动终端中双击一个单词并完成本地选择
- **THEN** 系统在双击位置附近显示备注按钮，打开输入框时原文为 xterm 选择的完整单词

#### Scenario: 三击整行后添加备注

- **WHEN** 用户在活动终端中三击一行并完成本地选择
- **THEN** 系统在三击位置附近显示备注按钮，打开输入框时原文为 xterm 选择的完整终端行

#### Scenario: 输入备注时保留选区原文

- **WHEN** 用户已打开原文为 `编译失败` 的备注输入框，并点击或输入备注内容
- **THEN** 输入框持续显示未改变的原文 `编译失败`，直至用户保存或取消

#### Scenario: 空选区不显示入口

- **WHEN** 用户在活动终端内容区单击但未选择任何文本
- **THEN** 系统不显示备注按钮且不打开备注输入框

#### Scenario: 取消备注输入

- **WHEN** 用户打开原文为 `编译失败` 的备注输入框后取消
- **THEN** 当前终端的备注列表保持不变，浮动按钮和输入框均关闭

### Requirement: 从当前终端标题栏查看、复制并发送备注

系统 MUST 在每个活动终端标题栏提供备注面板入口，其无障碍标签和悬浮说明 MUST 包含当前终端备注数量。打开面板后，系统 MUST 按创建顺序显示当前终端的原文与备注；没有记录时 MUST 显示空态并禁用复制和发送按钮。面板底部 MUST 提供默认勾选的“操作后清空”复选框、“复制到剪贴板”和“发送到终端”按钮。复选框值 MUST 仅在当前终端会话的应用运行期间保持，切换终端或关闭并重新打开面板时保留，且不同终端互不影响。

复制和发送按钮 MUST 使用当前终端的全部记录按已保存模板生成的同一份汇总文本。复制 MUST 写入系统剪贴板；发送 MUST 仅通过该终端 xterm 会话的模拟粘贴机制写入。系统 MUST NOT 追加未配置的提交字符，且不得将内容写入其他终端。任一操作尝试后，若当前终端的“操作后清空”已勾选，系统 MUST 清空该终端的全部备注；未勾选时 MUST 保留备注。复制或发送失败时 MUST 显示相应错误，且仍按当前勾选状态处理备注。

#### Scenario: 查看当前终端的备注数量和内容

- **WHEN** 当前终端保存两条备注并点击标题栏备注入口
- **THEN** 面板显示数量为 2，并按创建顺序显示两条原文和备注及可用的发送按钮

#### Scenario: 默认勾选时复制后清空当前终端记录

- **WHEN** 当前终端有两条备注，用户保持默认勾选并在面板点击复制到剪贴板
- **THEN** 系统将格式化汇总文本写入系统剪贴板，随后清空这两条记录并使面板显示空态

#### Scenario: 取消勾选后复制和发送保留记录

- **WHEN** 当前终端取消勾选“操作后清空”，先复制汇总文本再发送到终端
- **THEN** 两种操作都使用相同的格式化汇总文本，且当前终端的备注保持不变；关闭并重新打开该终端的备注面板时复选框仍未勾选

#### Scenario: 目标终端已关闭时按勾选状态清空

- **WHEN** 用户打开备注面板后目标终端会话关闭，且“操作后清空”已勾选，再点击发送
- **THEN** 系统不向任何终端写入内容，显示终端不可用错误，并清空该终端的备注

### Requirement: 设置中持久化备注汇总模板和自动换行规则

系统 MUST 在应用设置中持久化备注模板，包含原文前缀、备注前缀和列表统一后缀。新安装和缺少模板字段的既有设置 MUST 使用原文前缀 `原文：`、备注前缀 `备注：` 和空列表统一后缀；用户保存的空字符串 MUST 作为有效模板内容保留。设置编辑必须使用既有设置草稿，取消设置不得修改已保存模板。

汇总每条记录时，系统 MUST 按 `原文前缀 + 原文 + 换行 + 备注前缀 + 备注` 生成文本；多条记录按创建顺序以换行连接。最后系统 MUST 再追加一个换行、列表统一后缀和一个结尾换行，不论统一后缀是否为空。系统 MUST 按原样保留原文、备注和模板字段，不得额外裁剪、替换或插入命令执行字符。

#### Scenario: 保存模板并在重启后保留

- **WHEN** 用户将原文前缀设为 `引用：`、备注前缀设为 `处理：`、列表统一后缀设为 `请逐项处理。` 后保存设置并重新打开应用
- **THEN** 设置显示相同的三个模板字段，后续备注汇总使用这些内容

#### Scenario: 取消模板草稿

- **WHEN** 用户修改备注模板后取消设置
- **THEN** 系统不持久化修改，重新打开设置时显示上次保存的模板

#### Scenario: 自动换行汇总两条记录

- **WHEN** 原文前缀为 `原文：`、备注前缀为 `备注：`、列表统一后缀为 `请处理`，两条记录依次为原文 `一`、备注 `甲` 与原文 `二`、备注 `乙`
- **THEN** 发送文本恰好为 `原文：一\n备注：甲\n原文：二\n备注：乙\n请处理\n`

#### Scenario: 空统一后缀仍保留结尾换行

- **WHEN** 列表统一后缀为空且当前终端有一条有效备注
- **THEN** 汇总文本在该条备注后仍包含两个自动追加的换行位置，不添加其他文本或提交字符
