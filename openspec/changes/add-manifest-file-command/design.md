## 背景

当前生命周期编排同时支持自定义 Shell 命令和固定系统命令。内置 Git 仓库克隆命令会读取任务保存的 Git 附加信息，并在 Git 信息的 `branch` 为空时使用任务模板中的 `branch` 值。外部工具若需要相同的仓库清单，只能实现自定义命令并自行处理生命周期 JSON 输入，容易与内置 Git 行为脱节。

本变更新增固定系统命令“生成清单文件”，由后端直接构造 YAML 并写入任务工作目录。该命令跨越生命周期设置、命令参数校验、命令链执行、任务模板分支解析和前端设置展示，需要在实现前固定安全边界和数据解析规则。

## 目标 / 非目标

**目标：**

- 在 `beforeStart`、`postStart` 与 `updateTask` 链中提供可复用的清单生成命令。
- 以任务标题、描述和已选内置 Git 信息生成稳定、可安全解析的 YAML。
- 统一 Git 克隆与清单导出的分支回填规则。
- 限制所有输出到任务工作目录，并安全覆盖已有普通文件。

**非目标：**

- 不提供用户自定义 YAML 模板、字段映射或任意额外信息分类导出。
- 不在该命令中克隆、拉取或校验远程 Git 仓库。
- 不修改现有自定义生命周期命令的标准输入输出管道。
- 不为已有命令链自动插入清单生成命令。

## 决策

### 新增固定命令类型，而非复用自定义 Shell 命令

为设置层新增固定命令标识、命令类型和默认命令定义，并将其限制为 `beforeStart`、`postStart`、`updateTask`。命令链执行器增加对应分支，直接生成文件而不启动 Shell。

固定命令可以复用任务快照、Git 信息筛选与错误呈现机制，使用户不必依赖本机脚本或手动解析 JSON。备选方案是仅通过自定义命令配合标准输入实现；它不需要后端改动，但无法保证 YAML 转义、路径安全和模板分支逻辑的一致性，因此不采用。

### 参数以 `dir` 和 `name` 表达，并在设置保存时规范化

链级追加参数只接受至多一个 `dir=<相对目录>` 和至多一个 `name=<文件名>`，允许任意顺序。缺省 `dir` 解析为 `.`，缺省 `name` 解析为 `manifest.yaml`。`dir` 必须是留在任务工作目录内的相对路径；`name` 必须是单个非空文件名，不能是绝对路径、`.`、`..` 或包含目录分隔符。重复、未知或格式错误的参数会在命令链保存时被拒绝。

`dir` 与 `name` 分离使目录意图和文件名意图明确，也避免允许 `name` 绕开目录校验。允许任意输出路径的方案更灵活，但会增加越界写入风险，因此不采用。

### 从任务 Git 快照构建 YAML，并在生成时解析分支回填

清单根节点固定为 `iteration`、`desc`、`repos`。前两者分别取任务标题与描述；`repos` 按任务已选择的内置 Git 附加信息保存顺序生成。每个条目固定写入 `name`、`url`、`branch`，分别来自 Git 信息的项目名称、仓库地址和分支。

每个 Git 条目的分支先取去除首尾空白后的 Git 信息 `branch`；为空时取当前任务模板定义下任务保存的 `branch` 值；仍为空时写入空字符串。即使任务快照曾在保存时回填过，也在生成阶段再次执行该规则，使历史快照与当前导出一致。只输出任务已选择的内置 Git 信息；没有 Git 信息时写入空序列。

使用 `gopkg.in/yaml.v3` 从结构化数据序列化，避免任务标题、描述、仓库地址或分支中的引号、换行和 YAML 保留字符破坏清单。手工拼接文本无法可靠处理这些情况，因此不采用。

### 在受验证的工作目录内原子替换文件

执行时先确认任务工作目录存在且不是符号链接，再解析并逐级检查 `dir`，拒绝会离开工作目录的路径或符号链接。不存在的合法子目录按受限权限创建。目标如为符号链接、目录或其他非普通文件则失败；普通文件可被覆盖。

清单先写入目标同目录的临时文件，成功关闭后再以重命名替换目标文件，失败时清理临时文件。这样 `updateTask` 重试或重复运行不会遗留部分 YAML。直接截断写入虽然更简单，但崩溃或写入失败可能留下损坏清单，因此不采用。

### 生命周期时机与失败语义保持既有约定

`beforeStart` 使用该命令时，命令链必须先创建任务工作目录；若目录不存在，生成命令失败并阻止任务启动。`postStart` 与 `updateTask` 的失败遵循现有提交后钩子规则：保留已提交的任务状态或编辑结果，并显示可重试的生命周期错误。系统命令不改变传入或传出的自定义命令字节流。

## 风险 / 权衡

- [在 `beforeStart` 中未先创建任务工作目录] → 返回明确目录不可用错误，并在命令说明和测试中要求“创建任务工作目录”在前。
- [用户配置越界路径或通过符号链接跳出工作目录] → 在参数规范化与运行时逐层执行路径、符号链接和目标类型检查。
- [重复运行覆盖了用户手动修改的清单] → 这是用户已确认的覆盖语义；通过原子替换保证覆盖只发生在完整内容准备成功后。
- [模板字段或历史 Git 快照缺少分支] → 导出阶段再执行分支回填，最终明确输出空字符串而非省略字段。
- [新增 YAML 依赖增加构建体积] → 仅引入成熟的 Go YAML 库，并以结构化序列化换取正确的字符转义和稳定维护性。

## 迁移计划

1. 将固定命令纳入默认生命周期命令规范化逻辑，使已有设置在下次加载和保存后自动包含该命令。
2. 保持已有命令链不变，不自动配置新命令；用户按需将它加入三个允许的钩子。
3. 发布后如需回退，移除新命令的链引用即可停止生成；已生成的清单文件不自动删除。
