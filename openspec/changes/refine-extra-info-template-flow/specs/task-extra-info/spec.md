## MODIFIED Requirements

### Requirement: 独立维护额外信息分类和模板
系统 MUST 在设置功能之外提供独立的额外信息管理入口。额外信息模板即用户可选择的分类，模板 MUST 保存唯一标识、非空且唯一的分类名称、一个或多个固定字段定义及零个或多个动态参数定义。固定字段定义 MUST 保存键、显示名称和默认值；动态参数定义 MUST 保存键、显示名称和必填标记。系统 MUST 允许用户基于模板创建、查看、修改和删除可复用的信息；信息 MUST 保存其模板引用和固定字段实际值。

#### Scenario: 创建自定义模板并创建信息
- **WHEN** 用户新建一个非 Git 模板，并基于该模板填写固定字段后保存信息
- **THEN** 系统保存该模板和信息，且后续创建或编辑任务时将该信息作为该模板分类下的可选项提供

#### Scenario: 新建模板自动包含名称字段
- **WHEN** 用户开始新建一个非内置模板
- **THEN** 系统预置键为 `name` 的固定字段，且用户可修改该字段的显示名称

#### Scenario: 信息使用名称字段展示
- **WHEN** 用户保存一条 `name` 字段值为“API 服务”的信息
- **THEN** 系统在信息列表、任务选择器和任务已选标签中展示“API 服务”，且不要求用户另行填写独立展示名称

#### Scenario: 模板存在信息时不可删除
- **WHEN** 用户尝试删除仍关联一条或多条信息的模板
- **THEN** 系统拒绝删除并提示先删除或迁移关联信息，且不修改任何已有任务快照

#### Scenario: 删除信息不改变任务快照
- **WHEN** 用户删除已经被一个或多个任务选用的信息
- **THEN** 系统从可选信息中移除该信息，且不修改任何已有任务保存的附加信息

#### Scenario: 管理入口不属于设置
- **WHEN** 用户查看顶部工具栏
- **THEN** 系统在设置按钮旁展示额外信息管理入口，且不在设置弹窗中提供额外信息管理标签

### Requirement: 校验模板字段与参数定义
系统 MUST 拒绝保存缺少分类名称、未包含固定字段、未包含键或显示名称的固定字段、未包含键或显示名称的动态参数、或包含冲突键的模板。每个模板 MUST 包含一个键为 `name` 的固定字段；该字段在非内置模板中可改显示名称。每条信息的 `name` 固定字段实际值 MUST 非空。模板内固定字段键和动态参数键 MUST 各自唯一且不得彼此冲突。

#### Scenario: 保存缺少名称字段的模板被拒绝
- **WHEN** 用户保存一个未包含键为 `name` 的固定字段的模板
- **THEN** 系统拒绝保存并说明必须包含名称字段

#### Scenario: 保存冲突字段键被拒绝
- **WHEN** 用户保存一个固定字段键与另一固定字段键或动态参数键相同，或保存重复动态参数键的模板
- **THEN** 系统拒绝保存并说明字段键冲突

#### Scenario: 保存空信息名称被拒绝
- **WHEN** 用户基于模板保存 `name` 字段为空白的额外信息
- **THEN** 系统拒绝保存并提示必须填写名称字段

#### Scenario: 已关联信息的字段键不可删除或改名
- **WHEN** 用户修改一个已经关联信息的模板，并删除或修改该模板固定字段的键
- **THEN** 系统拒绝保存并说明该字段已被信息使用

### Requirement: 创建和编辑任务时保存附加信息快照
系统 MUST 在创建和编辑任务时按分类筛选并选择已保存的信息，且允许一个任务选择多个信息。系统 MUST 在表单上方集中展示全部已选信息，每个信息使用紧凑方形标签并提供 `x` 移除按钮。选中信息后，系统 MUST 只读展示其固定字段，并展示模板定义的动态参数输入。用户 MUST 能够为当前任务新增、修改或删除动态参数，但不得在任务表单中修改或新增固定字段。必填动态参数去除首尾空白后为空时，系统 MUST 阻止保存。保存成功时，任务 MUST 记录分类、固定字段、动态参数定义和参数实际值的独立快照。

#### Scenario: 基于 Git 信息创建任务
- **WHEN** 用户选择一条 Git 信息，并为必填 `branch` 参数填写“main”
- **THEN** 系统创建任务并保存该信息的固定字段快照以及键为 `branch`、值为“main”的参数快照

#### Scenario: 固定字段在任务中只读
- **WHEN** 用户在创建或编辑任务时选择一条包含项目名称和仓库地址的 Git 信息
- **THEN** 系统展示这两个固定字段和值，且不提供修改或新增固定字段的输入控件

#### Scenario: 任务新增动态参数
- **WHEN** 用户在任务表单中为已选择信息新增一个键、显示名称、必填标记和值均有效的动态参数
- **THEN** 系统仅在该任务附加信息快照中保存该参数，且不修改模板或可复用信息

#### Scenario: 任务新增冲突动态参数被拒绝
- **WHEN** 用户新增的任务级动态参数键与固定字段或已有动态参数键相同
- **THEN** 系统拒绝保存并说明参数键冲突

#### Scenario: 跨分类选择保持不变
- **WHEN** 用户先在 `git` 分类选择一条信息，再切换到另一分类并选择一条信息
- **THEN** 两条信息均保留为已选状态，并在表单上方分别显示可通过 `x` 移除的方形标签

#### Scenario: 编辑已删除信息的历史快照
- **WHEN** 用户编辑包含已删除信息或模板快照的任务
- **THEN** 系统展示该快照，并允许用户修改、增加或删除其动态参数值，且固定字段继续只读

### Requirement: 任务详情按目录输出附加信息
系统 MUST 在 `GET /api/v1/tasks/{taskId}` 的成功响应中包含 `extraInfo` 对象。系统 MUST 以每条任务附加信息的 `catalogue` 作为对象键，并将同一 `catalogue` 的信息聚合为数组。每个数组元素 MUST 将每个固定字段键映射为任务快照中的值，并将每个动态参数键映射为该任务保存的参数值。

#### Scenario: 返回按 Git 目录聚合的信息
- **WHEN** 客户端查询一个包含两个 Git 信息附加项的任务详情
- **THEN** 响应的 `extraInfo.git` 为包含两个对象的数组，且每个对象都包含 `name`、`repository`、`branch` 键和值

#### Scenario: 接口不返回展示元数据
- **WHEN** 客户端查询包含附加信息的任务详情
- **THEN** `extraInfo` 中不包含模板标识、信息标识、固定字段显示名称、参数显示名称或独立的 `catalogue` 字段

#### Scenario: 查询未附加信息的任务
- **WHEN** 客户端查询未选择任何附加信息的任务
- **THEN** 响应包含空对象 `"extraInfo": {}`

#### Scenario: 返回未填写的可选参数
- **WHEN** 客户端查询包含未填写可选动态参数的任务详情
- **THEN** 响应包含该参数键，且其值为空字符串

#### Scenario: 返回复选框参数的布尔值
- **WHEN** 客户端查询包含值为 `true` 或 `false` 的复选框动态参数的任务详情
- **THEN** 响应将该参数键映射为 JSON 布尔值，而非字符串；文本参数和固定字段仍返回字符串

### Requirement: 任务详情返回活动终端
系统 MUST 仅在 `GET /api/v1/tasks/{taskId}` 的成功响应中返回 `terminals` 数组。数组每项 MUST 包含终端 `id`、执行 `command` 和实时 `status`；普通终端的命令 MUST 为 Shell 路径，自定义命令终端的命令 MUST 为启动命令。`status` MUST 为 `idle`、`working`、`unread` 或 `error`。系统 MUST 只返回当前活动会话，不持久化终端历史；任务没有活动会话时 MUST 返回空数组。任务列表接口不得增加该字段。

#### Scenario: 返回普通与命令终端
- **WHEN** 客户端查询一个同时运行普通 Shell 终端与自定义命令终端的任务详情
- **THEN** `terminals` 包含两项，普通终端返回 Shell 路径，自定义终端返回执行命令，并各自返回当前实时状态

#### Scenario: 未运行终端时返回空数组
- **WHEN** 客户端查询没有活动终端的任务详情
- **THEN** 响应包含 `"terminals": []`

#### Scenario: 任务列表不返回终端
- **WHEN** 客户端请求 `GET /api/v1/tasks`
- **THEN** 列表元素不包含 `terminals` 字段

### Requirement: 保持旧数据和既有任务接口兼容
系统 MUST 能够读取没有模板、信息或任务附加信息字段的既有数据文件。系统 MUST 将当前单层额外信息模板迁移为新模板定义和对应的信息，并确保内置 Git 模板存在。迁移 MUST 保留旧固定字段、参数定义、静态值和原展示名称；原展示名称 MUST 作为迁移信息的 `name` 值。对于同一旧分类中字段结构不一致的记录，系统 MUST 拆分为独立模板以避免丢失信息。系统 MUST 将旧单键、键显示名称和静态值的模板及任务快照兼容为包含一个固定字段的数据。系统 MUST 保持 `GET /api/v1/tasks` 的响应字段和筛选行为不变。

#### Scenario: 读取没有额外信息字段的数据文件
- **WHEN** 应用加载不含额外信息模板、信息或任务附加信息字段的既有数据文件
- **THEN** 系统正常加载任务和设置，并提供内置 Git 模板供用户开始管理附加信息

#### Scenario: 读取当前单层模板数据
- **WHEN** 应用加载包含当前分类和单层额外信息模板的旧数据文件
- **THEN** 系统迁移出可用模板和对应的信息，且旧展示名称成为迁移信息的 `name` 值

#### Scenario: 读取同分类不同结构的旧模板
- **WHEN** 应用加载同一旧分类下字段或参数结构不同的多个旧模板
- **THEN** 系统保留每条旧模板对应的信息和全部字段值，并为不同结构创建可区分的迁移模板

#### Scenario: 读取旧单键值任务快照
- **WHEN** 应用加载使用旧版单一信息键和静态值保存的任务快照
- **THEN** 系统将其作为包含一个固定字段的兼容数据读取，且任务详情继续返回该键和值

#### Scenario: 查询任务列表
- **WHEN** 客户端请求 `GET /api/v1/tasks`
- **THEN** 系统按既有规则返回任务列表，且列表元素不增加 `extraInfo` 字段

## ADDED Requirements

### Requirement: 提供受保护的内置 Git 模板
系统 MUST 提供且持久化一个不可删除的内置 Git 模板。该模板 MUST 包含键为 `name`、显示名称为“项目名称”的固定字段，键为 `repository`、显示名称为“仓库地址”的固定字段，以及键为 `branch`、显示名称为“仓库分支”的动态参数。系统 MUST 拒绝删除或修改这些内置字段和参数的键或显示名称；系统 MUST 允许用户为 Git 模板新增字段和动态参数、设置固定字段默认值，并调整 `branch` 的必填标记。

#### Scenario: 首次打开额外信息管理
- **WHEN** 用户在没有任何额外信息数据的新安装中打开额外信息管理
- **THEN** 系统展示内置 Git 模板及其项目名称、仓库地址和仓库分支定义

#### Scenario: 基于 Git 模板创建信息时应用默认值
- **WHEN** 用户为 Git 模板的仓库地址设置默认值后新建一条 Git 信息
- **THEN** 信息表单将仓库地址输入框初始化为该默认值，且用户可在保存信息前修改该值

#### Scenario: 修改 Git 内置字段键被拒绝
- **WHEN** 用户尝试修改 Git 模板中 `name`、`repository` 或 `branch` 的键或显示名称，或删除其中任一项
- **THEN** 系统拒绝保存并说明 Git 内置字段不可修改

#### Scenario: 配置 Git 分支必填标记
- **WHEN** 用户将 Git 模板的 `branch` 参数设置为必填并保存
- **THEN** 后续创建或编辑任务时未填写仓库分支将无法保存，已存在任务快照不受影响

## ADDED Requirements

### Requirement: 信息保存模板之外的动态参数
系统 MUST 允许用户在创建或编辑一条信息时维护仅属于该信息的动态参数。每个信息级动态参数 MUST 保存键、显示名称、默认值和必填标记。系统 MUST 拒绝与模板固定字段、模板动态参数或同一信息已有动态参数重名的参数键。选择信息创建任务时，系统 MUST 复制信息级参数及其默认值到任务快照；任务中仅允许修改这类参数的值，且不得回写信息默认值。

#### Scenario: 信息保存模板之外的动态参数
- **WHEN** 用户基于 Git 模板创建“API 服务”信息，并新增键为 `environment`、显示名称为“环境”、默认值为“production”的动态参数
- **THEN** 系统仅在该条信息中保存该参数，且不会向 Git 模板或其他 Git 信息新增该参数

#### Scenario: 信息动态参数键冲突被拒绝
- **WHEN** 用户为信息新增与模板固定字段、模板动态参数或同一信息已有动态参数重名的参数键
- **THEN** 系统拒绝保存并说明参数键冲突

#### Scenario: 选择信息时带入信息级参数默认值
- **WHEN** 用户在任务中选择一条保存了“环境=production”信息级动态参数的 Git 信息
- **THEN** 系统在该信息的动态参数区域显示“环境”和值“production”，用户可修改该值，且不会修改可复用信息中的默认值

### Requirement: 稳定展示分类模板并按名称搜索信息
系统 MUST 将分类模板定义区与信息列表区分开显示。分类模板定义区 MUST 支持整体折叠，且模板多于一条时布局 MUST 在窄宽度下换行而不遮挡或挤压操作控件。信息列表 MUST 按模板保留全部分类分组；名称模糊搜索 MUST 只筛选信息行，不得隐藏分类模板定义或分类分组标题。系统 MUST 在搜索命中时自动展开对应信息分组，并默认展开 Git 信息分组。

#### Scenario: 搜索信息不隐藏分类
- **WHEN** 用户在额外信息管理中搜索“缺陷”，且 Git 分类没有匹配信息
- **THEN** Git 模板定义和 Git 信息分类标题仍显示，缺陷分类自动展开并仅显示名称匹配的信息

#### Scenario: 折叠分类模板定义
- **WHEN** 用户点击“分类模板”面板标题
- **THEN** 系统折叠或展开整块模板定义列表，不影响下方信息分组的展开状态或搜索条件

#### Scenario: 低高度窗口展示全部模板
- **WHEN** 分类模板面板展开且窗口高度不足以同时容纳模板列表和信息列表
- **THEN** 模板列表中的每个模板均按顺序展示，信息区域不得覆盖模板行，用户可滚动管理弹窗内容查看其余内容

### Requirement: 支持复选框动态参数
系统 MUST 允许模板、信息和任务级动态参数声明 `text` 或 `checkbox` 输入类型。未声明类型的历史参数 MUST 视为 `text`。`checkbox` 参数 MUST 仅保存字符串 `true` 或 `false`，新建默认值为 `false`，且不得标记为必填；系统 MUST 在保存模板、信息和任务快照时强制执行这些约束。任务中来自模板或信息的复选框参数 MUST 仅允许修改布尔值，任务级新增参数可选择类型。

#### Scenario: 任务使用信息中的复选框参数
- **WHEN** 用户为一条信息新增键为 `deploy`、显示名称为“允许部署”的复选框参数，并在任务中选择该信息
- **THEN** 任务默认显示未选中状态；用户选中后任务快照保存 `deploy` 为 `true`，且该参数不显示必填设置
