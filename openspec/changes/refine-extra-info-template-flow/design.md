## Context

当前 `ExtraInfoTemplate` 同时承担分类、字段结构、固定值和任务选择项的职责。用户必须为每一条仓库等信息重复定义相同的字段和参数，且“模板”的含义在管理界面和任务表单之间不一致。持久化数据仅包含分类集合和单层模板集合，任务中保存的是独立的 `ExtraInfo` 快照。

本变更需要将模型拆为三个明确层次：模板定义可填写的结构；信息保存一条可复用的固定字段值；任务快照保存任务实际使用的固定值和动态参数值。变更涉及 Go 领域模型、JSON 迁移、Wails 绑定、React 表单、HTTP 输出和测试。旧数据和既有任务详情 API 必须保持可读。

## Goals / Non-Goals

**Goals:**

- 让用户先创建模板，再基于模板创建多条信息，并在任务中选择信息。
- 保证每个模板都有固定字段 `name`，以该字段值作为信息的展示和保存名称来源。
- 提供受保护、开箱即用的 Git 模板，并允许在不改变内置字段的前提下扩展字段和动态参数。
- 使固定字段值在任务中只读，动态参数值及任务级新增动态参数可编辑，并保留完整任务快照。
- 将当前单层模板数据迁移为新模型，避免丢失现有模板信息和历史任务快照。

**Non-Goals:**

- 不改变任务列表 HTTP 接口的字段或筛选语义。
- 不为任务级动态参数反向修改模板，也不将任务中的参数值同步回信息。
- 不提供模板间批量迁移信息、跨模板复用字段组或远程 Git 仓库校验。
- 不自动改写历史任务快照以反映之后的模板或信息修改。

## Decisions

### 1. 使用模板、信息和任务快照三层模型

- `ExtraInfoTemplate` 表示原分类的可选类型，保存唯一标识、分类名称、固定字段定义（键、显示名称、默认值）、动态参数定义（键、显示名称、必填标记）和内置标记。
- `ExtraInfo` 表示一条可复用信息，保存模板标识、分类名称及固定字段值。其 `name` 固定字段值是信息的展示名称和持久化名称来源，不再维护可被独立修改的旧 `DisplayName`。
- `Task.ExtraInfo` 仍表示任务快照，保存分类、固定字段、动态参数定义和动态参数值。创建快照时由“信息固定值 + 当前模板参数定义 + 任务输入”组装。

保留 `catalogue` 作为任务详情 `extraInfo` 的分组键和分类名称，避免破坏对外 HTTP 结构。相比直接让任务引用信息，快照模型可确保信息或模板之后被修改、删除时，历史任务不受影响。

备选方案是让信息直接携带模板全部定义并由任务引用信息 ID。该方案会让任务历史随着引用变化，且仍然混淆模板与信息，因此不采用。

### 2. 模板以字段定义保存默认值，信息只保存固定字段实际值

模板固定字段由 `key`、`displayName` 和 `defaultValue` 描述；创建信息时，表单按字段定义渲染并以默认值初始化。保存信息时要求 `name` 值非空，其他固定字段允许为空，除非未来新增明确的必填属性。信息列表、任务选择器和任务选中标签均使用 `name` 字段的实际值展示。

模板字段定义与信息值分离，能够让同一 Git 结构创建多个仓库信息，且默认仓库地址等值只在新建信息时提供初始值。默认值后续调整只影响新建信息，不回写已有信息或任务。

### 3. 内置 Git 模板是受保护的初始数据

仓库首次读取或迁移数据时确保存在一个内置 Git 模板。它的分类名称为 `git`，并含有：

- 固定字段 `name`，显示名称“项目名称”；
- 固定字段 `repository`，显示名称“仓库地址”；
- 动态参数 `branch`，显示名称“仓库分支”，其必填标记可由用户配置。

Git 模板不可删除；上述字段和参数的键与显示名称不可修改或删除。用户可新增固定字段、动态参数，并调整固定字段默认值及 `branch` 的必填标记。新建的非内置模板自动插入 `name` 固定字段，且该字段显示名称可编辑。

使用数据层校验保护该规则，而不是仅在前端禁用控件，以保证 Wails 调用、未来界面和迁移路径均不能破坏内置约束。

### 4. 任务只编辑动态参数，并允许任务级新增参数

任务选择已保存的信息后，表单使用信息的 `name` 值显示选择项，并在只读区域展示该信息的固定字段。模板定义的动态参数在可编辑区域显示，按其 `required` 标记校验。用户可在此区域新增参数；新增项必须包含不与固定字段或已有参数冲突的键、显示名称、必填标记和值，并只写入当前任务快照。

固定字段在任务表单没有编辑或新增入口。编辑已有任务时，即使其来源模板或信息已被删除，也以快照数据继续展示，并仍允许修改、增加或删除动态参数。

### 5. 显式迁移当前单层模板数据

读取数据时按以下顺序归一化：

1. 确保模板、信息和任务快照集合均为非 `nil`，并确保内置 Git 模板存在。
2. 对当前 `ExtraInfoTemplates`（同时含固定值的旧格式）逐条创建或复用迁移模板：保留其 `catalogue` 作为分类名称，将旧字段转成字段定义，并补入 `name` 字段。若旧记录没有 `name`，使用原 `displayName` 作为迁移信息的 `name` 值和新字段显示名称；旧固定值成为模板默认值。
3. 为每条旧记录创建一条信息，固定字段值保留旧静态值，`name` 取原展示名称。多个旧记录的同一分类字段结构不一致时，为每种结构创建带稳定迁移后缀的模板，避免合并时丢失字段或参数。
4. 旧集合完成迁移后以新模板集合和信息集合写回；历史 `Task.ExtraInfo` 仅做既有规范化，不按新模板或信息重建。

迁移必须具备幂等性：再次读取已迁移数据不会重复创建模板或信息。若迁移遇到无法归一化的旧记录，读取失败并保留原文件，不进行部分写入。

### 6. 删除关系与结构变更优先保证可引用数据完整

模板存在关联信息时不可删除；信息删除不会影响任何任务快照。内置 Git 模板始终不可删除。模板修改只影响之后创建的信息和任务；已存在信息保留自己的固定字段值，已存在任务保留自己的快照。实现时对会导致已关联信息无法解释的字段键删除或改名进行拒绝，用户可新建模板替代；新增字段、显示名称和默认值调整必须保持既有信息可读。

该约束避免静默丢失固定字段值。备选方案是编辑模板时批量重写信息；该方案会产生难以回滚的隐式数据更新，因此不采用。

### 7. 信息保存自身的动态参数及默认值

`ExtraInfo` 增加 `parameters` 集合，每项使用任务快照相同的 `key`、`displayName`、`required` 和 `value` 结构。这里的 `value` 是信息级默认值：创建或编辑信息时可维护，创建任务选择该信息时会被复制到任务快照，任务内只允许修改复制后的值。

信息级参数不能与模板固定字段、模板动态参数或同一信息内其他参数重名。任务快照按“模板动态参数、信息级动态参数、任务级新增参数”的顺序合成；模板与信息级参数的键、显示名称和必填标记由来源锁定，任务级参数才可编辑其定义并删除。已有数据没有该字段时归一化为一个空集合，不改写历史任务快照。

将信息级参数存在模板中的备选方案会使一条信息的补充配置泄漏到同分类的所有信息；只在前端临时拼接的方案无法在重启或后续任务创建时带出默认值，因此均不采用。

### 8. 管理弹窗的分类模板与搜索互不干扰

“分类模板”定义区使用一个默认展开、可整体折叠的面板。模板行采用窄屏单列、宽屏内容与操作分列的响应式网格，操作按钮可换行，不依赖单行剩余宽度。管理弹窗内容采用纵向流式布局；窗口高度不足时内容区滚动，模板面板不被后续信息区域覆盖或裁剪。

信息列表继续按模板分组。名称搜索只筛选每个分组内的信息行，所有模板分组标题始终保留；搜索命中的分组自动展开，Git 分组初始展开。这样分类结构在搜索前后稳定，用户可以辨认没有结果的分类，而不会因过滤而误以为模板缺失。

### 9. 动态参数使用显式输入类型

参数定义和任务快照均保存 `inputType`。缺失或无效的旧字段归一化为 `text`，保证已有 JSON 可继续读取。`checkbox` 参数的值仅为字符串 `true` 或 `false`，新建默认 `false`，且归一化时总是清除必填标记。这样布尔语义不会依赖字符串猜测，模板、信息和任务快照也能稳定渲染相同控件。

模板、信息和任务级新增参数均可选输入类型。切换到复选框会将值重置为 `false`；任务中来自模板和信息的参数继续只允许修改值，不允许改类型或定义。

### 10. HTTP 详情响应保留复选框的 JSON 类型

参数快照的 `value` 继续使用字符串保存，兼容既有 JSON、表单状态和归一化规则；其中复选框仅允许 `true` 或 `false`。任务详情 HTTP 输出在平铺快照时检查 `inputType`：复选框转换为 JSON 布尔值，固定字段和文本参数保持字符串。任务列表接口不返回 `extraInfo`，因此不改变其响应结构。

将领域模型的 `value` 改为多态值会影响持久化迁移、Wails 绑定和现有表单校验；只在 HTTP 输出边界转换能以最小范围提供面向 API 客户端的正确类型。

### 11. 任务详情仅返回活动终端的实时快照

`GET /api/v1/tasks/{taskId}` 增加 `terminals` 数组，每项包含 `id`、`command` 和实时 `status`。终端管理器在会话创建时记录有效命令：普通终端使用 Shell 路径，自定义命令终端使用请求命令；应用层再从实时服务读取 `idle`、`working`、`unread` 或 `error` 状态。

终端信息不持久化到任务 JSON，也不出现在任务列表接口。数组只描述仍被终端管理器持有的活动会话，关闭、退出、任务完成或应用重启后不返回历史记录；没有活动会话时详情返回空数组。持久化历史的备选方案会扩大任务数据模型，并与现有会话级终端生命周期不一致，因此不采用。

## Risks / Trade-offs

- [旧模板同一分类存在不同字段结构] → 迁移按结构拆分模板并保留全部旧信息，必要时以稳定后缀区分，而不强行合并。
- [前端只读限制被绕过] → 后端在创建和更新任务快照时只接受信息提供的固定字段，并校验任务传入快照的结构。
- [内置 Git 被 JSON 手工修改] → 加载时执行受保护字段规范化；非法变更报错或恢复为内置定义，且不改写历史任务快照。
- [模板更新造成关联信息不完整] → 拒绝删除或改名已被信息使用的字段键，并让新增字段带默认值或在信息编辑中补全。
- [迁移中断造成数据丢失] → 在内存中完整归一化且验证成功后再一次性持久化；失败时保留原始文件。

## Migration Plan

1. 为新持久化结构增加模板定义集合和信息集合，并保留旧字段的兼容反序列化能力。
2. 在仓库加载路径中执行幂等迁移和 Git 内置模板补种，随后持久化规范化结果。
3. 更新应用绑定与前端数据类型，使旧单层模板不再作为新建任务的候选项。
4. 以单元测试覆盖空数据、当前单层模板、旧单键模板、不同结构的同分类模板、缺少信息级参数的兼容数据和含历史任务快照的数据文件。
5. 回滚仅限尚未持久化前替换应用版本；一旦新模型写入，旧版本不保证能够读取新增集合，因此发布前应备份数据文件。

## Open Questions

无。模板结构变更对已关联信息的边界按本设计的完整性约束实现。
