## Why

当前额外信息将字段结构、固定值和任务可选项保存为同一个“模板”，无法表达“先定义可复用字段结构，再分别保存多条信息”的工作流，也无法提供开箱即用且受保护的 Git 信息结构。随着同一结构需要复用到多条仓库、环境或业务信息中，继续沿用现有模型会造成重复配置和任务表单含义不清。

## What Changes

- 将额外信息的领域模型拆分为“模板（字段与参数结构）”“信息（模板对应的固定字段值）”和“任务快照”三层；创建任务时选择已保存的信息，而不是直接选择模板。
- 内置不可删除的 Git 模板，固定包含 `name`（项目名称）、`repository`（仓库地址）和动态参数 `branch`（仓库分支）；这些内置字段的键和显示名称不可修改，用户可追加字段、参数并设置固定字段默认值。
- 所有新建模板自动包含固定字段 `name`；自定义模板允许修改该字段的显示名称。信息以其 `name` 字段值作为保存和展示名称。
- 创建信息时按模板渲染固定字段并采用模板默认值；创建或编辑任务时固定字段只读，动态参数可填写、修改和新增，必填动态参数继续校验。
- 调整持久化、应用绑定和前端管理界面，并迁移现有模板数据为可继续使用的模板和信息；历史任务快照保持不变。
- 保持任务详情 `extraInfo` 依分类聚合并按字段键、参数键平铺值的对外行为。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-extra-info`: 将额外信息从分类下的单层模板改为模板、信息和任务快照三层，并定义内置 Git 模板、默认值、可编辑边界与兼容迁移行为。

## Impact

- 受影响的后端包括 `internal/task` 领域模型、`internal/storage` 数据文件与迁移、应用绑定以及任务详情 HTTP 映射。
- 受影响的前端包括额外信息管理、信息创建、任务创建和编辑表单、Wails 绑定模型与相关测试。
- 本地 JSON 数据会新增模板与信息的独立集合；需要兼容当前单层模板数据和既有任务快照。

## 后续细化

- 信息除固定字段外，可保存仅属于该信息的动态参数定义与默认值；这些参数不会写回模板，也不会影响同一分类中的其他信息。
- 创建任务选择信息时，同时复制模板动态参数和信息级动态参数；任务仍只能修改参数值，并可继续新增仅属于当前任务的动态参数。
- 管理弹窗中的分类模板定义与信息列表分区展示：模板定义整体可折叠，信息搜索仅筛选信息行且不隐藏任何分类分组。
