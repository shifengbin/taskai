## Context

TaskAI 当前依赖 xterm 的默认鼠标行为：终端程序未开启鼠标追踪时，xterm 用左键创建本地选区；终端程序开启鼠标追踪后，xterm 禁用普通选择并把鼠标事件编码后写入 PTY。备注入口和自动复制都读取 xterm 本地选区，因此 Claude、Codex 等全屏终端程序运行期间无法通过普通鼠标使用这些功能。

项目另有 `disableTaskAIMouseClipboard` 设置，用于让某个菜单终端完全绕过 TaskAI 的自动复制、右键粘贴和备注入口。用户已经确认不再需要这套分支，所有终端都应遵循相同规则：前端处理拖拽、双击、三击选择、自动复制、备注和右键粘贴；真正的单击、滚轮、中键及其他非选择操作仍由 xterm 按终端程序启用的鼠标协议处理。

这个变更跨越前端事件处理、xterm 会话封装、Go 设置和终端数据模型、Wails 生成绑定及现有规格。实现必须兼容 Linux、macOS 和 Windows，不得手写带平台假设的终端坐标或 PTY 命令。

## Goals / Non-Goals

**Goals:**

- 所有活动终端都能用普通拖拽、双击和三击形成 xterm 本地选区，进而自动复制并显示备注入口。
- 单击仍能操作开启鼠标追踪的终端程序，滚轮、中键及其他非选择鼠标操作保持原有终端行为。
- 右键在所有活动终端中继续由 TaskAI 从系统剪贴板粘贴。
- 删除 `disableTaskAIMouseClipboard` 的界面、持久化模型、终端快照字段和条件分支，并兼容读取带旧字段的数据。
- 用单元测试和真实 `wails dev` 集成测试验证普通 Shell 与开启鼠标追踪的终端程序。

**Non-Goals:**

- 不改变键盘输入、终端输出、快捷输入、文件拖放、终端生命周期或备注保存期限。
- 不向 Claude、Codex 或其他具体终端程序增加适配代码。
- 不实现同一次选择手势既创建本地选区又发送给终端程序；选择手势归前端，单击及其他操作归终端程序。
- 不修改 xterm 依赖源码或维护项目内补丁。

## Decisions

### 在 xterm 处理前捕获左键序列并延迟判定

会话层在 xterm 根元素的捕获阶段暂存左键按下，记录目标、坐标、按钮、修饰键、时间和点击次数。在手势尚未归类前，原始左键按下、移动和松开不得到达 xterm：

- 移动距离超过统一阈值时归类为拖拽选择。
- 连续第二次、第三次按下分别归类为单词选择和整行选择。
- 在多击判定窗口结束前没有拖拽或后续点击时归类为单击。

单击需要等多击判定窗口结束后才发送，因此会产生短暂但有上限的延迟。选择该方案是因为鼠标按下瞬间无法知道用户之后会拖拽还是继续点击；立即把第一次按下发给终端程序后无法撤销，也就不能保证双击和三击完整归前端。

未采用“同一次手势同时选择并发送”的方案，因为终端程序可能因收到按下、拖动和松开而改变焦点或选项，使备注原文在用户操作期间变化。也未采用固定修饰键，因为用户要求普通鼠标即可选择。

### 通过受控 DOM 事件重放复用 xterm 的协议和选择语义

手势分类器使用重放标记避免再次捕获自身生成的事件：

- 对单击，按原始坐标、按钮和修饰键向 xterm 根元素重放一组按下和松开事件。xterm 自己根据当前 `mouseTrackingMode` 决定是否以及如何编码到 PTY；普通 Shell 不会收到多余数据，Claude 等开启鼠标追踪的程序收到正常单击。
- 对拖拽、双击和三击，向 xterm 重放强制本地选择事件。拖拽保留起止坐标，双击使用 xterm 的单词边界，三击使用 xterm 的整行选择语义。Linux 和 Windows 使用 xterm 支持的 Shift 强制选择；macOS 会为会话启用 xterm 的 Option 强制选择选项，并仅在内部重放中使用该修饰键。

重放选择完成后，以会话层的显式回调提供结束坐标；`TerminalView` 在下一动画帧读取同一 xterm 会话的选区，沿用现有边界限制显示备注按钮。选区变化仍通过既有 `onSelectionChange` 自动写入剪贴板，因此备注和复制读取同一份原文。

选择该方案而不是手写 SGR、VT200 等鼠标转义序列，是为了让 xterm 继续负责协议、坐标、按钮和终端模式差异。也不直接修改 xterm 私有 SelectionService，避免依赖升级时维护源码补丁。

### 只接管左键选择序列和右键粘贴

没有处于待判定左键序列时，鼠标移动、滚轮、中键和其他按钮事件继续进入 xterm。右键沿用现有 TaskAI 处理：阻止上下文菜单，读取系统剪贴板，并通过当前 xterm 会话的模拟粘贴写入；失败和空剪贴板保持静默，不向其他会话写入。

如果终端失活、切换、关闭或组件卸载，分类器必须取消计时器和全局监听器，丢弃尚未重放的事件并清除临时选区入口，避免把迟到的单击写入错误会话。

### 删除配置字段并容忍旧 JSON

Go 的 `TaskMenuItem`、终端记录及前端对应类型删除 `disableTaskAIMouseClipboard`；菜单编辑器删除开关、草稿默认值和保存映射；会话层与备注界面删除字段判断。重新生成 Wails 绑定，不能手工保留生成类型中的旧字段。

Go JSON 解码默认忽略未知字段，因此已有设置文件仍可读取。后续保存设置时序列化新模型，旧字段自然消失，不新增数据版本或一次性迁移程序。回滚到旧版本时字段缺失会按旧模型零值恢复原默认行为。

## Risks / Trade-offs

- [单击需要等待多击判定，Claude 中的点击反馈略有延迟] → 使用固定且较短的多击窗口，并通过计时器测试锁定只发送一次和取消条件。
- [拖拽阈值过小会把轻微抖动误判为选择，过大则选择起步迟钝] → 使用像素级统一常量，测试阈值内外边界，并在真实高低 DPI 环境中集成验证。
- [合成事件可能因 xterm 升级改变处理方式] → 只依赖公开终端根元素和既有强制选择行为，集中封装重放逻辑，并以开启鼠标追踪的集成测试保护升级。
- [双击后紧接三击时备注按钮短暂出现] → 在多击窗口未结束前延迟发布选择完成回调，最终以单词或整行选区只显示一次入口。
- [会话切换时仍有待发送单击] → 卸载、失活和释放会话时同步取消计时器与监听器，绝不向非当前或已关闭会话重放。
- [删除设置改变已有用户为特殊终端保存的行为] → 发布说明明确所有终端改为统一分流；旧字段被忽略但数据文件仍可由旧版本读取。

## Migration Plan

1. 先加入手势分类和事件重放的失败测试，覆盖普通模式和 `mouseTrackingMode` 非 `none` 的会话。
2. 实现统一鼠标处理并让备注入口改由选择完成回调驱动，确认现有自动复制和右键粘贴继续工作。
3. 删除前后端字段与设置控件，重新生成 Wails 绑定，并验证旧 JSON 能正常读取且再次保存后不再包含旧字段。
4. 使用 `wails dev` 启动应用，从输出取得调试地址，通过 Chrome DevTools 对普通 Shell、Claude/Codex 鼠标追踪终端执行完整集成测试；测试完成后关闭调试进程。
5. 回滚时恢复旧字段和条件分支即可；新版本没有写入旧版本无法识别的新持久化数据。

## Open Questions

无。拖拽、双击、三击、单击、右键、滚轮和配置移除的归属均已确认。
