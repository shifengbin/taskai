## Context

终端输出状态判定在前端的 `TerminalSessionRegistry` 中完成。每次 xterm 解析完 PTY 输出后，前端比较缓冲区快照；只有字符、空白单元格或样式实际变化时，才调用既有 Wails 接口上报活动。

目前快照从 `buffer.viewportY` 开始读取，并在用户滚动时重建基线。`viewportY` 表示用户当前查看的历史位置，而 xterm 的 `baseY` 表示终端底部活动页的起始行。因此用户查看历史时，状态判定观察的是与新输出无关的区域。

该变更只影响前端快照来源。后端仍负责状态模式校验、工作中状态和 1.5 秒静默计时。

## Goals / Non-Goals

**Goals:**

- 无论用户查看终端历史还是底部，新输出造成的活动终端页单元格变化都能一致地上报活动。
- 用户滚动不改变状态比较基线，也不产生活动上报。
- 继续忽略光标位置、未落到单元格上的样式设置、标题、响铃等非画面变化。
- 为滚动历史时的活动页变化补充自动化回归测试。

**Non-Goals:**

- 不改变终端滚动体验、回滚容量或 xterm 的渲染逻辑。
- 不修改 Wails API、实时状态服务、状态聚合优先级和静默计时。
- 不将整个滚动缓冲区纳入每批输出的比较范围。

## Decisions

### 以活动页而非用户视口作为快照范围

快照从活动缓冲区的 `baseY` 开始，读取 `rows` 行和 `cols` 列。xterm 将 `baseY` 定义为完全滚动到底部时视口的起始行；它代表程序正在更新的逻辑终端页，而不随用户向上浏览历史而改变。备用缓冲区没有滚动历史，`baseY` 为零，沿用同一规则。

不把 `baseY` 本身作为快照相等性的一部分。状态信号的语义是单元格画面发生变化；内部行号变化而页面单元格未变时不应产生活动。

备选方案是比较整个滚动缓冲区。该方案会随回滚内容增长增加每次输出的开销，也会将用户无关的历史变动混入状态信号，因此不采用。

### 移除滚动造成的状态基线重建

用户滚动只改变浏览位置，不改变程序输出所驱动的逻辑终端页。状态快照不再依赖 `viewportY` 后，滚动监听不再参与活动检测，也无需保留仅用于重建快照的监听和释放逻辑。

保留尺寸适配和外观更新时的基线重置。这些操作可改变 xterm 行布局或显示上下文，重置能避免用户界面调整被错误识别为输出活动。

### 保留现有解析时机与单元格签名

继续在 `onWriteParsed` 回调中读取快照，以保证控制序列已经由 xterm 解析。比较仍包含字符、宽度、前景色、背景色和可见文本样式，且不包含光标状态。前端只在 `output-change` 状态模式下将比较结果上报给后端。

## Risks / Trade-offs

- [用户向上查看历史时，新输出不再对应浏览区域] → 状态语义定义为程序实际运行页的变化；这正是任务活动状态需要反映的内容。
- [快照不包含 `baseY`，可能遗漏行号变化] → 仅当逻辑终端页的单元格内容或样式变化时才报告活动，符合既有“画面实际变化”的过滤规则。
- [xterm 缓冲区 API 的行对象在更新后不可长期保存] → 在同一个快照循环内立即读取每个单元格签名，不持有行对象，沿用现有访问方式。

## Migration Plan

该变更不修改持久化数据、公开 API 或设置值。发布后，新建和既有终端会话都在下一次前端加载时使用新的快照逻辑；无需数据迁移或兼容分支。

若需要回退，可恢复以 `viewportY` 为起点的快照和滚动基线处理；不会影响已持久化的任务或设置数据。
