## MODIFIED Requirements

### Requirement: 一次性补齐可删除的仓库命令链预置
系统 MUST 为新安装提供 `iterations-ai` 与名称为“更新框架仓库”的仓库更新命令链，并 MUST 通过既有持久化预置迁移版本为旧设置各补齐一次 `iterations-ai` 与名称为“更新仓库”的仓库更新命令链。新安装和旧设置中的两条链 MUST 分别使用相同的稳定标识，但 MUST 作为普通命令链管理，不得成为不可编辑或不可删除的系统固定链。系统 MUST 在既有一次性补齐后记录对应预置迁移版本，并且在后续加载时 MUST 不重新创建用户删除的预置链。本次新增的新安装名称和公司框架预设 MUST NOT 提升预置迁移版本，MUST NOT 补入已有持久化设置，也 MUST NOT 重命名已有仓库更新链。删除仍 MUST 遵循既有规则：被未执行或执行中任务或任何命令链预设引用的链不可删除，其他情况允许删除。升级到包含“更新默认分支”的既有预置版本时，系统 MUST 仅更新完全匹配上一版本原始名称、范围、命令 ID、参数与顺序的预置链；缺失或已修改的预置链 MUST 保持不变。

#### Scenario: 新安装使用更新框架仓库名称
- **WHEN** 用户首次启动且应用数据目录中不存在持久化数据文件
- **THEN** 系统创建 `iterations-ai` 和“更新框架仓库”两条可管理的预置链，并以既有稳定 ID 保存仓库更新链

#### Scenario: 旧设置只补齐一次
- **WHEN** 系统加载未记录既有仓库链预置迁移版本的旧设置
- **THEN** 系统按原有名称补齐 `iterations-ai` 与“更新仓库”并持久化既有最新版本，之后用户删除其中任一链再重启应用时该链不再自动出现

#### Scenario: 当前已有设置保持原名称和默认选择
- **WHEN** 系统加载已经持久化“更新仓库”链和任意默认预设选择的设置
- **THEN** 系统保留该链名称、预设集合和默认预设 ID，不补入“公司框架”且不切换默认项

#### Scenario: 可以删除未被活动任务或预设引用的预置链
- **WHEN** 用户删除未被未执行、执行中任务或命令链预设引用的 `iterations-ai` 或仓库更新链
- **THEN** 系统删除该链，并且不修改其他命令链或预设

#### Scenario: 保护被活动任务引用的预置链
- **WHEN** 未执行或执行中任务选择了某条预置链，用户尝试删除该链
- **THEN** 系统拒绝删除并说明该链仍被任务引用

#### Scenario: 保护被命令链预设引用的预置链
- **WHEN** 任一命令链预设选择了某条预置链，用户尝试删除该链
- **THEN** 系统拒绝删除并说明该链仍被预设引用

#### Scenario: 升级未修改的版本 3 预置链
- **WHEN** 系统加载两个均完全匹配版本 3 原始结构的预置链
- **THEN** 系统仅在两个链首插入“更新默认分支”，并记录新的既有预置版本

#### Scenario: 升级保留已修改的预置链
- **WHEN** 系统加载预置版本 3 且用户已修改 `iterations-ai` 的名称、范围、命令、参数或顺序
- **THEN** 系统不向该链插入“更新默认分支”，也不恢复原始内容

### Requirement: 预置 iterations-ai 开始前命令链
系统 MUST 提供名称为 `iterations-ai`、仅适用于 `beforeStart` 的预置命令链。该链 MUST 按以下顺序引用命令：更新默认分支且不传追加参数；创建任务工作目录；克隆指定 Git 仓库并传入唯一参数 `repository=git@gitlab.jiandan100.cn:webdev/iterations-ai.git`；生成清单文件且不传追加参数；Git 仓库克隆并传入唯一参数 `dir=workspaces`。新安装的“公司框架”预设 MUST 明确引用该链；加载已有持久化设置时，系统 MUST NOT 因该链存在而将其加入任何已有预设或切换默认预设。

#### Scenario: 用户在开始前选择 iterations-ai 链
- **WHEN** 用户为任务的 `beforeStart` 钩子选择 `iterations-ai` 并开始任务
- **THEN** 系统在任务进入执行中前依序更新执行态默认分支、创建目录、将指定仓库克隆到任务目录根部、生成清单文件，并将选定 Git 信息克隆到任务目录下的 `workspaces` 路径

#### Scenario: 新安装公司框架预选 iterations-ai
- **WHEN** 新安装用户打开使用默认“公司框架”预设的新建任务表单
- **THEN** 系统在开始前预选 `iterations-ai`，但不得立即执行该链

#### Scenario: 已有预设不会自动选择 iterations-ai
- **WHEN** 系统加载已有持久化设置
- **THEN** 系统不因预置 `iterations-ai` 链而修改任何已有生命周期预设

### Requirement: 预置更新仓库命令链
系统 MUST 提供仅适用于 `updateTask`、使用稳定 ID `preset.lifecycle-chain.update-repositories` 的仓库更新预置链。新安装中该链名称 MUST 为“更新框架仓库”，已有持久化设置中该链的已保存名称 MUST 保持不变。该链 MUST 先引用更新默认分支命令且不传追加参数，再引用生成清单文件命令且不传追加参数，最后引用 Git 仓库克隆命令并传入唯一参数 `dir=workspaces`。新安装的“公司框架”预设 MUST 通过稳定 ID 引用该链；该链的 Git 仓库克隆步骤 MUST 保持既有语义，仅克隆缺失目标而不得执行拉取、合并、覆盖或删除已有 Git 工作树。

#### Scenario: 新安装创建更新框架仓库链
- **WHEN** 用户首次启动且应用数据目录中不存在持久化数据文件
- **THEN** 系统创建名称为“更新框架仓库”的仓库更新链，链 ID、适用范围、命令 ID、参数与顺序保持既有定义

#### Scenario: 已有更新仓库名称保持不变
- **WHEN** 系统加载已保存名称为“更新仓库”或用户自定义名称的稳定仓库更新链
- **THEN** 系统保留已保存名称且不因本次变更重命名该链

#### Scenario: 执行中任务更新时运行预置链
- **WHEN** 执行中任务选择稳定仓库更新链作为 `updateTask` 链并成功保存任务更新
- **THEN** 系统先更新执行态默认分支，再重新生成任务目录根部的清单文件，最后以 `dir=workspaces` 执行 Git 仓库克隆

#### Scenario: 已有仓库不被更新链覆盖
- **WHEN** 稳定仓库更新链运行时 `workspaces` 下的某个选定 Git 信息目标已存在
- **THEN** 系统保留已有目标并按 Git 仓库克隆的既有跳过语义继续处理，不执行 Git 拉取或覆盖
