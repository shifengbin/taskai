## Why

新用户首次使用时仍需手动把公司框架所需的开始、结束和任务更新命令链组合起来，容易漏配或选错。应用应直接提供一套可见、可编辑且默认选中的“公司框架”预设，同时保持已有用户配置不变。

## What Changes

- 新安装保留现有“默认预设”，并新增“公司框架”生命周期命令链预设。
- 新安装将“公司框架”设为默认预设：开始前选择 `iterations-ai`，结束后选择“删除任务工作目录”，任务更新选择“更新框架仓库”；开始后和结束前不选择命令链。
- 新安装把现有仓库更新预置链的初始显示名称设为“更新框架仓库”，继续使用稳定链 ID 和既有命令顺序。
- 已有持久化设置不补齐“公司框架”、不切换默认预设，也不重命名已有的“更新仓库”链。
- 预设和命令链继续使用现有编辑、复制、删除、引用校验与任务独立保存规则。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-lifecycle-command-chains`：定义新安装的“公司框架”预设、默认选择及既有用户兼容边界。
- `default-branch-lifecycle-presets`：定义新安装的“更新框架仓库”链名称、稳定 ID 复用及既有配置保留规则。

## Impact

- 后端设置默认值与新安装初始化数据。
- 生命周期预设、仓库预置链及任务默认链选择的 Go 测试。
- 设置页和新建任务表单的前端回归测试；不新增 Wails 绑定或前端数据类型。
- `openspec/specs/`、`README.md` 与实施记录需要同步更新。
