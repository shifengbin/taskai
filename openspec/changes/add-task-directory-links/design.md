## Context

TaskAI 通过任务绑定模板解析任务的扩展字段，并把任务持久化数据作为唯一事实来源。任务工作目录由生命周期命令创建和删除，删除流程使用任务 ID、所有权令牌、目录身份与 `.taskai-ownership` 元数据目录限制删除边界。模板字段只支持 `string` 和 `bool`，生命周期命令库也没有把已有本地目录映射到任务工作目录的安全能力。

本变更横跨任务模型、模板设置、Wails 表单、生命周期命令、默认链迁移和跨平台文件系统操作。设计必须保留现有钩子提交时序：`beforeStart` 失败阻止启动，`updateTask` 在执行中任务保存后运行且失败不回滚已保存数据。任何链接同步和清理都不得跟随链接删除来源目录，也不得覆盖任务工作目录中的未知条目。

## Goals / Non-Goals

**Goals:**

- 允许模板声明一个或多个独立目录地址，并通过原生目录选择器填写。
- 让模板决定字段在任务创建后是否仍可更新，并由前后端共同执行该限制。
- 通过可重试的系统生命周期命令，把当前目录字段同步为任务工作目录根级链接。
- 自动、确定性地解决来源目录同名问题，并保护普通文件、目录、外部链接和来源目录。
- 只迁移仍保持系统默认形状的链、预设和任务选择，保留用户自定义配置。

**Non-Goals:**

- 不复制、移动、监视或同步来源目录内容。
- 不允许手工输入目录路径，也不提供链接名称自定义功能。
- 不把目录字段注入环境变量，不为目录字段提供默认值。
- 不修改用户自定义命令链，也不自动把命令加入用户创建的链。
- 不让链接内的 Git 仓库绕过现有任务工作目录边界参与仓库扫描或仓库管理。

## Decisions

### 1. 使用模板字段扩展，而不是增加独立任务目录属性

`TaskTemplateField.InputType` 新增 `directories`。字段增加 `Multiple` 与 `Updatable`：`Multiple=false` 时值数组最多一项，`Multiple=true` 时每一项都是独立绝对目录地址；`Updatable=false` 时创建成功后立即锁定。持久化层需要区分旧数据中缺失 `updatable` 与显式 `false`，旧字段归一化为可更新并在后续保存时写出明确值。

任务的 `TemplateFields` 继续使用键值对象，但允许目录字段保存 `[]string`。从 JSON 解码得到的字符串数组必须归一化为 `[]string`；其他数组或混合类型被拒绝。任务创建时记录模板 ID，既有任务始终通过该 ID 读取绑定模板的最新定义作为显示、校验与可更新策略来源；全局当前模板只决定新建任务使用哪个模板。历史字段继续保留但不输出。

选择这一方案是因为目录字段需要复用模板的排序、必填、历史值、HTTP 与生命周期上下文。独立 `Task.Directories` 会形成第二套模板和兼容规则；分别增加 `directory`、`directories` 两种类型则会造成值格式分叉，因此不采用。

### 2. 模板和任务保存执行结构及状态校验

目录字段不接受默认值和环境变量注入；`multiple` 只对 `directories` 有效。模板保存继续拒绝改变已使用字段的输入类型，并增加两项跨任务检查：已有任务保存多个值时拒绝把字段改为单目录；模板变更会让已有任务形成“必填、空值且不可更新”的状态时拒绝保存。

任务创建时允许填写全部目录字段。任务更新时，后端把传入值和已保存值都归一化后比较，只要任务绑定模板将字段标记为不可更新且值发生变化，就拒绝整个更新；任务状态不改变该规则。修改绑定模板使字段可更新会立即允许修改，改为不可更新会立即锁定；切换全局当前模板不得改变既有任务的模板绑定。

每个目录值必须是清理后的绝对路径，保存时必须存在、可访问且解析为目录。系统使用解析后的规范路径执行任务范围内的重复检测，但保存用户选择的清理后绝对地址；同一任务的所有当前目录字段不得重复指向同一个目录。同步命令再次检查路径，以处理保存后目录被移动、删除或替换的情况。

### 3. 原生目录选择器是唯一输入入口

模板编辑器为目录字段展示“允许选择多个目录”“必填”“允许创建后更新”，隐藏默认值和环境变量注入。任务表单通过一个前端目录选择适配器调用 Wails 原生 `OpenDirectoryDialog`，不渲染可编辑路径输入框。

单目录字段显示一条只读完整路径及“重新选择”“移除”；多目录字段显示独立路径列表及“添加目录”，每次添加调用一次原生选择器。前端先做数量、必填和重复提示，后端仍执行完整校验，防止伪造 Wails 请求绕过限制。目录选择适配器保持可替换，以便浏览器集成测试注入临时路径而不操作系统对话框。

### 4. 使用内置生命周期命令同步链接

新增固定 ID `system.lifecycle.sync-directory-links`、名称“同步任务目录链接”的只读系统命令，不接收链级参数，适用于 `beforeStart`、`postStart` 与 `updateTask`。命令从本次执行加载到的当前任务和任务绑定模板重新计算期望状态，不使用上次请求缓存，因此重试会采用最新持久化值。

选择内置生命周期命令，是为了复用现有钩子时序、执行记录、锁定、失败展示和重试。任务保存时直接操作文件系统会使 pending 任务缺少工作目录，并绕过生命周期失败语义；Shell 命令难以安全处理路径、Windows 链接和受管理清理，因此不采用。

### 5. 链接位于任务工作目录根级并使用确定性名称

每个来源目录对应任务工作目录根级的一个目录链接。系统先按来源目录 basename 分组；无冲突时直接使用 basename。同名组中的所有来源都从直接父目录开始逐级增加祖先组件并以 `-` 连接，例如 `/project-a/src` 与 `/project-b/src` 生成 `project-a-src` 与 `project-b-src`。比较采用保守的大小写不敏感规则，直到任务内全部名称唯一；到达文件系统根、名称无效或超出平台限制后仍不能唯一时，同步失败。

命名每次根据当前全部目录值重新计算，因此新增同名来源时，原有 `src` 可以改名为 `project-a-src`。如果期望名称已被普通文件、普通目录、未登记链接或目标不同的登记链接占用，命令失败，不覆盖目标，也不改用与规则无关的名称。

手工命名需要新增一套模板值结构、重命名交互和冲突策略；只保留第一个 `src` 并给后来项改名会让结果依赖添加顺序。确定性地重命名整个同名组更容易预测和重试，因此采用该方案。

### 6. 用所有权元数据中的事务清单限制清理范围

链接清单保存在工作区根的 `.taskai-ownership` 元数据目录下，并按任务所有权令牌隔离，不在任务工作目录中增加控制文件。清单记录任务 ID、所有权令牌、已管理链接的相对名称和绝对来源目标；写入前复用现有根目录、元数据目录、任务目录和所有权身份检查。

同步先完整预检来源、名称、目标占用和旧链接身份，再原子写入包含旧状态与期望状态的 pending 清单，随后执行链接删除、创建或替换，最后原子提交稳定清单。进程中断后，下一次同步根据 pending 清单的旧状态与期望状态继续收敛。删除条目前必须使用不跟随链接的检查确认它仍是清单登记且指向登记来源的链接；不匹配时失败并保留条目。删除任务工作目录成功后再清理对应链接清单。

把清单放在任务工作目录内会污染 Git 工作树和需要空目标的克隆命令；只把已管理名称存在内存中则无法在重启、部分失败和移除字段后证明链接所有权，因此均不采用。

### 7. 文件系统链接由平台适配器实现

共享同步逻辑只依赖“创建目录链接、读取链接目标、判断链接类型、删除链接本身”接口。Unix 使用目录 symlink；Windows 可使用目录 symlink 或 junction，但必须以不弹出终端窗口的原生实现完成。平台实现必须能在不遍历来源内容的情况下验证和删除链接本身。若当前文件系统不支持安全目录链接，命令明确失败，不回退为复制目录。

### 8. 更新系统默认链并进行形状保护迁移

新增稳定同步链 `system.lifecycle-chain.sync-directory-links`，仅包含同步命令，并适用于 `beforeStart`、`postStart` 与 `updateTask`。系统链的新顺序为：

- “创建任务工作目录”：创建工作目录、同步目录链接。
- `iterations-ai`：更新默认分支、创建工作目录、同步目录链接、克隆指定仓库、生成清单、克隆 Git 仓库。
- “更新仓库/更新框架仓库”：同步目录链接、更新默认分支、生成清单、克隆 Git 仓库。
- “删除任务工作目录”：保持不变。

“默认预设”增加 `updateTask` 到同步链的选择；“公司框架”继续选择仓库更新链，由更新后的链完成同步。同步命令始终补齐到系统命令库，但迁移只替换与上一个系统版本在 ID、名称、钩子、命令顺序和参数上完全一致的链及预设。已有任务只有在链选择完整匹配旧系统默认映射时才增加同步链；自定义链、自定义预设和自定义任务选择保持不变。

## Risks / Trade-offs

- [新增同名来源会改变已有链接名称] → 对同名组使用确定性规则，并在同步前一次性预检全部旧、新目标；文档和错误信息展示最终名称。
- [来源在保存后被移动或替换] → 保存和每次同步都校验，错误包含字段名和路径；`beforeStart` 阻止启动，`updateTask` 保留已保存任务值并允许重试。
- [进程在多步文件系统更新中中断] → 使用原子 pending 清单记录旧状态和期望状态，重试只处理有所有权证据的链接并收敛到当前值。
- [Windows 创建 symlink 可能需要额外权限] → 平台适配器可采用 junction；不支持时明确失败，禁止静默复制或启动可见命令窗口。
- [目录链接使任务工作目录不再为空] → 同步命令顺序固定且可由用户在自定义链中调整；需要空工作目录根的克隆命令与非空目录字段组合时按现有非空目标规则失败。
- [绑定模板策略变化会立即影响旧任务] → 模板保存拒绝不可恢复的结构变化，其他变化明确按任务绑定模板最新定义执行，不复制策略到任务快照。
- [旧版本无法识别新字段类型或命令类型] → 迁移不删除来源内容并保留版本前数据备份策略；降级时需要恢复升级前设置数据，不承诺新格式可被旧二进制写回。

## Migration Plan

1. 扩展数据模型和归一化逻辑，先保证旧模板缺失 `updatable` 时按 `true` 加载，旧任务字段保持原值。
2. 增加系统命令、同步链及新版系统链定义，提高预设迁移版本。
3. 仅对完全匹配旧系统形状的链、预设和任务选择应用迁移，并用迁移测试证明自定义配置不变。
4. 首次同步时创建任务专属链接清单；没有目录字段的任务产生空期望状态，不创建工作目录外的额外链接。
5. 回滚代码前恢复升级前的设置数据备份；已创建链接可以由新版本同步为空或随受控任务工作目录删除，来源目录无需迁移或恢复。

## 集成测试设计

1. 在临时根目录创建 `project-a/src`、`project-b/src` 和第三个不同名称目录，并为测试任务创建受所有权保护的工作目录。
2. 使用真实生命周期服务执行同步命令，验证单目录生成 `src`，加入第二个同名目录后收敛为 `project-a-src`、`project-b-src`，每个链接解析到各自独立来源。
3. 更新任务值覆盖添加、移除、替换、字段删除和模板切换；每次重复执行命令，验证链接集合与清单不发生额外变化。
4. 分别放置同名普通文件、普通目录、未登记链接和被替换的登记链接，验证同步失败且任何未知条目和来源目录均未修改。
5. 模拟 pending 清单和部分完成状态，验证重试能继续创建或清理已登记链接，且不会删除清单之外的条目。
6. 验证来源缺失、不可访问或不是目录时错误包含模板字段和绝对路径；验证 `beforeStart` 失败保持 pending，执行中任务 `updateTask` 失败保留新值并提供重试。
7. 构造旧系统链、已修改系统链、自定义链、默认预设、公司框架预设和不同任务选择快照，验证只迁移完全匹配的系统形状。
8. 运行 `go test -race ./...`，并在支持的构建环境中覆盖 Unix symlink 与 Windows 目录链接适配器测试。
9. 运行 `wails dev`，从输出取得调试地址，使用 chrome-devtools 打开应用；创建目录模板，验证单/多目录开关、必填、创建后锁定、重新选择、移除和后端错误展示。
10. 浏览器测试替换目录选择适配器，使其依次返回上述临时绝对路径，并确认页面不存在可编辑路径输入；另执行一次真实原生目录选择器 smoke test。
11. 完成任务并执行删除工作目录链，确认工作目录和链接清单被清理，而三个来源目录及其内容保持完整。
