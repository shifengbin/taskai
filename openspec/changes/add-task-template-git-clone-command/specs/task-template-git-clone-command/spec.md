## ADDED Requirements

### Requirement: 提供独立的指定仓库克隆系统命令
系统 SHALL 提供固定 ID、不可编辑且不可删除的“克隆指定 Git 仓库”生命周期命令。该命令 MUST 仅适用于 `beforeStart` 与 `postStart`，并允许命令链为其配置追加参数。该命令 MUST 与既有“Git 仓库克隆”命令使用不同的命令类型和参数解析逻辑；既有命令继续只依据任务所选 Git 附加信息批量克隆项目。

#### Scenario: 设置中补齐独立系统命令
- **WHEN** 应用加载没有“克隆指定 Git 仓库”命令的设置
- **THEN** 系统补齐该固定命令，且其适用钩子仅为 `beforeStart` 与 `postStart`

#### Scenario: 与既有批量克隆命令顺序组合
- **WHEN** `beforeStart` 命令链依次包含创建任务工作目录、克隆指定 Git 仓库和既有 Git 仓库克隆命令
- **THEN** 系统先将指定仓库检出到配置目标，再按 Git 附加信息执行既有批量克隆，且两个命令的仓库来源互不影响

#### Scenario: 拒绝修改或删除新命令
- **WHEN** 客户端提交修改新命令名称、类型、适用钩子或删除该命令的设置
- **THEN** 系统恢复固定定义并保留该命令

### Requirement: 通过安全链级参数克隆一个指定仓库
“克隆指定 Git 仓库”命令引用 MUST 包含唯一且非空的 `repository=<仓库地址>` 参数，并且可包含唯一的 `dir=<相对目录>` 参数，两个参数顺序不限。系统 MUST 拒绝未知参数、重复参数、空仓库地址、空目录、绝对目录以及会跳出任务工作目录的目录。省略 `dir` 时，克隆目标 MUST 为任务工作目录；提供 `dir` 时，目标 MUST 为任务工作目录下的该目录。系统 MUST 直接将该目标传给 Git，而不得追加项目名称、仓库名称或任何 Git 附加信息值。

#### Scenario: 默认直接初始化任务工作目录
- **WHEN** 命令链引用只配置 `repository=https://example.com/task-template.git`
- **THEN** 系统将该仓库直接克隆到任务工作目录，并在其中保留 Git 工作树

#### Scenario: 克隆到指定子目录本身
- **WHEN** 命令链引用配置 `repository=https://example.com/task-template.git` 与 `dir=template`
- **THEN** 系统将仓库直接克隆到 `<任务工作目录>/template`，且不会创建额外的项目名称子目录

#### Scenario: 拒绝无效仓库或目录参数
- **WHEN** 命令引用缺少 `repository`、包含多个 `repository` 或 `dir`、包含未知键、使用空值、绝对路径或会跳出工作目录的 `dir`
- **THEN** 系统拒绝保存或执行该命令链，并说明指定仓库克隆参数无效

### Requirement: 安全处理初始化克隆目标
系统 MUST 在执行指定仓库克隆前确认任务工作目录存在且为目录，并确保解析后的目标实际位于其中。系统 MUST 拒绝符号链接、非目录目标及任何非空目标目录；拒绝时不得调用 Git、不得删除或覆盖目标内容。系统 MAY 创建位于任务工作目录内的缺失父目录和空目标目录。成功克隆后，系统 MUST 保留 Git 生成的工作树和 `.git` 目录。

#### Scenario: 开始前在创建工作目录之后克隆
- **WHEN** `beforeStart` 链先创建任务工作目录，再执行指定仓库克隆
- **THEN** 系统使用新建的空任务工作目录作为默认克隆目标

#### Scenario: 目标目录非空时失败
- **WHEN** 指定仓库克隆的目标目录已包含任意文件或目录
- **THEN** 系统在不调用 Git 的情况下使该命令失败，且不修改目标内容

#### Scenario: 使用符号链接目标被拒绝
- **WHEN** 指定的 `dir` 或其目标是指向任务工作目录外的符号链接
- **THEN** 系统拒绝执行并说明克隆目标不安全

### Requirement: 按任务模板分支检出指定仓库
系统 MUST 从当前任务模板中键为 `branch` 的字符串字段读取指定仓库克隆的分支。去除首尾空白后非空的值 MUST 作为 Git 分支；字段不存在或值为空时，系统 MUST 不传 `--branch`，由远程仓库的默认分支完成检出，不得将该情形硬编码为 `main`、`master` 或其他名称。当前模板若将 `branch` 定义为非字符串，系统 MUST 拒绝保存含该命令的任务或在调度前报告字段类型错误。指定的远程分支不存在时，系统 MUST 复用既有 Git 克隆策略：先检出远程默认分支，再创建同名本地分支。

#### Scenario: 使用模板指定分支
- **WHEN** 当前模板的 `branch` 字段值为 `release/1.2`，命令链执行指定仓库克隆
- **THEN** 系统检出 `release/1.2` 分支

#### Scenario: 缺失模板分支时使用远程默认分支
- **WHEN** 当前模板没有 `branch` 字段，或该字段值为空
- **THEN** 系统不传 `--branch`，并由远程仓库选择其默认分支

#### Scenario: 远程不存在指定分支
- **WHEN** 模板 `branch` 为 `feature/local`，但远程不存在该分支
- **THEN** 系统先检出远程默认分支，再在克隆目标创建 `feature/local` 本地分支

### Requirement: 保持生命周期执行和标准输入语义
指定仓库克隆 MUST 由应用直接调用参数化 Git 子进程，不得经任务 Shell 解释仓库地址、目录或分支。成功后，系统 MUST 原样传递命令链的标准输入字节。`beforeStart` 中的克隆失败 MUST 阻止任务变为执行中；`postStart` 中的克隆失败 MUST 不回滚已提交的执行中状态，并按既有生命周期记录失败和重试入口。

#### Scenario: 指定仓库地址不会被 Shell 解释
- **WHEN** 仓库地址包含 Shell 特殊字符
- **THEN** 系统仅将其作为 Git 参数传递，且不启动任务选定的 Shell

#### Scenario: 开始前克隆失败阻止任务启动
- **WHEN** 指定仓库克隆在 `beforeStart` 链中失败
- **THEN** 任务保持未执行状态，并记录该命令失败

#### Scenario: 开始后克隆失败保留任务状态
- **WHEN** 指定仓库克隆在 `postStart` 链中失败
- **THEN** 任务保持执行中状态，并提供从该链首条命令开始的重试入口

### Requirement: 用模板分支补全 Git 附加信息快照
保存任务时，系统 MUST 先解析当前任务模板字段，再保存任务附加信息快照。当前模板的字符串 `branch` 字段为非空时，系统 MUST 将该值写入每条内置 Git 附加信息中值为空的 `branch` 参数；已有非空分支 MUST 保持不变。模板没有 `branch` 或其值为空时，Git 附加信息的空分支 MUST 保持为空，表示远程默认分支。回填后的分支 MUST 作为任务快照持久化，后续变更模板不得改写该快照。

#### Scenario: 模板分支回填空 Git 分支
- **WHEN** 当前模板 `branch` 为 `release/1.2`，任务选择两条 Git 附加信息，其中一条分支为空、另一条为 `hotfix`
- **THEN** 保存后的第一条 Git 快照分支为 `release/1.2`，第二条仍为 `hotfix`

#### Scenario: 空模板分支保留远程默认含义
- **WHEN** 当前模板没有 `branch` 字段或其值为空，且任务选择的 Git 附加信息分支为空
- **THEN** 保存后的 Git 快照分支保持为空，后续 Git 克隆使用远程默认分支

#### Scenario: 模板变更不改写已保存快照
- **WHEN** 任务已由模板分支 `release/1.2` 回填 Git 快照，随后模板分支改为 `main`
- **THEN** 该任务已保存的 Git 快照分支仍为 `release/1.2`

## MODIFIED Requirements

### Requirement: 提供受保护的内置 Git 模板
系统 MUST 提供且持久化一个不可删除的内置 Git 模板。该模板 MUST 包含键为 `name`、显示名称为“项目名称”的固定字段，键为 `repository`、显示名称为“仓库地址”的固定字段，以及键为 `branch`、显示名称为“仓库分支”的文本动态参数。系统 MUST 拒绝删除或修改这些内置字段和参数的键或显示名称；系统 MUST 允许用户为 Git 模板新增字段和动态参数、设置固定字段默认值。内置 `branch` 参数 MUST 始终可为空，以表示远程默认分支，且系统不得允许将其配置为必填；加载历史设置时 MUST 将该参数的必填标记归一化为 `false`，不修改已有任务快照。

#### Scenario: 首次打开额外信息管理
- **WHEN** 用户在没有任何额外信息数据的新安装中打开额外信息管理
- **THEN** 系统展示内置 Git 模板及其项目名称、仓库地址和可为空的仓库分支定义

#### Scenario: 基于 Git 模板创建信息时应用默认值
- **WHEN** 用户为 Git 模板的仓库地址设置默认值后新建一条 Git 信息
- **THEN** 信息表单将仓库地址输入框初始化为该默认值，且用户可在保存信息前修改该值

#### Scenario: 修改 Git 内置字段键被拒绝
- **WHEN** 用户尝试修改 Git 模板中 `name`、`repository` 或 `branch` 的键或显示名称，或删除其中任一项
- **THEN** 系统拒绝保存并说明 Git 内置字段不可修改

#### Scenario: Git 分支保持可为空
- **WHEN** 用户创建或编辑任务时未填写内置 Git 信息的 `branch`，或加载历史中将该参数标记为必填的 Git 模板
- **THEN** 系统允许空分支并将历史必填标记归一化为可选，已有任务快照保持不变
