## Why

现有“Git 仓库克隆”系统命令只能读取任务选择的 Git 附加信息，并将多个项目克隆到项目名称子目录，不能把一个 Git 仓库直接作为任务工作目录的初始化模板。任务模板中的分支字段也无法统一决定初始化仓库与未指定分支的 Git 附加信息所使用的分支。

## What Changes

- 新增不可编辑、不可删除的“克隆指定 Git 仓库”系统生命周期命令，仅适用于 `beforeStart` 和 `postStart`，用于以 Git 工作树初始化任务目录。
- 新命令通过命令链引用接收必填 `repository=<仓库地址>` 和可选 `dir=<相对目录>`；未提供 `dir` 时直接克隆到任务工作目录，提供时直接克隆到该目录，且不追加项目名称目录。
- 新命令只克隆命令链指定的单个仓库，不读取或依赖任何 Git 附加信息；现有“Git 仓库克隆”命令保持原有批量附加信息克隆语义不变，两者可在同一链中顺序组合。
- 新命令从任务模板字段 `branch` 选择分支：非空字符串使用该分支；字段缺失或值为空时使用远程默认分支，不硬编码 `main` 或 `master`。
- 保存任务时，若任务模板 `branch` 非空，则将其填入所选 Git 附加信息中为空的 `branch`；Git 附加信息的分支允许保持为空，以表示远程默认分支。
- 更新生命周期编排说明、项目 README、前后端类型与回归测试，覆盖目录安全、目标非空失败、生命周期失败语义和分支继承。

## Capabilities

### New Capabilities

- `task-template-git-clone-command`: 通过任务模板分支和命令链参数，将指定 Git 仓库直接克隆到安全的任务目录目标，并与 Git 附加信息分支继承保持一致。

### Modified Capabilities

- `task-extra-info`: 将内置 Git 模板的 `branch` 参数固定为可空，使空值可表示远程默认分支，并支持任务模板分支回填。

## Impact

- 后端：`internal/settings` 中新增固定系统命令和链级参数校验，并迁移 Git 分支必填配置；`internal/lifecycle` 中新增单仓库直接克隆与模板分支解析；`internal/task` 与任务保存服务中支持 Git 附加信息分支回填。
- 前端与绑定：生命周期编排中的系统命令说明、命令链参数交互及 Wails 生成类型。
- 文档与测试：README、设置/生命周期/任务服务测试、前端交互测试；最终按项目脚本完成 Linux 构建验证。
