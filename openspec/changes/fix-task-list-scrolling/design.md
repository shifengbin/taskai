## 背景

应用根容器占满视口并禁止页面级滚动。左侧任务面板当前使用固定高度的工具栏与 `calc(100% - 42px)` 组合来放置任务树；任务树内部则使用标签栏和任务 `List` 的两行栅格。虽然 `List` 已声明自动溢出，但左侧面板及中间容器没有完整建立可收缩的最小高度链，任务较多时内容会向外撑开并被视口裁切。

本变更仅影响前端展示布局。任务状态筛选、任务与终端数据、拖动排序和现有 API 都是既有边界条件。

## 目标与非目标

**目标：**

- 让左侧任务面板在任意窗口高度下保留固定工具栏，并将其余高度交给任务树。
- 让未执行、执行中和已完成标签的列表均能独立垂直滚动到全部任务。
- 不显示或占用空间展示原生滚动条，同时保留原生滚动输入。
- 保持既有的任务选择、终端展开、任务操作和拖动排序行为。

**非目标：**

- 不增加虚拟列表、分页、滚动位置持久化或自定义滚动条。
- 不改变任务状态、排序规则、终端展示或生命周期命令链行为。
- 不修改后端、Wails 绑定、HTTP API 或存储结构。

## 决策

### 使用显式的两行栅格约束左侧面板

左侧面板将由“42px 工具栏 + `minmax(0, 1fr)` 任务树区域”组成，并在作为栅格子项的相关容器上设置 `minHeight: 0`。这使剩余高度在 CSS Grid 中可被可靠分配和收缩，任务树不再依赖百分比 `calc()` 向上解析父元素高度。

保留 `calc(100% - 42px)` 的替代方案无法保证每一层栅格子项都可收缩，内容的最小固有高度仍可能撑开左侧面板；因此不采用。

### 将可滚动边界限定为任务 List

`TaskTree` 继续使用“状态标签 + 剩余空间列表”的两行栅格，导航容器与列表所在网格项均允许收缩。任务 `List` 负责 `overflowY: auto`，并限制横向溢出，避免整个窗口或左侧面板成为滚动容器。

让左侧面板整体滚动的替代方案会使工具栏随内容离开可见区域，也会与固定状态标签的浏览体验冲突；因此不采用。

### 仅隐藏视觉滚动条，不禁用滚动

列表使用标准的 `scrollbar-width: none` 及 WebKit 滚动条伪元素规则隐藏滚动条，兼顾 Wails 所使用的 WebView 平台。滚动属性仍保持为 `auto`，从而保留鼠标滚轮、触控板、键盘聚焦后的原生滚动和程序化滚动行为。

使用 `overflow: hidden` 隐藏滚动条会同时禁止用户查看被裁切的任务，不符合需求，因此不采用。

## 风险与取舍

- [隐藏滚动条降低可滚动区域的视觉提示] → 保留所有原生输入方式，并让列表在任务数量超出可见高度时自然响应滚动。
- [嵌套栅格缺少一个最小高度约束] → 在左侧面板、任务树承载容器和列表网格项逐层显式声明可收缩高度，并通过长列表场景测试回归。
- [浏览器对滚动条隐藏规则支持不同] → 同时使用标准属性和 WebKit 伪元素；即使某个平台不支持隐藏规则，列表仍必须保持可滚动。

## 迁移计划

前端发布后立即生效，无数据迁移或服务重启要求。若需回退，只需恢复相关布局与样式；任务数据和接口不受影响。
