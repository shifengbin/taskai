## 为什么

当前应用沿用 MUI 的默认化浅色工作台外观，主工作区、终端与多层弹窗之间缺少统一的视觉识别。用户已确认“松林夜跑”方向：它应让任务执行像夜间跑道一样有明确节奏，同时在亮色与真正深色模式下都保持高对比、可读和可操作。

## 变更内容

- 建立“松林夜跑”亮色与暗色视觉令牌，并将现有颜色模式设置映射到这两套令牌。
- 重塑启动页、顶栏、任务树、任务详情、终端、空状态、标签、列表、拖拽反馈、菜单、通知和所有现有弹窗的视觉外观。
- 采用松林绿的结构色、荧光橘的主要操作色、荧光黄绿的赛道提示色，以及斜向反光条纹、硬边鞋盒轮廓和夜跑路线细节。
- 为执行状态、拖拽落点、弹窗和启动过程加入克制的视觉动效，并尊重系统的“减少动态效果”偏好。
- 统一图标的线条、容器、悬停、焦点、禁用和危险操作表现，确保关键文本与其背景达到至少 4.5:1 对比度。
- 保持任务、终端、设置、生命周期、额外信息、菜单和窗口退出的全部业务逻辑、数据结构、API 调用、键盘行为及控件语义不变。

## 能力

### 新增能力

- `pine-night-run-visual-system`：为 TaskAI 的全部既有界面提供一致、可访问的松林夜跑视觉系统与状态反馈。

### 修改能力

- 无。

## 影响

- 影响 `frontend/src/App.tsx` 中的 MUI 主题、应用外壳、详情区及所有对话框的视觉属性。
- 影响 `frontend/src/App.css`、`frontend/src/style.css`、`frontend/src/components/TaskTree.tsx`、`frontend/src/components/TerminalView.tsx` 和 `frontend/src/components/TerminalStatusDot.tsx` 的样式与展示参数。
- 不增加后端接口、数据迁移、依赖包或配置字段；复用现有 `colorScheme` 设置切换亮色与暗色。
