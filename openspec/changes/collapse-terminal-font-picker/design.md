## Context

终端字体设置目前会在设置弹窗中直接渲染所有 `fontOptions`。每项包含字体名称、间距状态和三行预览，因此候选较多时会占据较大的滚动区域。`fontOptions` 已确保当前已保存但不可用的字体仍会出现在列表中；设置草稿、保存和取消行为也已独立于终端会话。

项目已有基于 Radix 的 `SnapAccordion`，可提供受控的展开状态、键盘访问和展开状态语义。此变更只影响前端设置页。

## Goals / Non-Goals

**Goals:**

- 设置初次打开时只显示当前选中字体的完整摘要与预览。
- 用户能够显式展开全部候选，并在选择后立即回到新选中字体的摘要。
- 保留默认回退字体、字体发现失败和已保存字体不可用时的可见状态。
- 保留现有“编辑草稿，保存后持久化，取消后放弃”的语义，并保持候选列表的键盘可访问性。

**Non-Goals:**

- 不改变系统字体发现、候选排序、间距筛选或 Wails 接口。
- 不在保存前更新已创建终端的字体，也不改变新建终端读取设置的行为。
- 不增加字体搜索、收藏、排序或自定义字体安装功能。

## Decisions

### 使用受控 accordion 承载选择器

新增仅在设置弹窗存续期间有效的展开状态，并在每次打开设置时初始化为收起。使用已有的 `SnapAccordion` 渲染当前字体摘要作为触发器，候选区作为内容；避免新增依赖或手写展开动画。

备选方案是在摘要旁放置菜单或下拉框。该方案会压缩多行字体预览，且需要单独处理焦点、滚动和长候选列表，因此不采用。

### 用同一份候选数据渲染摘要与列表

摘要从现有 `fontOptions` 中取当前草稿的候选项，保留默认回退项和“当前字体不可用”占位项。候选列表继续使用同一集合，确保字体发现异步完成前后都不会丢失当前选择。

备选方案是仅根据已发现字体生成摘要。该方案会在已保存字体不可用或字体发现进行中时丢失当前选择，故不采用。

### 选择后更新草稿并关闭列表

候选项点击处理会先更新 `terminalFontFamily` 草稿，再将 accordion 设为收起。保存按钮仍是唯一的持久化入口；取消仍丢弃草稿。展开触发器使用按钮及展开状态语义，展开内容继续使用 `radiogroup` 和 `radio` 候选项，避免可交互元素嵌套。

备选方案是选择后保持展开，或在选择时直接保存。前者不符合快速返回摘要的目标，后者会破坏现有取消设置的行为，故不采用。

### 以交互测试保护状态转换

更新前端测试以验证初始收起、显式展开、选择后自动收起、取消不保存，以及字体发现失败和字体不可用时仍能展示当前摘要。保留字号预览测试，确认其继续使用当前字体草稿和字号。

## Risks / Trade-offs

- [字体发现异步完成时摘要的候选元数据变化] → 摘要和列表统一从 `fontOptions` 派生，加载状态继续单独显示。
- [accordion 触发器与候选项的无障碍语义混淆] → 触发器只负责展开，候选区才承担 `radiogroup` 语义，并通过测试验证展开状态和单选状态。
- [字体预览 JSX 在摘要和候选项间重复] → 限制在本地表现层；仅在重复妨碍可读性时抽取无状态的本地渲染单元，不引入新的共享组件。

## Migration Plan

无需数据迁移。已有 `terminalFontFamily` 值继续作为收起摘要的当前选择；发布只改变设置页的展示和交互。若需回退，恢复直接渲染候选列表即可，持久化设置和终端会话不受影响。
