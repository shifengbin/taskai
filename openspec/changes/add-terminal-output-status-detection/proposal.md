## 为什么

有些终端程序不会更新 OSC 标题，导致当前仅依赖标题变化的默认状态无法反映其工作进度。终端输出本身已由应用统一接收，可作为无需程序配合的活动信号。

## 变更内容

- 在实时状态设置中新增“根据终端输出变化”方式，作为标题变化和 HTTP 接口之外的第三种状态管理方式。
- 该方式下，任意非空终端输出都会将对应终端标记为工作中，并重置 1.5 秒静默计时；计时结束后沿用现有的选中终端空闲、未选中终端未读规则。
- 将输出活动判定接入后端终端事件分发，保持标题变化和 HTTP 接口的现有行为不变。
- 更新任务详情中的状态 API 环境变量说明，覆盖输出判定下独立启用本机 HTTP 服务的场景。

## 能力

### 新增能力

- `terminal-output-status-detection`：根据终端输出判定实时状态，并提供对应的持久化设置和状态转换规则。

### 修改能力

- `task-detail-command-context`：说明输出判定方式下独立启用的本机 HTTP 服务同样会为后续新终端注入状态 API 地址。

## 影响

- 后端：`internal/settings`、`internal/realtime` 与 `app.go` 的终端事件编排。
- 前端：实时状态设置选项、说明文案和生成的 Wails 设置类型。
- 验证：补充 Go 领域与应用测试、前端设置测试，以及 OpenSpec 规格场景。
