# windows-conpty-lifecycle Specification

## ADDED Requirements

### Requirement: 进程退出后关闭伪控制台以结束输出流

Windows 终端会话 MUST 在客户端进程退出并取得真实退出结果后，关闭伪控制台句柄以促使控制台宿主结束输出管道，从而使会话读循环得以退出并让终端退出事件及时发布。读循环随后收到的"管道已结束"（错误 109）或"操作已中止"（错误 995）MUST 被识别为预期的读取结束，不得视为读取故障。

#### Scenario: shell 自然退出后退出事件及时到达
- **WHEN** 用户在嵌入终端里让 shell（如 cmd）自然退出
- **THEN** 终端退出事件在亚秒级时间内发布，携带进程的真实退出码，前端终端条目按退出状态分类处理

#### Scenario: 预期读取结束不报错
- **WHEN** 会话读循环在输出管道结束后收到错误 109 或错误 995
- **THEN** 该错误被当作预期的读取结束处理，不产生错误日志或异常状态

### Requirement: 读循环退出前不得释放输出管道

会话 MUST 在读循环退出（排空全部剩余输出）之后才释放伪控制台属性表、输入管道、输出管道和进程句柄；MUST NOT 在控制台宿主冲刷最终输出之前关闭输出管道读端，避免丢失退出前的最终输出。

#### Scenario: 退出前的最终输出不丢失
- **WHEN** shell 在退出前产生输出（如最后一条 echo 命令的回显）
- **THEN** 该输出完整出现在终端输出流中，随后输出流才结束

### Requirement: 主动关闭按两阶段拆卸且不悬挂

用户或系统主动关闭会话时，系统 MUST 先关闭伪控制台解除读循环阻塞，再在进程尚未退出时终止进程，并在读循环收尾后释放全部句柄资源；读循环未按期退出时 MUST 有有界超时兜底，保证关闭调用在有限时间内返回且不残留句柄。

#### Scenario: 用户关闭运行中的终端
- **WHEN** 用户关闭一个 shell 仍在运行的嵌入终端
- **THEN** 关闭在有限时间内完成，进程被终止，管道与进程句柄全部释放，不产生悬挂的读取或句柄泄漏

#### Scenario: 关闭与自然退出竞态
- **WHEN** 关闭与进程自然退出同时发生
- **THEN** 拆卸操作幂等执行，退出结果与关闭语义不被破坏
