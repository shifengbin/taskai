## Context

应用当前由 `defaultDataDirectory()` 调用 `os.UserConfigDir()`，再将结果传给 `settings.Default()` 和 `storage.New()`。在 macOS 上，这会生成 `~/Library/Application Support/taskai/tasks.json`，而 `settings.Default()` 又将默认工作区根目录派生为同一数据目录下的 `workspaces`。

本变更同时影响新安装路径和升级数据发现。直接改变路径会让升级用户看起来丢失全部任务和设置；直接移动整个旧目录又会移动已有任务工作区，使任务保存的路径快照失效。因此配置文件迁移和已有工作区处理必须分开。

## Goals / Non-Goals

**Goals:**

- macOS 新安装使用 `~/.taskai/tasks.json` 和 `~/.taskai/workspaces`。
- 已有 macOS 用户首次使用新版时自动发现并安全迁移旧配置。
- 仅把旧默认工作区设置更新为新默认值，保留用户明确配置的其他路径。
- 保持已有任务工作目录快照和磁盘内容不变。
- 保持 Linux、Windows 的现有行为不变。

**Non-Goals:**

- 不把旧任务目录批量移动到 `~/.taskai/workspaces`。
- 不合并两套已经同时存在的配置数据。
- 不改变设置数据结构、Wails 绑定或设置界面。
- 不自动清理 `~/Library/Application Support/taskai` 中留下的旧工作区和迁移来源文件。

## Decisions

### 在仓库初始化前解析并迁移 macOS 数据目录

应用必须先确定最终数据目录，再构造 `settings.Default()` 和 `storage.Repository`。macOS 路径解析将使用 `os.UserHomeDir()` 生成 `~/.taskai`；其他平台继续使用 `os.UserConfigDir()/taskai`。平台选择和文件系统操作应封装为可注入依赖的内部辅助逻辑，使 Linux 测试环境也能覆盖 macOS 的路径与迁移场景。

备选方案是继续统一依赖 `os.UserConfigDir()` 并在 macOS 修改返回结果，但 Go 标准库行为不可由应用控制。另一个方案是在设置加载后才迁移，这时仓库已经可能在新目录创建空配置，无法可靠区分首次启动和迁移失败，因此不采用。

### 只迁移持久化配置，不移动旧工作区

当前持久化状态集中在 `tasks.json`。迁移将把该文件完整复制到 Home 下的临时迁移目录，按现有数据模型读取并仅处理默认工作区设置，成功后再以目录重命名发布为 `~/.taskai`。旧目录和旧工作区保持不动，已有任务继续使用保存的旧路径快照。

若旧 `Settings.WorkspaceRoot` 精确等于旧默认路径，则改为 `~/.taskai/workspaces`，使以后开始的任务使用新默认位置；任何其他值都视为用户自定义并原样保留。任务记录中的 `WorkspaceRoot` 和 `WorkspacePath` 均不改写。

备选方案是移动整个旧目录并重写所有任务快照。它会扩大文件系统操作范围，并可能影响正在执行、被外部工具引用或采用符号链接的工作区，因此不采用。只改变新安装默认值而不迁移配置也会造成升级用户数据不可见，因此同样不采用。

### 用目录发布保证失败时可回退

迁移先在 `~/.taskai` 的同级临时目录完成。只有配置读取、必要的默认路径更新和持久化全部成功后，才将临时目录重命名为 `~/.taskai`。任一步骤失败都清理临时目录并返回旧数据目录，使本次启动继续读取旧配置；旧文件始终不被修改。

如果 `~/.taskai` 已经存在，无论旧目录是否存在，都直接使用新目录，不进行自动合并。即使新目录中的 `tasks.json` 尚不存在，现有目录也代表用户已经选择或准备了新位置；自动导入旧数据可能覆盖该意图。

### 沿用现有设置和任务快照语义

`settings.Default(dataDirectory)` 已会从数据目录生成 `workspaces`，因此新安装不需要新增设置字段。任务开始时仍由 `PrepareStartTask` 从当前 `Settings.WorkspaceRoot` 生成并保存快照，设置界面的“仅影响之后开始执行的任务”语义保持不变。

## Risks / Trade-offs

- [旧配置目录会继续占用空间] → 为保护旧任务快照和提供人工回退，不自动删除旧目录；后续如需清理应单独设计可确认的迁移工具。
- [迁移后旧版应用读取到旧的配置副本] → 本变更不保证新旧版本并行使用；保留旧文件主要用于失败恢复，文档和测试以新版单实例启动为前提。
- [新目录被提前创建但内容为空] → 将“目录存在”视为明确冲突并优先使用新目录，避免自动覆盖；用户可手动移走空目录后再次触发迁移。
- [Home 目录或迁移写入不可用] → 不破坏旧数据并回退到旧数据目录；新安装则沿用现有配置目录或临时目录回退策略，确保应用仍可启动。

## Migration Plan

1. 发布包含 macOS 数据目录解析和迁移逻辑的版本。
2. macOS 启动时先检查 `~/.taskai`；存在则直接使用。
3. 新目录不存在且旧 `tasks.json` 存在时，在 Home 下准备临时目录并迁移配置。
4. 旧工作区设置等于旧默认值时仅更新设置中的根目录；已有任务快照不变。
5. 完成后发布新目录；失败则删除临时目录并使用旧目录启动。
6. 回滚到旧版本时，旧配置和工作区仍保留；新版迁移后的新增状态不会自动回写旧配置。
