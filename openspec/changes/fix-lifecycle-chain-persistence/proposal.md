## 为什么

用户刚保存的生命周期命令链可能在创建任务并点击开始后消失，导致执行阶段只能找到已被覆盖的旧链定义。任务状态或其他设置保存使用完整快照时，缺失或过期的生命周期字段会覆盖专用接口刚保存的命令库、命令链和默认链。

## 变更内容

- 调整设置保存语义：通用设置快照更新不得清空或回退当前已持久化的生命周期命令、命令链和默认链。
- 保留生命周期专用保存接口的完整配置，任务创建、状态切换等普通设置更新只能修改其负责的字段。
- 增加覆盖“保存命令链 -> 创建任务 -> 开始任务”流程的后端回归测试，并覆盖缺失生命周期字段和过期快照。
- 在不改变现有 API 形状的前提下，保证旧设置数据仍可按现有归一化规则加载。

## 能力

### 新增能力

- `lifecycle-settings-persistence`: 生命周期命令、命令链及默认链在普通设置保存和任务生命周期操作中的持久化保护。

## 影响范围

- 后端设置保存入口、设置归一化和存储仓库的读改写逻辑。
- 任务创建与状态切换触发的设置保存调用，以及生命周期链运行时读取配置的路径。
- Go 存储、设置和应用层回归测试；不要求前端 API 结构变更。
