## 上下文

设置文件同时保存普通工作台设置和生命周期配置。前端在创建任务、切换当前状态或调整面板宽度时，会把设置对象作为完整快照提交；生命周期命令和命令链则通过独立接口保存。当前 `SaveSettings` 在仓库层整体替换 `data.Settings`，因此旧快照中的空值或旧值可以覆盖刚写入的生命周期配置。

任务开始时，生命周期执行器会根据任务保存的链 ID 从当前设置读取链定义。配置被覆盖后，任务仍保存原链 ID，但执行器只能报告链不存在，表现为“刚保存的命令链消失”。

## 目标与非目标

**目标：**

- 明确普通设置与生命周期配置的写入边界，普通设置保存不能删除或回退生命周期配置。
- 保持生命周期命令、命令链和默认链专用接口的完整读改写能力。
- 用回归测试固定保存链、创建任务、开始任务这一用户流程，并验证旧快照不会覆盖新链。
- 兼容已有设置文件和现有生命周期归一化逻辑。

**非目标：**

- 本变更不引入全局设置版本号、冲突提示或跨进程事务协议。
- 不重构任务生命周期执行器、链 ID 格式或命令链数据模型。
- 不改变生命周期命令的执行顺序、钩子语义和前端交互布局。

## 决策

### 1. 普通设置保存只拥有普通设置字段

`SaveSettings` 在持久化时从当前数据中保留生命周期命令、命令链和默认链；生命周期字段由专用命令、命令链和默认链接口写入。前端 `saveSettings` 不再把生命周期字段加入普通设置请求，避免 React 中的旧快照参与生命周期配置写入。

这样可以直接阻断“任务创建/开始触发的普通保存覆盖命令链”路径，同时不需要猜测请求中的生命周期数组是用户有意修改还是过期快照。需要修改生命周期配置的调用方必须使用已有专用接口。

备选方案是给设置增加版本号并对所有写入做乐观并发控制；它能处理更广泛的并发冲突，但会扩大 API、前端状态和迁移范围，本次问题不需要承担该复杂度。

### 2. 默认链使用专用仓库读改写

将 `SaveLifecycleDefaultChain` 的后端实现从通用 `SaveSettings` 改为仓库专用方法。该方法在最新数据上只更新一个钩子的默认链，并继续执行链存在性和适用范围校验，避免新的字段所有权规则阻止合法默认链更新。

备选方案是在通用保存中增加“生命周期字段已授权”的标记；这会让同一个接口同时承担两套语义，且容易被旧客户端误用，因此不采用。

### 3. 以持久化回归测试作为修复入口

测试先通过专用接口写入自定义命令和命令链，再使用只修改普通字段的旧设置快照保存，最后创建并开始任务。断言命令、命令链和默认映射仍存在，并且执行器能解析该链。另加直接仓库测试，验证普通保存不会覆盖当前生命周期配置。

## 风险与权衡

- [风险] 旧的外部调用方可能依赖 `SaveSettings` 同时写入生命周期字段。→ 保留请求结构和读取结果不变，在 README/API 注释中说明生命周期字段必须通过专用接口保存，并将现有 Go 测试迁移到专用接口。
- [风险] 普通设置保存与专用生命周期保存同时发生时仍可能存在普通字段的最后写入覆盖。→ 本次只保护生命周期字段；全量并发冲突协议列为后续变更。
- [风险] 前端缓存的设置对象在专用保存后仍可能短暂过期。→ 专用接口返回最新记录，前端继续刷新设置；普通保存不再携带生命周期字段，所以过期缓存不会破坏持久化配置。

## 迁移计划

1. 先增加仓库和应用层回归测试，确认当前实现能复现覆盖问题。
2. 实现字段所有权调整、专用默认链保存和前端请求裁剪。
3. 运行 Go race 测试、前端测试和生产构建。
4. 若需要回滚，恢复 `SaveSettings` 的旧实现即可；数据文件格式无需迁移。
