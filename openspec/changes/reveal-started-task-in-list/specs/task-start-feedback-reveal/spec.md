## ADDED Requirements

### Requirement: 开始反馈前定位目标任务

系统 SHALL 在本会话确认任务进入“执行中”、切换到执行中任务列表并渲染目标条目后，于开始任务反馈前检查目标条目是否完整位于任务列表的可视区域。目标条目被裁切时，系统 MUST 仅调整任务列表自身的垂直滚动位置，使目标条目完整可见；系统不得滚动应用窗口、左侧面板之外的容器或右侧内容区。

#### Scenario: 目标任务位于执行中列表视口外
- **WHEN** 一条未执行任务进入执行中列表，且其目标条目位于任务列表可视区域的上方或下方
- **THEN** 系统仅滚动任务列表到目标条目完整可见，并在定位后为该条目播放一次开始反馈

#### Scenario: 目标任务已经完整可见
- **WHEN** 一条未执行任务进入执行中列表，且其目标条目已完整位于任务列表可视区域内
- **THEN** 系统不得改变任务列表当前滚动位置，并为该条目播放一次开始反馈

#### Scenario: 生命周期事件确认任务进入执行中
- **WHEN** 开始任务的异步生命周期事件确认任务进入执行中，且目标条目初始位于任务列表可视区域外
- **THEN** 系统应用与即时开始响应相同的列表定位和开始反馈行为

### Requirement: 定位后保持可访问的反馈语义

系统 MUST 在目标任务完成可见性定位后保留既有的一次性开始反馈语义：默认偏好下仅目标执行中任务闪烁两次，减少动态效果偏好下不播放闪烁且仅目标任务显示短暂静态高亮。定位不得改变任务尺寸、排序、状态、选择或展开状态。

#### Scenario: 减少动态效果时定位目标任务
- **WHEN** 用户启用减少动态效果偏好，且开始任务进入执行中列表时目标条目位于视口外
- **THEN** 系统将目标条目即时定位至可视区域，并仅为该条目显示短暂静态高亮

#### Scenario: 反馈期间目标任务不再可见
- **WHEN** 开始反馈令牌存在，但对应任务在定位前已不在执行中列表中渲染
- **THEN** 系统不得滚动任务列表或为其他任务显示开始反馈
