## ADDED Requirements

### Requirement: 滚动后打开的任务操作菜单保持在视口内

系统 MUST 在任务列表滚动后的任意可见任务上，为“任务操作”下拉菜单和右键菜单计算不超出应用可用视口的展示位置。系统 MUST 优先在触发位置下方展示菜单；下方空间不足时 MUST 将菜单展示在触发位置上方，并在水平方向调整位置以避免越过视口左右边缘。

#### Scenario: 列表底部任务打开下拉菜单
- **WHEN** 用户滚动到任务列表靠下的位置，并点击剩余下方空间不足以展示完整菜单的“任务操作”按钮
- **THEN** 菜单展示在按钮上方或其他可用位置，所有菜单项均保留在视口内并可选择

#### Scenario: 列表底部任务打开右键菜单
- **WHEN** 用户在任务列表靠下的位置右键点击任务，且点击位置下方空间不足以展示完整菜单
- **THEN** 菜单展示在点击位置上方或其他可用位置，所有菜单项均保留在视口内并可选择

#### Scenario: 菜单在视口右边缘打开
- **WHEN** 用户在靠近视口右边缘的位置打开任务操作菜单或右键菜单
- **THEN** 系统调整菜单的水平位置，使菜单不越过视口右边缘且不遮挡其可访问性

### Requirement: 高度受限的任务操作菜单保留全部操作

当完整任务操作菜单的高度超过任何一侧可用视口高度时，系统 MUST 限制菜单高度并提供菜单内部纵向滚动。系统 MUST 不裁切菜单项，也不得因此使任务列表或应用根容器滚动。

#### Scenario: 菜单项目数量超过可用高度
- **WHEN** 用户打开包含超过可用视口高度的任务操作菜单
- **THEN** 菜单在视口内展示，并允许用户在菜单内部滚动到每一项操作

### Requirement: 视口定位不改变任务操作语义

系统 MUST 在调整任务菜单位置后保持既有的菜单项目过滤、生命周期锁定、菜单项回调、点击外部关闭和 Escape 关闭行为。

#### Scenario: 从翻转后的菜单执行操作
- **WHEN** 用户从因视口空间不足而翻转或限制高度的任务菜单中选择一个可用操作
- **THEN** 系统执行与同一菜单在普通位置打开时相同的任务操作，并关闭菜单
