## 背景

当前应用在调度生命周期链时，将活动模板的 `branch` 解析为 `GitCloneRepositoryBranch`。该值同时由“克隆指定 Git 仓库”和“生成清单文件”消费；任务服务在创建和编辑时还会把同一个值持久化写入空的内置 Git 信息分支。于是分支继承既不受命令链顺序控制，也会改变任务快照。

本变更必须将分支补全限制在单次生命周期执行内。内置命令仍保持不经过 Shell 执行、系统命令不改变相邻自定义命令字节流、Git 显式分支优先于默认分支，以及空分支由远程决定的既有边界。

## 目标 / 非目标

**目标：**

- 提供可在命令链中显式放置的固定“更新默认分支”命令。
- 支持以可选的 `templateField` 参数选择任务模板字符串字段，默认选择 `branch`。
- 使默认分支只在当前执行请求的任务副本和单仓库克隆状态中生效。
- 让单仓库克隆、清单生成和批量 Git 克隆只读取执行态数据。
- 为新安装和未修改的既有预置链加入该命令，同时不重建、覆盖或改写用户修改后的预置链。

**非目标：**

- 不向任务、额外信息或模板持久化回写解析出的默认分支。
- 不改变 Git 仓库地址、目录安全、远程分支检查、本地分支创建或已存在目标跳过规则。
- 不改变自定义生命周期命令的标准输入、标准输出、环境变量或执行顺序。
- 不为用户自定义命令链自动插入“更新默认分支”命令。

## 决策

### 1. 使用独立固定命令和链级参数，而非让消费者继续隐式解析模板

新增固定命令 ID `system.lifecycle.update-default-branch`、类型 `update-default-branch`、名称“更新默认分支”，允许范围固定为 `beforeStart`、`postStart` 与 `updateTask`，并允许链级参数。参数只接受至多一行 `templateField=<模板字段键>`；未提供参数时规范化为空参数列表，运行时使用 `branch`。空值、重复键、未知键或不含等号的参数在保存链时拒绝。

字段是否存在及其类型在执行时按活动模板和冻结的任务模板字段解析：字段不存在或字符串为空时得到空默认分支；字段存在但不是字符串时按现有模板分支规则使命令链失败。将字段选择放在命令自身而不是复制为单仓库克隆和清单命令的参数，可以让一个链明确表达何时、以哪个模板字段应用默认值。

备选方案是在“克隆指定 Git 仓库”和“生成清单文件”各自增加模板字段参数。该方案会重复解析、类型校验和空值规则，也无法让批量 Git 克隆共享结果，因此不采用。

### 2. 在运行器中维护隔离的执行态任务副本和默认分支

应用调度命令链时解析当前活动模板可见字段，并将该解析结果冻结到 `CommandChainRequest`。命令链运行器开始执行前深复制任务的 Git 信息快照；“更新默认分支”读取冻结字段，保存解析出的执行态默认分支，并仅为内置 Git 信息中空白的 `branch` 填入非空解析值。显式 Git 分支绝不覆盖，其他额外信息也不处理。

同一请求中的后续“克隆指定 Git 仓库”读取执行态默认分支，即使任务没有 Git 信息也能得到相同分支；“生成清单文件”和“Git 仓库克隆”只读取已更新的执行态 Git 信息。没有先执行该命令时，三类消费者都视为没有默认分支：单仓库和批量克隆交由远程检出默认分支，清单保留空字符串。

不调用任务服务或存储库保存该副本。任务创建和编辑也移除模板分支回填，使 Git 信息快照保持用户提交的原值。系统命令继续不改写链中传递给自定义命令的字节流。

备选方案是在调度层预先向所有消费者传入一个全局默认分支。它会让“更新默认分支”成为没有实际时序效果的标记，且无法用链顺序限制其影响，因此不采用。持久化回填已被明确排除，会造成意外的任务数据变更。

### 3. 将预置升级建模为版本 4 的精确结构迁移

默认配置中的 `iterations-ai` 在链首新增“更新默认分支”，随后保持创建目录、指定仓库克隆、清单生成和批量克隆的顺序；“更新仓库”在链首新增该命令，随后生成清单并克隆缺失仓库。两个链仍不是任何钩子的默认链。

预置版本提升到 4。加载旧设置时，仅当稳定 ID、名称、适用范围和命令引用完全匹配版本 3 的原始预置定义时，才在链首插入新命令；缺失的链和任意已修改链均保持不变。版本 1、2、3 的识别使用各自独立的历史预置定义，不能用最新 `DefaultLifecycleChains` 反推旧结构，以免新命令改变后破坏旧版本迁移判断。

备选方案是按预置 ID 无条件改写或重建链。它会覆盖用户自定义或重新插入已删除的链，违反既有可删除预置契约，因此不采用。

### 4. 保持界面与失败语义一致

固定命令归一化时恢复中文说明、适用范围与参数模式，前端仅需扩展生命周期命令类型并展示已有的命令链追加参数输入。`beforeStart` 中的字段类型错误继续阻止任务开始；`postStart` 和 `updateTask` 中的错误继续保留已提交状态并提供重试。空字段不是错误，保持既有远程默认分支和清单空字符串规则。

## 风险 / 权衡

- [用户链未加入新命令后不再自动继承模板分支] → 这是显式编排的预期行为；在中文命令说明与 README 中说明，并且仅升级未修改的内置预置链。
- [活动模板在任务保存后切换] → 与现有生命周期模板解析一致，在调度时读取当时活动模板并冻结可见字段，运行中不受之后设置变化影响。
- [多个更新默认分支命令出现在同一链] → 每次命令仅补全仍为空的 Git 分支；单仓库克隆使用其之前最近一次命令解析出的执行态默认分支，链顺序可预测。
- [旧预置迁移误将用户修改识别为原始链] → 以完整名称、钩子、命令 ID、参数和顺序比较版本 3 的静态定义，并为修改、删除和早期版本各增加回归测试。

## 迁移计划

1. 扩展固定命令模型、绑定类型和参数规范化；新安装直接写入版本 4 预置。
2. 保留版本 1 至 3 的历史预置匹配定义，执行既有迁移后仅升级完全匹配版本 3 的两个预置链。
3. 移除保存期分支回填和消费者的模板分支回退，接入执行态默认分支命令。
4. 发布前覆盖设置迁移、生命周期执行器、任务保存、应用调度、前端命令编辑及 README，并执行 Go、前端和构建验证。
5. 回滚时移除新命令引用与版本 4 升级逻辑；用户的持久化 Git 信息仍保持原始值，不需要数据恢复。
