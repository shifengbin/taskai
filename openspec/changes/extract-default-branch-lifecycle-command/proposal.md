## 为什么

当前任务模板的 `branch` 字段被单个仓库克隆、清单生成和任务保存逻辑分别隐式读取或回填。分支继承无法通过命令链明确编排，且会永久改写任务保存的 Git 信息快照，难以按不同链选择模板字段来源。

## 变更内容

- 新增固定生命周期命令“更新默认分支”，在执行链内根据指定的任务模板字段补全空的内置 Git 信息 `branch`；参数 `templateField=<字段键>` 可选，省略时使用 `branch`。
- 默认分支补全仅作用于当前命令链的内存任务快照和单仓库克隆所需的执行态分支，不得回写持久化任务。
- “克隆指定 Git 仓库”不再直接读取模板 `branch`；“生成清单文件”不再自行回退模板字段，二者都只消费命令链执行态数据。
- 移除任务创建、编辑时将模板分支写入空 Git 信息分支的行为，保留 Git 信息显式分支优先和空分支使用远程默认分支的语义。
- 更新 `iterations-ai` 与“更新仓库”预置链，在链首加入“更新默认分支”，并通过一次性预置迁移仅升级未被用户修改的旧预置链。

## 能力

### 新增能力

- `lifecycle-default-branch-update`：定义默认分支更新命令的参数、执行态补全、单仓库克隆协作和非持久化边界。

### 修改能力

- `default-branch-lifecycle-presets`：预置命令链顺序与一次性迁移规则改为包含默认分支更新命令。
- `manifest-file-generation`：清单分支只读取命令链执行态 Git 信息，不再直接解析任务模板字段。

## 影响

- 影响 `internal/settings` 的固定命令定义、参数校验、预置版本和预置链迁移。
- 影响 `app.go`、`internal/lifecycle` 与 `internal/task` 的生命周期执行态分支解析、Git 克隆、清单生成及任务保存逻辑。
- 影响生命周期编排的前端命令类型与中文说明、Go/前端测试和 README 生命周期文档。
