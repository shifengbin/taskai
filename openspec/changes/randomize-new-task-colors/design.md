## 背景

任务创建弹窗目前以固定的 `#4f46e5` 初始化颜色，并在保存后重置为同一颜色。颜色由前端表单传入既有的任务创建绑定，后端负责校验与持久化；任务列表直接使用任务已保存的颜色作为视觉标记。

本变更只调整桌面端新建表单的默认选色。用户已经确认随机色的目的在于提升任务之间的可区分性，且仍需要保留颜色选择器供用户在提交前修改。

## 目标 / 非目标

**目标：**

- 每次进入新建任务表单时，为颜色选择器预选一个随机的、适合界面展示的颜色。
- 使用有限且经过选择的颜色集，使任务列表在浅色和深色主题中均能保持清晰的颜色标记。
- 保持用户手动选择颜色以及编辑任务时的现有行为。
- 让随机选择可通过受控随机值进行前端测试。

**非目标：**

- 不保证所有历史任务的颜色全局唯一，也不修改历史任务。
- 不在后端、Wails 绑定或 HTTP 接口中生成随机颜色。
- 不新增颜色偏好设置、颜色标签或调色板配置界面。

## 决策

### 使用前端预设颜色集作为随机来源

在前端定义单一的任务颜色常量，并提供从该集合中按均匀随机索引选取颜色的辅助逻辑。颜色集应包含多个红、橙、黄、绿、青、蓝、靛、紫、粉等色相，以服务任务树的色条和浅色背景标记。

选择有限颜色集而非随机生成任意十六进制值：任意 RGB 可能过暗、过亮或在不同主题下难以分辨；预设集也让测试能验证结果属于受支持范围。随机选择不承诺颜色唯一，偶然重复仍符合随机默认值的语义。

### 仅在打开新建表单时生成默认色

打开新建表单时生成随机颜色并写入表单草稿；打开编辑表单时读取任务已保存的颜色。提交成功后清理草稿，下一次打开新建表单才重新生成随机色。这样同一次表单编辑、验证失败或重新渲染都不会无故改变用户当前看到的颜色。

选择在前端生成而非后端为空值回退时生成：颜色选择器需要在提交前展示默认颜色，并允许用户对其覆盖；前端直接传递最终颜色还能保持现有创建接口和后端校验逻辑不变。

### 保持手动颜色覆盖优先

随机色只作为新建草稿的初始值。颜色选择器的变更仍直接更新草稿，提交时沿用草稿值，因此用户指定的颜色始终优先于随机默认值。

## 风险 / 权衡

- [连续随机结果可能相同] → 不将随机预选描述为全局唯一；使用多个色相的颜色集降低相邻任务重复的概率。
- [测试依赖随机数] → 将随机选择封装为可单独验证的逻辑，并在测试中控制随机值或验证结果属于预设集。
- [颜色集在某个主题下辨识度不足] → 复用任务树当前的色条和淡色背景展示方式，并在浅色、深色主题下覆盖关键渲染测试。

## 迁移计划

无需数据迁移。发布后仅影响之后打开的新建任务表单；已有任务继续读取和展示已保存的颜色。若需要回退，只需恢复固定默认色，不影响已创建任务的数据。
