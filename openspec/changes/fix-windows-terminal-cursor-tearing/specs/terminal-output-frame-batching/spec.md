## ADDED Requirements

### Requirement: 同一静默期内的输出事件合并为一次写入

系统 MUST 按终端会话缓冲 PTY 输出事件，输出静默满约 32 毫秒后把该会话缓冲的全部数据按到达顺序合并为一次写入交给终端组件解析。同一会话的输出 MUST NOT 重排或丢弃；不同会话的缓冲 MUST 相互独立，一个会话的输出量 MUST NOT 推迟其他会话的冲刷。

#### Scenario: 同一静默期多次输出合并写入

- **WHEN** 某会话在输出静默期内先后收到多个 PTY 输出事件
- **THEN** 该会话在这些事件全部到达且静默期满后按顺序拼接为一次终端写入，而不是每个事件各写入一次

#### Scenario: 连续输出按截止时限冲刷

- **WHEN** 某会话的输出事件持续到达、静默期始终未满足
- **THEN** 自首批缓冲起不超过约 64 毫秒冲刷已缓冲内容，输出顺序与到达顺序一致，写入延迟有界

#### Scenario: 退出事件先冲刷缓冲

- **WHEN** 某会话收到退出事件时缓冲中仍有未写入的输出
- **THEN** 系统 MUST 先按顺序冲刷缓冲中的输出（不改变光标状态），再处理退出展示，缓冲不残留数据

### Requirement: 缓冲占用有界

单会话缓冲 MUST 设置大小上限（约 1MB 字符），超过上限时 MUST 立即同步冲刷，不得无界占用内存。会话销毁时 MUST 取消未决的冲刷与光标恢复回调并丢弃缓冲，不产生悬挂定时器或对已销毁终端的写入。

#### Scenario: 突发大输出触发上限冲刷

- **WHEN** 单个会话累积的未冲刷输出超过缓冲上限
- **THEN** 系统立即同步冲刷该缓冲并继续接收后续输出，应用内存占用不随输出量无界增长

#### Scenario: 会话销毁取消未决回调

- **WHEN** 会话在缓冲未冲刷或光标恢复未执行时被销毁
- **THEN** 未决回调全部取消，已销毁的终端不再收到任何写入

### Requirement: 高频重绘不出现可见的中间态渲染

对以"逐行重绘 + 光标定位"方式高频刷新屏幕的终端程序（ConPTY 合成流的典型形态：一帧拆成多个以 `ESC[?25h` 结尾的绘制批次），嵌入终端的可见画面 MUST 只呈现重绘完成后的状态，光标 MUST NOT 在重绘过程中可见地跳到中间位置。判定为绘制批次的冲刷（约 ≥64 字符且真实以显示光标序列结尾）MUST 在写入末尾追加合成的隐藏光标序列，并在输出静默约 48 毫秒后补写恢复序列；批间继续输出时恢复 MUST 被跳过。小于阈值的冲刷（如击键回显）与不含光标序列的流式纯文本 MUST 保持光标可见。该行为 MUST 同时适用于前台选中会话和后台会话切回后的画面。

#### Scenario: 合成重绘流下光标稳定

- **WHEN** 在 Windows 嵌入终端中运行一个循环执行"光标归位、重写多行、重新定位光标"的合成脚本（模拟 codex 等 TUI 的高频重绘）
- **THEN** 屏幕字符持续更新为各帧的最终内容，期间不出现光标在行间反复跳变的中间态；帧间隙光标出现在帧末位置

#### Scenario: 击键回显光标保持可见

- **WHEN** 用户在交互中输入字符、终端回显少量输出（不含绘制批次特征）
- **THEN** 光标在这些小冲刷写入后立即可见，不被合成的隐藏序列掩盖

#### Scenario: 后台会话切回画面无丢失

- **WHEN** 某终端在后台持续重绘输出，用户切换到其他终端后再切回
- **THEN** 该终端呈现重绘完成后的最新画面，各行动作帧号一致、无内容丢失

#### Scenario: 集成验证方法

- **WHEN** 使用 `wails dev` 启动应用并从输出获取浏览器调试地址，用浏览器工具（chrome-devtools MCP）打开应用
- **THEN** 在任务终端中运行上述合成重绘脚本（300 帧/15fps/20 行，约 20 秒），以 rAF 采样 `.xterm-cursor` 可见样本的位置分布：修复前光标出现约 90-102 个不同位置，修复后收敛到个位数且仅剩合法位置（键入回显位、帧末停靠位、结束提示位）；辅以 PerformanceObserver 确认无长任务回归；测试完成后关闭调试进程
