## Context

任务开始前会根据工作区根目录和任务 ID 生成并保存工作目录快照，但只有被选中的生命周期命令链才会真正创建该目录。任务创建时清空全部链选择是有效配置，因而执行中的任务可能持有一个不存在的 `WorkspacePath`。

当前新增终端、命令终端、直接任务命令、任务菜单自定义命令以及“打开任务文件夹”都从同一执行中任务校验取得 `WorkspacePath`。该校验只拒绝空字符串，底层 PTY 或目录打开逻辑随后因目录实际不存在而失败。本变更只解决用户明确选择完全无命令链时的预期默认目录，不改变生命周期命令本身的工作目录。

## Goals / Non-Goals

**Goals:**

- 让完全未选择生命周期命令链的执行中任务通过交互操作使用当前用户的 Home 目录。
- 让所有任务级交互入口使用同一目录解析逻辑，避免某个菜单项遗漏回退。
- 保持任务工作区快照、目录创建和安全删除逻辑不变。
- 让 Home 目录无法获取、无法访问或不是目录时返回明确错误，而不是继续执行操作。

**Non-Goals:**

- 不为无命令链任务创建、修复或删除任务工作目录。
- 不为已选择任意命令链但目录缺失、路径异常或权限不足的任务回退到 Home。
- 不改变生命周期钩子、Git 命令或前端菜单和 Wails 绑定的接口。

## Decisions

### 以空链选择作为唯一回退条件

操作上下文仅在 `LifecycleChains` 规范化后为空时解析 Home 目录。模型会移除空白链 ID，所以该条件同时覆盖显式空映射和各钩子均被清空的保存结果。

不以 `WorkspacePath` 是否存在作为条件。这样能保留已选择命令链任务的错误信号，避免把命令链排序错误、目录被手动删除或访问异常静默地变成在 Home 执行。

备选方案是在开始任务时隐式创建任务目录。该方案会绕过“创建目录”内置命令及其顺序语义，因而不采用。

### 在应用层集中生成交互操作目录

在应用层、执行中任务状态和生命周期锁定校验成功后，使用一个共享的操作上下文或目录解析函数取得目录。空链任务通过 `os.UserHomeDir` 取得 Home，并确认其为可用目录；其余任务返回持久化的 `WorkspacePath`。

新增终端、命令终端、直接任务命令、打开任务文件夹和任务菜单命令均使用该结果。任务菜单的前置和后置脚本沿用同一调用上下文，确保它们与菜单主命令的工作目录一致。

备选方案是在每个入口分别判断空链。这会造成重复的 Home 查询，并容易遗漏脚本或未来的命令入口，因而不采用。

### 不将 Home 写回任务记录

Home 目录只作为一次交互操作的运行目录。`WorkspaceRoot` 和 `WorkspacePath` 继续保存任务工作区的预期位置，不写入或迁移为 Home。生命周期的创建、删除和安全路径校验继续只面对任务工作区，避免把用户主目录带入受控清理边界。

### 使 Home 目录解析可在测试中替换

应用层将 Home 目录查询封装为可替换依赖，使测试不依赖运行测试的账户和文件系统。测试通过固定的临时目录验证传给终端、命令、脚本和目录打开器的路径，并覆盖查询失败或非目录的错误。

## Risks / Trade-offs

- [在 Home 运行无命令链任务的自定义命令可能访问用户文件] → 仅在用户明确保存空链选择时启用；任何已选链任务继续使用任务工作区。
- [系统无法提供 Home 目录] → 在启动终端、命令或目录打开前返回错误，不启动部分操作。
- [新增任务级入口绕过共享解析] → 将解析置于应用层共享操作上下文，并为各现有入口编写覆盖测试。
- [误改工作区快照会扩大清理目标] → 保持任务持久化字段和 `workspace` 包不变，不让 Home 参与生命周期删除。

## Migration Plan

无需迁移已有任务或设置。已保存为空链的执行中任务在升级后首次使用交互操作时直接按新规则使用 Home；已选链任务保持现有行为。回滚仅恢复此前版本，持久化数据不受影响。
