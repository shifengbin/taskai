## Context

任务工作台当前将任务目录创建固化在开始流程中、将目录删除固化在结束流程中。自定义菜单项可运行前后脚本，但脚本只能围绕单一菜单命令执行，既不支持复用的链，也没有任务生命周期级别的进度、失败和重试状态。

本变更为任务引入可复用的全局命令链。命令链会在 `beforeStart`、`postStart`、`beforeEnd`、`postEnd` 和 `updateTask` 五个钩子执行；其中 `updateTask` 仅适用于执行中任务保存修改之后。任务详情 HTTP 响应是首命令输入的基础结构，HTTP 服务正在运行时还需在顶层加入 `baseURL`。

实现必须延续现有 JSON 持久化、Wails Go 绑定、任务工作区安全校验和已选 Shell 初始化环境。目录创建/删除必须不再作为生命周期服务的隐式副作用，而是系统内置命令，且用户可将它们自由放入任意链中。

## Goals / Non-Goals

**Goals:**

- 提供全局命令库、可排序和可复制的命令链，以及按钩子设置默认链的能力。
- 为每个任务保存五个独立链引用，并在新建及未执行任务编辑中按名称选择；执行中和已完成任务编辑时只读展示。
- 以可观察、可重试且不破坏任务状态机的方式串行运行链。
- 将每一命令的标准输出原样传给下一命令，并安全执行系统内置目录命令。
- 在配置、任务和运行状态持久化后保持删除约束和旧数据兼容。

**Non-Goals:**

- 不支持链内并行、条件分支、变量替换、命令输出合并或自动补偿/回滚。
- 不为自定义命令提供交互式终端、输出日志浏览器或跨应用重启后继续运行的子进程。
- 不因后置钩子或 `updateTask` 钩子失败而回滚已经提交的任务业务数据。

## Decisions

### 1. 使用全局命令、全局链和任务引用组成三层模型

在设置持久化中新增以下结构：

- `LifecycleCommand`：稳定 ID、名称、类型、可执行命令和逐行参数；类型分为自定义命令、创建任务目录和删除任务目录。
- `LifecycleCommandChain`：稳定 ID、名称和有序命令 ID 列表。
- `LifecycleDefaultChains`：以钩子名为键、链 ID 为值的默认映射，一个钩子至多有一个默认链。

任务新增以钩子名为键、链 ID 为值的选择映射；未选择的钩子不执行链。系统内置目录命令使用固定 ID，并在设置规范化时补回，因此可被引用但不可编辑或删除。初始设置提供单命令“创建任务工作目录”链作为 `beforeStart` 默认链，以及单命令“删除任务工作目录”链作为 `postEnd` 默认链。

任务只保存链 ID 而非链快照，因此后续执行和重试会读取链的最新定义。运行一轮链时，运行器会先冻结该轮所需的链和命令内容，避免用户在命令执行中修改配置而改变正在运行的顺序；下一次重试会重新读取最新版本。

选择引用而非任务副本可让命令和链的维护即时作用于后续任务运行。替代方案是将链快照保存到任务中；该方案会让全局修改无法生效，违背“已选择任务使用新版链”的约定。

### 2. 用持久化执行记录实现进度、锁定与失败重试

任务新增可选的生命周期执行记录，保存钩子、链 ID、当前命令 ID/名称/序号、运行或失败状态和错误消息。开始一轮链前写入运行记录；每进入一个命令更新进度；成功后清除记录；失败后保存失败记录。前端通过 Wails 事件实时刷新，同时在重新读取任务后仍能展示失败与重试入口。

有运行或失败执行记录的任务均保持锁定。前端禁用右键任务操作、任务操作菜单、编辑、排序和状态变更，后端也在所有相应绑定入口进行同样的检查。重试只能由同一任务发起，并从当前所选链的第一个命令开始。

应用启动发现未完成的运行记录时，将其标为失败并说明被应用重启中断；不会假定外部进程仍可安全继续。此做法避免重启后显示永不结束的运行状态，同时与“从链首重试”相容。

### 3. 明确五个钩子的状态时序

开始任务时先锁定任务并运行 `beforeStart`。其成功后才写入任务目录快照并将状态改为执行中，随后运行 `postStart`。`beforeStart` 失败时任务仍为未执行；若它已经通过内置命令创建目录，该目录保留，下一次重试从链首安全复用。

结束任务时先运行 `beforeEnd`；成功后关闭全部终端并将状态改为已完成，随后运行 `postEnd`。目录删除仅由用户链中的内置删除命令完成，生命周期服务不再隐式删除目录。`beforeEnd` 失败时任务保持执行中；`postStart`、`postEnd` 和 `updateTask` 失败时业务状态及已保存的修改保持不变。

保存任务修改时，未执行和已完成任务只保存数据；执行中任务保存成功后才运行 `updateTask`。该钩子失败不回滚保存结果。

将前置/后置钩子拆为两次链运行，而不是将状态变更嵌入单一链中，能严格保证前置失败不变更状态，并允许后置失败保留已变更状态后重试。

### 4. 采用原样标准输入输出传递上下文

运行器为每个命令提供前一阶段的标准输出作为标准输入，不解析、不合并、不追加字段。首命令输入由任务详情 HTTP 响应结构编码而成；`beforeStart` 使用尚未提交但已计算任务目录的未执行任务详情，其他钩子使用已提交的任务详情。HTTP 服务正在监听时，在该 JSON 顶层增加 `baseURL`，值与现有状态 API 基址一致；服务未运行时不添加该字段。

自定义命令必须自行读取输入并产生下一命令需要的完整输出；框架不对空输出、非 JSON 输出或字段缺失做自动修复。非零退出码、无法启动、内置命令失败或上下文传递错误均使当前链失败。标准错误只用于诊断，不参与下一命令输入。系统内置目录命令不改变输入字节，成功后原样写至标准输出。

原样直传而非 JSON 合并使命令可以自行决定后续协议和字段移除规则，也符合“下一条输入是上一条输出”的约定。JSON 只在首命令输入构造时由应用保证。

### 5. 目录命令保留安全边界并让排序决定行为

创建和删除命令都只允许操作“当前任务 ID 在工作区根目录下的直接子目录”，沿用符号链接与路径穿越校验。创建命令在目标目录已经存在时成功复用，删除命令在目录不存在时成功结束，以支持从链首重试。

`beforeStart`、`postStart`、`beforeEnd` 使用预期或已保存的任务专属目录作为命令工作目录；因此用户将创建目录排在 `beforeStart` 链后方时，前序外部命令会因工作目录不存在而失败。`updateTask` 仅对执行中任务运行，始终使用任务专属目录。`postEnd` 的所有命令始终在任务工作区根目录运行。创建或删除命令可以放在任意钩子和任意顺序，目录存在与否由用户链的执行顺序决定。

### 6. 删除约束优先保证可运行任务的可重试性

自定义命令仍被任意链引用时不可删除，避免生成损坏的全局链。链若被未执行或执行中任务引用则不可删除；若只被已完成任务引用则允许删除，并清除指向它的默认值。已完成任务的 `postEnd` 失败后，若其链被删除，重试按钮显示“命令链已删除，无法执行”，不尝试恢复或回滚。

此约束刻意允许已完成任务丢失可重试链，以满足已确认的删除规则；替代方案是保留执行快照或一律禁止删除，但会分别违背动态引用和已完成任务可删除链的需求。

### 7. 用双层适用范围保证每次执行都有有效命令

自定义命令和命令链分别保存至少一个钩子范围。链内每条命令必须覆盖链的全部范围，因此链一旦被标记为多个钩子，就能在其中任一钩子完整执行；链编辑界面只提供满足该覆盖条件的命令。系统“创建任务工作目录”命令固定仅适用于 `beforeStart`，系统“删除任务工作目录”命令固定仅适用于 `postEnd`，对应初始链也使用相同范围。

默认链下拉框、新建任务和未执行任务编辑的每个钩子选择器只显示覆盖当前钩子的链。应用绑定检查默认值、任务新建及未执行任务链修改，避免直接调用 API 写入跨范围引用；专用链更新入口只接受未执行任务，因此不会触发只适用于执行中任务的 `updateTask` 钩子。执行中和已完成任务不提供修改链引用的前端操作，后端也拒绝其直接调用。若链被未执行或执行中任务引用，保存该链时不得移除那些任务所需的范围，避免任务永久指向不可执行配置。

旧的自定义命令和链没有范围字段时迁移为五个钩子均适用；没有共同范围的历史链保留为不可选配置，用户可在链管理中重新指定范围和命令。范围不匹配的默认值在加载时清理。

## Risks / Trade-offs

- [重试重复执行外部副作用] → 系统目录命令保持幂等；自定义命令由用户按其业务需要设计为幂等。
- [前置链失败后留下任务目录] → 不做隐式清理，保留链顺序的可见影响；用户可修复链后重试。
- [命令输出不符合下一命令协议] → 框架保留原样传递，记录启动、退出和标准错误诊断，责任明确归属产生输出的命令。
- [应用重启中断链] → 将未完成记录标记为失败并从链首重试，避免在不可信的外部进程状态上继续执行。
- [已完成任务引用的链被删除] → 重试时明确提示链已删除，状态保持已完成。
- [目录命令被放在非常规钩子] → 仍执行严格任务目录安全校验，不限制用户链顺序。

## Migration Plan

1. 设置加载时补齐两个系统内置目录命令、初始目录链和五钩子默认映射，同时兼容没有这些字段的旧快照。
2. 任务加载时补齐五钩子选择和空执行记录：未执行任务预选创建/删除默认链，执行中任务预选删除默认链，已完成任务保留为空。
3. 发布后先运行后端和前端迁移测试，再构建 Wails 应用；失败时可回滚到旧二进制，新增 JSON 字段会被旧版本忽略。
4. 不删除旧任务目录；迁移后目录删除仅在用户所选链执行内置删除命令时发生。

## Open Questions

无。命令传递方式、钩子时序、目录工作目录、默认选择、删除约束和失败重试行为均已确认。
