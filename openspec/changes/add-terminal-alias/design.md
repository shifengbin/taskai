## Context

当前前端以 `TerminalRecord.title` 保存从 PTY 输出解析出的实际终端标题，并直接用该字段展示终端名称。该标题还参与 `title-change` 实时状态方式的变化判定。启动命令已随会话记录提供，但活动终端及其前端元数据均不跨应用重启恢复。

本变更要让用户为单个活动终端起一个更容易辨认的名称，并在任务树和右侧终端标题栏保持一致。用户仍需在悬浮时查看实际标题和启动命令，且别名不能改变终端状态逻辑。

## Goals / Non-Goals

**Goals:**

- 为单个当前会话设置、修改和清空别名。
- 在任务树和终端标题栏一致显示别名，并通过两行悬浮提示保留实际会话信息。
- 让别名与实际标题、启动命令及实时状态判定完全分离。
- 保持现有终端创建、输出、关闭和标题解析流程不变。

**Non-Goals:**

- 不在设置、任务菜单或后端持久化别名。
- 不为同一启动命令的未来终端预设别名。
- 不改变 Shell 中手动运行子程序后的名称或启动命令。
- 不修改 `title-change`、`output-change` 和 HTTP 实时状态方式的语义。

## Decisions

### 将别名保存在前端 `TerminalRecord`

在终端记录中增加可选别名字段；编辑仅更新对应会话的前端状态。应用重新加载、终端退出或任务结束后，别名随现有终端会话数据一并消失。

这与活动终端当前的生命周期一致，无需新增 Wails API、后端可变状态或设置迁移。相比在后端管理别名，避免了没有跨重启价值的 IPC 和同步复杂度；相比为任务菜单命令设置默认别名，能够区分同一命令创建的多个终端。

### 区分实际标题与展示名称

保留 `title` 作为 PTY OSC 标题解析结果，增加单独的名称解析逻辑：非空别名优先显示；别名为空时沿用现有实际标题及其默认值。实际标题的解析、暂存事件合并和 `shouldReportTerminalTitleActivity` 只读取 `title`，绝不读取别名。

这使用户改名和终端输出造成的标题变化相互独立，`title-change` 状态方式仍仅在实际标题发生变化时上报活动。

### 两处使用同一名称编辑与提示规则

任务树终端项和终端标题栏均从同一终端记录派生显示名称。双击任一名称后，该位置替换为已聚焦的单行输入框：输入框失焦或按下 Enter 时保存去除首尾空白后的值；按 Escape 时放弃本次编辑。保存空字符串会清除别名。

有别名且未处于编辑状态时，名称的悬浮提示严格以两行显示：第一行固定为 `标题: <实际标题>`，第二行固定为 `命令: <启动命令>`。两处共用同一套格式化和编辑规则，避免别名或提示内容不一致。

### 维持无别名的既有体验

没有别名的终端继续只显示现有名称，不为其新增提示信息。启动命令缺失时，提示的第二行仍保留并以明确的缺省文本呈现，保证两行结构稳定。

## Risks / Trade-offs

- [双击与选择终端的单击竞争] → 单击继续负责选择终端；双击只进入编辑并阻止其默认的额外选择行为。
- [编辑输入失去焦点导致意外保存] → Escape 始终恢复编辑前的值，Enter 与失焦采用同一规范化保存规则。
- [别名错误参与状态判定] → 将别名字段与标题字段分离，并为标题变化状态添加回归测试。
- [两处 UI 演变不一致] → 抽取共享的展示名称、实际名称和两行提示逻辑，并分别覆盖两个入口的组件测试。

## Migration Plan

无需数据迁移。旧会话记录不含别名时按无别名处理；部署后已有终端继续显示其实际标题。若需回退代码，别名仅存在于前端内存，重载应用即可清除，不会留下持久化数据。
