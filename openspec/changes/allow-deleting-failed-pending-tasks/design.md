## Context

现有批量删除只接受 `pending` 或 `completed` 且没有 `LifecycleExecution` 的任务。`beforeStart` 失败时任务仍为 `pending`，但失败执行记录会锁定全部操作并保留重试入口，因此用户无法放弃失败任务。若简单允许删除，开始前链可能已经创建工作目录并写入仓库或清单；只删除记录会遗留目录，而根据当前设置拼接目录、根据命令序号推断或仅检查目录存在又可能误删 TaskAI 未创建的内容。

开始前运行目前只在内存中的已准备任务上携带工作目录路径，任务进入 `running` 后才把路径提交到任务记录。失败任务因而不一定保留实际使用的根目录与任务目录快照，设置变化后更不能用当前根目录代替。目录创建函数还会成功复用已经存在的同名目录，执行过创建命令并不等于 TaskAI 新建了目录。

本变更同时影响持久化模型、异步命令执行、重试、批量删除和前端资格判断。目录删除必须继续经过 `internal/workspace` 的任务 ID、直接子目录和符号链接边界校验。

## Goals / Non-Goals

**Goals:**

- 允许用户删除 `pending + beforeStart + failed` 的任务，并把该操作定义为放弃重试。
- 准确区分 TaskAI 本次启动过程新建的目录、复用的既有目录和未执行创建命令的情况。
- 仅清理有可靠归属证据的任务目录；无需清理时不调用目录删除。
- 清理失败时保留任务记录、失败信息和重试能力。
- 让开始前失败的重试沿用原路径和已有目录归属，避免设置变化导致旧目录失联。

**Non-Goals:**

- 不允许删除运行中的生命周期命令链、执行中任务、其他钩子失败的任务或目录归属未知的旧版失败任务。
- 不改变普通未执行任务与已完成任务“只删除记录”的现有语义。
- 不运行 `postEnd` 命令链，不执行用户自定义清理命令，也不删除任务工作区根目录。
- 不提供任意目录选择、强制删除、回收站或删除撤销。

## Decisions

### 1. 仅为开始前失败的未执行任务增加删除例外

统一删除资格调整为两类：原有的 `pending/completed + LifecycleExecution == nil`，以及 `pending + beforeStart + failed`。第二类在普通任务界面仍保持编辑、排序、开始、菜单等操作锁定并保留重试入口，但进入未执行任务选择模式后可以勾选并删除。`running` 执行记录、`completed + postEnd + failed` 和任何不一致组合继续由前后端拒绝。

替代方案是允许删除全部失败记录。该方案会把执行中和已完成任务的清理、终端及后置链语义一并扩大，不符合本次只解决启动失败任务的范围，因此不采用。

### 2. 在执行记录中保存路径快照、三态归属和随机所有权令牌

`LifecycleExecution` 增加开始前工作区根目录、任务目录、目录归属状态和随机所有权令牌。归属使用 `unknown`、`not-created`、`created` 三态，而不是仅用布尔值：旧版记录缺少字段时归一化为 `unknown`；新开始前运行在后台命令启动前保存路径快照、令牌并设为 `not-created`；只有目录创建函数确认目标原先不存在且本次成功新建后，才同步更新为 `created`。创建命令不存在、尚未执行、执行失败或复用已有目录时均保持 `not-created`。

TaskAI 在工作区根目录的私有 `.taskai-ownership` 目录中保存令牌对应的侧车凭据，其中记录任务 ID 和文件系统目录身份；该目录必须由当前用户所有且不允许其他用户访问，Unix 同时校验 BSD 权限与 macOS 扩展 ACL，Windows 在创建目录时直接使用仅当前用户可访问的受保护 DACL，避免先继承宽松 ACL 再收紧的中断窗口。新目录先在该私有目录中准备，在目录自身写入同一随机令牌的扩展属性（Windows 使用备用数据流），再写入侧车凭据并以“不覆盖已有目标”的原子重命名完成创建。删除时必须同时匹配侧车令牌、目录自身标记和文件系统身份，避免目录删除后 inode 或文件索引被同名重建目录复用而造成误删。因此进程在创建与 `created` 状态更新之间退出时，下一次删除或重试仍可根据令牌恢复归属，而不会把后来出现的同名目录当作 TaskAI 所有。目录自身标记不占用目录项，避免影响要求空目录的 Git 克隆命令。TaskAI 在创建目标目录前还会在同一文件系统中探测目录标记读写能力；不支持扩展属性或备用数据流时安全失败且不创建任务目录，不降级为无法证明归属的目录。

目录创建函数返回“该令牌是否拥有目标”的结果，命令执行器通过可返回错误的进度回调把 `created` 事实持久化后再继续下一条命令。归属一旦为 `created`，同一启动尝试及其重试中只能保持为 `created`，后续创建命令复用目录不得降级。若归属持久化失败，命令链停止并立即使用令牌凭据补偿本次新建目录，避免继续向未受追踪的目录写入内容。

重试 `beforeStart` 时继承失败记录中的路径快照和归属状态，不根据当前设置重新计算；若此前未创建且重试时实际新建，则升级为 `created`。其他钩子不使用这些字段。

替代方案包括在任务目录中写标记文件，或根据当前命令 ID、序号和目录存在性推断。任务目录内标记会令 Git 克隆目标不再为空，也可能被任务命令修改或删除；进度在命令执行前发布，且创建命令会复用既有目录，推断无法证明归属，因此均不采用。

### 3. 先全量校验，再按凭据隔离清理，最后基于最新快照原子删除

生命周期服务在任务写临界区内重新读取持久化数据并全量校验全部任务 ID。对于启动失败任务：`not-created` 仍检查令牌侧车凭据，以恢复“目录已创建但进程尚未写回 `created`”的中断；没有凭据时不触碰任务目录；`created` 必须找到与当前目录文件系统身份匹配的凭据；`unknown` 拒绝整个请求。目录不存在仍按幂等规则视为清理成功。任何路径边界、凭据、目录身份、符号链接或文件系统错误都会中止请求并保留全部任务记录。

删除时先把匹配身份的任务目录原子移动到令牌专属隔离路径，再复核身份并删除隔离目录；同名目录在校验后被替换时不会作为原目录直接递归删除。全部必要目录清理成功后，仓储重新读取最新任务数据，确认目标记录未变化，再只过滤目标 ID 并一次保存；所有任务写操作共用服务级互斥锁，避免并发操作用旧快照复活已删任务。批量请求中若后续目录清理失败，先前已经成功清理的目录无法恢复，但所有任务记录仍保留；若最终保存失败，已经清理的目录保持缺失，而任务记录和失败信息仍可再次提交删除。文件系统与 JSON 持久化无法形成单一事务，优先保证不会误删替换目录或在目录尚未安全处理时丢失任务记录。

桌面入口在构造 `App` 和首次加载仓储前，先对应用数据目录中的实例锁文件获取非阻塞排他锁；未取得锁的第二进程不得进入 Wails 启动流程。Wails 单实例锁继续作为窗口层补充，实例内任务写操作仍由服务锁串行化。该约束与清理后最新快照校验共同避免第二进程把运行记录误恢复为失败，或以旧快照覆盖删除结果。

替代方案是在应用层先清理再调用原删除服务，或调度内置 `postEnd` 删除链。前者会在两次数据读取之间产生竞态，后者会改变钩子状态并允许自定义命令介入；因此由生命周期服务直接编排安全目录删除。

### 4. 前端使用与后端一致的可删除谓词并明确条件清理

前端集中判断原有无执行记录任务与新增的开始前失败任务，`App` 的可删除 ID 集合和 `TaskTree` 复选框不得继续使用简单的 `!lifecycleExecution`。正常浏览时失败任务仍只显示失败详情和重试入口；只有删除选择模式开放复选框。确认对话框说明普通任务只删除记录，启动失败任务中仅 TaskAI 实际新建的工作目录会被一并删除，复用或未创建的目录不会处理。后端拒绝时保留选择并展示具体错误。

## Risks / Trade-offs

- [旧版失败记录没有可靠路径或归属] → 归一化为 `unknown` 并继续拒绝删除，不根据当前设置或磁盘内容猜测；用户重试后由新执行记录建立可验证状态。
- [创建目录后归属持久化失败] → 停止命令链并立即安全回滚本次新建目录；不得执行后续命令。
- [进程在创建目录后、归属写回前退出] → 已持久化令牌与侧车凭据恢复实际目录归属；删除仍清理 TaskAI 创建的目录，复用目录没有凭据且不处理。
- [TaskAI 创建的同名目录后来被替换或删除后同名重建] → 侧车令牌、目录自身标记和文件系统身份任一不匹配时拒绝删除并保留任务，不把路径相同或可复用的文件系统身份当作所有权证明。
- [批量清理部分成功后发生错误] → 保留全部任务记录并允许幂等重试，不尝试重建已删除目录。
- [工作目录被替换为指向外部的符号链接] → 复用 `workspace.Remove` 的真实路径校验并拒绝删除，任务记录保持不变。
- [设置中的工作区根目录在失败后变化] → 始终使用失败执行记录的路径快照，重试和删除不读取新设置替代旧路径。
- [前端资格判断与持久化状态发生竞态] → 前端只负责呈现，服务端串行化任务写操作并在清理后基于最新快照提交删除。
- [文件系统不支持目录扩展属性或 Windows 备用数据流] → 在创建任务目录前执行同文件系统能力探测；能力不足时停止开始前链且不创建任务目录，不使用仅凭路径或 inode 的不安全降级。
- [私有元数据目录继承了额外访问权限] → macOS 清除并复核扩展 ACL，Windows 在 `CreateDirectory` 时原子应用受保护 DACL；既有不安全目录只拒绝使用，不擅自修改。
- [多个桌面进程并发保存任务快照] → 在 `NewApp` 和仓储加载前获取数据目录文件锁，第二进程无法进入启动恢复；Wails 单实例锁作为窗口层补充，实例内继续使用任务写锁与最新快照校验。
- [创建凭据已写入但目标路径在重命名前被占用] → 只隔离、复核并删除令牌对应的 staging 与侧车凭据，把同名占用目录作为复用目录保留；删除失败任务时同样可回收 staging 而不触碰占用目录。

## Migration Plan

1. 新字段使用向后兼容的 JSON 形式；既有执行记录缺少归属字段时读取为 `unknown`，不自动访问或删除磁盘。
2. 新版本产生的 `beforeStart` 执行记录在后台运行前写入路径快照、随机令牌和 `not-created`，无需迁移普通任务。
3. 前后端同时发布新增资格与条件清理，避免前端可选但后端拒绝或后端放开但界面无入口。
4. 回滚时旧版本忽略新增 JSON 字段；已经删除的任务记录和目录无法自动恢复，但普通删除语义不受影响。
