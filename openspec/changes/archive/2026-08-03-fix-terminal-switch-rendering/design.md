## Context

`App` 仅渲染当前选中的 `TerminalView`，并以终端 ID 作为 React key；因此在终端 A、B 间切换时，xterm 实例会被销毁并为新选中的终端重新创建。`TerminalView` 当前在 `open()` 后立即回放累计输出，但将 `FitAddon.fit()` 留到下一动画帧，且没有等待异步 `write()` 完成后刷新可见行。

这使静态历史输出可能未被 WebKitGTK 的 xterm canvas 画出，而之后抵达的输出仍能局部更新。窗口大小变化触发 `ResizeObserver` 和 xterm resize 后会重新绘制，因此暂时掩盖问题。终端输出、输入和 PTY 均由既有接口管理；本变更只调整前端 xterm 的显示生命周期。

## Goals / Non-Goals

**Goals:**

- 在活动终端挂载时，以当前内容容器尺寸建立 xterm 网格，再回放历史输出。
- 在初始回放完成和容器尺寸变化后完整刷新可见终端行，消除静态空白区域。
- 保持现有的自动聚焦、输入写入、剪贴板、实时输出、关闭操作与后端尺寸同步。
- 以可控 xterm、动画帧和 `ResizeObserver` mock 覆盖切换与重绘时序。

**Non-Goals:**

- 不保存多个 xterm DOM 实例、不在隐藏终端之间移动 DOM，也不更换终端库或渲染器。
- 不改变 PTY 创建尺寸、Go 终端管理器、Wails 绑定、输出缓冲格式或终端 API。
- 不对每条实时输出调用整屏 `refresh()`；xterm 继续负责增量输出渲染。

## Decisions

### 在回放历史输出前执行初始尺寸适配

在 `instance.open(container)` 后立即执行已有尺寸适配逻辑，并继续保留下一动画帧的适配作为 WebView 完成布局后的校正。初始输出随后以已适配的列数和行数写入，避免先按 xterm 默认网格解析、再改变网格而产生不稳定的画布状态。

仅等待下一动画帧才进行首次尺寸适配是现有方案，不能保证初始输出以正确网格回放，因此不采用。长期保留并隐藏每个终端实例会增加资源占用和隐藏容器的零尺寸适配问题，因此不采用。

### 以初始 `write()` 完成回调作为完整刷新边界

xterm 的初始 `write()` 使用完成回调；回调确认该段历史输出已解析后，对 `0` 至 `rows - 1` 的可见行执行一次刷新。回调和动画帧逻辑都必须确认实例仍未销毁且行数有效，避免快速切换时操作已释放的终端。

只依赖 xterm 增量渲染无法保证 WebKitGTK canvas 对已存在行完成首帧绘制；在组件更新阶段无条件刷新全部行会在实时输出期间造成不必要开销，因此两者都不采用。

### 将容器尺寸变化视为适配与可见行重绘事件

既有 `ResizeObserver` 保留为窗口和面板宽度变化的唯一容器尺寸来源。其回调在适配网格并同步 PTY 尺寸后，刷新当前可见行；可使用动画帧合并同一帧的重复观察通知。实时输出不走该路径。

监听全局 `window.resize` 不能覆盖侧栏拖拽造成的内容区变化；只执行 `fit()` 而不刷新会重现当前静态区域未绘制的问题，因此不采用。

### 测试真实的显示协调协议而非空观察器

终端组件测试将暴露 `FitAddon.fit`、`Terminal.write` 完成回调、`Terminal.refresh` 和可触发的 `ResizeObserver`。测试必须断言：带历史静态输出的终端在 A -> B -> A 切换后对新实例刷新可见行；容器尺寸观察回调也会适配并刷新；实时输出仍使用 xterm 写入而不会导致额外的整屏刷新。

仅保留当前空实现的 `ResizeObserver` 和单实例挂载测试无法触发此缺陷，因此不采用。

## Risks / Trade-offs

- [完整刷新大终端可见区域增加少量切换开销] -> 刷新仅发生在初始历史回放和尺寸变化，不发生在普通实时输出事件上。
- [xterm 回放回调可能在用户快速切换后到达] -> 在回调中检查实例存活状态，并在清理时取消待执行的动画帧。
- [立即 `fit()` 时 WebView 布局尚未最终稳定] -> 保留下一动画帧和 `ResizeObserver` 的后续适配与刷新。
- [测试环境与 WebKitGTK 的画布行为不同] -> 测试锁定调用顺序与完整刷新契约，并在 Linux Wails 构建后进行手工切换验证。

## Migration Plan

前端发布后立即生效，无数据迁移、服务重启或协议兼容工作。若出现与特定 WebView 的兼容问题，可回退 `TerminalView` 的初始化与刷新协调逻辑；终端会话、输出和用户数据均不受影响。
