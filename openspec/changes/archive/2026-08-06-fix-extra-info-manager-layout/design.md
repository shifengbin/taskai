## Context

额外信息管理弹窗位于 `frontend/src/App.tsx`，模板定义区使用受控 Radix Accordion，主体内容使用 `SnapScrollArea`。模板定义的 Accordion 内容被 `forceMount` 强制挂载；管理弹窗的滚动区域只设置了 `max-height`，而 `SnapScrollArea` 的视口依赖父级提供确定的高度。两者在数据量增加或窗口高度较低时分别造成内容无法真正收起和内容被裁切。

变更只涉及前端布局和交互，不改变额外信息的持久化结构、后端接口或任务快照语义。

## Goals / Non-Goals

**Goals:**

- 让“分类模板”面板关闭后不再渲染可见模板行，也不再占据模板列表的布局高度。
- 让额外信息管理弹窗的主体内容在低高度窗口中形成真实的纵向滚动容器，能够访问全部模板、信息分组和搜索结果。
- 保留现有搜索、信息分组默认展开、模板编辑/删除和底部关闭操作。
- 用前端测试覆盖折叠后的内容可见性、长内容滚动样式和底部操作可达性。

**Non-Goals:**

- 不调整模板或信息的 Go 模型、校验、迁移和 API。
- 不改变信息分组的展开状态管理或搜索自动展开规则。
- 不在本次变更中重构所有弹窗的通用滚动布局；其他弹窗仅在不影响本变更范围的前提下审查其使用方式。

## Decisions

### 移除模板定义区的 `forceMount`

模板定义区直接使用 Radix Accordion 默认的 Presence 生命周期。关闭时内容节点会被卸载，不会继续保留内部模板行或占据高度；打开时仍由受控的 `templateSectionExpanded` 状态驱动。模板行不包含需要跨折叠保存的编辑控件，因此不需要强制挂载来保留局部状态。

备选方案是在通用 Accordion 内容组件中为 `forceMount` 增加关闭态 `hidden` 或固定高度样式。该方案会把特定使用场景的状态语义写入通用组件，并且容易与动画高度变量冲突，因此不采用。

### 管理弹窗主体使用原生纵向滚动容器

将管理弹窗主体从仅提供 `max-height` 的 `SnapScrollArea` 改为自身同时拥有 `max-height` 和 `overflow-y: auto` 的容器，并保留弹窗标题与底部操作区在滚动区域之外。原生容器的实际高度由自身内容和最大高度共同决定，超出部分由该容器直接滚动，不依赖百分比高度向父级传递。

备选方案是为 `SnapScrollArea` 的根节点和视口强制分配固定或 flex 高度，再把该契约推广到所有弹窗。该方案会改变通用滚动组件的布局契约，且可能让短表单出现不必要的空白高度；本次只处理管理页的确定问题，避免扩大变更范围。

### 保持信息分组的受控状态不变

信息分组继续使用 `expandedExtraInfoTemplateIDs`，搜索命中时继续自动加入匹配分组，模板定义区的折叠状态继续使用 `templateSectionExpanded`。滚动修复只改变容器，不改变这些状态的来源或持久化方式。

### 以行为断言补足测试

折叠测试在第二次点击后检查模板行不再位于文档中或不可见，而不只检查 `aria-expanded`。布局测试检查管理主体具有 `max-height` 与 `overflow-y: auto`，并确认底部“关闭”操作仍在对话框内可用；不依赖 jsdom 伪造的滚动尺寸来断言像素位置。

## Risks / Trade-offs

- [原生滚动条的视觉样式与 Radix 滚动条不同] → 保留项目现有的滚动条隐藏样式和滚轮/触控滚动能力，功能优先于自绘滚动条一致性。
- [移除 `forceMount` 后关闭内容会卸载] → 模板定义区只有展示行和操作按钮，没有需要在关闭期间保留的未提交表单状态；编辑模板仍由独立弹窗管理。
- [管理页与其他弹窗暂时存在两种滚动实现] → 在任务中记录其他 `SnapScrollArea` 的调用点，后续若要统一组件契约可单独提出变更。
- [内容高度接近视口上限时底部操作可能被遮挡] → 保持弹窗底部操作区位于主体滚动容器之外，并在回归测试中确认“关闭”按钮可见且可点击。

## Migration Plan

无需数据迁移或绑定重新生成。发布前运行前端测试和构建；若回滚，只需恢复管理页的原滚动容器和模板内容挂载属性，不影响已有模板、信息或任务快照。

## Open Questions

无。实现方案已确定为移除该处 `forceMount`，并让管理弹窗主体直接负责纵向滚动。
