## Context

TaskAI 已经能够通过 `TerminalSessionRegistry` 将 xterm 的键盘输入写入指定 PTY，并在 `TerminalView` 顶栏提供上下文操作。当前全局可复用数据包括顶层持久化的额外信息和设置中的配置，但没有可供终端快速插入的文本库。

本变更需要同时修改 Go 持久化、Wails 绑定、React 信息管理弹窗和 xterm 交互。快捷输入名称可重复、内容可为任意长度的多行文本，并且用户要求编辑、删除、排序后立即持久化。普通 PTY 写入的换行可能等同于提交；xterm 的 `paste()` 能在目标程序启用 bracketed paste 时发送粘贴边界，是保留该终端协议语义的正确入口。

## Goals / Non-Goals

**Goals:**

- 保存与任务无关、全局可复用且顺序稳定的名称与文本内容。
- 在“信息管理”中沿用额外信息的即时保存体验管理快捷输入。
- 让活动终端能通过工具栏或仅终端聚焦时的键盘快捷键快速搜索并插入内容。
- 支持多行模拟粘贴，且不由 TaskAI 额外附加执行用的 Enter。
- 兼容缺少快捷输入字段的既有 JSON 数据文件。

**Non-Goals:**

- 不提供系统级全局快捷键、任务专属输入、模板变量、分类、标签、历史、收藏、导入导出或同步。
- 不预置示例，不增加加密、钥匙串或其他机密数据保护。
- 不保证未启用 bracketed paste 的第三方终端程序把多行内容视为未提交文本。
- 不改变现有键盘输入、右键粘贴、文件拖放或 PTY 生命周期。

## Decisions

### 1. 以顶层持久化集合保存快捷输入

在 `internal/quickinput` 定义 `QuickInput` 值对象，包含稳定 ID、名称、内容和顺序。`storage.Data` 新增 `QuickInputs` 数组，仓库加载和保存时将缺失字段归一化为空数组，并通过该包集中校验：ID 有效、名称去除首尾空白后非空且不超过 100 字符、内容至少含一个非空白字符。名称不要求唯一，内容不施加长度上限；内容原样保存，展示层自行截断预览。

快捷输入不放入 `settings.Settings`。设置采用整份草稿保存且含有生命周期等并发保护规则，而快捷输入需要独立的逐项新增、编辑、删除和排序操作。顶层集合也与额外信息的持久化模型一致，避免一次设置保存覆盖刚修改的快捷输入。

### 2. 用专用应用接口维护单项和完整排序

Wails 暴露列出、保存、删除和重排快捷输入的应用方法。保存时，已有 ID 更新原项，新 ID 创建原项；删除按 ID 精确执行；重排接口接收完整、无重复且与现有集合一致的 ID 序列，原子地更新顺序。后端生成新 ID，前端不能借由重复名称推断身份。

管理窗口打开时重新读取集合。新增、编辑和删除在各自操作成功后更新前端状态；拖动排序在放置成功后立即调用重排接口。此接口边界能让前端处理同名项，并让仓库拒绝缺失、重复或外来 ID 的排序请求。

### 3. 在现有信息管理窗口中增加标签页和独立编辑器

顶部入口和弹窗标题改为“信息管理”。现有额外信息管理内容置于默认激活的“额外信息管理”标签，新“快捷输入管理”标签显示可搜索、可排序的列表。每个同名项必须同时显示内容摘要；管理与终端搜索均匹配名称和内容。

快捷输入使用独立的名称和多行内容编辑弹窗，内容输入使用等宽文本区域并显示字符数。列表操作使用明确的新增、编辑、删除和排序控件；删除先在确认弹窗中显示名称。空库不插入示例内容。保持现有额外信息模板、分组、搜索和滚动逻辑，不将两类数据混合。

### 4. 终端选择器通过会话注册表调用 xterm 模拟粘贴

`TerminalView` 在活动终端工具栏增加图标按钮，提示文本包含平台快捷键。选择器锚定在该按钮附近，打开时自动聚焦搜索框，结果显示名称和内容摘要。空搜索使用持久化排序，非空搜索匹配名称和内容；方向键选择、Enter 立即插入、Escape 关闭，点击结果的效果相同。成功插入后关闭选择器并将焦点恢复给该终端。

`TerminalSessionRegistry` 新增面向快捷输入的粘贴方法，并在目标会话仍活动时调用 xterm `terminal.paste(content)`，而不是直接调用后端写入。xterm 会依照终端私有模式发出 bracketed paste 包装，最终仍沿用登记的 `onWrite` 回调和既有 `WriteTerminal` Wails 接口。TaskAI 不在内容尾部添加换行或执行字符。关闭、缺失或写入失败的会话通过现有错误反馈报告，且不得写入其他终端。

直接从选择器把字符串调用 `api.writeTerminal` 会绕过 xterm 的粘贴语义；复制到系统剪贴板再请求用户粘贴则增加步骤且不可靠。注册表方法复用了唯一的终端会话所有权，并可由前端测试直接验证。

### 5. 把快捷键限制在当前终端视图

终端视图监听 `Ctrl+Shift+P`，macOS 使用 `Meta+Shift+P`。只有所属终端处于活动状态、组合键未被编辑控件占用且没有打开其他文字编辑操作时才拦截事件；打开选择器后不再由终端把该组合键作为普通输入转发。按钮的 `title`、`aria-label` 和 `aria-keyshortcuts` 暴露同一信息。该策略不注册操作系统级快捷键，也避免在信息管理的文本编辑器中意外打开选择器。

## Risks / Trade-offs

- [目标程序未启用 bracketed paste] → xterm 仍会按目标程序支持程度传递多行内容；规格和界面不承诺跨所有 Shell 阻止换行提交。
- [内容没有大小上限] → 后端不截断用户数据；前端列表只生成受控摘要、搜索避免在渲染路径重复处理全文，并通过测试覆盖大文本保存和插入。
- [名称允许重复] → 始终以稳定 ID 更新、删除和排序，终端和管理列表均展示内容摘要。
- [排序与即时保存并发] → 仓库在互斥的保存路径内验证完整 ID 集合；保存后前端采用返回顺序更新状态。
- [全局快捷键与文本编辑冲突] → 只在终端焦点路径注册，选择器打开后由自身接收导航键，信息管理编辑器不监听该组合键。

## Migration Plan

1. 新增快捷输入模型和 `Data.QuickInputs`，在加载路径把缺失字段归一化为空数组，保证旧数据文件直接可用。
2. 增加仓库、应用和 Wails 绑定接口，并以 Go 测试固定校验、顺序与迁移规则。
3. 接入信息管理标签和终端选择器，重新生成前端绑定并补齐前端交互测试。
4. 运行 Go 测试、前端测试、生产构建和项目编译脚本。

回滚时可以删除前端入口和应用接口；旧版本会忽略 JSON 中未知的 `quickInputs` 字段，已有任务、设置和额外信息不受影响。

## Open Questions

无。已确认的多行兼容性边界由 bracketed paste 支持决定，不作为本次变更的阻塞项。
