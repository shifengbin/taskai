## ADDED Requirements

### Requirement: 命令链保存并合并单次命令参数
系统 SHALL 将命令链中的每个命令保存为包含命令 ID 和有序参数列表的命令引用。运行链时，系统 MUST 按“全局命令定义参数在前、链命令引用参数在后”的顺序合并参数，并将合并结果传给该命令。命令链复制 MUST 复制每个引用的参数。命令链的适用范围、删除约束和命令存在性校验 MUST 基于引用的命令 ID 保持既有行为。

#### Scenario: 链级参数追加到自定义命令参数
- **WHEN** 全局自定义命令的参数为 `--verbose`，命令链中该命令的参数为 `--profile` 和 `dev`
- **THEN** 系统以 `--verbose`、`--profile`、`dev` 的顺序执行该自定义命令

#### Scenario: 复制命令链保留链级参数
- **WHEN** 用户复制一条包含 Git 命令及 `dir=repositories` 参数的命令链
- **THEN** 系统创建新链并保留该参数，之后修改副本参数不得影响原链

#### Scenario: 读取旧命令 ID 列表
- **WHEN** 系统加载仅含有序 `commandIds` 的既有命令链数据
- **THEN** 系统按原顺序迁移为参数为空的命令引用，且既有链仍可执行

### Requirement: 提供带参数说明的 Git 克隆系统命令
系统 SHALL 提供固定 ID 的“Git 仓库克隆”系统命令。该命令 MUST 不可编辑、不可删除，且仅适用于 `beforeStart`、`beforeEnd` 和 `updateTask`。系统 MUST 为该命令公开只读使用文档，包含必填参数 `dir`、其 `dir=<相对目录>` 用法、相对于任务工作目录的解析规则、目标目录命名规则及分支处理规则。命令库 MUST 在该系统命令概要之后显示该文档，命令链编辑器 MUST 在配置该命令的链级参数处显示相同文档。

#### Scenario: 在命令库查看 Git 参数说明
- **WHEN** 用户在设置中的命令库查看“Git 仓库克隆”系统命令
- **THEN** 系统在命令概要之后显示 `dir` 的用法和克隆行为说明，且不提供编辑或删除操作

#### Scenario: 用不支持的钩子配置 Git 命令
- **WHEN** 用户尝试将 Git 克隆系统命令加入包含 `postStart` 或 `postEnd` 的命令链
- **THEN** 系统拒绝保存该链并说明命令不适用于该钩子范围

#### Scenario: 校验 Git 的链级目录参数
- **WHEN** 用户保存 Git 命令引用但缺少 `dir`、重复提供 `dir`、提供空值或提供绝对/越界目录
- **THEN** 系统拒绝保存命令链并提示 `dir` 参数无效

### Requirement: 按任务内置 Git 信息批量克隆仓库
系统 SHALL 在执行 Git 克隆系统命令时，仅处理任务已选的内置 Git 信息快照。系统 MUST 对每条 Git 信息按其保存顺序读取项目名称、仓库地址和仓库分支，并将项目克隆至 `<任务工作目录>/<dir>/<项目名称>`。系统 MUST 创建缺失的 `dir` 根目录，且项目名称 MUST 是安全的单个目录名。没有可处理的 Git 信息时，命令 MUST 成功且不改变链标准输入输出上下文。

#### Scenario: 开始任务时克隆多个仓库
- **WHEN** 用户将创建任务工作目录命令和 Git 克隆命令按顺序放入 `beforeStart` 链，Git 命令参数为 `dir=repositories`，任务选择了两个 Git 信息
- **THEN** 系统依次将两个项目克隆到任务工作目录的 `repositories/<项目名称>` 目录，再继续开始任务

#### Scenario: 目标项目目录已存在
- **WHEN** Git 信息对应的 `<dir>/<项目名称>` 已存在
- **THEN** 系统跳过该项目且不访问远程仓库、不覆盖目录内容，并继续处理后续 Git 信息

#### Scenario: 执行中任务更新后补齐新仓库
- **WHEN** 执行中任务的 `updateTask` 链包含 Git 克隆命令，用户保存任务时新增一条 Git 信息且旧项目目录已存在
- **THEN** 系统跳过旧项目目录并克隆新增项目，且保留已保存的任务更新结果

#### Scenario: 结束前链可执行 Git 克隆
- **WHEN** 执行中任务的 `beforeEnd` 链包含 Git 克隆命令
- **THEN** 系统使用该链配置的 `dir` 执行相同的批量克隆规则，并在命令成功后继续结束任务

### Requirement: 按远程分支状态克隆或创建本地分支
对于仓库分支非空的 Git 信息，系统 MUST 先检查远程同名分支。分支存在时，系统 MUST 克隆并检出该远程分支；分支不存在时，系统 MUST 克隆远程默认分支，并基于该初始检出的提交创建同名本地分支。仓库分支为空时，系统 MUST 直接克隆远程默认分支。

#### Scenario: 克隆存在的远程分支
- **WHEN** Git 信息指定的仓库分支在远程存在
- **THEN** 系统在目标目录中克隆并检出该分支

#### Scenario: 创建不存在的远程分支
- **WHEN** Git 信息指定 `feature/task-1`，但远程没有该分支
- **THEN** 系统克隆远程默认分支并在目标仓库中创建基于当前 `HEAD` 的本地 `feature/task-1` 分支

#### Scenario: 批量克隆中途失败后重试
- **WHEN** 批量克隆的某个项目因 Git、认证或网络错误失败，用户在修复原因后重试生命周期链
- **THEN** 系统终止失败的本轮链，重试时跳过先前已存在的成功项目，并从失败项目继续按顺序处理其余项目
