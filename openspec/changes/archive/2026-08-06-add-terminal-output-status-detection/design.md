## 上下文

当前默认方式只在前端从终端输出中解析到实际变化的 OSC 标题后，调用 Wails 绑定上报活动。实时状态服务将终端标记为工作中，并在 1.5 秒无活动后将选中的终端置为空闲、未选中的终端置为未读。HTTP 方式则由本机接口直接设置状态。

终端管理器已经在后端为每个非空 PTY 读取片段发布 `output` 事件，应用层再将该事件转发给前端。输出是跨平台、无需终端程序配合的活动信号；状态仍只保存在内存，不能写回任务的持久化生命周期状态。

## 目标 / 非目标

**目标：**

- 新增持久化的 `output-change` 状态管理方式，并保持旧设置缺失该字段时默认使用 `title-change`。
- 在 `output-change` 下，以任意非空终端输出作为活动，严格按最后一次收到输出后 1.5 秒判定静默。
- 复用既有工作中、空闲、未读、异常的优先级、选中态和终端退出清理规则。
- 在设置中可选择输出方式；独立 HTTP 服务的开关与环境变量注入规则继续适用于非 HTTP 方式。

**非目标：**

- 不比较 xterm 屏幕的可见字符，也不解析 ANSI 控制序列后再判断差异。
- 不改变 OSC 标题解析、终端输出渲染、HTTP 接口格式、任务生命周期状态或状态点的视觉含义。
- 不让多个判定方式同时驱动同一个终端；用户一次只能选择一种状态管理方式。

## 决策

### 1. 在后端终端事件分发处识别输出活动

`app.publishTerminalEvent` 在处理非空 `output` 事件时向实时状态服务报告输出活动，再继续发布既有终端事件。终端在进程启动前已登记到实时状态服务，因此首个输出可被正确关联；已关闭或已结束终端的晚到输出会按现有登记检查忽略。

这比前端监听终端事件后逐段调用 Wails 绑定更合适：活动信号与 PTY 数据源同处、不会依赖前端订阅是否就绪，也避免每个输出片段跨进程往返一次。标题方式仍由前端只在标题实际变化时调用既有绑定，保持其解析和显示职责不变。

备选方案是在前端报告每个输出片段。它改动较小，但高频输出会产生大量 Wails 调用，并使状态正确性依赖前端事件处理。

### 2. 将活动来源和方式匹配，但复用同一状态转换

实时状态服务增加 `ModeOutputChange` 和输出活动入口；标题活动仅在 `ModeTitleChange` 下生效，输出活动仅在 `ModeOutputChange` 下生效。HTTP 接口的显式状态更新在本机服务已启用时继续保留既有可用性，`http` 方式只负责自动启用该服务。两个自动方式共享“工作中 → 静默后空闲或未读”的转换、异常退出处理和任务聚合优先级，避免出现两套超时语义。

活动逻辑只接受 `output` 事件的非空数据。命令回显、进度刷新、ANSI 控制序列和 OSC 序列都算输出；这是“终端有输出”的可靠定义，而不是昂贵且容易偏差的屏幕内容差异判断。仅创建终端、用户输入但没有回显、空数据和错误事件不触发活动。

### 3. 用最后活动时间维持单个静默计时器

输出可能远比标题频繁。每段输出都重新创建并停止一个 1.5 秒计时器会在大量日志下产生无用分配。终端状态保存最后活动时间和一个有效计时器：第一次活动立即转为工作中并安排计时器；后续活动只更新时间。计时器到期时若距离最后活动不足 1.5 秒，则按剩余时间再次安排；否则才转为空闲或未读。

计时器保持版本标识。终端显式设定状态、关闭、任务结束或方式切换都会使旧计时器失效，因此回调不能覆盖更新后的状态。重复输出已经是工作中时不重复发布相同的前端状态投影；但必须继续更新时间以推迟静默判定。

备选方案是沿用标题方式的“每次活动创建计时器”。它更直接，但对持续输出的终端不必要地放大计时器和实时事件数量。

### 4. 将设置扩展为第三个枚举值

`internal/settings` 接受并持久化 `output-change`，默认值仍是 `title-change`。应用层把它映射到实时状态服务的输出方式；切换任一方式继续调用既有模式切换逻辑，清除当前临时状态和计时器。只有 `http` 方式自动启动本机 HTTP 服务，`output-change` 与 `title-change` 一样可通过独立开关启用服务。

前端在“实时状态”下拉框增加“根据终端输出变化”，并让说明文案随方式准确描述活动信号。重新生成 Wails 绑定后，前端设置类型自然包含新枚举值；不新增前端活动上报 API。

## 风险 / 权衡

- [持续高频输出增加状态工作量] → 复用单个静默计时器，并仅在状态投影变化时向前端发布事件。
- [控制序列或命令回显也算活动] → 明确将方式命名为“根据终端输出变化”，不承诺可见屏幕文本差异。
- [方式切换时旧回调迟到] → 采用版本标识，在切换、关闭和显式状态更新时使旧计时器失效。
- [输出与终端退出并发到达] → 沿用实时服务的终端存在性检查和退出清理；失效的活动报告不改变已移除终端。

## 迁移计划

1. 为旧 JSON 缺失的方式字段保留 `title-change` 默认值，现有用户无需迁移。
2. 发布后仅在用户保存并选择“根据终端输出变化”时启用新行为；现有标题和 HTTP 行为不变。
3. 若需回退，移除该下拉选项和对应枚举分支；已保存的 `output-change` 设置应由兼容策略回退为默认标题方式，而不是阻止应用启动。

## 开放问题

无。已确认任何非空 PTY 输出都应视为内容变化。
