## Context

生命周期命令链在后台执行。自定义命令由 `ShellCommandExecutor` 经配置的 Shell 启动，内置 Git 命令由 `DirectGitExecutor` 直接启动；两条路径都会接管标准输入、标准输出和标准错误。Windows 桌面应用本身通常没有附属控制台，因此这些控制台子进程可能创建可见的命令行窗口。

项目已经使用 Windows 构建约束隔离平台相关实现，并已依赖 `golang.org/x/sys/windows`。本变更只处理命令链的后台子进程，不改变需要展示交互终端的执行路径。

## Goals / Non-Goals

**Goals:**

- Windows 上执行自定义生命周期 Shell 命令和内置 Git 命令时不创建可见控制台窗口。
- 保留工作目录、环境变量、标准输入输出管道、错误内容和命令顺序。
- 使 Windows 专用属性不进入非 Windows 构建。

**Non-Goals:**

- 不改变应用内嵌终端的 ConPTY 行为。
- 不改变用户主动从任务菜单启动的命令窗口行为。
- 不阻止生命周期命令自身显式启动的 `cmd`、Windows Terminal 或图形程序窗口。
- 不增加交互式控制台输入能力。

## Decisions

### 以平台专用辅助函数配置后台进程

在 `internal/lifecycle` 增加配置后台进程的辅助函数：Windows 实现为 `exec.Cmd` 设置 `SysProcAttr`，非 Windows 实现为空操作。Shell 和 Git 执行器在完成命令构造后、调用 `Run` 前统一调用该函数。

该做法将构建约束和 Windows 类型限制在少量文件中，并覆盖两种当前独立的链命令启动路径。直接在每个执行器中设置 `SysProcAttr` 会让非 Windows 构建无法通过编译，复制逻辑也容易遗漏后续新增的链执行器。

### 同时禁止控制台分配并隐藏启动窗口

Windows 辅助函数使用 `CREATE_NO_WINDOW` 阻止控制台应用为后台进程分配新控制台，并设置 `HideWindow` 作为窗口显示层面的保护。生命周期执行器已经重定向三个标准流，因此不需要为获取输出而保留控制台。

仅使用 PowerShell 的窗口参数会遗漏 `cmd.exe` 和直接运行的 Git；仅使用 `HideWindow` 可能仍创建不可见控制台。两项 Windows 进程属性能覆盖这些入口，且不要求修改用户配置的 Shell 命令或参数。

### 以平台隔离测试验证进程属性与既有回归

为 Windows 辅助函数增加构建约束测试，断言后台进程获得无控制台和隐藏窗口属性；保留并扩展现有生命周期执行器测试，验证标准输入输出与错误语义不变。常规测试继续在当前平台运行，Windows 交叉编译用于验证 Windows 专用文件能够构建。

## Risks / Trade-offs

- [命令依赖交互控制台] → 生命周期链本就以受接管的标准流后台执行；命令应使用管道输入、环境变量或非交互参数，失败信息继续回传到链执行状态。
- [命令自身显式创建窗口] → 进程属性只能约束应用直接启动的子进程；在命令链帮助或错误排查中说明显式启动窗口不在本变更控制范围内。
- [Windows 专用代码无法在非 Windows 运行验证] → 使用构建约束单元测试并在验证中执行 Windows 目标交叉编译。

## Migration Plan

无需数据迁移或配置迁移。升级后的 Windows 客户端会自动对已有和新建命令链生效；回滚时移除后台进程属性配置即可恢复原有窗口行为，命令链数据不受影响。
