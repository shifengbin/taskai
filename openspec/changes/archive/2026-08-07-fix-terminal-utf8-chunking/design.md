## Context

`internal/terminal.Manager.watch` 从 Unix PTY 或 Windows ConPTY 读取原始字节，并立即将每次读取转换为 `Event.Data` 字符串。读取边界是传输细节，不对应 UTF-8 字符边界；当中文或 emoji 被拆开时，Wails 对事件做 JSON 编码会把无效字节替换为 U+FFFD。前端 xterm 收到的已经是不可恢复的替换字符。

输出读取循环为每个 `managedSession` 启动一个独立协程，因此输出的分片状态可以归属于该会话，不需要共享锁。终端事件的数据类型已经是字符串，且前端以增量方式写入对应 xterm 会话。

## Goals / Non-Goals

**Goals:**

- 在 PTY 读取边界跨越完整 UTF-8 字符时，保留原字符并按原顺序交付给前端。
- 使每个发布的终端输出事件都包含有效 UTF-8。
- 在读取结束时处理残留字节，保证输出事件先于错误和退出事件完成发布。
- 用共享管理器逻辑同时覆盖 Unix PTY 与 Windows ConPTY。

**Non-Goals:**

- 不支持将 GBK 等非 UTF-8 终端输出转码为 Unicode。
- 不改变 Wails 事件名称、`TerminalEvent` 数据结构、前端 xterm 写入方式或终端输入行为。
- 不改变 PTY 尺寸同步、终端状态判定、滚屏保留和生命周期语义。

## Decisions

### 在终端管理器中按会话帧化输出字节

每个 `managedSession` 持有仅供其读取协程使用的未完成输出尾字节。每次 `Read` 后，读取循环把该尾字节与新字节拼接，扫描并发布已构成完整 UTF-8 标量值的前缀；结尾尚不足以组成字符的字节留到下一次读取。这样修复位于无效字符串进入 Wails 前的最早公共边界，并且不需要改变前端事件协议。

备选方案是将事件数据改为 `[]byte`（JSON base64）并在前端使用流式 `TextDecoder`。它能承载任意字节流，但会扩大 Wails 与 TypeScript 契约、增加编码开销，并超出当前 UTF-8 分片问题的范围，因此不采用。

### 对完整但非法的 UTF-8 保持可显示且不阻塞

扫描时，完整的 UTF-8 标量值按原字节输出；确认非法的字节序列转换为 U+FFFD，而不是无限保留在缓冲区。这与现有 JSON 层的可见结果一致，但将结果前移到终端边界并保证事件字符串有效。只有“可能被下一次读取补全”的尾字节才进入缓冲。

备选方案是只检查末尾字节并继续把中间的非法字节转成 Go 字符串。该方案仍会把无效字符串交给 Wails，不能建立事件数据有效 UTF-8 的保证，因此不采用。

### 读取结束前刷出尾缓冲

当 `Read` 同时返回数据和错误时，先帧化该数据；当读取循环即将因 EOF 或平台预期关闭错误退出时，再把未完成尾字节按 U+FFFD 处理并发布，之后才发布错误或退出事件。这样不会因流结束永久丢失已接收字节，且输出、错误、退出的相对顺序清晰。

## Risks / Trade-offs

- [实际终端输出不是 UTF-8] → 无法按原字符转码；非法序列显示为 U+FFFD，保持与现有 JSON 传输一致且不阻塞后续输出。
- [实现将 ANSI 控制序列误当作文本] → ANSI 控制字节均为单字节 ASCII，使用 UTF-8 标量值扫描不会改变其字节或顺序；测试保留包含控制序列的普通输出。
- [缓冲在终端关闭时漏刷] → 让读取循环在所有返回路径统一刷新尾缓冲，并测试带数据加 EOF、仅残留不完整序列和预期 PTY 关闭错误。
- [多终端输出串扰] → 缓冲状态挂在 `managedSession`，并沿用现有按任务和终端 ID 发布事件的测试。

## Migration Plan

该变更不涉及持久化数据、绑定或配置迁移。发布后，新创建的终端会话立即使用新的输出帧化逻辑；回滚只需还原终端管理器和测试变更。

## Open Questions
