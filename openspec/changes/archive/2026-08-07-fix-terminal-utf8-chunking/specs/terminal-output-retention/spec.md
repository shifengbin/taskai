## ADDED Requirements

### Requirement: 增量终端输出保持 UTF-8 字符完整性

系统 MUST 在将活动终端的 PTY 输出作为字符串事件发送给前端前，保留跨读取边界的未完成 UTF-8 字节序列，并在后续读取补全后按原始顺序发送。发送给前端的每个普通输出事件 MUST 是有效 UTF-8；完整的 ANSI 控制序列和完整文本字符 MUST 保持其原始顺序。终端流结束时，系统 MUST 在错误或退出事件前处理尚未补全的尾字节，且不得无限等待后续读取。

#### Scenario: 中文字符跨两个 PTY 读取
- **WHEN** 一个中文字符的前导字节在首次读取中到达，剩余字节在下一次读取中到达
- **THEN** 前端依次收到的输出拼接后包含原始中文字符，且不包含 U+FFFD 替换字符

#### Scenario: emoji 跨多个 PTY 读取
- **WHEN** 一个四字节 emoji 被拆分到多个连续的 PTY 读取中
- **THEN** 系统在完整 emoji 到达后按原始输出顺序发送它，并且其他终端输出不被重排或丢失

#### Scenario: 输出中包含 ANSI 控制序列
- **WHEN** 带 ANSI 样式或光标控制序列的 UTF-8 文本跨读取边界到达
- **THEN** 系统保持控制序列和文本的原始字节顺序，并且完整文本字符不会因读取分片变为替换字符

#### Scenario: 终端在残留未完成序列后结束
- **WHEN** 终端流结束时仍有无法由后续读取补全的 UTF-8 尾字节
- **THEN** 系统在对应错误或退出事件之前完成该尾部的可显示处理，并且不会无限缓冲或阻止终端结束
