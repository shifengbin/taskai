## Context

生命周期命令链、预设和默认预设已经是持久化设置，设置页与新建任务表单均由这些数据驱动。当前 `settings.Default(...)` 为没有数据文件的新安装生成初始设置，但生命周期规范化也会在已有数据缺少字段时复用部分默认构造函数；如果直接修改共享默认值，可能给已有用户补入“公司框架”、切换默认预设或重命名“更新仓库”，违反本次只影响新用户的边界。

现有 `iterations-ai`、“删除任务工作目录”和仓库更新链已经具备所需的钩子范围与执行步骤。本次无需增加执行器、Wails API 或前端组件，只需调整新安装种子并保护旧数据兼容路径。

## Goals / Non-Goals

**Goals:**

- 新安装同时获得“默认预设”和“公司框架”，并默认选择“公司框架”。
- “公司框架”固定展开为开始前 `iterations-ai`、结束后“删除任务工作目录”、任务更新“更新框架仓库”。
- 新安装的仓库更新链显示为“更新框架仓库”，同时复用现有稳定链 ID 和命令内容。
- 已有持久化设置不因本次变更被补预设、切换默认项或重命名命令链。
- 保持预设和命令链现有的编辑、复制、删除、引用校验与任务独立保存语义。

**Non-Goals:**

- 不执行 `iterations-ai` 或仓库更新链，也不改变其命令顺序、参数和失败语义。
- 不把“公司框架”或其命令链改成不可编辑、不可删除的系统固定项。
- 不为已有用户提供自动迁移或手动导入入口。
- 不新增设置页面、新建任务表单或 Wails 绑定。

## Decisions

### 1. 分离新安装种子与旧数据兼容默认值

没有 `tasks.json` 时，仓库继续使用 `settings.Default(...)` 创建新安装数据；该路径生成新的命令链名称、两个预设和“公司框架”默认 ID。已有 `tasks.json` 缺少生命周期字段时，规范化与历史迁移使用独立的兼容构造值，继续生成原有“更新仓库”和“默认预设”语义。

不提升 `CurrentPresetVersion`，也不增加 `ApplyPresetMigration` 分支。这样现有完整配置和历史缺字段配置都不会因为本次发布进入新的公司预设迁移。

备选方案是提升预置迁移版本并按结构匹配后更新旧数据，但这仍会改变部分已有用户设置，与确认范围冲突。另一个方案是在前端虚拟展示预设，但会造成前后端默认选择、复制和删除行为不一致。

### 2. 复用稳定命令链 ID，新增稳定预设 ID

仓库更新链继续使用 `preset.lifecycle-chain.update-repositories`，只在新安装种子中显示为“更新框架仓库”。“公司框架”使用新的稳定预设 ID `preset.lifecycle-preset.company-framework`，其映射为：

```text
beforeStart -> preset.lifecycle-chain.iterations-ai
postStart   -> 空
beforeEnd   -> 空
postEnd     -> system.lifecycle-chain.delete-workspace
updateTask  -> preset.lifecycle-chain.update-repositories
```

原 `preset.lifecycle-preset.default` 和“默认预设”内容保持不变并继续出现在新安装列表中，但新安装的 `DefaultLifecyclePresetID` 指向“公司框架”。复用链 ID 能让现有执行、引用校验和任务保存逻辑保持不变。

### 3. 继续使用现有数据驱动界面

设置页已经遍历预设列表并根据默认 ID 标记默认项；新建任务表单已经读取默认预设并展开完整钩子映射。因此后端返回新安装种子后，界面会自然显示两个预设并预选“公司框架”，不需要增加条件分支或专用文案。

### 4. 分层验证新安装与兼容边界

Go 单元测试验证新安装默认设置、首次持久化、旧数据重载和旧创建入口；前端测试验证设置页与任务表单对返回数据的展示。集成测试使用独立配置目录启动真实 Wails 开发应用，只创建和重新打开未执行任务，不启动任务，从而验证持久化映射且避免实际克隆公司仓库。

集成测试步骤如下：

1. 创建临时目录并设置 `XDG_CONFIG_HOME` 指向该目录，确保不存在 `taskai/tasks.json`。
2. 执行 `wails dev` 且不禁用终端颜色、不让进程自动退出，从输出读取调试地址。
3. 使用 Chrome DevTools 打开调试地址，进入设置的“生命周期编排”。
4. 确认预设列表同时显示“默认预设”和“公司框架”，“公司框架”带“默认”标记；确认命令链列表显示“更新框架仓库”。
5. 打开新建任务表单，确认预设为“公司框架”，开始前为 `iterations-ai`、结束后为“删除任务工作目录”、任务更新为“更新框架仓库”，开始后与结束前为空。
6. 创建一个满足当前任务模板必填字段的未执行任务，再重新打开编辑，确认三个链选择已经持久化。
7. 不启动或结束该任务，避免运行真实生命周期命令；验证完成后关闭 `wails dev`。

## Risks / Trade-offs

- [默认构造函数仍被旧数据规范化复用] → 为新安装和兼容补齐提供明确的独立构造函数，并用旧数据快照测试锁定边界。
- [同一稳定链 ID 在新旧用户中可能显示不同名称] → 名称是可编辑展示字段，执行和引用均依赖稳定 ID；文档明确这是有意的兼容结果。
- [“公司框架”引用使三条链暂时不可删除] → 沿用现有引用保护；用户可先编辑或删除预设，再删除不再被任务引用的链。
- [回滚后新用户数据包含旧版本未预置的预设] → 旧版本已支持普通预设和稳定链 ID，能够按普通用户数据读取；无需破坏性回滚。

## Migration Plan

1. 发布后，仅缺少 `tasks.json` 的首次启动使用新安装种子。
2. 已有数据继续执行原有规范化和历史迁移，不增加本次变更的迁移版本。
3. 回滚时不删除已经由新版本创建的“公司框架”预设；旧版本按普通预设继续读取。
