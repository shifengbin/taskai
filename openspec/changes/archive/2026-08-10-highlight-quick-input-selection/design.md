## Context

终端快捷输入选择器已有 `selectedQuickInputIndex` 状态，并将当前结果标记为 `aria-selected=true`。搜索输入框始终持有键盘焦点，结果项目前只定义了悬停和自身获得焦点时的背景色，因此用户按上下方向键切换后看不到当前选择。

本变更只涉及 React 前端的选择器呈现。现有搜索、方向键边界、Enter 插入、Escape 关闭、鼠标悬停以及终端焦点恢复逻辑必须保持不变。

## Goals / Non-Goals

**Goals:**

- 让当前键盘选中的快捷输入结果在亮色和暗色模式下均可立即识别。
- 让视觉选中状态与既有 `selectedQuickInputIndex` 及 `aria-selected` 语义保持一致。
- 以自动化测试防止将来只保留无障碍属性而丢失可见反馈。

**Non-Goals:**

- 不改变快捷输入的排序、搜索、插入内容或键盘快捷键。
- 不移动键盘焦点到结果项，也不改变上下方向键的边界行为。
- 不新增快捷输入数据、后端接口或第三方依赖。

## Decisions

### 以现有选中索引作为唯一状态来源

结果项的可见选中态直接由现有 `selectedQuickInputIndex` 决定，并与 `aria-selected` 使用相同条件。这样方向键和鼠标悬停已经更新的状态可同时驱动语义和样式，不需要维护第二个视觉状态。

备选方案是把焦点转移到结果项，利用 `focus` 样式显示选择；这会中断搜索输入，并改变用户继续输入搜索词的体验，因此不采用。

### 使用主题色背景和左侧强调线区分当前项

当前结果使用已有的青色主题变量形成弱背景，并配合左侧强调线；未选中项不使用这组样式。该组合在亮色和暗色主题均可依赖现有主题变量保持对比度，也不会与结果项文字和内容摘要冲突。

仅依赖 `:hover` 或 `:focus` 的备选方案不能反映搜索框保持焦点时的键盘选中态，因此不采用。

### 在现有键盘导航测试中验证可见状态

扩展方向键测试，除验证 `aria-selected` 外，还验证当前选项携带驱动选中样式的标记或类，且上一个选项不再携带该状态。测试继续以搜索输入框触发方向键，确保覆盖实际焦点路径。

## Risks / Trade-offs

- [主题样式过于微弱] → 同时使用背景与左侧强调线，并复用已在两种主题定义的高对比主题色。
- [鼠标与键盘状态不一致] → 复用单一选中索引，不引入独立的悬停状态。
- [测试只覆盖属性而未覆盖样式] → 断言选中状态对应的结构化样式标记或类名。
