## Context

当前应用将任务和设置保存在同一个本地 `tasks.json` 文件中。任务仅保存标题、描述、颜色、生命周期和工作目录信息；设置中保存任务菜单、Shell 和 HTTP 服务相关配置。本机 HTTP 服务已提供任务详情接口，但其响应只包含现有任务字段。

本变更需要让用户先维护 Git 等可复用分类，再在分类中维护可复用的信息模板，并在创建或编辑任务时将选中的多个固定字段及动态参数保存到任务。模板管理必须作为顶部工具栏中的独立功能，而不是设置页的一个标签。任务详情必须可供外部工具按 `catalogue` 读取这些数据。

约束：保持单文件持久化和现有本机 HTTP 服务；旧数据文件必须可读取；生成的 OpenSpec 文档使用中文；实现完成时必须使用 `scripts/` 中的构建脚本生成新的可执行程序。

## Goals / Non-Goals

**Goals:**

- 提供独立的分类与额外信息模板管理入口、持久化和表单校验。
- 在创建和编辑任务时以分类筛选选择多个信息，并收集多个固定字段与动态参数。
- 将信息完整快照保存到任务，使模板后续变更或删除不会影响历史任务。
- 在任务详情 HTTP 响应中稳定输出按 `catalogue` 聚合、字段扁平的附加信息。

**Non-Goals:**

- 不对模板变更进行反向同步，也不通过删除模板级联删除任务数据。
- 不新增远程服务、鉴权、导入导出或额外 HTTP 管理接口。
- 不为参数增加数值、枚举、文件等类型；本期参数值均为字符串。
- 不在任务列表接口中返回附加信息。

## Decisions

### 1. 分类、模板与任务快照分别存储

仓储顶层数据新增分类名称集合和额外信息模板集合，均独立于 `settings.Settings`。分类名称唯一且非空。模板通过分类名称关联分类；新建或更新模板时，分类必须已经存在。分类仅在其下没有任何模板时可以删除，删除分类不会遍历或修改任务快照。

每个模板包含稳定 ID、分类、信息展示名称、一个或多个固定字段和零个或多个参数定义。固定字段包含键、字段显示名称和静态值；参数定义包含参数键、显示名称和必填标记。任务新增附加信息快照集合。快照复制模板的分类、展示名称、全部固定字段、参数定义和本次填写的参数值。快照只用于该任务，不保存对模板或分类的活动引用。删除模板或分类只会改变可选项，不遍历或修改任务。

选择此方案是因为任务详情必须在模板或分类删除后仍可返回原始数据，且用户已明确要求模板修改不影响历史任务。实时引用模板会违反该约束；仅保存模板 ID 和参数值也会在模板删除后丢失固定字段与展示信息，因此不采用。

### 2. 以展示名称降低任务表单复杂度

模板的“信息展示名称”是独立于固定字段显示名称的必填字段。额外信息管理列表和任务表单使用该名称识别一条可选信息。任务表单用分类选择器过滤可选模板，再以展示名称呈现多选项；切换分类仅改变当前可选项，不会移除之前在其他分类勾选的模板。所有已选模板会在表单上方集中显示为紧凑的方形标签，每个标签提供 `x` 按钮以移除该项；选中后显示其固定字段说明和参数输入框。

同一分类下的信息展示名称必须唯一，避免用户无法区分选项。模板必须选择已有分类，且展示名称不能为空，并至少包含一个固定字段；每个固定字段的键、显示名称和静态值均不能为空。固定字段键和参数键在同一模板内必须全局唯一，防止 HTTP 扁平化时覆盖字段。选中的同一模板不得在一个任务中重复出现。必填参数去除首尾空白后为空时，创建或更新任务必须失败。

### 3. 使用独立弹窗维护模板，并复用任务编辑弹窗保存快照

顶部工具栏在设置按钮旁增加额外信息管理按钮。该按钮打开独立管理弹窗：用户可新建、选择和删除分类，并在选中分类后创建、修改、删除模板、多个固定字段和多个参数定义；模板表单的分类使用选择控件，不提供自由输入。保存时通过新的 Wails 应用绑定写入仓储。分类下仍有模板时，删除操作必须被拒绝并提示先删除该分类的模板。

创建和编辑任务弹窗新增“附加信息”区域。新建任务从当前选中分类的模板中勾选信息；编辑任务显示已保存快照，即使其源模板或分类已经删除也允许保留、移除或修改参数值。编辑任务新增的信息仍必须来自当前模板。任务编辑不会反向修改模板的固定字段或参数定义。

单独的管理功能符合现有应用通过顶部按钮打开对话框的交互模式，并将任务工作流与全局可选信息维护分开。

### 4. 任务详情使用按目录聚合的扁平 JSON

仅 `GET /api/v1/tasks/{taskId}` 增加 `extraInfo` 字段。服务读取该任务的快照，以 `catalogue` 作为对象键；每个目录键对应一个数组，数组元素为对象。元素将每个固定字段键映射到静态值，并在同一层加入每个参数键到本次参数值的映射，例如：

```json
{
  "extraInfo": {
    "git": [
      {"repository": "git@example.com:team/api.git", "branch": "main"}
    ]
  }
}
```

HTTP 响应不返回信息展示名称、固定字段显示名称、`catalogue` 字段或参数显示名称。`catalogue` 已由外层键表达，展示字段只服务桌面应用。固定字段键与参数键冲突在模板校验阶段阻止，因此扁平化时不会覆盖静态值。未选择额外信息的任务返回空对象 `{}`；可选参数未填写时仍返回该参数键及空字符串，以便客户端获知其定义。

现有列表接口保持不变，避免列表响应随附加信息数量线性增大。

## Risks / Trade-offs

- [快照重复保存模板字段] → 这是保留历史任务数据的必要成本；信息规模通常较小，仍沿用现有单文件存储。
- [用户删除模板后无法为新任务再次选择该项] → 管理界面在删除前明确提示其仅影响未来选择，历史任务不受影响；分类必须先清空模板才可删除，避免悬空模板。
- [任意键会成为 HTTP JSON 字段名] → 保存时校验非空、唯一和不冲突，并在接口文档中说明客户端按配置键读取。
- [历史快照与当前模板内容不同] → 编辑任务明确将已保存快照与当前可选模板分开呈现，避免误以为编辑会同步模板。

## Migration Plan

1. 新增固定字段集合使用 JSON 的零值；仓储读取缺失分类集合的旧 `tasks.json` 时，会从旧模板已有的 `catalogue` 去重生成分类列表；不含模板的旧数据则使用空分类集合。
2. 旧版单键、键显示名称和静态值的模板及快照在读取时迁移为只包含一个固定字段的兼容数据，保留其原有键、显示名称和值。
3. 发布后首次保存会以扩展字段写回同一数据文件，原有任务生命周期、排序和设置数据保持不变。
4. 若需要回滚到旧版本，旧版本会忽略未知 JSON 字段；新保存的分类、模板与任务快照仍保留在文件中，重新升级后可继续使用。
5. 不需要数据迁移脚本或停机窗口。
