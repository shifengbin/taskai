## Context

`refine-task-status-transitions` 已在任务确认进入“执行中”后切换标签，并向 `TaskTree` 传递一次性反馈令牌。任务树的 `List` 是固定面板内唯一的纵向滚动容器，但反馈样式目前直接附加到目标行；当目标行超出列表视口时，用户无法看见该反馈。

任务进入执行中的即时绑定响应和异步生命周期事件都共用同一令牌。方案必须保留这一时序，且不能将页面、左侧面板或右侧内容区滚动到意外位置。

## Goals / Non-Goals

**Goals:**

- 在开始反馈的首个可见画面前，保证目标执行中任务已位于任务列表可视区域内。
- 仅在目标条目被列表视口裁切时调整列表滚动位置；条目已完整可见时保持用户当前位置。
- 保留两次快速闪烁、静态高亮和现有 700ms 一次性反馈的语义。
- 使即时开始响应和生命周期事件开始两条路径获得一致的定位结果。

**Non-Goals:**

- 不改变任务排序、创建时间顺序、展开状态、选择状态或状态标签的切换规则。
- 不增加平滑滚动、滚动位置持久化、虚拟列表或新的用户设置。
- 不为任务结束、手动切换标签、普通列表刷新或初次加载触发自动滚动。
- 不修改后端任务状态、生命周期接口或 Wails 绑定。

## Decisions

### 1. 由任务树在绘制前滚动其自身列表

`TaskTree` 为任务 `List` 保存 DOM 引用，并在收到新的开始反馈令牌、且“执行中”目标条目已渲染后使用布局副作用读取列表与目标行的矩形。若目标行上边缘位于列表上方，或下边缘位于列表下方，则仅修改该 `List` 的 `scrollTop` 至最近可见位置。

布局副作用发生在浏览器绘制前，因此样式动画的首帧不会在视口外被用户看见；现有应用层令牌和 700ms 清理超时无需承担 DOM 滚动职责。使用 `scrollIntoView()` 的替代方案可能连带滚动应用窗口或其他可滚动祖先，不符合固定左侧面板的边界，因此不采用。

### 2. 使用“最近可见”而非居中或平滑滚动

目标行仅移动必要距离，使其完整进入列表可视区域。已可见时不滚动，避免用户因开始另一条任务而失去当前浏览上下文。滚动为即时定位，不使用平滑动画，确保两次 350ms 闪烁仍有完整时长可见，也不额外引入动态效果。

始终居中目标行的替代方案会在条目已经可见时无故改变阅读位置；平滑滚动则可能消耗或遮盖短暂反馈，均不采用。

### 3. 保持反馈令牌的渲染条件与可访问性分支

开始反馈仍只匹配令牌任务 ID 且任务状态为“执行中”的行。列表定位完成后，同一渲染周期中的闪烁样式生效；`prefers-reduced-motion: reduce` 时仍进行即时定位，但显示静态高亮而非闪烁。目标行在令牌到达时不存在（例如已被隐藏或状态再次改变）则不滚动，也不对其他任务应用反馈。

将滚动逻辑放到 `App` 的替代方案需要跨组件查询内部 DOM，并容易与任务树重新渲染、状态标签切换和组件测试脱节，因此不采用。

## Risks / Trade-offs

- [浏览器或测试环境未提供真实布局矩形] → 通过可注入的矩形模拟测试滚动计算；运行时只有当目标行确实超出列表边界才写入 `scrollTop`。
- [状态切换与令牌更新分两次渲染] → 布局副作用依赖反馈递增标识、活动状态和可见任务，直到目标行渲染后再执行定位。
- [目标任务在反馈期间被隐藏或完成] → 找不到匹配行时不滚动；现有令牌超时仍会清理状态。
- [减少动态效果用户不希望额外动画] → 仅执行即时滚动，并继续使用静态高亮，不引入平滑滚动。

## Migration Plan

1. 在任务树中增加列表引用与绘制前的目标可见性判断。
2. 保持现有开始反馈令牌、闪烁和静态高亮样式，只在定位后让它们可见。
3. 覆盖目标在视口外、已可见、生命周期开始和减少动态效果的测试场景。
4. 若需回滚，移除列表定位副作用；任务状态、设置和后端数据均无需迁移。

## Open Questions

无。使用最近可见的即时定位，避免不必要的阅读位置跳动和额外动态效果。
