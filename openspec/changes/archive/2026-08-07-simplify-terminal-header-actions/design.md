## Context

当前 `TerminalView` 的标题栏把状态点、快捷输入和关闭按钮都放在终端标题右侧，并复用任务树的上下文操作样式。在可悬停设备上，该样式会让两个按钮默认隐藏。左侧终端项已经持续展示同一终端的实时状态，并保留关闭入口，因此右侧状态与关闭功能重复。

本变更仅调整前端呈现和入口职责。右侧标题栏仍只对应活动终端，左侧终端项继续拥有状态展示和关闭终端回调；终端会话、PTY、快捷输入数据和 Wails 接口均不变。

## Goals / Non-Goals

**Goals:**

- 将右侧活动终端标题栏收敛为图标、标题和常显快捷输入入口。
- 移除右侧实时状态点和关闭终端按钮，释放标题可用空间并避免重复功能。
- 保持左侧终端项的状态点、关闭入口及既有悬浮、焦点和无悬停设备行为。
- 保持快捷输入 Popover、平台快捷键、终端聚焦和现有可访问语义不变。

**Non-Goals:**

- 不移除左侧终端项的关闭入口，不改变终端关闭后的会话清理。
- 不改变实时状态的检测、颜色、轮询或事件传递。
- 不改变快捷输入的保存、搜索、插入、快捷键或 Popover 内容。
- 不修改后端、Wails 绑定、PTY 协议、持久化模型或 API。

## Decisions

### 将右侧标题栏操作区从上下文操作样式中分离

`TerminalView` 将为快捷输入入口使用标题栏专用操作区，而不再使用 `taskai-contextual-container` / `taskai-contextual-actions` 样式钩子。现有全局悬浮规则因此继续只影响任务行和左侧终端子项，快捷输入入口在所有输入设备上直接可见。

选择专用样式钩子而不是在全局样式中覆盖标题栏透明度，因为后者会继续把右侧标题栏定义为上下文操作容器，未来新增按钮时容易再次被意外隐藏。

### 右侧只保留快捷输入，左侧承担状态与关闭管理

移除 `TerminalView` 中的状态点与关闭按钮渲染，同时移除不再使用的图标和状态点依赖。活动终端的快捷输入 Popover 保持原有触发器、标题、无障碍标签和快捷键；左侧 `TaskTree` 不作行为改动，继续呈现状态点和关闭按钮。

保留右侧状态点但取消关闭按钮会留下重复状态信息；隐藏而不移除则仍占用标题空间并向辅助技术暴露无用元素，因此均不采用。

### 以组件测试锁定入口职责

`TerminalView` 测试将断言活动终端标题栏不包含状态角色或关闭按钮，包含可用的快捷输入入口，且不再带有上下文操作显隐样式。既有快捷输入快捷键、选择器与插入测试继续覆盖其行为；`TaskTree` 既有状态和关闭测试保证左侧入口未受影响。

## Risks / Trade-offs

- [用户无法从右侧关闭终端] -> 左侧终端项保留同名关闭入口，并继续显示终端实时状态。
- [将来有人复用上下文操作类名] -> 右侧使用专用类名，避免重新落入悬浮隐藏选择器。
- [移除状态点使右侧缺少实时提示] -> 状态唯一呈现在左侧，避免两个位置不同步或信息重复。
