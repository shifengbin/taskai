## 背景

任务工作台当前通过 `App.tsx` 中的 MUI 主题令牌和组件覆盖层提供全局视觉，通过 `App.css` 为工作台、任务树和详情区追加松林夜跑装饰；`TaskTree.tsx` 还包含任务行与终端子项的局部 `sx` 外观，`TerminalView.tsx` 独立配置 xterm 的颜色。现有任务树宽度、顶部栏、分隔条、详情/终端切换和全部状态管理均已满足庭院方案所需的信息架构，不需要改变组件树或业务调用。

本变更只替换视觉语言。受影响的用户包括长时间使用任务队列、配置弹窗和终端的开发者；他们需要低干扰的视觉层级，同时仍能一眼识别实时状态、危险操作和任务自定义颜色。

## 目标 / 非目标

**目标：**

- 以岩灰、鼠尾草绿、受控黏土色和深森林终端建立完整的亮暗庭院令牌。
- 让工作台、详情、任务树、终端和全部覆盖层遵循相同的低饱和、留白和细分隔线语言。
- 在两种颜色模式中保持正文、状态、表单标签和焦点可读，且继续支持减少动态效果偏好。
- 保持全部 React 组件边界、Wails 调用、任务/终端状态、快捷键和可访问语义不变。

**非目标：**

- 不调整任务树、终端和详情区的布局位置或信息层级。
- 不新增网络字体、图像资源、主题选择项或运行时依赖。
- 不修改任务数据、颜色值、生命周期、设置持久化或后端接口。

## 决策

### 1. 使用令牌优先的庭院调色，而非添加新的装饰图形

亮色模式以岩灰绿画布、近白表面、墨绿文字与鼠尾草主色构成层级；暗色模式以墨绿画布、深层表面和柔亮文字构成低照度层级。黏土色只用于警告、错误、破坏性动作或少量辅助提示，任务自定义颜色只作为任务行边线或小状态标记。

这比保留斜纹、荧光绿或叶片插画更适合高密度桌面工作台，也不会让装饰与实时状态争夺注意力。备选的“增加庭院背景纹理”被否决：它重新引入噪声，并降低终端周围的专注度。

### 2. 将跨组件外观集中在 MUI 主题，将区域细节保留在样式表

`createAppTheme` 负责 palette、字体层级、焦点环及 Button、Dialog、TextField、Tabs、Chip、Menu、Alert、Accordion、Switch 等 MUI 组件的庭院外观。`App.css` 负责顶栏、侧栏、分隔条、详情卡、空状态和启动屏等布局相关选择器，并删除所有条纹、硬阴影和不规则跑道圆角。

`TaskTree.tsx` 仅调整其局部圆角、选中态、任务色面积和拖拽反馈；不改变事件处理或数据属性。`TerminalView.tsx` 的 xterm 色板独立映射到庭院终端令牌，以保证深色终端在亮暗工作台中均可读。

### 3. 保留现有正文资源，使用系统衬线字体表达标题层级

正文、控件和等宽数据继续使用现有的 Nunito/中文无衬线回退与等宽字体，避免新增字体文件。仅在应用标题、任务详情标题和少量大标题使用 `Songti SC`、`Noto Serif CJK SC` 等系统衬线回退；不可用时回退到现有正文栈。

这可以表达庭院的安静与阅读感，同时不引入下载失败、体积增长或平台字体加载阻塞。备选的全局衬线字体被否决，因为密集表单和终端标签的扫描效率更依赖无衬线字体。

### 4. 以静态层级取代装饰性动画

保留任务开始、拖拽和实时状态的功能性反馈；它们使用低幅度色彩、边框或状态点变化，持续时间不超过既有约束。移除启动卡片旋转、条纹相关效果和硬阴影位移；`prefers-reduced-motion` 下继续禁用非必要动画。

### 5. 用现有组件测试保护行为边界

视觉变更后，保留并运行任务树、终端和应用测试，特别验证选择、拖拽、状态标签、终端标题、关闭与键盘可达性。新增或调整测试只断言稳定的可访问语义、状态和类名/令牌，不为纯 CSS 像素细节建立脆弱快照。

## 风险 / 权衡

- [低饱和色降低状态辨识度] → 使用状态点、图标、文字和符合对比度的语义色共同表达；测试亮暗两种模式的焦点与状态。
- [MUI `sx` 与 CSS 覆盖优先级冲突] → 跨组件样式只在主题覆盖中定义，布局私有样式使用现有 `taskai-*` 类名；避免同一属性在两处竞争。
- [系统衬线字体在不同平台差异较大] → 仅将其用于非关键大标题，并提供现有无衬线回退。
- [遗留松林令牌未完全清除] → 用文本搜索检查荧光绿、斜纹、硬阴影和旧变量，并通过亮暗模式人工走查验证。
- [终端配色与 xterm 可读性不一致] → 单独测试亮暗模式下的前景、光标和选择区，终端始终维持深背景。

## 迁移计划

1. 在前端内替换令牌、主题覆盖和局部装饰样式，不改设置中保存的 `colorScheme` 值。
2. 运行组件测试、完整前端测试和生产构建；人工切换亮暗模式并走查任务、终端和主要弹窗。
3. 发布后，已有用户仍按其保存的亮色或暗色偏好进入对应庭院主题；不需要数据迁移。
4. 若发现可读性或覆盖层回归，回退本次前端样式提交即可，任务数据和后端行为不受影响。
