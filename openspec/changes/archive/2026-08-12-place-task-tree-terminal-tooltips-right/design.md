## Context

`TerminalName` 同时服务于左侧任务树终端项和右侧终端标题栏，并使用共享的 Radix Tooltip 展示别名对应的实际标题与启动命令。该组件当前未指定提示方向，因此任务树中的提示可能显示在条目上方并覆盖相邻终端；任务描述提示则由任务树固定放在条目右侧。

本次变更只调整任务树调用场景。提示内容、显示条件、别名编辑、终端标题解析和实时状态数据流均保持不变。

## Goals / Non-Goals

**Goals:**

- 让任务树中的别名终端提示显示在对应终端项右侧，并与任务描述提示保持一致的方向和间距。
- 保证提示覆盖层不接收鼠标事件，不影响终端选择及相邻条目的点击。
- 保持 `TerminalName` 的共享复用，并允许不同调用场景选择提示定位策略。

**Non-Goals:**

- 不调整右侧终端标题栏的提示定位。
- 不改变提示的两行内容、样式或出现条件。
- 不修改任务描述提示、全局 Tooltip 默认值、终端数据结构或状态管理。

## Decisions

1. 为 `TerminalName` 增加可选的提示定位参数，并将参数传给已有 `TooltipContent`。任务树传入右侧定位、顶部对齐、8px 间距并关闭该实例的碰撞翻转，确保提示与任务描述提示一样固定在右侧；右侧标题栏不传入参数，继续使用现有默认定位和碰撞处理。这样能够把行为差异保留在调用场景中，而不是改变所有 Tooltip 或复制终端名称组件。

2. 在终端别名提示内容上禁用鼠标事件。提示只承担只读信息展示，不需要点击、选择或其他交互；禁用鼠标事件可以保证覆盖层不会成为终端选择和鼠标操作的命中目标。

3. 继续使用 Radix Portal 和现有样式。该机制已经处理层级、打开关闭和无障碍属性，本次只提供显式定位，不引入手工坐标状态或新的提示组件。

4. 通过组件测试验证定位参数和非交互属性，通过任务树测试验证该调用场景启用了右侧策略；右侧标题栏测试确认未被任务树专用策略影响。桌面集成测试需要实际悬浮多个相邻终端，确认提示不会出现在上方，也不影响终端点击。

## Risks / Trade-offs

- [极窄窗口中固定右侧的提示可能超出可视区域] → 仅对任务树终端提示关闭碰撞翻转，以满足固定右侧且不遮挡相邻终端的要求；提示不接收鼠标事件，右侧标题栏和其他全局提示继续保留碰撞保护。
- [给共享组件增加参数可能被其他调用方误用] → 参数保持可选，只有任务树明确传入，标题栏和未来调用方继续获得现有默认行为。
- [提示位于右侧时可能覆盖右侧工作区的一小部分] → 提示不接收鼠标事件且仅在悬浮期间显示，优先保证任务树内部相邻终端可点击。
