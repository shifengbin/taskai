## Context

当前前端在开始任务成功后调用既有的标签切换逻辑，因此会进入“执行中”标签；任务结束确认成功后也调用同一逻辑，因而强制进入“已完成”标签。任务树按当前标签筛选任务，刚开始的任务进入新列表后没有额外的定位线索。

活动变更 `improve-lifecycle-command-progress` 会将生命周期命令链改为异步执行。开始动作的初始响应可能仍为“未执行”，后续生命周期事件才会将任务变为“执行中”。本变更必须同时适用于即时响应和后续事件，且不得在应用初次加载历史任务时误触发反馈。

## Goals / Non-Goals

**Goals:**

- 在已确认任务进入“执行中”时自动打开并持久化“执行中”标签。
- 让刚进入执行中列表的唯一目标任务以短暂闪烁或高亮被准确定位。
- 在已确认任务进入“已完成”时保持用户当前标签和已持久化的标签偏好不变。
- 与生命周期进度事件共用同一状态迁移判定，避免响应与事件的时序差异改变交互结果。

**Non-Goals:**

- 不修改任务状态接口、后端状态机、任务排序或已完成任务的展示规则。
- 不为一般的列表刷新、手动切换标签、应用首次加载或实时终端状态更新播放动效。
- 不增加通知、声音、持续闪烁或新的用户设置。

## Decisions

### 1. 按已确认的状态迁移决定标签行为

前端只在本次会话中观察到任务从“未执行”变为“执行中”后，调用既有标签切换和设置持久化路径；不能在用户点击“执行”时提前切换。这样，开始前置命令失败或仍在等待时不会错误跳转。

任务从“执行中”变为“已完成”后仅替换任务快照、刷新计数、清理终端关联状态，不再调用标签切换或保存设置。当前视图因此保持不变，用户需要时可自行打开“已完成”标签。

`improve-lifecycle-command-progress` 中“状态迁移时同步当前标签”的决策仅保留前一种迁移；其结束迁移必须遵循本变更的保持当前标签规则。

备选方案是在开始或结束按钮的点击处理器中直接处理标签。该方案无法覆盖异步生命周期事件，也会在状态未实际改变时造成错误跳转，因此不采用。

### 2. 使用受控的一次性任务条目反馈

应用层保存一次性反馈令牌，令牌包含刚开始的任务 ID 和递增标识，并将其作为任务树属性传递。任务树只为 ID 匹配的、可见的执行中任务条目附加反馈样式；递增标识确保同一任务条目重新挂载或未来重试时仍可重新触发动画，而不会影响其他任务。

反馈采用不改变条目尺寸和列表排序的背景/描边闪烁，两次快速变化后结束。动效结束事件和短超时兜底都会清理令牌，避免后续列表重渲染重复播放。启用 `prefers-reduced-motion: reduce` 时取消闪烁，保留短暂的静态高亮，确保可定位但不强制动态效果。

备选方案是直接查询 DOM 并添加 CSS 类。它会绕过 React 生命周期，在任务列表切换、重渲染或测试环境中容易遗留样式，因此不采用。

### 3. 集中处理绑定响应和生命周期事件

任务列表更新入口将保留更新前快照，并在初始化完成后的实时更新中识别状态迁移。开始绑定的返回值和生命周期事件都经过该入口，使“未执行→执行中”只触发一次标签切换和反馈，“执行中→已完成”绝不触发标签切换。初次加载直接建立任务列表基线，不产生迁移反馈。

现有生命周期进度版本合并仍负责丢弃过期任务快照；本变更的迁移判断必须在快照通过该合并规则后执行，避免迟到响应重新播放反馈或改变标签。

### 4. 以可观察状态验证行为

任务树为正在反馈的条目暴露稳定的 `data-*` 标识，供组件测试断言；测试不依赖浏览器实际播放 CSS 动画。应用测试验证开始后的标签持久化、结束后当前标签不变，以及异步生命周期事件完成状态迁移时的同等结果。

## Risks / Trade-offs

- [任务在反馈尚未结束时被完成或隐藏] → 任务树卸载时反馈自然消失，应用层清理令牌，后续列表不再播放。
- [生命周期响应与事件乱序] → 先执行既有版本/运行标识合并，再判定是否发生迁移；已处理的反馈令牌不重复执行。
- [减少动态效果用户仍需要定位线索] → 使用短暂静态高亮替代动画，而非完全不提供反馈。
- [两个活动 OpenSpec 变更同时修改前端事件处理] → 实现任务明确协调 `improve-lifecycle-command-progress` 的标签规则，并以本变更的测试为最终行为约束。

## Migration Plan

1. 在前端状态更新路径中加入状态迁移与一次性反馈令牌，不引入数据迁移。
2. 移除结束成功后的自动标签切换，并调整生命周期进度变更中的同类逻辑。
3. 补充组件和应用测试，运行前端测试、前端构建及项目 Linux 构建脚本。
4. 若需回滚，仅移除前端反馈状态并恢复结束处理器调用既有标签切换；任务、设置和后端数据均无需迁移。

## Open Questions

无。反馈采用两次快速闪烁，并以减少动态效果偏好下的静态高亮作为确定的可访问性降级方案。
