## MODIFIED Requirements

### Requirement: 一次性补齐可删除的仓库命令链预置
系统 MUST 通过持久化的预置迁移版本为新安装和旧设置各补齐一次 `iterations-ai` 与“更新仓库”命令链。两个预置链 MUST 使用稳定标识，但 MUST 作为普通命令链管理，不得成为不可编辑或不可删除的系统固定链。系统 MUST 在一次性补齐后记录最新预置迁移版本，并且在后续加载时 MUST 不重新创建用户删除的预置链。删除仍 MUST 遵循既有规则：被未执行或执行中任务或任何命令链预设引用的链不可删除，其他情况允许删除。升级到包含“更新默认分支”的预置版本时，系统 MUST 仅更新完全匹配上一版本原始名称、范围、命令 ID、参数与顺序的预置链；缺失或已修改的预置链 MUST 保持不变。

#### Scenario: 旧设置只补齐一次
- **WHEN** 系统加载未记录本预置迁移版本的既有设置
- **THEN** 系统补齐两个预置链并持久化最新版本，之后用户删除其中任一链再重启应用时该链不再自动出现

#### Scenario: 可以删除未被活动任务或预设引用的预置链
- **WHEN** 用户删除未被未执行、执行中任务或命令链预设引用的 `iterations-ai` 或“更新仓库”链
- **THEN** 系统删除该链，并且不修改其他命令链或预设

#### Scenario: 保护被活动任务引用的预置链
- **WHEN** 未执行或执行中任务选择了某条预置链，用户尝试删除该链
- **THEN** 系统拒绝删除并说明该链仍被任务引用

#### Scenario: 保护被命令链预设引用的预置链
- **WHEN** 任一命令链预设选择了某条预置链，用户尝试删除该链
- **THEN** 系统拒绝删除并说明该链仍被预设引用

#### Scenario: 升级未修改的版本 3 预置链
- **WHEN** 系统加载两个均完全匹配版本 3 原始结构的预置链
- **THEN** 系统仅在两个链首插入“更新默认分支”，并记录新的预置版本

#### Scenario: 升级保留已修改的预置链
- **WHEN** 系统加载预置版本 3 且用户已修改 `iterations-ai` 的名称、范围、命令、参数或顺序
- **THEN** 系统不向该链插入“更新默认分支”，也不恢复原始内容

### Requirement: 预置 iterations-ai 开始前命令链
系统 MUST 提供名称为 `iterations-ai`、仅适用于 `beforeStart` 的预置命令链。该链 MUST 按以下顺序引用命令：更新默认分支且不传追加参数；创建任务工作目录；克隆指定 Git 仓库并传入唯一参数 `repository=git@gitlab.jiandan100.cn:webdev/iterations-ai.git`；生成清单文件且不传追加参数；Git 仓库克隆并传入唯一参数 `dir=workspaces`。系统 MUST 不自动将该链加入默认生命周期预设。

#### Scenario: 用户在开始前选择 iterations-ai 链
- **WHEN** 用户为任务的 `beforeStart` 钩子选择 `iterations-ai` 并开始任务
- **THEN** 系统在任务进入执行中前依序更新执行态默认分支、创建目录、将指定仓库克隆到任务目录根部、生成清单文件，并将选定 Git 信息克隆到任务目录下的 `workspaces` 路径

#### Scenario: iterations-ai 不会自动预选
- **WHEN** 用户新建任务且未手动选择 `beforeStart` 命令链
- **THEN** 系统不因预置 `iterations-ai` 链而在默认生命周期预设中保存该链选择

### Requirement: 预置更新仓库命令链
系统 MUST 提供名称为“更新仓库”、仅适用于 `updateTask` 的预置命令链。该链 MUST 先引用更新默认分支命令且不传追加参数，再引用生成清单文件命令且不传追加参数，最后引用 Git 仓库克隆命令并传入唯一参数 `dir=workspaces`。系统 MUST 不自动将该链加入默认生命周期预设；该链的 Git 仓库克隆步骤 MUST 保持既有语义，仅克隆缺失目标而不得执行拉取、合并、覆盖或删除已有 Git 工作树。

#### Scenario: 执行中任务更新时运行预置链
- **WHEN** 执行中任务选择“更新仓库”作为 `updateTask` 链并成功保存任务更新
- **THEN** 系统先更新执行态默认分支，再重新生成任务目录根部的清单文件，最后以 `dir=workspaces` 执行 Git 仓库克隆

#### Scenario: 已有仓库不被更新链覆盖
- **WHEN** “更新仓库”链运行时 `workspaces` 下的某个选定 Git 信息目标已存在
- **THEN** 系统保留已有目标并按 Git 仓库克隆的既有跳过语义继续处理，不执行 Git 拉取或覆盖

### Requirement: 所需系统命令支持开始后链
系统 MUST 将“创建任务工作目录”和“Git 仓库克隆”系统命令的固定适用范围设为包含 `beforeStart` 和 `postStart`。现有标准默认生命周期预设中的创建目录链 MUST 保持仅适用于 `beforeStart`，系统 MUST 不因扩展命令范围改变既有默认预设映射或任务的默认选择。

#### Scenario: postStart 链可引用创建目录命令
- **WHEN** 用户保存仅适用于 `postStart` 且首个命令为“创建任务工作目录”的链
- **THEN** 系统接受该链并在任务状态提交为执行中后运行创建目录命令

#### Scenario: postStart 链可引用 Git 仓库克隆
- **WHEN** 用户保存仅适用于 `postStart` 且包含“Git 仓库克隆”命令的链
- **THEN** 系统接受该链并保留该命令既有的 `dir=<相对目录>` 参数校验和已存在目标跳过语义

#### Scenario: 既有开始前默认选择保持不变
- **WHEN** 系统加载包含既有默认生命周期预设的设置
- **THEN** 预设中的 `beforeStart` 仍选择创建目录链，系统不为 `postStart` 自动设置命令链
