## Context

现有 `TerminalSessionRegistry` 为每个终端维护一个 xterm 会话，已监听选区变化以自动复制文本，并提供直接写入和模拟粘贴到指定会话的入口。`TerminalView` 已承载活动终端的标题栏工具与弹出层，`App` 集中管理终端创建、关闭、任务结束与应用卸载。应用设置由 Go 后端持久化，经 Wails 绑定传给前端；设置对话框使用仅在确认保存时提交的草稿。

本功能需要把鼠标选区转换为只在当前应用运行期间有效的终端备注，且不能破坏已允许终端程序自行处理鼠标的 `disableTaskAIMouseClipboard` 边界。用户已确认：不使用快捷键；鼠标选区后显示入口；备注按终端绑定；发送后无论结果都清空；每条和整体模板均自动换行。

## Goals / Non-Goals

**Goals:**

- 让用户在活动终端选取文本后快速添加备注，并在同一终端标题栏查看该会话的备注数量和列表。
- 让用户在设置中持久化原文前缀、备注前缀和列表统一后缀，并以确定的自动换行规则构造汇总文本。
- 仅在内存中按 `taskId + terminalId` 保存备注，并在终端、任务和应用生命周期结束时释放。
- 将汇总作为 xterm 模拟粘贴写入原终端会话，不隐式提交命令；发送尝试结束后清空该会话记录。

**Non-Goals:**

- 不持久化、搜索、编辑、删除单条备注，也不在任务详情中展示已关闭终端的备注。
- 不增加全局快捷键、系统级浮层、任务共享备注、跨终端发送、导入导出或同步。
- 不改变终端选区自动复制、右键粘贴、快捷输入和已有自定义快捷键的行为。
- 不为禁用 TaskAI 鼠标剪贴板的终端注入额外选区或鼠标交互。

## Decisions

### App 持有按会话分区的内存备注

在前端新增 `TerminalNote` 和以终端会话键为索引的记录表；`App` 作为唯一持有者，向当前 `TerminalView` 传递对应记录和新增、清空回调。会话键复用现有 `terminalEventKey(taskId, terminalId)`，因此同一任务的不同终端绝不共享记录。

选择此方案而不是把记录放进 `TerminalSessionRegistry`，因为会话注册表负责 xterm 资源和 PTY 通道，而 React 需要驱动标题栏数量与面板内容；放在 `App` 也能在已有关闭、任务结束、删除与卸载路径集中释放。选择此方案而不是后端持久化，是因为用户明确要求仅在应用运行期间保存且终端绑定。

### 选区完成后在终端内容区显示本地备注入口

`TerminalView` 在可交互内容区记录鼠标完成选区的位置，并在下一帧向注册表读取同一会话的 xterm 选区。文本非空时，以内容区相对坐标在鼠标旁显示带消息图标的半透明按钮；空选区、点击其他位置、打开输入框、切换视图或终端失活时隐藏按钮。位置须限制在内容区边界内，避免按钮被右侧或底部裁切。

选择在终端视图本地计算位置，而不是把坐标混入 xterm 会话或使用全局浮层：选区只属于当前已挂载的内容区，容器相对定位能在多窗口尺寸下正确对齐并自动随视图销毁。只处理鼠标完成的选区，符合已确认的鼠标触发方式，不为键盘选区增加未要求的入口。

当 `disableTaskAIMouseClipboard` 为 `true` 或终端不是活动状态时，视图既不读取选区来显示备注入口，也不新增备注；这与现有“由终端程序处理鼠标”的设置保持一致。

### 模态备注输入与标题栏会话面板

点击悬浮按钮后打开 Radix 对话框，展示选中的原文和多行备注输入。保存仅接受含非空白字符的备注，并将原文与输入内容作为不可变记录追加到当前会话；取消不添加。保存或取消后关闭对话框、隐藏浮动入口，并把焦点还给同一终端。

标题栏增加备注图标按钮，标签包含当前数量；点击弹出面板，按创建顺序显示原文和备注，在底部显示“发送到终端”按钮。空列表时按钮禁用并显示空态。采用标题栏而非任务树入口，是因为记录与当前终端一一绑定，用户能直接判断将把内容发送到哪里。

### 模板只持久化格式参数，格式化函数统一加换行

设置模型新增嵌套的 `terminalNoteTemplate`，字段为 `originalPrefix`、`notePrefix` 和 `listSuffix`。默认值分别为 `原文：`、`备注：` 和空字符串；既有设置缺少整个字段时迁移为该默认值并回写。用户保存空字段仍表示空模板文本，不被误判为旧数据而恢复默认值。

前端新增纯格式化函数。每条记录固定产生 `原文前缀 + 原文 + 换行 + 备注前缀 + 备注`；多条记录依次以一个换行连接；最后无论后缀是否为空都再写入一个换行、列表统一后缀和结尾换行。原文、备注和三个模板字段按原样保留，只有换行连接由函数补齐。集中格式化能让界面预览、单元测试和实际发送使用完全相同的输出。

### 复制或发送采用会话级清空控制

备注面板底部提供“操作后清空”复选框、“复制到剪贴板”和“发送到终端”按钮。复选框按 `taskId + terminalId` 仅在前端运行期保存；缺失记录时默认勾选，关闭面板或切换终端后保持，终端关闭或退出、任务结束或删除、应用卸载时释放，应用重启后恢复默认。它不属于设置、任务或后端持久化状态。

两种操作共享同一份格式化文本。“复制到剪贴板”调用 Wails `ClipboardSetText`；“发送到终端”把该文本交给 `TerminalSessionRegistry.pasteInput(taskId, terminalId, text)`，以保持 xterm 对多行和 bracketed paste 的既有语义，并且不由 TaskAI 额外添加 Enter 或执行字符。任一操作结束后，已勾选时清空此会话的备注，未勾选时保留；复制或发送失败同样遵循当前勾选状态并显示错误。操作结束后关闭面板并恢复终端焦点。

没有选择后端 `WriteTerminal` 直写，因为原始多行控制字符可能被当前 Shell 或全屏程序当作逐行提交；模拟粘贴已是项目向终端注入多行文本的受测机制。

## Risks / Trade-offs

- [鼠标松开与 xterm 选区更新存在事件时序差异] → 在下一动画帧读取选区，并测试空选区、非空选区和取消行为。
- [小尺寸内容区使按钮超出可见区域] → 使用内容区尺寸限制相对坐标，并在窗口调整或选区失效时隐藏入口。
- [模板字段缺失与用户故意保存空字符串难以区分] → 存储层仅依据原始 JSON 是否缺少整个嵌套字段做迁移；正常保存后的空字段原样保留。
- [终端在面板打开期间关闭] → 发送方法失败时保留既有错误提示，不把内容写入其他会话，并按当前会话的清空偏好处理记录。
- [备注包含大量选区文本] → 记录只在运行期内保存且随终端释放；本变更不为记录数量或文本长度另设持久化容量承诺。

## Migration Plan

1. 发布时旧数据文件会在首次读取时补齐默认备注模板，已有其他设置保持不变。
2. 重新生成 Wails 前端绑定，使新增设置字段进入 TypeScript 模型。
3. 回滚时可忽略该设置字段；备注从未写入持久化数据，运行中记录随应用退出消失。
