## 为什么

用户在标题变化状态管理下独立启用本机 HTTP 服务时，服务已经可用，生命周期首条自定义命令的输入 JSON 也包含 `baseURL`，但之后新建的终端没有获得对应的 API 地址环境变量。HTTP 服务的实际可用性与终端环境变量的注入条件不一致，导致终端中的工具无法直接访问已启用的本机接口。

## 变更内容

- 将新建终端的 `TASKAI_STATUS_API` 注入条件改为本机 HTTP 服务正在监听，而不是仅限状态管理方式为 HTTP。
- 保持 `TASKAI_STATUS_API` 的现有变量名和值格式，不新增 `baseURL`、`BASE_URL` 或其他重复环境变量。
- 更新任务详情和 HTTP 帮助中的环境变量适用范围，明确独立 HTTP 服务与 HTTP 状态管理都会使后续新建终端获得该变量。
- 明确不改变生命周期自定义命令的首段标准输入 JSON、模板环境变量，或无终端菜单命令与前后置脚本的环境变量范围。

## 能力

### 新增能力

无。

### 修改能力

- `task-detail-command-context`: 将 `TASKAI_STATUS_API` 的终端注入条件从 HTTP 状态管理方式扩展为本机 HTTP 服务正在监听。

## 影响

- 后端终端环境构造与应用层回归测试。
- 设置页 HTTP 帮助、任务详情中的系统环境变量说明及相关前端测试。
- README 中的终端环境变量说明。
