## Context

TaskAI 使用 Wails、React 和 `@xterm/xterm` 渲染桌面终端。当前 xterm 会话在创建时固定使用 `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace`，设置模型只有颜色模式，没有终端字体字段。

字体列表不能由浏览器可靠枚举，且“等宽”不能只通过字体名称判断。不同平台需要读取系统字体元数据；中文终端字体还可能是英文单宽、中文双宽的组合，因此应把单宽和双宽字体都作为终端候选。字体选择只对之后创建的 xterm 会话生效，避免改变已有会话的网格和 PTY 尺寸。

## Goals / Non-Goals

**Goals:**

- 从 Windows、macOS 和 Linux 的系统字体来源发现适合终端的字体族，并去重、稳定排序。
- 在普通设置中保存字体族名称，兼容缺少该字段的既有设置文件。
- 在设置界面展示字体名称以及中文、英文和常见终端字符预览。
- 让新创建的 xterm 会话使用保存的字体；输出先于视图挂载时创建的会话也必须读取最新配置。
- 在字体已被系统移除或不可用时保留设置文件可加载，并回退到当前默认字体栈。

**Non-Goals:**

- 不改变已有 xterm 会话的字体，不触发已有终端的 PTY resize。
- 不支持上传、下载或打包字体文件，不引入远程字体资源。
- 不在本次变更中增加字号、行高、字重、连字或终端主题设置。
- 不把普通比例字体作为终端字体选项，即使它包含完整中文字符集。

## Decisions

### 1. 使用平台字体元数据发现候选

新增 `internal/fonts` 平台抽象，向 Wails 暴露只读的终端字体列表。Windows 使用 GDI 字体枚举及固定间距/Modern 家族信息；macOS 使用 CoreText 的等宽特征；Linux 使用 Fontconfig 的 spacing 信息。Linux 的 mono 和 dual spacing 都纳入候选，proportional 排除。返回值只包含字体族名称和 spacing 类别，不暴露字体文件路径。

备选方案是前端维护常见字体名称列表，或扫描字体文件并自行解析 OpenType 表。前者会漏掉用户安装的字体，后者需要跨平台字体目录、字体集合和字形指标解析，且构建依赖更复杂；平台原生元数据更符合“系统字体”语义。

### 2. 持久化字体族名称，空值代表默认回退栈

在 `settings.Settings` 和前端 `SettingsRecord` 增加 `terminalFontFamily` 字段。默认值为空字符串，渲染时解析为空值为当前默认字体栈；非空值保存系统返回的字体族名称，并在 xterm 的 CSS `fontFamily` 中追加默认等宽回退。

不把字体文件路径或平台内部 ID 写入设置，因为路径和 ID 可能随系统升级、用户迁移或字体重新安装变化。保存时不强制要求字体仍然存在；应用字体时若不可用，由 WebView 的字体回退机制处理。

### 3. 在会话创建路径解析字体，而不是只在视图挂载时设置

`TerminalSessionRegistry` 使用可读取最新设置的字体提供器，创建 `Terminal` 时将解析后的字体写入 `fontFamily`。`handleTerminalEvent` 可能在视图挂载前创建会话，因此不能只在 `TerminalView.attach` 中设置字体；否则早到的输出会创建一个使用旧默认值的会话。

备选方案是在每次设置保存后更新所有现有 xterm 的 `options.fontFamily`。虽然 xterm 支持运行时选项更新，但这会改变网格尺寸、需要保存每个会话的 resize 回调并通知 PTY，且与本次“新终端生效”的范围不符。

### 4. 使用自定义预览列表，而不是原生 select

设置界面使用可滚动的字体选项列表。每项显示系统字体族名称、spacing 标签和两行预览：中文示例与英文/终端字符示例。原生 `<select>` 无法稳定地让每个 option 使用自己的字体，也不适合同时展示预览。

预览只反映 WebView 的实际字体回退结果，不把中文预览是否由主字体绘制作为筛选条件；中文回退是正常情况。

### 5. 字体发现失败时保留可用默认选项

平台字体 API 不可用、Fontconfig 命令缺失或返回空列表时，接口返回一个代表当前默认字体栈的内置选项，并允许设置继续打开和保存。这样字体发现故障不会阻断任务和终端功能。

## Risks / Trade-offs

- [平台 API 行为不同] → 将字体发现放在独立的平台文件中，使用共享结果类型和表格驱动测试；每个平台至少覆盖去重、排序和空结果回退。
- [字体元数据可能不准确] → 只把元数据作为候选筛选，预览使用实际 WebView 渲染；允许 mono/dual 两类终端字体。
- [用户保存的字体后来被卸载] → 设置保存不因字体缺失失败，xterm 使用 CSS 回退栈；设置界面重新打开时显示默认选项或“当前字体不可用”状态。
- [系统字体族包含多个风格或本地化名称] → 以系统返回的 family name 去重并保存 family，而不是具体 style 或文件路径。
- [字体列表较大] → 设置打开时读取并在前端按名称排序，使用现有滚动区域；不在每次渲染中重新扫描系统字体。

## Migration Plan

1. 增加可选的 `terminalFontFamily` 设置字段，旧 JSON 缺失时归一化为空字符串。
2. 增加字体发现 Wails 接口和平台实现，先验证返回结果，再接入设置界面。
3. 接入新会话创建路径和字体预览，重新生成 Wails 前端绑定。
4. 运行相关 Go、前端测试和构建验证。

回滚时删除字体设置控件和字体发现接口即可；未知的 `terminalFontFamily` JSON 字段可被旧版本忽略，旧版本继续使用原有默认字体栈。

## Open Questions

- macOS 是否采用 CoreText 的 cgo 桥接，还是使用随系统提供的命令行字体信息；需要在目标 macOS 构建机上确认构建依赖和签名流程。
- 是否在字体选项中显示“中文由回退字体绘制”的提示，还是只保留预览结果。
