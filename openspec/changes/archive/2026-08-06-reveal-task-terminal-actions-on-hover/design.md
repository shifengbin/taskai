## Context

当前任务树在每个任务行中始终渲染展开、执行、结束、重试及任务操作按钮；终端子项和右侧终端标题栏也始终渲染关闭按钮。按钮位于 `TaskTree` 和 `TerminalView` 中，复用全局 `IconButton`，任务和终端的状态、禁用条件、点击处理及菜单定位均已稳定。

本变更只改变这些局部操作控件的视觉可见性。应用虽然以桌面窗口为主，但仍需支持键盘与无法悬停的输入设备；现有视觉规格也要求保留可见焦点与既有业务行为。

## Goals / Non-Goals

**Goals:**

- 减少未操作任务和终端时的按钮噪声，释放标题的视觉注意力。
- 在鼠标悬停、键盘焦点和任务菜单打开期间清楚展示对应操作。
- 保持按钮的占位尺寸，避免标题截断宽度和任务行高度随显隐变化。
- 保持触控设备、屏幕阅读器、禁用状态和既有点击行为可用。

**Non-Goals:**

- 不隐藏状态点、生命周期进度或错误提示、批量选择复选框。
- 不改变任务操作菜单内容、右键菜单、终端关闭确认、快捷键或任务/终端生命周期。
- 不将悬停显隐推广到顶栏、详情页、对话框或设置界面中的其他按钮。

## Decisions

### 以局部操作容器控制显隐

为任务行、终端子项和右侧终端标题栏增加各自的操作容器/样式钩子；仅其中的操作按钮参与显隐。状态点和错误/进度信息继续位于操作容器外并始终可见。

选择局部样式而不是修改 `IconButton` 的默认样式，因为该组件同时服务于顶栏、对话框和设置页，全局修改会意外隐藏不属于本需求的操作。

### 使用不改变布局的视觉隐藏方式

在支持悬停的环境中，操作容器默认使用透明度和指针事件控制；当所属任务行、终端子项或标题栏处于 `:hover`、`:focus-within` 或其任务操作菜单打开状态时恢复可见和可点击。按钮本身继续保留在 DOM 与布局中，不使用 `display: none`、条件卸载或宽度折叠。

透明度方案能避免标题、状态点和按钮位置跳动；`:focus-within` 让通过 Tab 到达的隐藏按钮先显示再接收操作。任务菜单打开期间保持触发任务的操作区域可见，避免菜单锚点失去视觉关联。

### 对无法悬停的设备保持按钮可见

仅在 `(hover: hover)` 能力成立时应用默认隐藏样式。触控或其他无悬停输入环境中保留当前始终可见的按钮，避免用户没有发现或触发操作的途径。

### 保持现有语义和处理函数

按钮的元素、`aria-label`、`title`、`disabled` 条件和事件处理函数不变。终端状态点、生命周期错误信息和批量选择复选框不归入操作容器，因此实时状态和错误仍会立即被看见。

## Risks / Trade-offs

- [透明按钮占用空间，标题可用宽度不会增加] → 保持固定布局能避免悬停时重排，满足稳定扫描和标题截断行为。
- [仅靠鼠标悬停会让键盘用户看不到操作] → 用 `:focus-within` 同步揭示操作，并保留现有焦点环与按钮语义。
- [触控设备不支持悬停] → 在无悬停媒体条件下禁用默认隐藏样式。
- [任务菜单通过 portal 渲染，鼠标移出任务行后可能失去触发器关联] → 菜单打开期间以任务菜单状态维持该任务的操作区域可见。
- [运行或失败生命周期任务的禁用规则可能被视觉样式遮蔽] → 只调整显示，不调整禁用条件；失败任务的重试入口仍在同一交互条件下显示。
