## Context

`TaskTree` 同时承载“任务操作”按钮和任务行右键菜单。两者当前使用同一个自绘菜单，但仅保存按钮下沿或鼠标位置，并以 `position: fixed` 直接放置菜单。菜单通过 portal 脱离任务列表的滚动裁切区域，却没有根据视口剩余空间翻转、平移或限制高度；任务较多时，列表底部任务的菜单会超出窗口。

本变更只影响前端展示。任务操作的可用性、执行回调和持久化均保持现有边界。

## Goals / Non-Goals

**Goals:**

- 让任务操作下拉菜单和右键菜单在任意任务列表滚动位置都可完整访问。
- 让两种触发方式共享同一套视口定位规则。
- 在菜单本身高于可用空间时保留全部菜单项的可访问性。
- 保持现有菜单项目、锁定校验、点击外部关闭和 Escape 关闭行为。

**Non-Goals:**

- 不重新设计任务菜单的外观或菜单项顺序。
- 不变更任务状态、生命周期命令、持久化数据或 Wails API。
- 不将所有应用浮层统一迁移到新的组件库或新增运行时依赖。

## Decisions

### 使用共享的已测量定位规则

菜单状态继续保存任务 ID 和触发来源。打开菜单后，先以不可见状态渲染菜单并取得菜单实际尺寸，再由一个共享计算过程生成最终位置和最大高度，避免按固定菜单高度猜测。

定位过程保留一小段视口安全边距，并按下列顺序选择位置：

1. 优先放在按钮下方或右键位置下方。
2. 下方空间不足且上方空间足够时，翻转到触发点上方。
3. 上下空间都不足时，选择可用空间较大的一侧，限制菜单最大高度并启用菜单内部纵向滚动。
4. 将左侧坐标限制在视口左右边界之间，防止靠近右侧的右键菜单被截断。

窗口尺寸变化或会改变按钮位置的滚动发生时，重新计算定位。菜单初次定位完成前保持不可见，避免先显示在错误位置再跳转。

这比为下拉菜单和右键菜单分别维护特例更小且更容易测试。项目现有的 Radix `DropdownMenu` 已提供碰撞避让，但它无法直接覆盖当前的右键触发流程；为此新增 Context Menu 组件并重构两种触发方式会扩大本次修复范围。

### 保持 portal 和菜单动作渲染不变

菜单继续挂载到 `document.body`，避免重新引入任务列表 `overflow` 带来的裁切。只替换定位样式与可用高度样式；菜单项过滤、图标、回调和关闭时机保持不变。

### 用可测试的纯计算覆盖边界情形

将位置选择提炼为输入触发矩形或鼠标坐标、菜单尺寸和视口尺寸即可验证的计算逻辑。`TaskTree` 测试覆盖按钮下拉和右键菜单分别在底边和右边触发的情形，并覆盖菜单项目数量超过单侧可用空间的内部滚动限制。

## Risks / Trade-offs

- [首次测量可能造成短暂闪烁] → 菜单在得到最终坐标前使用不可见状态。
- [菜单项目很多时无法同时展示所有项目] → 限制菜单最大高度，并让用户在菜单内部滚动到全部操作。
- [滚动或窗口大小变化使锚点位置改变] → 在相关事件发生后重新计算位置，仍无法定位时关闭菜单。
- [在本次范围内自行维护定位计算] → 将计算集中为单一逻辑并以边界测试固定其行为；后续若统一浮层组件，可再迁移到 Radix。
