## MODIFIED Requirements

### Requirement: 持久化并校验终端快捷键动作

系统 MUST 在应用设置中持久化终端快捷键动作数组。每项 MUST 包含稳定唯一标识、规范化组合键和有序动作步骤；每项 MAY 包含一个"生效程序"列表（include 语义），用于把该快捷键的作用范围收窄到由匹配启动命令创建的终端。步骤类型 MUST 支持非空文本和按键。按键步骤 MUST 保存规范化按键名称及修饰键，并表示发送对应的终端输入序列。系统 MUST 兼容读取旧的回车步骤并归一化为 `Enter` 按键。新安装不得预置自定义快捷键，缺少该字段的既有设置 MUST 作为空数组加载。

系统 MUST 对"生效程序"列表做归一化：去除每项首尾空白、丢弃空白项、按忽略大小写去重。缺失或空的"生效程序"列表 MUST 作为"在所有终端生效"加载。

系统 MUST 拒绝空组合键、空动作、空文本步骤、未知步骤类型、重复组合键，以及与当前平台快捷输入选择器组合键冲突的配置；保存失败时不得替换原有设置。

#### Scenario: 保存反斜杠后回车动作

- **WHEN** 用户保存组合键为 `Shift+Enter`、步骤依次为文本 `\\` 和按键 `Enter` 的终端快捷键动作
- **THEN** 系统重新打开应用后保留同一稳定标识、组合键和步骤顺序

#### Scenario: 保存含生效程序列表的快捷键

- **WHEN** 用户保存组合键为 `Shift+Enter`、步骤为文本 `\\` 与按键 `Enter`、生效程序列表为 `["codex", "vim"]` 的终端快捷键动作
- **THEN** 系统重新打开应用后保留同一稳定标识、组合键、步骤顺序，以及已去重去空白的生效程序列表

#### Scenario: 加载不含快捷键字段的既有设置

- **WHEN** 应用加载一个不含终端快捷键数组的既有数据文件
- **THEN** 系统正常加载其他设置，并提供空的自定义终端快捷键列表

#### Scenario: 加载不含生效程序字段的既有快捷键

- **WHEN** 应用加载一个其终端快捷键项不含生效程序列表的既有数据文件
- **THEN** 系统将该快捷键作为"在所有终端生效"加载，其余配置不变

#### Scenario: 拒绝重复或保留组合键

- **WHEN** 用户保存与已有自定义动作重复的组合键，或保存当前平台的快捷输入选择器组合键
- **THEN** 系统拒绝保存并说明组合键已被使用或保留，既有配置保持不变

### Requirement: 在设置中管理终端快捷键动作

系统 MUST 在设置对话框提供终端快捷键管理入口，展示每项的组合键和动作摘要，并支持新增、编辑和删除。编辑器 MUST 提供文本和按键两种动作类型；按键动作 MUST 通过一次实际按键记录按键名称及修饰键，并允许按顺序配置文本与按键步骤。编辑器 MUST 允许为每条快捷键从"可显示终端的程序"中选择"生效程序"列表项，并支持逐项新增与删除，且 MUST 向用户说明"留空表示在所有终端生效"。可显示终端的程序由当前 Shell 路径与标记为显示终端的任务菜单命令项的启动命令经归一化去重后组成；后台启动（不显示终端）的命令项 MUST NOT 出现在选择范围中。保存设置前的修改 MUST 仅存在于设置草稿；取消设置 MUST 放弃未保存的修改。

#### Scenario: 捕获并配置快捷键动作

- **WHEN** 用户在终端快捷键编辑器中添加文本 `\\` 步骤，并通过按键录入控件按下 `Enter` 后保存设置
- **THEN** 设置列表显示文本和 `Enter` 按键动作，并保持动作顺序

#### Scenario: 配置快捷键的生效程序

- **WHEN** 任务菜单中存在显示终端的命令项 `codex` 与 `vim`，用户在某条快捷键的"生效程序"列表中依次选择 `codex`、`vim` 后保存设置
- **THEN** 设置列表显示该快捷键的生效程序为 `codex`、`vim`

#### Scenario: 仅可显示终端的程序可供选择

- **WHEN** 任务菜单中存在显示终端的命令项 `codex` 与后台启动（不显示终端）的命令项 `cleanup`
- **THEN** "生效程序"选择范围包含 `codex` 而不包含 `cleanup`

#### Scenario: 取消未保存的快捷键编辑

- **WHEN** 用户新增或编辑终端快捷键动作后取消设置对话框
- **THEN** 系统不持久化该修改，重新打开设置时显示上次已保存的列表

### Requirement: 仅向当前聚焦终端执行快捷键动作

系统 MUST 仅在已聚焦的活动终端中匹配自定义终端快捷键。命中后，系统 MUST 进一步判定该终端是否处于该快捷键的生效范围内：当快捷键的"生效程序"列表为空时，视为对所有终端生效；当列表非空时，仅当该终端的启动命令与列表按既定规则匹配时才视为在生效范围内。命中且在生效范围内时，系统 MUST 阻止原组合键作为普通终端输入，并按保存顺序向同一终端会话直接写入每个步骤；系统 MUST NOT 使用模拟粘贴、追加未配置的字符或将步骤写入其他终端。命中但不在生效范围内时，系统 MUST 不拦截该按键、不写入任何步骤，保持 xterm 原有键盘行为（原始按键透传给终端）。未命中时，xterm 原有键盘行为 MUST 保持不变。

现有 `Ctrl+Shift+P`（macOS 为 `Command+Shift+P`）快捷输入选择器 MUST 继续优先打开选择器，且不得执行同名自定义动作。设置对话框、文本输入框和未聚焦终端 MUST 不触发终端快捷键动作。

#### Scenario: 在活动终端发送反斜杠和回车

- **WHEN** 当前活动终端获得焦点、处于快捷键生效范围内，且用户按下已配置的 `Shift+Enter`
- **THEN** 系统仅向该终端依次写入 `\\` 和 `Enter` 对应的终端序列，且不把原始 `Shift+Enter` 或额外字符写入 PTY

#### Scenario: 生效范围外的终端透传原始按键

- **WHEN** 一条 `Shift+Enter` 快捷键配置了生效程序列表 `["powershell"]`，当前聚焦终端由任务菜单命令 `codex` 创建（启动命令为 `codex`），用户按下 `Shift+Enter`
- **THEN** 系统不拦截该按键、不写入任何步骤，原始 `Shift+Enter` 透传给该终端

#### Scenario: 生效范围内的终端执行动作

- **WHEN** 一条 `Shift+Enter` 快捷键配置了生效程序列表 `["powershell"]`，当前聚焦终端为普通 PowerShell 终端（启动命令为 `powershell.exe`），用户按下 `Shift+Enter`
- **THEN** 系统仅向该终端依次写入 `\\` 和 `Enter` 对应的终端序列，且不把原始 `Shift+Enter` 或额外字符写入 PTY

#### Scenario: 空生效列表对所有终端生效

- **WHEN** 一条 `Shift+Enter` 快捷键未配置生效程序列表，当前聚焦终端由任意命令创建，用户按下 `Shift+Enter`
- **THEN** 系统向该终端依次写入已配置的步骤序列，行为与未引入生效范围前一致

#### Scenario: 在设置输入框中按下相同组合键

- **WHEN** 用户在设置或快捷键编辑器的文本输入框中按下已配置的 `Shift+Enter`
- **THEN** 系统不向任何终端发送动作，并保留该表单控件的原有键盘行为

#### Scenario: 动作目标终端已关闭

- **WHEN** 用户按下已配置的组合键时对应终端会话已经关闭或在发送过程中关闭
- **THEN** 系统停止发送剩余步骤、报告该终端不可用，且不得将任何步骤写入其他终端

## ADDED Requirements

### Requirement: 按启动命令判定终端所属程序

系统 MUST 以 TaskAI 创建终端时使用的启动命令作为该终端的"所属程序"，用于快捷键生效范围的匹配。该启动命令来源于任务菜单命令项与生命周期命令链创建的命令终端；系统 MUST NOT 跟踪用户在终端 shell 内手动运行的子程序——这类终端按其自身的启动命令（通常为 shell）判定。

匹配 MUST 按以下归一化与比较规则：分别取启动命令与生效程序列表每一项的文件名部分（去除目录），去除 Windows 可执行文件扩展名（`.exe`、`.com`），并转换为忽略大小写的形式；当启动命令归一化后的名称与列表中任一归一化后的项完全相等时，视为匹配（列表中任一命中即生效）。当终端缺少启动命令信息时，视为不匹配任何非空生效列表，但不影响"空列表表示全部生效"的判定。

#### Scenario: 菜单命令创建的终端按命令名匹配

- **WHEN** 一条快捷键的生效程序列表包含 `codex`，用户通过任务菜单命令 `codex` 创建的终端获得焦点
- **THEN** 该终端的所属程序归一化为 `codex`，判定为匹配，快捷键在该终端生效范围内

#### Scenario: 启动命令的路径与扩展名被归一化

- **WHEN** 一条快捷键的生效程序列表包含 `codex`，终端启动命令为 `C:\tools\codex.exe`
- **THEN** 归一化后启动命令为 `codex`，判定为匹配，快捷键在该终端生效范围内

#### Scenario: 不同程序名不相互匹配

- **WHEN** 一条快捷键的生效程序列表为 `["codex"]`，终端启动命令为 `pwsh.exe`
- **THEN** 归一化后启动命令为 `pwsh`，与 `codex` 不相等，判定为不匹配，快捷键在该终端生效范围外

#### Scenario: 在 shell 内手动运行程序不影响判定

- **WHEN** 一个由普通 shell（启动命令为 `powershell.exe`）创建的终端中，用户手动运行 `codex`
- **THEN** 该终端的所属程序仍判定为 `powershell`，不受手动运行的子程序影响

#### Scenario: 缺少启动命令的终端不匹配非空列表

- **WHEN** 一条快捷键的生效程序列表为 `["codex"]`，某终端的启动命令信息缺失（如由不带该信息的旧版本创建）
- **THEN** 该终端不匹配该生效列表，快捷键在该终端按生效范围外规则透传原始按键
