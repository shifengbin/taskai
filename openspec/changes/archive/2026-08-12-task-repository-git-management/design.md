## Context

任务开始后保存 `Task.WorkspacePath`。现有生命周期使用受控 Git 执行器克隆仓库，但没有供任务详情读取状态或提交、发布、同步的接口。本变更在任务工作目录中支持多个普通仓库和 Git worktree，且不接受来自前端的任意目录、子命令或参数。

## Goals / Non-Goals

**Goals:**

- 为任务工作目录内的每个仓库独立读取状态并执行受控操作。
- 以 Git 真实状态驱动“提交”“发布分支”“同步远程”单按钮。
- 将文件系统与 Git 操作限制在任务保存的工作目录内。

**Non-Goals:**

- 不提供历史、差异、暂存区选择、分支切换、合并、变基、冲突解决或远程管理界面。
- 不开放任意 Git 命令、远程名称或文件路径。
- 不改变生命周期 Git 克隆流程或持久化 Git 状态。

## Decisions

### 受限服务和绑定

新增 `internal/repositorygit` 服务；Wails 仅暴露列出、提交、发布和同步方法。仓库以相对任务工作目录的路径标识，所有操作重新校验任务目录、真实路径和 Git 顶层目录。前端不能调用通用任务命令执行接口。

### 发现和状态

递归遍历任务工作目录，跳过 `.git` 和符号链接目录，以 `git rev-parse --show-toplevel` 验证并以规范化顶层路径去重，覆盖普通仓库、嵌套仓库和 worktree。遍历深度读取持久化的 Git 最大扫描深度设置，默认值为 2：任务工作目录本身为第 1 层、直属子目录为第 2 层；服务在达到上限的目录仍检查其是否为仓库，但不再进入子目录。设置限制为 1–10，并将旧设置中缺失的值归一为默认值。状态优先级为：有改动时提交；工作区干净且远端无同名分支时发布；其他有分支情形同步。无远程、多远程无 `origin` 或 detached HEAD 均以卡片提示说明。

### 固定操作序列

提交固定为 `git add -A`、`git commit -m`。发布固定为 `git push -u <remote> <branch>`。同步先确认干净，必要时获取并建立同名上游，再执行 `git pull`、`git push`；拉取失败时不得推送。远程选择为 `origin` 优先，否则唯一远程；其他情形提示配置。

### 前端隔离

任务详情以“项目信息”和“Git”标签组织。每张仓库卡片保存独立的提交信息、进行中状态、错误和刷新结果；一个仓库的操作不会覆盖其他卡片。

## Risks / Trade-offs

- [大目录扫描耗时] → 跳过 Git 元数据和符号链接，仅在 Git 标签挂载时读取，并限制为用户设置的最大目录层级。
- [认证、网络或冲突失败] → 展示 Git 标准错误，失败后只刷新对应仓库。
- [目录被替换或移出任务区] → 每次操作重新校验真实路径边界。
- [远程暂时不可达] → 在该仓库卡片显示状态提示，不影响其他仓库列出。
