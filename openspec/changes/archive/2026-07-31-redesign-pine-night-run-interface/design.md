## 背景

TaskAI 是基于 React、MUI 与 xterm 的桌面任务工作台。当前主题入口位于 `createAppTheme`，但大量界面由内联 `sx` 控制，终端另有硬编码色值；因此仅替换主色无法让任务树、详情、弹窗、设置页和终端形成完整主题。现有设置已保存 `colorScheme`，可作为亮色与暗色的唯一模式来源。

本次只重构视觉呈现。用户选择的“松林夜跑”不是装饰性皮肤：它要把任务执行的推进感编码为清晰的层级、路线和状态反馈，同时保证密集工作界面的信息优先级。

## 目标 / 非目标

**目标：**

- 以统一的语义令牌覆盖应用外壳、任务树、详情、终端、所有既有弹窗、菜单、提示与空状态。
- 在既有亮色和暗色模式下提供可感知不同、文本高对比的松林夜跑界面。
- 让选中、执行、完成、异常、拖拽、悬停、焦点、禁用和危险操作具有一致且可辨认的视觉反馈。
- 在不增加依赖的前提下使用 CSS、MUI 主题覆盖和现有 MUI 图标实现材质、图标容器与动效。
- 保留减少动态效果偏好、键盘焦点与现有 ARIA 标签。

**非目标：**

- 不修改任务、终端、生命周期、额外信息、设置和退出流程的业务规则或数据模型。
- 不新增设置项、服务端接口、图片资源、外部字体请求或第三方依赖。
- 不重排现有操作路径、变更控件语义、删除功能或把视觉预览页耦合进应用。

## 决策

### 1. 用语义令牌驱动 MUI 与 CSS，而不是逐页硬编码

亮色令牌为：画布 `#edf3ed`、主表面 `#fbfffb`、侧栏 `#d7e5d9`、详情表面 `#ffffff`、正文 `#10291e`、辅助文字 `#3d604d`、分隔线 `#20533d`、结构绿 `#176b4b`、操作橘 `#ff8a3d`、赛道荧光绿 `#b6e338`。暗色令牌为：画布 `#07130e`、主表面 `#0e2118`、侧栏 `#173a28`、详情表面 `#0a1911`、正文 `#edfff4`、辅助文字 `#afcfbd`、分隔线 `#d5f5e0`、结构绿 `#6cd39a`、操作橘 `#ffad6c`、赛道荧光绿 `#d5ff5f`。

`createAppTheme` 将定义两套完整 palette、文本、action、背景、分割线、状态色、圆角、组件默认值和 `contrastText`。`App.css` 定义同名 CSS 变量、背景层、焦点环、条纹和统一动效；局部 `sx` 仅引用语义色，不再散落使用无关的固定十六进制色。

备选方案是只覆盖 MUI 的 `primary` 与 `background`。不采用该方案，因为 xterm、任务行颜色、弹窗装饰与现有显式 `sx` 会继续保留旧视觉，无法达到“全部界面”一致性。

### 2. 保留工作台信息架构，以“跑道”处理层级而非重新布局

顶栏是低矮的夜跑起跑带，包含鞋盒式图标底座、标题和工具按钮；任务树仍在左侧，状态标签仍在顶部，详情或终端仍在右侧，尺寸拖拽保持原样。斜向反光条纹只出现于顶栏、选中区、对话框标题和局部状态带，避免影响文字阅读。硬边圆角、深色外框与小面积橘色投影提供鞋盒结构感；大面积留白仍服务于任务正文与终端内容。

任务颜色继续表示用户的任务颜色，不会被主题色覆盖。主题只为选中、动作、状态和容器提供基底。

备选方案是重构为卡片式多栏仪表盘。未采用，因为它会改变任务树拖拽、终端选择和详情浏览的既有空间记忆，超出纯视觉改造范围。

### 3. 让所有覆盖层使用同一套“夜跑补给站”语言

任务编辑、额外信息管理/编辑、模板编辑、设置、状态帮助、菜单项编辑、结束确认和退出确认均使用同一个对话框外壳：深色轮廓、斜纹标题带、结构化内容区与清晰的操作栏。菜单、Popover、Snackbar、Alert、Accordion、Chip、Tab、TextField、Checkbox 与 Switch 通过 MUI 组件覆盖同步获得边框、焦点、密度和状态色。

这能以主题覆盖处理绝大多数弹窗，个别显式 `sx` 只补充布局，不改变任何打开、关闭、提交或校验逻辑。

### 4. 终端按当前颜色模式适配，但不改变终端行为

`TerminalView` 从现有 MUI 主题读取颜色，配置 xterm 的背景、前景、光标、选择区和滚动条邻接容器。无论工作台处于亮色或暗色模式，终端均保持深色表面以保证命令输出可读；暗色模式使用更深的夜林底色。终端标题栏不额外放置会与标题或终端图标竞争空间的装饰。主题切换只更新 xterm 的视觉 options；终端实例、输入输出、尺寸计算、剪贴板、焦点和生命周期处理保持不变。

### 5. 动效用于状态确认，并可被完全关闭

启动屏使用一次性的路线入场；任务执行状态沿用脉冲并使用主题色；任务开始、拖拽落点、按钮悬停和弹窗进场使用 120–350ms 的透明度、描边或轻微位移动画。不得使用持续的大幅背景动画或改变布局尺寸的动画。所有新增动画均置于 `prefers-reduced-motion: reduce` 规则之下，并在该偏好下立即稳定。

### 6. 把可读性作为视觉令牌的验收条件

正文、辅助正文、按钮文字、状态标签和表单文字与各自背景的对比度必须至少为 4.5:1；仅无语义的装饰条纹可以使用更低对比。焦点环必须在亮暗两种模式与任务自定义颜色之上均可见。危险操作继续使用语义错误色和文字标签，而不只依赖颜色。

本次令牌计算结果为：亮色正文/主表面 `15.32:1`、亮色辅助文字/详情表面 `7.05:1`、亮色主操作 `6.42:1`、亮色橘色操作 `6.59:1`；暗色正文/主表面 `16.18:1`、暗色辅助文字/详情表面 `10.76:1`、暗色主操作 `10.30:1`、暗色橘色操作 `10.33:1`。所检查的主要组合最低为亮色错误操作的 `5.81:1`。

### 7. 长任务表单在弹窗内滚动，提交操作保持可达

新建和编辑任务共用的对话框采用受限高度的纵向 Flex 布局：标题和操作栏不参与压缩，表单内容区作为唯一的纵向滚动容器。对话框在视口高度内滚动内容而非扩张页面，因此模板字段、额外信息和生命周期命令链增加时，取消与创建/保存操作始终留在可操作区域。

该方案只调整弹窗的显示层级和溢出行为，不改变字段顺序、表单提交、校验、关闭或任务创建逻辑。

### 8. 选中任务不用斜纹尾标表示状态

任务行的自定义颜色左边框、选中背景和内描边已能明确传达选中状态，因此移除右上角黄绿斜纹尾标。该装饰容易被误认为只属于新创建任务的状态，且与任务颜色和拖拽插入提示产生视觉竞争。拖拽时的全宽插入指示器仍保留，因为它具有明确的排序语义。

## 风险 / 权衡

- [MUI 局部 `sx` 的优先级可能遮蔽主题覆盖] → 在实施时检索固定色值并逐项替换；通过亮暗模式逐屏验收。
- [高饱和荧光色可能抢占正文注意力] → 荧光绿只用于细条纹、焦点与状态提示，正文容器使用低饱和松林表面。
- [xterm 使用独立的主题 API] → 将其颜色集中为视觉映射并在模式变化时更新 options，不触碰终端数据或事件。
- [动效可能影响高密度任务操作] → 动效只表达一次性结果，支持减少动态效果并保留静态状态边框。
- [工作区已有未提交的 `App.tsx` 与测试改动] → 实施前先确认其来源；仅在视觉范围内叠加修改，避免覆盖既有工作。

## 迁移计划

1. 在前端样式层建立亮暗令牌和 MUI 组件覆盖。
2. 按工作台、任务树、详情/终端、覆盖层的顺序应用视觉样式，并保持事件处理器和 props 不变。
3. 分别验证亮色、暗色、空状态、选中任务、运行终端、拖拽、错误提示和每类弹窗。
4. 运行前端测试及项目规定的 `scripts/build-linux.sh`；若发现回归，回退本变更涉及的视觉文件即可，不需要数据迁移。

## 开放问题

- 无。沿用现有设置中的亮色/暗色切换，不增加第三种主题模式。
