# 修复 cmd 拖放路径转义在 Windows 26200 构建上的回归

## 为什么

`internal/terminal/file_paths.go` 的 cmd 分支沿用"引号内 caret 转义"策略（`&`→`^&`、`%`→`^%` 等）。在 Windows 10.0.26200.9168 构建上，cmd.exe 不再处理双引号内的 caret 转义——caret 一律字面保留。结果：向 cmd 终端拖放任何含 `& | < > ^ % !` 的路径时，写入终端的是带字面 caret 的错误文本（例如路径 `a&b.txt` 变成 `a^&b.txt`），cmd 解析后参数与原路径不一致，且旧策略试图达成的 `%VAR%` 防展开也一并失效。这直接违反 terminal-file-drop 规格中"cmd.exe 接收包含元字符的路径"场景。

真实 ConPTY cmd 会话探针（5 轮，见 design.md 证据矩阵）在本构建上确认：

1. 引号内 caret 转义全部字面残留（当前实现的输出即错误结果）；
2. 引号内 `& | < > ^ !` 与空格**裸放即字面安全**，`for %~A` 与外部 .exe 接收方（CRT argv）均完美还原原路径；
3. 引号内单个不成对 `%`（如 `50%.txt`）保持字面；
4. 成对 `%VAR%` 在引号内仍会展开，且 `%""` 打断、`%%` 加倍、引号外 `^%` 混合分段三种候选方案分别存在 CRT 引号泄漏、先折叠再展开、相位交互不可预测的问题——没有一种构造既防展开又保持 argv 干净。

## 什么变化

- `quoteDroppedFilePath` 的 cmd 分支：移除全部 caret 转义，改为"整体加双引号、内容原样"；继续拒绝包含双引号的路径。
- 成对 `%VAR%` 的展开定为 cmd.exe 已知限制，与 Windows Terminal 拖放行为一致（WT 同样不保护 `%`），在规格中明确记录。
- 更新 `file_paths_test.go` 表驱动期望与 `file_paths_windows_test.go` 的 cmd 解析集成断言（测试路径改用单个 `%` 避免踩入已知限制；断言改为子串匹配以容忍 `/Q` 模式下输出与提示符同行）。

## 影响

- 仅影响 Windows cmd 终端的拖放路径格式化；POSIX/fish/PowerShell 分支不变。
- 含成对 `%` 且恰好匹配已定义变量名的路径在按下回车时仍会被 cmd 展开（接受，与生态一致）；单个 `%` 或未定义变量名不受影响。
