## Context

当前结束任务确认弹窗固定声明会删除任务工作目录，并以“结束并删除”作为确认按钮。实际的目录删除由任务配置的 `postEnd` 命令链决定；任务可以不配置该链，或者配置不包含删除目录命令的链。前端的确认处理只调用既有结束任务接口，接口随后按生命周期规则关闭终端、更新任务状态并调度命令链。

## Goals / Non-Goals

**Goals:**

- 让结束任务确认弹窗准确区分任务结束和可配置的结束后清理。
- 将确认按钮表述为结束任务，而非删除目录。
- 用前端测试固定新的文字和确认行为。

**Non-Goals:**

- 不变更 `beforeEnd`、`postEnd` 的执行顺序、失败处理或任务状态转换。
- 不变更内置删除任务工作目录命令、命令链配置或工作目录安全校验。
- 不根据每个任务的链配置动态生成不同的确认弹窗。

## Decisions

### 使用统一的条件式说明

确认说明将表达结束任务和关闭终端，并说明结束后命令链按该任务配置执行；它不再承诺删除工作目录。统一文案不需要在打开弹窗时解析链内容，也不会把“链存在但不删除目录”“未选择链”和“删除链失败”等不同情形误归纳为确定删除。

替代方案是在弹窗中分析当前任务的 `postEnd` 链，仅在包含删除目录命令时提示删除。该方案增加前端对链定义的依赖，并且链可在确认前后变化；本次只需纠正固定的错误承诺，因此不采用。

### 保留现有确认机制和危险操作样式

弹窗标题保持“结束任务？”，确认操作改为“结束任务”，继续调用现有 `confirmFinishTask`。任务结束仍不可撤销，因此确认按钮继续使用现有危险操作样式；只修正文字，不改变状态、终端或错误处理。

替代方案是移除确认弹窗或改为普通样式。这会扩大交互变更范围，且不能解决用户在确认前理解生命周期清理责任的问题，因此不采用。

### 用组件测试覆盖文案和确认调用

现有结束任务测试将改为点击新的确认按钮，并断言描述包含结束后命令链的条件式说明且不再出现删除工作目录表述。测试继续保证取消前不调用接口、确认后只调用既有结束任务接口并释放终端会话。

## Risks / Trade-offs

- [用户期待弹窗列出实际会执行的具体链] → 本次明确只说明职责边界；具体链仍在任务配置和进度界面中查看。
- [结束前命令链失败导致任务未结束] → 不改变既有错误反馈和状态保护；文案不承诺绕过 `beforeEnd` 失败。
- [文案修改后误改变交互行为] → 保留既有确认处理和测试中的接口调用断言。

## Migration Plan

前端发布后立即使用新文案，不涉及数据迁移、接口兼容或回滚步骤。若需回滚，仅恢复弹窗文字和对应测试；生命周期实现不受本变更影响。
