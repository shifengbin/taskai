## Context

TaskAI 的 xterm 会话当前在创建时固定使用 13px 字号。前一个终端字体选择变更解决了字体族问题，但字体族在不同显示器和 WebView 上仍可能显得过小。终端内容区使用 `FitAddon` 计算网格，并把行列尺寸发送到 PTY；改变字号本质上也是一次终端尺寸变化，不能只用 CSS 视觉缩放替代。

用户已确认字号是全局持久化设置，并需要在设置页中知道精确的放大程度。

## Goals / Non-Goals

**Goals:**

- 提供 10px 至 24px 的全局终端字号，默认 13px。
- 在设置页用滑块、像素值、相对比例和实时预览，让用户能准确理解选中的大小。
- 保存后让所有现有会话使用新字号；当前可见终端立即重新 fit 并同步 PTY 尺寸，后台终端在下次显示时按新字号 fit。
- 让之后创建、或在视图挂载前先收到输出的终端同样使用已保存字号。
- 兼容没有字号字段的旧设置，并归一化不合法值。

**Non-Goals:**

- 不缩放任务树、对话框、菜单或整个应用界面。
- 不增加每个终端独立字号、快捷键缩放、鼠标滚轮缩放或自定义字号范围。
- 不改变字体族、行高、字重、连字或终端主题的设置范围。
- 不通过 CSS `transform` 缩放终端内容，也不试图让未挂载的后台终端按不可测量的容器尺寸 resize PTY。

## Decisions

### 1. 以 `terminalFontSize` 像素值持久化，比例仅用于显示

在 Go `settings.Settings` 和前端 `SettingsRecord` 中增加数值字段 `terminalFontSize`。默认值为 13，校验时将值限制在 10 至 24 的闭区间；旧 JSON 缺少字段时按 13 处理。

设置页显示 `16 px（123%）` 这样的值，其中百分比按 `round(fontSize / 13 * 100)` 得出。存储像素值能直接对应 xterm 的 `fontSize` API，并在未来调整默认字号时避免保存“第几级放大”这类含糊语义。

备选方案是在配置中存放百分比或放大级别。前者需要额外的基准换算，后者难以让用户准确知道实际显示大小，因此不采用。

### 2. 使用受控滑块编辑设置草稿，保存后才影响终端

在现有终端字体设置区域增加“终端字号”字段，使用 10 至 24、步长 1 的范围滑块。滑块旁固定显示像素与比例，并提供恢复默认 13px 的图标按钮；下方的字体预览读取草稿字号即时更新。

滑动时只更新 `settingsDraft`，不修改活动 xterm。用户点击保存后才持久化并应用字号；取消或关闭设置会丢弃草稿，因此不会造成终端网格和 PTY 尺寸的意外变化。

备选方案是滑动时立即更新全部终端。它可以更快看到主终端效果，但取消无法恢复之前的网格和 PTY 尺寸，且连续滑动会产生大量 resize，因此不采用。

### 3. 更新所有会话的 xterm 选项，由可见视图负责即时 fit

`TerminalSessionRegistry` 接收最新已保存字号的读取器，并在创建 `Terminal` 时将其设置为 `fontSize`。它还提供批量更新已有会话字号的操作，直接修改每个 `Terminal.options.fontSize`，不销毁会话或滚屏内容。

保存字号后，App 更新读取器和所有已有会话。当前 `TerminalView` 通过字号变化触发 `fitAndRefresh`，使用现有 `onResize` 回调将新列数和行数发送给 PTY。未显示的会话虽然立即持有新字号，但没有有效容器尺寸；它们在下次 attach 时使用新的字号执行既有 fit 流程。

备选方案是只让之后创建的终端使用新字号。这会与用户选择的全局放大目标不符；另一种 CSS 缩放不会改变 xterm 字符度量，会导致内容模糊或裁切且 PTY 网格失真，因此不采用。

### 4. 字体族与字号保持独立

`terminalFontFamily` 继续表示字体族，`terminalFontSize` 只表示字号。设置中的预览同时应用两者，但分别保存和校验。这样已保存但不可用的字体仍可回退到 CSS 等宽字体栈，字号设置不受影响。

## Risks / Trade-offs

- [保存字号会改变当前终端网格] → 设置页明确说明保存后当前终端会重新适配；复用现有 PTY resize 链路并保留会话和滚屏。
- [后台终端没有可测量容器] → 只更新其 xterm 字号，待下次挂载到可见容器时再 fit 和 resize。
- [字号设置错误影响可读性] → 限制在 10px 至 24px，显示精确数值与比例，并提供恢复默认操作。
- [用户取消设置后期待终端保持不变] → 草稿阶段只更新设置预览，保存前不更新 xterm 或 PTY。

## Migration Plan

1. 增加带默认值和范围校验的 `terminalFontSize`；旧设置文件按 13px 加载。
2. 先接入设置草稿、滑块、比例和预览，再接入会话创建与已存在会话更新。
3. 通过前端会话测试验证保存、取消、当前终端 resize、后台终端延迟适配和新会话字号。
4. 回滚时移除控制和会话更新逻辑；旧版本会忽略新增 JSON 字段并继续使用原固定字号。

## Open Questions

无。未来若需要快捷键或每终端临时缩放，应作为独立变更设计，避免与全局设置混合。
