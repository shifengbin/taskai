## Context

TaskAI 通过前端的 xterm.js 渲染 PTY 输出。当前 `terminalVisualTheme(mode)` 以工作台 `colorScheme` 构造整套 xterm 主题：亮色模式使用浅背景和深前景，暗色模式使用深背景和浅前景。用户无法独立设置终端，而且将深色背景单独固定在亮色模式下会导致当前亮色前景不可读。

终端字体和字号已经保存在普通设置中。字号在保存后更新已有会话，字体只在创建 xterm 会话时读取，因此已有终端不会采用已保存的新字体。终端会话注册表集中管理 xterm 实例，终端视图负责在可见容器中挂载和适配网格。

## Goals / Non-Goals

**Goals:**

- 为 xterm 主题的全部当前使用颜色提供持久化、可视化配置和一致的暗色默认值。
- 让终端配色完全独立于工作台亮色和暗色模式。
- 保持设置草稿可取消；仅点击保存后才更新真实终端。
- 在保存后让已有会话立即采用主题、字体和字号；对可见终端重新适配网格并同步 PTY 尺寸，不丢失滚屏或输入状态。

**Non-Goals:**

- 不改变系统终端、Shell、PTY 输出内容或 ANSI 转义序列的语义。
- 不提供主题导入导出、命名主题集合、按任务单独配置或手工输入颜色值。
- 不自动修改用户选定颜色以强制满足对比度；默认主题与设置页预览用于提供可读的起点和反馈。

## Decisions

### 使用强类型的完整终端主题设置

在普通设置中增加 `terminalTheme`，包含 xterm 当前使用的 22 个颜色：背景、前景、光标、光标反差色、选区背景、选区前景、常规 ANSI 八色和高亮 ANSI 八色。颜色使用由选择器生成的规范十六进制格式；选区背景保留透明度信息。

默认对象逐项使用当前暗色终端值，而不是根据 `colorScheme` 计算。后端归一化将缺失或无效的单项恢复为相应默认值，确保旧设置、部分旧设置和损坏的持久化值都能继续加载。

相比把原始 CSS 颜色字符串或整个 xterm JSON 对象直接保存，这个结构能在 Go、Wails 绑定和 React 中保持明确契约，也能安全执行逐项迁移。

### 终端主题由保存设置单独解析

将终端主题解析改为从 `terminalTheme` 生成 xterm `ITheme`，不再接收工作台 `colorScheme`。`TerminalView` 从已保存设置取得主题，工作台亮暗模式切换不会改变其 xterm 选项。

这样默认终端在亮色和暗色工作台中都维持当前暗色终端的可读前景、光标和 ANSI 调色板。用户选择背景或其他颜色时，xterm 仅使用已保存的新主题，不改变任务树、详情或设置对话框的工作台配色。

### 设置页只提供可视化颜色选择

“工作区与外观”中的终端外观区域保留字体和字号控件，并新增可折叠的终端配色区域。基础颜色、常规 ANSI 和高亮 ANSI 分组为可访问的色块选择控件，不展示或允许编辑十六进制文本。选区背景在颜色选择外提供透明度滑块；设置页终端预览使用草稿显示颜色、字体和字号。

恢复默认配色将草稿中的整套 `terminalTheme` 置为暗色默认对象。编辑草稿、预览、重置和关闭折叠区都不得修改正在运行的 xterm；保存或取消继续使用既有设置对话框的提交语义。

### 保存后以一次会话更新应用终端外观

保存设置成功后，应用以保存后的主题、字体和字号更新会话注册表中的全部 xterm 实例。主题更新会刷新可见行；字体和字号更新会触发当前可见终端的重新适配和 PTY 尺寸同步。没有内容容器的后台会话保存新选项，并在下次显示时适配。更新不得重新创建会话、回放输出或清空输入。

将字体、字号和主题合并为同一保存后更新路径，避免字体继续保留“仅新终端生效”的例外，也避免用户在一次保存中看到部分终端外观更新。

## Risks / Trade-offs

- [用户可选择低对比度配色] → 不暗中覆盖用户设置；默认主题和草稿预览提供安全起点，恢复默认可立即回到可读配色。
- [浏览器原生颜色选择器不包含透明度] → 仅选区背景另设透明度滑块，其他当前主题色保持不透明，满足现有 xterm 默认主题的需要。
- [字体变更会改变字符宽度] → 对可见终端重新适配并同步 PTY；后台会话延迟到下次显示适配。
- [旧视觉规格要求终端跟随亮暗模式] → 在本变更中完整修改该需求，避免归档后规格与实现冲突。

## Migration Plan

1. 发布时，设置加载流程为缺少 `terminalTheme` 的既有数据写入当前暗色默认主题；字体和字号仍沿用已有归一化规则。
2. 生成 Wails 前端绑定，使设置请求和返回值携带完整主题。
3. 回退到不支持该字段的旧版本时，旧版本忽略该字段并继续使用其原终端主题；若旧版本随后保存设置，新的主题字段可能被覆盖，属于回退时的可接受配置损失。
