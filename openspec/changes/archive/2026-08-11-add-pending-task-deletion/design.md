## Context

现有批量删除功能仅在“已完成”标签可用。前端状态、`TaskTree` 属性、确认文案和 `DeleteCompletedTasks` 调用都以已完成任务为前提；后端服务也只接受 `completed` 且没有 `LifecycleExecution` 的任务。未执行任务通常不存在工作目录，但开始前命令链失败时可能已有工作目录或失败记录，删除不能绕过这些受控操作。

本次变更横跨 React 任务树、应用绑定、生命周期服务、Wails 生成绑定和行为规格。任务持久化数据是唯一事实来源；删除资格必须以后端在提交前重新读取的数据为准。

## Goals / Non-Goals

**Goals:**

- 在“未执行”和“已完成”标签提供一致的显式批量选择、全选、确认和记录删除体验。
- 仅删除状态为 `pending` 或 `completed`、且没有生命周期执行记录的任务，并保持全量校验与单次持久化。
- 删除成功后清理前端对已删任务的所有瞬时引用。
- 无论任务是否已有工作目录，都保持记录删除与文件、生命周期操作严格分离。

**Non-Goals:**

- 不支持删除执行中任务、跨标签混合选择、撤销、回收站或批量编辑。
- 不删除、移动、检查或创建任务工作目录。
- 不取消、重试、补偿或改变生命周期命令链的调度和失败语义。

## Decisions

### 1. 将选择模式扩展为两个独立的可删除标签

`App` 将现有仅限已完成任务的选择状态泛化为任务删除选择状态。用户只可在当前为“未执行”或“已完成”时进入；选择集合仅包含当前标签中符合资格的任务。切换标签、取消或删除成功后，均退出模式并清空集合。

`TaskTree` 在选择模式中复用现有复选框和禁用交互：带生命周期执行记录的任务不可选，任务菜单、拖拽和详情选择保持关闭。侧栏工具栏显示已选数量、全选可删除任务、删除和取消。不会永久显示复选框，也不会将删除放入单项任务菜单，以避免干扰正常浏览或造成误删。

替代方案是在任务操作菜单提供单项删除，或允许多个状态混合选择。前者与现有高效清理交互不一致，后者扩大状态管理和误操作范围；因此不采用。

### 2. 后端以通用批量删除契约维持原子性

将应用层、生命周期服务和前端 API 中的删除方法改名为 `DeleteTasks`，使名称不再错误暗示只能删除已完成任务。调用路径继续在应用层按稳定顺序取得任务生命周期锁；服务在同一临界区加载任务、拒绝空集合、重复 ID、缺失 ID、`running` 状态和任何 `LifecycleExecution`，所有目标通过后才一次性保存剩余任务并返回完整列表。

可删除状态明确为 `pending` 或 `completed`。前端的可选判断仅用于呈现，不能替代服务端校验；确认时任务已被开始或进入命令链的请求必须整体失败，并保留全部记录。

替代方案是继续保留 `DeleteCompletedTasks` 名称并扩大其行为，或让前端逐项删除。前者会使绑定契约与行为不符，后者会产生部分删除；因此不采用。

### 3. 删除仅处理记录，并复用统一的前端清理

确认对话框使用“删除任务记录”的通用措辞，展示当前选择数量，并说明操作不可撤销且不影响工作目录。服务和应用层不得调用工作目录删除，也不得触发生命周期命令。即使未执行任务的开始前命令链已经创建目录后失败，删除仍只移除其持久化记录；带失败执行记录的任务则保持不可删除，以保留重试路径。

前端在接口成功返回后以完整任务列表替换本地任务状态，并从终端列表、详情选择、终端选择、展开状态、终端会话及实时状态追踪中移除被删任务。将现有已完成任务的清理逻辑抽为状态无关的路径，确保两个标签得到相同行为。

## Risks / Trade-offs

- [确认前任务已开始或命令链状态变化] → 后端重新全量校验并原子拒绝；前端保留当前选择并显示错误。
- [开始前命令链失败已留下工作目录] → 删除资格要求无生命周期执行记录，且删除路径绝不处理磁盘。
- [删除后详情或终端仍引用已删任务] → 成功响应后统一清理任务相关的本地会话和选择状态。
- [重命名 Wails 导出方法后前端绑定过期] → 重新生成绑定并通过前端类型检查、测试和桌面构建验证。

## Migration Plan

1. 将删除绑定改为通用名称并重新生成 Wails 前端模块；不改变持久化任务结构。
2. 发布后，现有未执行任务立即可在无生命周期执行记录时进入选择并删除；无需数据迁移。
3. 回滚时移除未执行标签入口并恢复原绑定；已经删除的记录无法自动恢复，工作目录始终保持不变。
