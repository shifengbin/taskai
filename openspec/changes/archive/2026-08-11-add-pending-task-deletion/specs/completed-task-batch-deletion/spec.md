## MODIFIED Requirements

### Requirement: 已完成任务选择模式
系统 SHALL 仅在“未执行”和“已完成”任务标签中提供显式的选择模式。进入选择模式后，系统 MUST 允许用户逐项选择当前标签中符合删除资格的任务、全选当前标签中全部符合资格的任务，以及取消选择模式；离开选择模式或切换到其他状态标签时，系统 MUST 清空本次选择。

#### Scenario: 选择多个可删除任务
- **WHEN** 用户在“未执行”或“已完成”标签进入选择模式并勾选多个符合资格的任务
- **THEN** 系统显示已选任务数量，并仅将当前标签中这些任务作为待删除目标

#### Scenario: 全选当前标签中的可删除任务
- **WHEN** 用户在“未执行”或“已完成”标签的选择模式触发全选
- **THEN** 系统选择当前标签中全部符合删除资格的任务，且不选择其他状态的任务

#### Scenario: 取消或切换标签会清空选择
- **WHEN** 用户取消选择模式或切换到其他状态标签
- **THEN** 系统退出选择模式并清空所有待删除任务 ID

### Requirement: 删除资格保护
系统 MUST 仅允许删除状态为 `pending` 或 `completed` 且不存在生命周期执行记录的任务。存在运行中或失败生命周期执行记录的未执行或已完成任务 MUST 保持不可选择和不可删除，以保留其进度或重试路径。

#### Scenario: 完成任务的结束后命令链失败
- **WHEN** 一项已完成任务存在失败的结束后生命周期执行记录
- **THEN** 系统不得将该任务加入可删除选择或删除请求，并保留现有重试能力

#### Scenario: 未执行任务的开始前命令链失败
- **WHEN** 一项未执行任务存在失败的开始前生命周期执行记录
- **THEN** 系统不得将该任务加入可删除选择或删除请求，并保留现有重试能力

#### Scenario: 删除请求混入不可删除任务
- **WHEN** 批量删除请求包含执行中、带生命周期执行记录或不存在的任务 ID
- **THEN** 系统拒绝整个请求且不删除任何任务记录

### Requirement: 原子化批量删除任务记录
系统 SHALL 提供接收多个任务 ID 的批量删除接口。该接口 MUST 在一次持久化操作前校验全部 ID，拒绝空集合和重复 ID；所有目标均符合删除资格时，系统 MUST 一次性移除全部目标任务记录，并返回最新完整任务列表。

#### Scenario: 成功删除多个未执行或已完成任务
- **WHEN** 用户确认删除多个符合资格的未执行或已完成任务
- **THEN** 系统一次性移除这些任务记录，返回不含这些任务的最新任务列表，并更新对应任务标签的计数

#### Scenario: 一个目标已被其他操作移除
- **WHEN** 用户确认删除时，所选 ID 中有一个已不存在
- **THEN** 系统拒绝整个请求，保留其余所有任务记录，并向用户报告错误

### Requirement: 记录删除不影响文件与生命周期操作
系统 MUST 将批量删除限定为任务记录操作。确认界面 MUST 明确说明该操作仅删除任务记录且不可撤销；批量删除 MUST NOT 删除、移动或修改任务工作目录，MUST NOT 调度、取消或重试生命周期命令链。

#### Scenario: 删除具有保留工作目录的未执行或已完成任务
- **WHEN** 用户确认删除一项工作目录仍存在的符合资格未执行或已完成任务
- **THEN** 系统只移除任务记录，工作目录及其内容保持不变，且不执行任何生命周期命令
