## Context

现有终端会话已经按静默期合并 PTY 输出，但冲刷时会在输出末尾附加 `ESC[?25l`，再由定时器写入 `ESC[?25h`。xterm 将这两个序列作为持久的终端状态处理，而不是单纯的渲染标记；恢复定时器遇到待处理输出时提前返回后，普通输出和用户输入都可能留下隐藏光标。该逻辑只根据输出字节特征判断，Windows 和 Unix 会话都会受到影响。

xterm 当前版本已经支持同步输出模式。该模式只缓存待刷新的行，在同步状态解除时统一渲染，不改变光标可见性、闪烁选项或程序发送的控制序列。

## Goals / Non-Goals

**Goals:**

- 将渲染同步与终端程序的光标状态解耦，消除永久隐藏、异常闪烁和方向键后不显示。
- 在静默冲刷和连续输出截止冲刷之间保持一致的渲染边界，避免高频重绘中间态。
- 让前台、后台、Windows ConPTY 和 Unix PTY 使用一致的会话状态机。
- 在退出、分离、重新附着和销毁时清理同步状态及定时器，不向已销毁会话写入。

**Non-Goals:**

- 不改变 Go 侧 PTY/ConPTY 读取、事件协议或终端输入语义。
- 不改变 `output-change` 的画面比较范围、比较字段和静默状态判定。
- 不修改终端程序自身发送的 `ESC[?25l`、`ESC[?25h`、光标样式或闪烁控制。
- 不引入新的用户设置，也不更换 xterm 渲染器。

## Decisions

### 决策 1：使用会话级同步输出代替合成光标序列

每个终端会话维护独立的渲染同步状态。第一次冲刷一个输出突发时进入同步输出模式，后续因 64 毫秒截止时限产生的冲刷继续沿用该状态；输出静默后才解除同步模式，让 xterm 一次渲染最新缓冲区。

同步模式的开关序列只写入本地 xterm 解析器，不发送到后端 PTY。输出数据本身保持原样，因此程序自己的光标控制序列按原顺序生效。

选择会话级状态而不是每次写入都包裹开关的原因：连续输出的截止冲刷不能暴露半帧光标，也避免每次写入都重置光标渲染节奏。若终端程序自身已经启用同步输出，注册器不应在会话结束时强制关闭非自身拥有的状态。

### 决策 2：保留现有输出队列和时序边界

继续使用现有的 32 毫秒静默期、64 毫秒截止时限和 1MB 缓冲上限。输出事件仍按会话、按到达顺序合并，超过上限时立即冲刷。同步状态的结束计时以该会话最后一次输出为基准；计时到期时先冲刷剩余数据，再解除同步模式。

这样只替换渲染抑制机制，不改变输出延迟、顺序、后台会话解析和 `onWriteParsed` 活动画面比较时机。

### 决策 3：删除应用层光标恢复状态

移除合成 `ESC[?25l` / `ESC[?25h`、`pendingCursorRestore` 及对应恢复定时器。注册器不得通过 `terminal.options.cursorBlink` 或光标样式选项补偿该逻辑；终端光标的可见性和闪烁完全由 xterm 与终端程序共同决定。

退出快照现有的“退出后隐藏光标”展示语义保持不变，但必须在写入退出提示前结束注册器自己拥有的同步状态，确保最终输出已经渲染。

### 决策 4：生命周期统一收尾

- 输出静默时：冲刷待处理数据，解除同步状态，保留最新画面。
- 切换或分离时：取消当前视图相关监听，并结束注册器自己拥有的同步状态；后台输出仍可继续进入新的输出突发。
- 异常退出时：先冲刷并解除同步状态，再写入退出快照提示。
- 销毁时：取消冲刷和同步定时器，清空队列；必要时解除同步状态后再释放 xterm 实例。

所有回调都必须检查会话是否仍存在，避免延迟计时器在终端销毁后写入。

### 决策 5：分层验证

单元测试继续覆盖队列的静默、截止、上限、顺序和生命周期，并让测试桩记录同步模式的进入与解除；断言应用层不再写入合成 `?25` 序列。

新增真实 xterm 测试或浏览器测试，验证以下顺序：大批次重绘、后续普通文本、字符输入、左右方向键、程序主动隐藏光标。测试同时检查光标最终可见性、位置、闪烁类名和同步状态，不依赖测试桩推断真实 parser 行为。

集成验证使用 `wails dev` 和浏览器调试工具，在 Windows 与 Linux 分别运行高频重绘脚本，采样光标位置和可见性，并验证后台切换与终端退出收尾。

## Risks / Trade-offs

- [xterm 同步输出模式被终端程序自身提前关闭] → 记录同步状态是否由注册器拥有；后续冲刷发现模式已关闭时重新建立，结束时只关闭注册器创建的状态。
- [同步输出持续时间过长导致画面延迟] → 保留 64 毫秒截止冲刷，并遵循 xterm 的同步输出安全超时；超时后下一次冲刷重新建立同步状态。
- [移除合成隐藏后仍存在极端中间态] → 通过会话级同步跨越截止冲刷；用浏览器位置采样验证，而不是只检查写入次数。
- [真实 xterm 测试在 jsdom 中缺少布局能力] → 将 parser 状态测试与 Wails/浏览器集成测试分开，布局和 CSS 闪烁只在真实浏览器中验证。
- [程序主动隐藏光标的场景与历史测试假设不同] → 增加明确的保持隐藏场景，禁止测试通过“最终总是显示”来掩盖程序状态。

## Migration Plan

这是纯前端运行时行为变更，不需要数据迁移或绑定更新。实现后先运行终端会话单元测试，再执行前端构建和浏览器集成验证；若验证失败，可回滚 `frontend/src/terminal-session.ts` 及其测试，不影响 PTY 协议和持久化数据。
