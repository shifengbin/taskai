## Why

用户目前只能逐条填写 Git 分类信息，面对私有 GitLab 中数量较多的可访问项目时操作重复，且容易遗漏项目或录错仓库地址。需要提供一次性读取、筛选和选择导入能力，让用户能够快速建立可复用的 Git 信息目录。

## What Changes

- 在额外信息管理的 Git 分类中增加“从 GitLab 导入”入口。
- 允许用户输入私有 GitLab 地址、用户名和个人访问令牌，读取该用户可访问的全部项目；成功连接后在 TaskAI 本地数据中明文记住三项输入并于下次打开时自动回填。
- 完整处理 GitLab 项目分页，并在任何一页失败时拒绝展示不完整结果。
- 提供按项目名称和完整路径的模糊筛选、当前筛选结果全选和取消选择，以及默认 SSH 的统一 SSH/HTTPS 地址格式选择。
- 标记并禁止选择已经导入的项目；显示归档项目但默认不选，用户仍可主动选择。
- 将所选项目原子批量写入内置 Git 分类，并在保存前再次去重；新发现的重复项目正常跳过，其他失败不写入任何项目。
- 允许连接未加密的 HTTP GitLab 地址，同时明确提示访问令牌将通过未加密连接发送。
- Git 信息继续使用项目名作为 `name`，并在信息列表和任务选择器中辅助显示仓库完整路径，以区分不同群组中的同名项目。

## Capabilities

### New Capabilities

- `gitlab-project-import`: 定义私有 GitLab 认证、全部可访问项目获取、分页、筛选选择、地址格式、重复识别和原子批量导入行为。

### Modified Capabilities

- `task-extra-info`: Git 信息列表和任务选择器增加从仓库地址提取的完整路径辅助展示，同时保持项目名称及克隆目录语义不变。

## Impact

- 后端新增 GitLab REST API 客户端、Wails 查询与批量导入方法，以及存储层原子批量保存能力。
- 前端额外信息管理新增 GitLab 连接和项目选择弹窗、明文本地保存提示及默认回填，并调整 Git 信息在管理列表和任务选择器中的展示。
- 需要重新生成并核对 Wails 前端绑定。
- 测试新增 GitLab HTTP 模拟服务、后端分页和失败测试、前端选择交互测试，以及通过 `wails dev` 和浏览器工具执行的集成测试。
- 在 TaskAI 现有数据文件的专用字段中明文持久化 GitLab 地址、用户名和访问令牌，不改变已有 Git 信息和任务快照的数据格式。
