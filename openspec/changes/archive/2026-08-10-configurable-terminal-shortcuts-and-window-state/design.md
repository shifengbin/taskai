## Context

TaskAI 的终端视图通过 `TerminalSessionRegistry` 将 xterm 产生的键盘字节写入指定 PTY。现有快捷输入只提供全局文本库和固定的 `Ctrl+Shift+P`（macOS 为 `Command+Shift+P`）选择器，并使用模拟粘贴，因此不会主动发送回车。设置作为 `settings.Settings` 保存于单个 JSON 数据文件；Wails 的 Go 运行时已提供读取和恢复窗口最大化状态的接口。应用内容区仍保留一个与原生标题栏重复的退出按钮。

本变更跨越设置持久化、Wails 生命周期、React 设置界面和 xterm 键盘拦截。终端快捷键必须继续限定在当前已聚焦的终端，不能变成系统级快捷键或影响普通表单输入。

## Goals / Non-Goals

**Goals:**

- 允许用户在设置中维护终端快捷键与有序输入动作。
- 支持把 `Shift+Enter` 配置为先发送 `\\`、再发送真正的回车字节 `\r`。
- 保持现有快捷输入选择器及其平台快捷键可用，并拒绝冲突绑定。
- 移除重复的应用内退出按钮，保留原生关闭确认。
- 在退出前保存窗口是否最大化，并在下次启动恢复。

**Non-Goals:**

- 不注册操作系统全局快捷键，不向未聚焦的终端、设置窗口或其他应用发送输入。
- 不改变快捷输入库的模拟粘贴语义，不把快捷键动作写入该库。
- 初始版本不提供 Enter 以外的特殊按键、条件判断、延迟、脚本执行、导入导出或跨设备同步。
- 不保存窗口尺寸、位置、最小化或全屏状态，也不改变任务与终端的退出语义。

## Decisions

### 1. 在设置中保存独立的终端快捷键动作

在 `settings.Settings` 中增加终端快捷键数组。每项含稳定 ID、规范化组合键和有序动作步骤；步骤类型为文本或按键。文本步骤原样保存，按键步骤保存规范化按键名称与修饰键，并映射为对应的终端输入序列。旧数据中的回车步骤会在读取时兼容并归一化为 `Enter` 按键。空动作、空文本步骤、未知按键、重复组合键和与快捷输入选择器冲突的组合键均拒绝保存；旧数据缺少该字段时归一化为不含自定义快捷键的空数组。

不复用 `quickinput.QuickInput`：快捷输入是可搜索、可模拟粘贴的全局文本库，而本能力需要直接发送按键序列和专属冲突校验。采用有序步骤而不是“文本 + 自动回车”布尔值，可以在不迁移既有数据的前提下扩展更多特殊按键。

### 2. 在设置对话框提供受控编辑器

设置对话框新增“终端快捷键”标签页，沿用现有草稿、保存和取消语义。列表展示组合键和动作摘要，支持新增、编辑与删除；编辑器通过捕获一次 `keydown` 记录组合键，并通过文本步骤与按键步骤组成动作序列。新增按键步骤时，用户直接按下目标按键或组合键，系统记录 `key` 和修饰键。组合键使用固定修饰键顺序和标准按键名称规范化，显示时按平台把 Meta 显示为 Command。

录入框只在编辑快捷键本身时拦截按键；普通设置字段不安装全局监听器。保存前在前端即时提示格式或重复问题，后端仍为唯一校验边界。

### 3. 通过当前会话直接发送精确字节

`TerminalView` 继续将 xterm 自定义键盘处理器安装在当前活动会话上。处理器首先保留现有快捷输入选择器的保留组合键，再匹配保存的终端快捷键；命中后阻止原事件，并通过 `TerminalSessionRegistry` 向同一 `(taskID, terminalID)` 顺序发送步骤。

文本步骤和按键步骤走物理键盘已有的直接 PTY 写入通道，不调用 `paste()`：模拟粘贴不应替用户产生提交动作。按键映射覆盖可打印键、控制组合键、导航键和常用功能键；发送前必须确认目标会话仍存在且未关闭；目标无效时显示错误且不将任何剩余步骤路由到其他终端。未命中的组合键保持 xterm 原有行为。

文档级快捷键监听会在弹窗、文本编辑器和未选中终端中误触发，因此不采用。把整段内容模拟粘贴后追加换行则会改变 bracketed paste 语义，也无法表达确认的“反斜杠后立即回车”，因此不采用。

### 4. 原生关闭是唯一退出入口

删除顶部 `LogOut` 图标、提示和只为该按钮服务的退出请求函数。Wails `OnBeforeClose` 继续负责拦截系统标题栏关闭：存在执行中任务时向前端发出确认事件；确认后沿用 `PrepareQuit` 关闭 PTY 而不改变任务状态或工作目录。

### 5. 关闭前以专用仓库操作记录最大化状态

在 `Settings` 中增加 `WindowMaximized` 布尔值，默认 `false`。应用启动加载设置后，若该值为真则调用 Wails `WindowMaximise`；每次 `beforeClose` 都在决定是否拦截关闭前调用 `WindowIsMaximised`，并以专用仓库更新仅写入该字段。这样原生关闭、确认后退出和无任务直接退出均会记录状态，且不依赖前端 `beforeunload` 时机或整份设置草稿。

状态记录失败不得阻止退出；最大化恢复失败也不得阻止启动。专用更新与现有设置保存共用仓库的互斥保护，避免关闭阶段覆盖其他设置字段。

## Risks / Trade-offs

- [直接发送 `\r` 的解释由目标程序决定] → 仅承诺发送精确顺序字节；示例和测试固定为反斜杠后回车，不承诺所有第三方程序的业务结果。
- [快捷键与系统或 xterm 原生组合键冲突] → 只允许终端聚焦时拦截，保留快捷输入选择器组合键，并在保存时拒绝重复或保留组合键。
- [目标会话在动作发送中关闭] → 发送前和每一步检查会话有效性，停止后续步骤并只报告该目标不可用。
- [关闭期间无法写入状态文件] → 采用尽力保存；窗口仍正常退出，下次以最近一次成功记录或非最大化状态启动。
- [跨平台按键名称差异] → 用浏览器 `KeyboardEvent` 及单一规范化函数保存和比较组合键，并为 macOS 单独显示 Command。

## Migration Plan

1. 扩展设置模型、归一化和测试；缺少快捷键列表或最大化字段的既有 JSON 保持可加载，分别采用空数组和 `false`。
2. 增加终端快捷键设置界面、会话发送接口和窗口生命周期调用，重新生成 Wails 前端绑定。
3. 更新 OpenSpec 规格与中文实施记录，执行相关 Go、前端、绑定差异、构建脚本和运行验证。
4. 回滚时，旧版本忽略 JSON 中未知的设置字段；既有任务、终端、快捷输入和窗口启动不受影响。
