## Context

TaskAI 在创建任务工作目录前会校验工作区根目录的 ACL 严格性，并在根目录下维护一个私有元数据目录存放侧车凭据。Windows 侧实现（`internal/workspace/ownership_windows.go`）要求根目录所有者为当前用户、DACL 中不得有其他 SID 的写入 ACE，并用 `PROTECTED_DACL` 创建元数据目录、主动 `SetNamedSecurityInfo` 硬化既有目录；Unix 侧实现（`internal/workspace/ownership_unix.go`）对称地校验 uid、组写入位、其他用户写入位，并把元数据目录收紧为 `0700`。

用户机器上，OpenAI Codex 沙箱在 `C:\Users\<user>\AppData` 上添加了 `CodexSandboxUsers` 组和孤儿 SID 的 Modify ACE，继承到默认工作区根目录 `%APPDATA%\taskai\workspaces` 后触发"任务工作区根目录不安全: 目录允许其他用户写入"，导致 `beforeStart` 命令链失败、任务无法启动。

删除安全性分析：删除任务目录前的五重校验（任务 ID、路径边界、随机令牌、目录自身所有权标记、文件系统身份）全部是应用层逻辑，不依赖目录 ACL。即使其他本地账户读取侧车凭据获得令牌，也无法伪造文件系统身份，替换目录仍会被识别。因此 ACL 严格性是冗余防御层，移除后删除安全独立成立。

## Goals / Non-Goals

**Goals:**

- 在带有宽松继承 ACL（沙箱组 ACE、孤儿 SID）的工作区根目录上，创建任务工作目录命令能正常成功。
- 根目录和元数据目录的校验目标从"必须是当前用户私有"改为"是普通目录、非符号链接、软件可访问"。
- 不再主动修改用户目录的安全描述符或权限位。
- 保留令牌机制、五重删除校验、路径边界检查、文件系统能力探测的全部现有行为。

**Non-Goals:**

- 不改变删除任务目录的安全校验逻辑和拒绝场景。
- 不改变"文件系统不支持备用数据流/扩展属性时拒绝创建"的行为。
- 不引入"修复 ACL"或"用户配置豁免列表"等替代机制。
- 不迁移既有任务数据；已存在的严格 ACL 元数据目录保持原样，仅不再校验。

## Decisions

### 决策一：直接移除 ACL 校验，而不是提供配置开关

用户明确决策"都不需要严格限制 ACL，只要软件本身可以访问就没问题"。配置开关会保留两条代码路径和两套测试面，且默认值无论取哪边都遗留本次问题。威胁模型按单人使用的个人电脑固定下来，写入本设计作为长期前提。

替代方案（已否决）：默认严格 + 设置页开关。否决原因：默认严格意味着默认环境（Codex ACE）仍然失败，开关只是把排障成本转移给用户。

### 决策二：校验收敛为"目录形状 + 访问能力"两级

- 根目录 `validateOwnershipRoot`：保留"存在、是普通目录、非符号链接"；删除所有者校验和 DACL/权限位扫描（Windows 与 Unix 对称处理）。软件可访问性不由显式探测承担，而是由后续实际操作（元数据目录创建、令牌读写探测）自然验证——这些操作已有清晰的失败路径和错误信息。
- 元数据目录：`createPrivateDirectory` 改为不带安全描述符的普通创建（Unix `os.Mkdir` 默认 0755 含 umask；Windows `os.Mkdir` 继承父目录 ACL）。`secureAndValidatePrivateDirectory` 不再 chmod、不再重写 DACL；校验仅保留"是普通目录、非符号链接"。既有目录带严格 ACL 时直接接受，不做放宽改写。

理由：既然不再要求私有性，就不应继续改写用户目录的 ACL——"软件自动修改用户目录权限"本身是一个副作用行为，一并移除。

### 决策三：令牌与删除校验原样保留

`setDirectoryOwnershipToken` / `directoryOwnershipToken`（Windows 备用数据流 `:taskai.workspace-token`，Unix xattr `user.taskai.workspace-token`）、令牌读写探测、删除前的任务 ID + 路径边界 + 令牌 + 目录自身标记 + 文件系统身份校验全部不动。这些是"别删错目录"的数据安全逻辑，与 ACL 无关且对使用零摩擦。

### 决策四：文件与测试命名沿用"所有权"概念

`ownership_*.go` 文件名和 `所有权令牌` 等术语保留。令牌机制仍是目录所有权的实际载体，仅移除其中的 ACL 分量，重命名会扩大无谓的改动面。

## Risks / Trade-offs

- [共享机器上其他本地账户可读写任务工作区内容] → 接受。本变更将支持场景明确为单人使用的个人电脑；沙箱类账户（如 Codex）触达工作区内容属于用户已知的信任决策。规格中的 BREAKING 标记向未来的维护者传达这一点。
- [其他用户读到侧车令牌后尝试伪造目录骗取删除] → 文件系统身份比对仍在删除路径上兜底，替换目录会被识别为"目录已被替换"并拒绝删除。
- [有人误以为 TaskAI 适合多用户共享环境] → 在 AGENTS.md 变更边界与本设计中记录威胁模型前提。
- [既有严格 ACL 的元数据目录与新逻辑共存] → 新逻辑只做形状校验，严格 ACL 目录自然通过；无需迁移。

## Migration Plan

纯代码行为变更，无数据迁移。发布后既有任务、执行记录、令牌和侧车凭据全部按原格式继续工作。回滚策略：恢复校验代码即可，期间创建的宽松 ACL 目录在恢复严格校验后会被拒绝使用（用户可通过重建工作区根目录恢复）。
