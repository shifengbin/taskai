## Why

Git 仓库克隆命令当前强制要求为每条命令链引用配置 `dir=<相对目录>`，即使仓库应直接放在任务工作目录下也必须填写 `dir=.`。这增加了不必要的配置步骤，并使默认行为不够直观。

## What Changes

- 允许 Git 仓库克隆命令不配置追加参数；未配置或仅有空白行时，默认以任务工作目录作为克隆根目录。
- 保留 `dir=<相对目录>` 作为可选的自定义克隆目录配置，并继续限制为一条安全的相对目录参数。
- 保持已有显式 `dir` 配置、目录越界防护和已存在目标跳过逻辑不变。
- 更新生命周期编排界面的使用说明、项目 README 与测试，明确默认和显式目录行为。

## Capabilities

### New Capabilities

- `git-clone-lifecycle-command`: 配置并执行 Git 仓库克隆生命周期命令，支持任务目录默认值和安全的自定义子目录。

### Modified Capabilities

- 无。主规格目录中尚无 Git 克隆生命周期命令的既有规格。

## Impact

- 后端：`internal/settings` 的 Git 克隆参数规范化，以及 `internal/lifecycle` 的默认目录解析与执行测试。
- 前端：生命周期命令使用说明与命令链保存交互测试。
- 文档：README 的 Git 仓库克隆配置说明。
