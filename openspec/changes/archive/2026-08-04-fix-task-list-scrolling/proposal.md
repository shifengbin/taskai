## 为什么

任务数量超过左侧面板可见高度时，未执行、执行中和已完成列表的下方条目会被窗口裁切，用户无法通过列表继续查看或操作。应用全局禁止页面滚动，因此需要让任务列表自身成为稳定且可滚动的内容区域。

## 变更内容

- 将左侧任务面板的标题栏与任务树组织为固定标题、剩余空间自适应的高度布局。
- 使未执行、执行中和已完成三个状态下的任务列表均可在自身区域内垂直滚动。
- 隐藏任务列表的原生滚动条，同时保留鼠标滚轮、触控板和键盘滚动能力。
- 保持任务标签筛选、展开终端、选择任务及任务拖动排序等既有交互不变。

## 能力

### 新增能力

- `task-list-scrolling`：在左侧固定任务面板中为各任务状态列表提供无可见滚动条的可滚动浏览能力。

### 修改能力

- 无。

## 影响

- 前端 `App` 的左侧面板高度布局和 `TaskTree` 的任务列表溢出样式将调整。
- 不涉及后端任务模型、任务状态、Wails 绑定、HTTP API 或持久化数据。
- 需要补充前端组件测试，并按项目脚本完成 Linux 构建验证。
