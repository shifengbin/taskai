## Context

右侧终端视图由 `TerminalView` 渲染内容容器，并通过 `TerminalSessionRegistry` 将长期存活的 xterm 会话附着到当前容器。注册器负责会话创建、输出写入、尺寸适配、可见行刷新和释放；`TerminalView` 当前无法获知活动缓冲区的滚动位置，也没有调用 xterm `scrollToBottom()` 的公共入口。

xterm 的活动缓冲区通过 `viewportY` 表示当前视口起始行，通过 `baseY` 表示底部页面起始行，并通过 `onScroll` 发布视口变化。现有终端活动状态判定始终从 `baseY` 捕获底部页面，不能因本功能重新与用户的 `viewportY` 绑定。

## Goals / Non-Goals

**Goals:**

- 仅在当前可见终端离开滚屏底部时显示清晰、可访问的“回到底部”按钮。
- 点击按钮后回到当前会话的最新输出；活动终端同时恢复输入焦点。
- 切换会话、重新附着、调整尺寸和查看异常退出快照时，按钮始终反映对应 xterm 会话的真实位置。
- 保留用户查看历史时的视口位置，新输出不得自动把用户拉回底部。
- 完整释放与视图绑定的滚动监听，不改变终端输出活动状态的判定基线。

**Non-Goals:**

- 不增加未读行数、滚动进度、自动跟随开关或可配置显示阈值。
- 不持久化滚动位置，也不在应用重启后恢复按钮状态。
- 不改变 xterm 的滚屏上限、输出合批、终端状态聚合或异常退出快照语义。
- 不修改 Go/Wails API、PTY 协议或设置数据结构。

## Decisions

### 1. 通过终端会话注册器封装滚动能力

`TerminalSessionRegistry` 提供当前可见会话的滚动位置订阅能力，并提供按任务 ID 和终端 ID 调用 `scrollToBottom()` 的方法。`TerminalView` 只接收“当前是否位于底部”的布尔状态，不直接访问 xterm 实例或查询 `.xterm-viewport` 等内部 DOM。

这样可以继续由注册器控制会话所有权、切换和释放，同时避免界面组件依赖 xterm 未公开的 DOM 结构。备选方案是在 `TerminalView` 中查找并监听 xterm 的滚动容器；该方案容易随 xterm 样式结构变化而失效，因此不采用。

### 2. 使用活动缓冲区坐标进行严格判定

注册器使用 `terminal.buffer.active.viewportY >= terminal.buffer.active.baseY` 判定视口位于底部。订阅建立后立即通知一次，并在 xterm `onScroll`、会话重新附着和尺寸适配完成后重新计算，以覆盖首次显示、会话切换与窗口调整。

判定使用离散行坐标，不设置容差：只要用户离开底部至少一行就显示按钮。备用屏幕通常没有滚屏且两个坐标均为零，因此自然保持隐藏，不需要识别具体终端程序。

### 3. 滚动订阅只绑定当前视图生命周期

滚动监听由注册器创建，但只在会话附着到当前 `TerminalView` 时向该视图发布状态。视图卸载、切换到其他终端或会话释放时必须取消订阅；再次附着原会话时重新读取该会话保留的滚动坐标。

该监听只更新“是否位于底部”的界面状态，不调用 `captureTerminalDisplay()`、`resetDisplay()` 或实时活动回调。这样既能复用 `onScroll`，又不会恢复此前滚动事件改变终端活动状态比较基线的行为。

### 4. 按钮是终端内容区内的局部覆盖层

`TerminalView` 在终端内容区右下角渲染紧凑的 `IconButton`，使用现有主题颜色、边框和层级变量，并提供“回到底部”的 `aria-label` 与 `title`。按钮不占用终端网格布局空间，也不改变 FitAddon 计算出的行列数。

点击后由注册器滚动当前会话到底部并立即重新同步按钮状态；活动终端随后恢复 xterm 焦点。异常退出的只读快照同样允许浏览滚屏和回到底部，但不因此恢复输入、粘贴或尺寸同步能力。

## Risks / Trade-offs

- [xterm 在输出或适配期间连续触发多次滚动事件] → 仅在布尔值实际变化时更新 React 状态，并在附着和适配完成后做一次确定性同步。
- [切换终端后旧监听继续更新新视图] → 将订阅与终端会话键绑定，在 detach、切换和 dispose 路径统一释放，并增加监听释放测试。
- [浮动按钮遮挡少量终端文本] → 使用紧凑尺寸并放置在内容区右下角内缩位置，仅在离开底部时显示，不改变网格尺寸。
- [点击按钮使浏览器焦点停留在按钮上] → 完成滚动后对活动终端调用现有 `focus()`，保持连续输入体验。
- [重新使用 `onScroll` 导致实时状态回归] → 滚动监听不得接触画面快照基线，并保留“仅滚动不触发活动、查看历史时底部变化仍触发活动”的回归测试。

## Migration Plan

本变更仅增加前端会话接口、局部状态和视图控件，不涉及数据迁移。发布时随前端资源一起生效；如需回滚，移除按钮、滚动订阅和注册器公共方法即可，不影响已有终端会话数据或后端兼容性。

## Open Questions

无。按钮位置、严格底部判定、活动终端聚焦和异常快照支持均按上述方案实施。
