## MODIFIED Requirements

### Requirement: 工作台与任务树保持跑道式层级
系统 SHALL 在不改变现有工作台布局和操作位置的前提下，使用 2–2.5px 实色描边、默认 `1px 1px 0`、交互 `2px 2px 0`、覆盖层 `3px 3px 0` 的错位硬投影、6–9px 圆角和 hover 抬起位移表现快门波普的新粗野层级。顶栏、任务树、状态标签、任务行、终端子项、详情区、空状态、分隔条及拖拽反馈必须使用同一视觉语言。每个未选中的任务行 MUST 以其用户定义的任务颜色渲染约 4% 不透明度的极浅背景，并继续以该颜色的左边框作为主要颜色标记。

#### Scenario: 查看未选中的任务项
- **WHEN** 用户在任一亮色或暗色模式中查看未选中的任务项
- **THEN** 任务项必须显示与左侧任务色条相同色相的极浅背景（约为该任务色的 4% 不透明度）、粗描边与 1px 硬投影卡片，且标题、描述、图标和操作控件保持清晰可辨

#### Scenario: 选择任务
- **WHEN** 用户在任务树中选择一个任务
- **THEN** 选中任务必须获得可见的快门波普选择态（钴蓝描边或填充），同时任务标题、描述、操作按钮和用户定义的任务颜色仍保持可辨认，且不得显示易被误解为新建任务状态的装饰性尾标

#### Scenario: 拖拽调整任务顺序
- **WHEN** 用户拖拽任务并悬停在有效插入位置
- **THEN** 插入指示器与拖拽预览必须使用快门波普主色或描边清晰标示目标，且不改变原有拖拽判定或排序行为

#### Scenario: 未选择任务或终端
- **WHEN** 用户未选择任务和终端
- **THEN** 详情区必须显示与快门波普主题一致、易读的引导空状态，且创建任务入口保持可见

### Requirement: 可访问的运动与交互反馈
系统 SHALL 为启动、任务开始、拖拽落点、执行状态、按钮悬停和对话框进场提供克制的快门波普动效与可见焦点状态，包括 hover/选中时的 `translate(-1px,-1px)` 抬起与由 1px 默认档提升至 2px 交互档的硬投影变化。系统 MUST 在用户启用减少动态效果偏好时禁用抬起与进场等非必要动画，并保留等价的静态描边与投影反馈。系统 MUST 提供基于钴蓝的可见焦点环，且在亮暗两种模式与任务自定义颜色之上均可辨认。

#### Scenario: 默认动态效果偏好
- **WHEN** 用户未启用减少动态效果偏好并触发可动画的视觉状态
- **THEN** 动画必须在 120 至 350 毫秒内完成或为低干扰状态脉冲，交互元素在悬停/选中时产生抬起位移与投影提升，且不得引起布局重排

#### Scenario: 减少动态效果偏好
- **WHEN** 用户的系统启用 `prefers-reduced-motion: reduce`
- **THEN** 抬起、入场和脉冲等非必要动画必须被关闭或立即稳定，焦点、选中、执行和拖拽状态仍必须可辨认
