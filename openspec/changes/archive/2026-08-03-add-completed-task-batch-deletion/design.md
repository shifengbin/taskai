## Context

任务列表按状态标签展示，`TaskTree` 当前使用单项选中状态打开任务详情；没有多选状态或任务删除绑定。任务完成后，结束后命令链可能仍在执行或失败并等待用户重试。工作目录的删除由可配置的生命周期命令链负责，而不是任务记录删除的固有副作用。

本次变更横跨 React 任务树、应用级状态、Wails 绑定、应用服务和持久化服务。用户已确定批量删除只移除任务记录，不处理工作目录。

## Goals / Non-Goals

**Goals:**

- 让用户在“已完成”标签显式进入选择模式、选择多个可安全删除的任务，并经确认后批量移除记录。
- 将删除资格和原子性放在后端校验，防止客户端状态过期、重复 ID 或混入非完成任务时出现部分删除。
- 删除成功后让前端任务列表和所有相关瞬时状态保持一致。
- 保持工作目录和生命周期命令链的职责边界不变。

**Non-Goals:**

- 不为未执行或执行中的任务提供删除入口。
- 不删除、归档、移动或检查任何任务工作目录及其内容。
- 不运行、取消、重试或补偿任何生命周期命令链。
- 不提供撤销、回收站、跨状态多选或批量编辑。

## Decisions

### 1. 使用仅限已完成标签的显式选择模式

`App` 保存本次会话的选择模式和任务 ID 集合，`TaskTree` 作为受控视图展示它们。用户通过侧栏标题区的“选择”命令进入该模式；此时可删除任务行显示复选框，行点击切换勾选而非改变详情选中。工具栏提供全选当前可删除任务、删除和取消选择模式。切换到其他状态标签、取消选择模式或成功删除后都会清空集合。

普通浏览保持现有单项详情选择、拖拽和右键行为，因此已完成列表在非选择模式下不改变。替代方案是在每一行永久显示复选框，但会增加常规任务列表的视觉噪音，并与现有行选中语义混淆。

### 2. 生命周期锁定的已完成任务不可被选择或删除

后端将任务状态为 `completed` 且 `LifecycleExecution` 为空作为唯一删除资格。带有运行中或失败的生命周期执行记录的完成任务保持在列表中，继续使用现有进度或重试界面，且不显示为可选择删除的项。

这种限制确保结束后链失败时，用户不会通过记录清理绕开待处理的工作区清理或其他后置操作。替代方案是允许删除并放弃重试状态，但会在用户尚未明确处理失败前不可逆地丢失恢复路径。

### 3. 批量接口全量校验后单次持久化，并返回最新列表

新增 `DeleteCompletedTasks(taskIDs []string) ([]task.Task, error)` 绑定。生命周期服务先加载数据、拒绝空列表、重复 ID、未知 ID、非完成状态或存在生命周期执行记录的任何目标；全部目标通过后才从 `Data.Tasks` 过滤，并以一次 `Repository.Save` 持久化，返回更新后的完整列表。这与现有 `ReorderTasks`、`SetTaskShelved` 的集合返回模式一致，前端可直接替换本地任务列表。

应用层在调用服务前按稳定顺序获取目标任务的生命周期锁，避免异步结束后链与删除在验证到保存之间交叉；删除成功后清理实时任务状态。替代方案是由前端逐个调用单项删除接口，或在遇到无效项时删除其余项；两者都会导致部分成功、难以恢复的结果。

### 4. 记录删除和文件清理严格解耦

确认对话框使用“删除任务记录”的明确措辞，展示数量并说明操作不可撤销。确认只调用新的记录删除接口；接口及其下游不得调用 `workspace.Remove`，不得创建、修改、删除任务工作目录，也不得调度生命周期命令。

保留文件操作于结束后命令链，可以继续支持用户的自定义清理策略。替代方案是在批量删除时尝试删除 `WorkspacePath`，但会绕过用户配置，并会在任务已完成而结束后清理失败时带来不可预期的数据丢失。

## Risks / Trade-offs

- [客户端选中集合在确认前已过期] → 服务端全量校验并原子失败；前端保留选择并显示错误，用户可刷新后重试。
- [后置命令链失败的任务被误当作普通完成任务] → 以 `LifecycleExecution == nil` 作为后端强制条件，前端只反映该资格而不承担安全判断。
- [删除后详情面板仍引用已删任务] → 成功响应后清理 `selectedTaskID`、终端选择、展开状态和选择集合中命中的 ID。
- [后台命令链与删除并发] → 应用层按确定顺序锁定全部目标，持久化层仅在验证完成后保存一次。
- [用户误以为删除记录会清理磁盘] → 进入选择模式和确认对话框都明确说明“仅删除记录，不影响工作目录”。

## Migration Plan

1. 新增服务、应用绑定和 Wails 前端绑定，不变更已持久化的任务结构。
2. 发布后，已有已完成任务立即可在符合资格时被选择和删除；不需要数据迁移。
3. 回滚时移除前端入口和绑定；已删除的记录无法从应用数据文件自动恢复，工作目录不受本变更影响。
