## Context

`App` 当前把每个终端的全部原始输出保存在 React `TerminalRecord.output` 中。每个输出事件都会复制并扩展该字符串；`TerminalView` 还会把新旧完整字符串作前缀比较。选择另一终端时，React 会销毁当前 xterm，再创建新实例并回放该终端的完整输出。因此切换成本和终端已产生的总输出量成正比。

xterm 默认仅保留 1000 行滚屏，且用户确认不需要更长的历史。Go 终端管理器只推送增量事件，不提供输出历史 API，因此必须在前端进程内保留可显示的终端状态。现有终端切换绘制修复要求在挂载和尺寸变化后执行尺寸适配及可见行刷新，该行为必须保留。

## Goals / Non-Goals

**Goals:**

- 使终端切换不再重新解析随运行时间增长的原始输出。
- 每个活动终端最多保留 1000 行滚屏及当前可见行，并保留 ANSI、光标和全屏模式等 xterm 状态。
- 保持终端输入、剪贴板、自动聚焦、PTY 尺寸同步、容器重绘和状态标题行为。
- 在终端关闭、任务结束及前端卸载时释放会话资源。

**Non-Goals:**

- 不保留超过 1000 行的终端历史，也不在应用重启后恢复终端屏幕。
- 不修改 Go 终端管理器、Wails 事件协议、PTY 协议或持久化模型。
- 不通过截取原始字符串实现输出上限，不增加服务器端日志或回放 API。

## Decisions

### 由前端终端会话注册表拥有 xterm 实例

新增以 `taskId + terminalId` 为键的前端会话注册表。注册表拥有 `Terminal`、`FitAddon`、输入与选择监听器以及一次性的输出写入队列；创建时设置 `scrollback: 1000`。`App` 的终端事件监听器先将输出块路由到注册表，再只将标题、状态等轻量元数据更新到 React。

这移除了 `TerminalRecord.output` 和由它驱动的完整字符串拼接、前缀比较与历史回放。对于创建 RPC 返回前到达的输出事件，注册表可直接按事件中的终端 ID 创建会话，避免以原始字符串暂存该竞争窗口。

继续在 React 中保存原始输出并在切换时裁为 1000 个换行符被否决：换行数不等于 xterm 的逻辑行，且会截断 ANSI 转义、光标位置或备用屏幕状态。后端保存输出快照被否决：它会扩大 PTY 与 Wails 协议的范围，不能解决当前前端的事件处理成本。

### 复用并重新挂载已有 xterm DOM

`TerminalView` 改为活动会话的宿主，而不是 xterm 的所有者。首次选择会话时，宿主在可见容器中打开该 xterm；后续选择将已有 xterm 根元素重新挂载到新的可见容器，而不创建第二个实例或再次写入历史。未曾显示的会话可以在没有 DOM 的状态下接收增量输出，首次挂载时显示其已解析的缓冲区。

每次附着仍先适配当前容器尺寸、向 PTY 同步网格，然后在下一动画帧刷新可见行并聚焦。宿主卸载只断开尺寸观察和取消自己的动画帧，不能释放会话；终端真正结束时才由注册表处置。这样保留现有 WebKitGTK 静态内容重绘保证，同时把切换工作限制为 DOM 重新挂载和当前可见行刷新。

保留每个终端在隐藏且有尺寸的 DOM 容器中被否决：它会持续占用渲染资源，隐藏容器还会产生零尺寸适配问题。每次切换新建 xterm 并从序列化快照恢复也被否决：仍需解析快照，增加依赖和状态同步复杂度，且不如直接复用实例。

### 以生命周期事件处置会话

终端关闭、收到退出事件、任务结束以及 `App` 卸载时，调用注册表的单终端或任务级清理操作。清理必须释放 xterm、附加组件、输入与选择监听器，并删除注册表项。已处置会话不得再接受晚到的输出或尺寸更新。

这比让 `TerminalView` 清理更准确，因为视图卸载只是用户切换了选择，并不代表后台 PTY 已结束。

### 将性能契约覆盖为可观察测试

测试将验证：xterm 构造参数使用 1000 行滚屏；大量后台输出不写入 React 的 `TerminalRecord`；A -> B -> A 切换复用 A 的实例且不回放其累计输出；首次显示后台输出过的会话仍会适配并刷新；关闭、退出、结束任务和应用卸载均释放会话。现有输入、剪贴板、自动聚焦与尺寸观察测试继续覆盖。

## Risks / Trade-offs

- [同时活动的终端越多，前端内存越多] -> 每个会话的滚屏固定为 1000 行，并在终端或任务生命周期结束时立即释放。
- [重新挂载 DOM 后 WebKitGTK 可能保留静态画布] -> 每次附着及尺寸变化继续执行现有适配与可见行刷新协议。
- [输出早于创建 RPC 返回] -> 使用事件中的稳定终端标识按需创建会话，不以无上限字符串缓存输出。
- [未挂载 xterm 的异步写入尚未解析完成] -> 会话保留 xterm 写入队列；首次附着后刷新已解析可见行，并以测试覆盖后台输出后首次选择。
- [迟到事件命中已处置会话] -> 注册表维护已关闭键并忽略其后续输出，保持现有任务结束事件隔离。

## Migration Plan

该变更只改变前端进程内的终端显示状态，没有数据迁移。发布后新建和已运行终端均按 1000 行滚屏工作；应用重载时原有的前端内存状态仍按当前行为丢失。若出现特定 WebView 的重新挂载兼容问题，可回退到现有的销毁并回放路径；PTY 会话、任务数据和后端协议均不受影响。
