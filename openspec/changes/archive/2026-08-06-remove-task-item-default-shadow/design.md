## Context

任务树任务项由 `frontend/src/App.css` 的 `.taskai-task-row` 统一渲染。当前默认状态同时使用外部 3px 硬阴影和任务色内嵌色条；悬浮状态通过 `@media (hover: hover)` 将任务项上移 1px，并把外部阴影提升到 4px。选中状态使用钴蓝外部阴影，选中悬浮状态也有独立的 4px 钴蓝阴影。

本次只调整任务项的视觉层级，不改变任务树 DOM、交互事件、尺寸、颜色标记或任何业务行为。

## Goals / Non-Goals

**Goals:**

- 让未选中任务项默认不显示外部阴影，降低连续列表的视觉噪声。
- 保留任务颜色的 5px 内嵌色条，确保任务身份标识不受影响。
- 保留未选中和选中任务项的悬浮位移及外部阴影反馈。
- 通过样式断言覆盖默认态、悬浮态和选中态的阴影差异。

**Non-Goals:**

- 不调整终端子项、按钮、弹窗或其他组件的阴影令牌。
- 不改变任务项边框、圆角、背景色、固定高度、排版或操作控件布局。
- 不改变任务选择、悬浮、拖拽、菜单和生命周期行为。

## Decisions

1. **只移除默认外部投影，保留内嵌色条。** 将未选中 `.taskai-task-row` 的 `box-shadow` 改为仅包含 `inset 5px 0 0 var(--task-color)`。这样 CSS 属性仍表达任务色标，而不会留下可见的外部偏移阴影。

2. **沿用现有悬浮规则。** 未选中悬浮继续使用 `4px 4px 0 var(--snap-outline)`，选中悬浮继续使用钴蓝版本；不新增选择器或改变位移，保持已有交互节奏。

3. **选中态继续保留外部阴影。** 选中是明确的非默认状态，需要钴蓝描边和投影来维持选择反馈；仅取消未选中默认态的外部阴影不会削弱选中可见性。

4. **使用测试驱动的样式契约。** 修改现有 `TaskTree.test.tsx` 的字符串断言，明确默认规则不包含外部投影、仍包含内嵌色条，并继续断言悬浮与选中规则存在。

## Risks / Trade-offs

- [默认态与悬浮态的视觉跳变更明显] → 保留现有 160ms `box-shadow` 过渡和 1px 位移，确保悬浮反馈仍然平滑。
- [误删内嵌色条导致任务颜色丢失] → 默认规则保留 `inset 5px 0 0 var(--task-color)`，并在测试中单独断言。
- [规格与实现描述不一致] → 同步提交 `pine-night-run-visual-system` 的完整修改要求和场景。

## Migration Plan

1. 更新 CSS 默认规则及对应前端样式测试。
2. 运行受影响的前端测试，再运行前端构建确认 CSS 处理正常。
3. 该变更无数据迁移、API 迁移或回滚脚本；回滚时恢复默认规则中的外部阴影即可。

## Open Questions

无。需求已明确为默认态移除阴影，悬浮和选中态保持现有反馈。
