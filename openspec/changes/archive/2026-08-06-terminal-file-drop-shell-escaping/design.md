## Context

终端视图使用 xterm.js 接收键盘输入，并通过 `WriteTerminal` 将原始字节写入 PTY。它目前没有文件拖放处理；Wails 已生成 `OnFileDrop` 前端运行时 API，但应用启动配置没有启用原生文件拖放。终端创建时后端已获得 `ShellPath`，但活动会话没有将该值作为拖放输入契约保存或提供给前端。

文件拖放需要使用操作系统提供的绝对路径，且必须依据实际 PTY 会话的 Shell 语法转义。只使用当前设置中的默认 Shell 会在用户修改设置后与既有终端不一致；让浏览器自行处理 `drop` 则无法稳定获得跨平台文件路径。

## Goals / Non-Goals

**Goals:**

- 仅允许当前活动终端的内容区域接收桌面文件拖放。
- 让每个拖入路径成为目标 Shell 的一个字面参数，支持多个文件和空格、引号、通配符等特殊字符。
- 使用创建该终端时的 Shell，而不是当前设置或操作系统默认值。
- 不追加换行，不自动执行命令，并在失败时避免写入任何原始或部分路径。

**Non-Goals:**

- 不支持将网页文件上传到终端，也不改变终端的剪贴板粘贴行为。
- 不尝试识别前台正在运行的交互程序，也不把拖放路径作为结构化参数直接传给该程序。
- 不为未识别的自定义 Shell 猜测转义规则。

## Decisions

### 使用 Wails 原生文件拖放，并限定到终端内容区

在 Wails 应用配置中启用文件拖放，并保持 WebView 的拖放接收链可用；Linux 下禁用该接收链会让原生文件投放事件无法送达回调。应用根组件始终取消文件型浏览器拖放事件的默认行为，防止没有活动终端时 WebView 打开被投放文件。`TerminalView` 注册 `OnFileDrop` 并使用 Wails 的 drop-target 过滤，只在当前可见终端内容区域命中时处理回调；组件卸载或切换终端时注销监听，避免全局运行时监听器残留。

不使用浏览器原生 `DataTransfer` 作为路径来源。桌面 WebView 对本地文件路径的暴露不一致，而 Wails 的原生回调直接提供绝对路径，并能在 Windows、macOS 和 Linux 间保持同一契约。

### Linux Wails 2.12 显式完成原生投放

Wails 2.12 在 Linux 中的 `drag-drop` 回调会在转发文件路径后返回“未处理”，使 WebKit 继续按默认行为打开投放文件；`DisableWebViewDrop` 又会移除 GTK 投放目标，因而不能与接收文件路径的功能组合使用。应用保持 `EnableFileDrop: true`、`DisableWebViewDrop: false`，由前端的 CSS drop target 决定哪个终端接收路径。

Linux 构建时，脚本将锁定版本的 Wails 模块复制到临时目录，应用随代码库维护的补丁。补丁保持 Wails 既有的 `drag-data-received` 路径解析和 `wails:file-drop` 转发，只在 GTK 的 `drag-drop` 信号已成功转发路径后调用 `gtk_drag_finish` 并返回已处理状态，阻止 WebKit 打开文件。构建为临时副本建立仅替换 `github.com/wailsapp/wails/v2@v2.12.0` 的 Go workspace；全局模块缓存不被修改。版本或源码不匹配时构建明确失败，避免静默套用到未来 Wails 版本。

### 在后端按活动会话的 Shell 格式化并写入

终端管理器在创建会话时保留规范化后的 `ShellPath`。新增一个由 App 暴露给 Wails 前端的“写入拖放路径”入口：它验证任务和终端仍处于活动状态，根据该会话的 Shell 生成完整输入文本，并在所有路径格式化成功后通过现有 PTY 写入路径一次性写入。

前端不接收或缓存 `shellPath`，也不自行拼接 Shell 语法。这个选择使 Shell 选择与 PTY 会话保持原子一致，并将 Windows 与 Unix 的语法差异集中在可单元测试的 Go 帮助函数中。替代方案是把 `shellPath` 放进 `terminal.Info` 后由 TypeScript 转义；它会扩大发送到前端的终端契约，并容易与已创建会话的实际 Shell 脱节。

### 按 Shell 家族生成字面参数

格式化器按 Shell 可执行文件名区分 POSIX 家族（`sh`、`bash`、`zsh`、`dash`、`ksh`）、fish、PowerShell（`powershell`、`pwsh`）和 `cmd`。每个输入路径独立转义，完成后以一个 ASCII 空格连接；输出不包含换行或命令分隔符。

POSIX 与 fish 使用各自可验证的字面字符串规则，PowerShell 使用单引号和单引号重复规则，`cmd.exe` 使用命令提示符的参数引用与元字符转义规则。实现将为每个家族的空格、引号、变量/通配符和命令分隔符建立回归测试，尤其在 Windows 上验证 `cmd.exe` 的实际解析结果。未识别的 Shell 返回明确错误，且不写入 PTY；不能退化为原样路径或假定 POSIX 语法。

### 拖放等同于一次非执行的终端输入

成功的拖放只将已格式化文本写入终端；不会调用终端的键盘事件、不会追加 Enter/CR/LF，也不会改变焦点、当前命令或会话生命周期。多个文件因此表现为连续的独立命令参数，用户仍决定何时编辑或执行。

## Risks / Trade-offs

- [Wails 文件拖放监听为运行时全局资源] → 将注册与可见终端组件生命周期绑定，并使用命中目标过滤及清理函数防止切换后写到错误终端。
- [自定义 Shell 不一定兼容已知引号规则] → 仅支持已识别的 Shell 家族；未知 Shell 显式失败，绝不写入可能被错误解析的原始路径。
- [`cmd.exe` 的变量和元字符解析复杂] → 将 Windows 格式化与真实 `cmd.exe` 解析的测试独立覆盖，避免仅凭字符串快照断言正确性。
- [拖放回调期间终端可能退出] → 后端入口在格式化和写入前验证活动会话，并在失败时不写入部分结果。
- [浏览器开发模式没有 Wails 运行时] → 前端将运行时注册封装在现有桌面 API 边界，缺失运行时时保持终端输入可用且不启用拖放。
- [Linux Wails 的原生回调没有完成投放] → 固定为 v2.12.0 的构建补丁保留 Wails 路径收集链，并在成功转发后完成 GTK 信号；补丁以隔离副本和回归测试维护，升级 Wails 时必须重新验证或更新补丁。

## Migration Plan

此变更不修改持久化数据或已有终端协议。部署时启用 Wails 文件拖放配置、发布新增 Wails 绑定，并在前端注册回调；已有键盘输入和右键粘贴继续通过 `WriteTerminal` 工作。

若需要回滚，移除前端监听并关闭 Wails 文件拖放配置即可；活动终端和用户已经输入的命令行内容不受影响。
