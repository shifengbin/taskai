## Why

桌面文件管理器将文件拖入终端时，用户期望得到可以直接作为 Shell 参数使用的路径。当前应用没有明确的文件拖放处理和 Shell 转义契约，带空格、引号或 Shell 特殊字符的路径可能被拆成多个参数，导致命令失败或产生歧义。

现在补齐这一交互，可以让常见的 `cat`、编辑器和脚本命令在拖入文件后保持跨平台一致，并避免拖放行为依赖 WebView 的默认处理。

## What Changes

- 启用桌面端原生文件拖放，并将当前终端内容区域声明为可接收文件的目标。
- 将拖入的一个或多个文件路径按创建该终端时实际使用的 Shell 进行转义，再写入当前终端的 PTY 输入流。
- 多个路径作为独立参数以空格连接；拖放只输入文本，不追加换行或自动执行命令。
- 处理 POSIX Shell、fish、PowerShell 和 `cmd.exe` 的路径转义规则，并覆盖空格、引号及 Shell 特殊字符。
- 为终端路径转义、拖放目标过滤和输入转发补充跨平台回归测试。

## Capabilities

### New Capabilities

- `terminal-file-drop`: 在当前终端区域接收文件拖放，将路径转义为当前 Shell 可解析的参数并输入终端。

### Modified Capabilities

- 无。

## Impact

- Wails 应用启动配置和运行时文件拖放监听；Linux 构建脚本会对固定的 Wails 2.12.0 源码副本应用原生拖放完成补丁。
- Go 终端管理器及 App/Wails API：需要能够依据活动终端取得其 Shell，并生成转义路径文本。
- React/xterm 终端视图和终端会话输入转发。
- Wails 前端绑定可能需要重新生成；不引入新的第三方运行时依赖。
- Unix 与 Windows 的终端实现、单元测试和前端构建测试。
