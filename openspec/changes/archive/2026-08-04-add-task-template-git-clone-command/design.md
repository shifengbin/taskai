## Context

当前系统已有固定的“Git 仓库克隆”命令。它只读取任务所选的内置 Git 附加信息，将每个项目克隆至 `<任务工作目录>/<dir>/<项目名称>`，目标存在时跳过。该命令适用于批量拉取关联项目，不能把单个 Git 仓库直接展开为任务目录本身。

生命周期命令链已经为每个命令引用保存逐行参数；应用在调度链时冻结命令和任务快照。任务模板字段由当前模板定义过滤并保存到任务中，Git 附加信息的 `branch` 是文本动态参数，但当前允许被配置为必填。后者会阻止“空分支代表远程默认分支”的语义。

本变更新增一个用于初始化任务目录的系统命令，而不是扩展或替换既有批量 Git 克隆命令。它可在创建任务目录后先检出模板仓库，再由既有命令继续克隆附属项目。

## Goals / Non-Goals

**Goals:**

- 提供独立、固定且安全的单仓库 Git 初始化命令，直接以指定目录作为 Git clone 目标。
- 仅在 `beforeStart` 和 `postStart` 提供该命令，并保持两类钩子的既有提交与失败语义。
- 通过任务当前模板的字符串 `branch` 字段统一选择克隆分支；未指定时交给 Git 使用远程默认分支。
- 在保存任务快照时，将非空模板分支补入空的内置 Git 附加信息分支，保留显式填写的值。
- 保持既有“Git 仓库克隆”命令、其链级 `dir` 参数和批量附加信息语义完全不变。

**Non-Goals:**

- 不修改、拉取、合并、推送或删除已初始化的 Git 工作树，不管理 Git 凭据、子模块或稀疏检出。
- 不支持一次命令引用克隆多个仓库，也不从命令标准输入或附加信息推断仓库地址。
- 不在任务创建后持续同步模板分支到已经写入的 Git 附加信息快照。
- 不让新命令适用于 `beforeEnd`、`postEnd` 或 `updateTask`。

## Decisions

### 1. 使用新的固定命令类型，而非改变既有 Git 命令

新增固定命令 ID `system.lifecycle.git-clone-repository` 和独立的 `git-clone-repository` 类型，名称为“克隆指定 Git 仓库”。规范化设置时始终恢复其 ID、类型、名称、追加参数模式、说明和适用钩子，因此用户不能编辑或删除它。适用钩子固定为 `beforeStart` 与 `postStart`。

既有 `system.lifecycle.git-clone` 保持现状：它继续依据 Git 附加信息批量克隆到项目名称子目录。两个命令使用不同的参数解析器和执行函数，但复用无 Shell 的参数化 Git 执行器及分支检出策略。

直接改写既有命令会使只保存 `dir=` 的历史命令链缺少仓库地址；按参数是否出现来复用同一命令会使同一 ID 有两种难以理解的语义。因此采用独立命令。

### 2. 用严格的键值参数表达单仓库和直接目标

新命令引用的逐行参数必须包含且仅包含一条 `repository=<仓库地址>`，可额外包含至多一条 `dir=<相对目录>`，顺序不限。解析时只在首个等号处分割，因此仓库地址中的等号保留为地址的一部分。空仓库地址、未知或重复键、空 `dir`、绝对路径、`..` 及清理后逃出任务工作目录的目录一律在保存命令链和运行前拒绝。

省略 `dir` 的目标为任务工作目录；填写 `dir` 时目标为 `<任务工作目录>/<dir>`。目标就是传给 `git clone` 的最后一个参数，绝不追加仓库名、项目名或其他推导目录。新命令完全不读取 `Task.ExtraInfo`。

选择键值格式而不是位置参数，是为了让带路径的仓库地址和可选目录没有位置歧义，并与现有链级 `dir` 配置保持一致。

### 3. 在已有空目录中克隆，拒绝非空或不安全目标

新命令在执行前验证任务工作目录存在且为目录；这要求 `beforeStart` 链将“创建任务工作目录”排在它之前。对于自定义 `dir`，命令可以在安全的任务工作目录下创建缺失的父目录和空目标目录。

解析后的目标必须位于任务工作目录内。实现会拒绝符号链接、非目录目标或含任意条目的目标目录；通过检查现有路径的实际位置避免符号链接将写入重定向到工作目录外。仅有空目标目录才允许继续执行 Git，且失败前不得调用 Git。成功克隆后的 `.git` 和工作树自然使目标非空，因此重复执行同一目标会失败而非跳过或覆盖。

这与既有批量命令的“项目目录已存在即跳过”故意不同：初始化模板必须避免把错误的既有目录认定为完成。`postStart` 使用根目录时也因此通常要求此前没有创建文件；需要在已运行任务内克隆子模板时，调用方应配置空的 `dir` 子目录。

### 4. 用当前模板的 `branch` 解析分支，并保留远程默认分支

应用调度新命令时，从当前选中的任务模板及任务保存的可见模板字段解析 `branch`。该字段存在时必须是字符串；去除首尾空白后非空则作为请求分支。字段不存在或值为空时，执行器不传 `--branch`，由 Git 检出远程声明的默认分支，不硬编码 `main`、`master` 或其他名称。

指定分支的远程存在性检查、远程不存在时先检出远程默认分支再创建同名本地分支、Git 标准错误呈现均复用既有 Git 批量命令的策略。分支值被添加到冻结的生命周期执行请求，避免任务开始后用户切换当前模板影响正在运行的链。

使用当前模板而非任意历史 `TemplateFields` 键，遵循任务模板对 HTTP、命令链输入和环境变量的既有可见字段规则。模板中将 `branch` 定义为布尔值时，保存包含新命令的链或调度该任务必须返回明确的类型错误。

### 5. 任务保存时一次性回填 Git 附加信息分支

任务创建或编辑时先按当前模板解析并校验模板字段，再生成或更新附加信息快照。若解析出的模板 `branch` 非空，服务仅对内置 Git 模板快照中值为空的 `branch` 参数写入该值；显式非空的 Git 分支始终优先。模板字段缺失或为空时，Git 附加信息分支保持空，表示远程默认分支。

回填后的值是任务快照的一部分。日后修改模板默认值或切换当前模板不会改写既有任务的 Git 附加信息，也无需引入“继承来源”状态。为了让无模板分支也可使用远程默认分支，内置 Git `branch` 参数固定为可选；加载旧设置时将其历史必填标记归一化为 `false`，不改写已有任务快照。

## Risks / Trade-offs

- [在 `postStart` 向非空任务根目录克隆失败] → 明确说明默认根目录只适合空目录；需要额外模板目录时使用安全的 `dir`。
- [私有仓库认证或网络错误使生命周期失败] → 继续沿用本机 Git、SSH 代理和凭据管理器，并保留 Git 标准错误；`beforeStart` 阻止启动，`postStart` 留下可重试失败记录。
- [分支名与远程默认分支混淆] → 空值绝不转换为 `main` 或 `master`，只省略 `--branch`。
- [模板分支在保存后被修改] → Git 快照已回填的值不跟随变化，避免既有任务被静默重定向到其他分支。
- [旧版本无法识别新固定命令] → 回滚前移除新命令及其链引用；既有批量 Git 命令和旧链不受影响。

## Migration Plan

1. 设置归一化补齐新的固定命令，并将旧内置 Git 模板的 `branch.required` 统一为 `false`；不迁移或修改任务快照及既有命令链。
2. 已保存链未引用新命令，继续按原样执行；用户显式将新命令加入 `beforeStart` 或 `postStart` 链时才启用新语义。
3. 发布前完成后端、前端和文档回归测试，并使用 `scripts/build-linux.sh` 执行 Linux 构建。
4. 如需回滚，先移除新命令引用和固定命令持久化记录；既有 Git 附加信息及其批量克隆链可继续由旧版本读取。
