## 为什么

执行中任务较多时，暂时无需关注的任务仍会占据主列表空间。用户需要在不改变任务生命周期或终端运行状态的前提下，将这些任务收纳到列表底部，并在重启后保留该选择。

## 变更内容

- 为任务增加持久化的“已搁置”展示标记，该标记仅适用于执行中任务，不改变任务状态。
- 在“执行中”标签的正常任务列表末尾增加与任务条目同级的“已搁置（n）”折叠区；该区域每次打开时默认收起。
- 在任务操作菜单中提供“搁置任务”与“取消搁置”，取消搁置后的任务追加到正常执行中列表末尾。
- 保持搁置任务位于正常执行中任务之后，且不参与正常任务的拖动排序。
- 约束生命周期命令链执行中的任务不可切换搁置状态；任务开始或结束后不保留搁置标记。

## 能力

### 新增能力

- `running-task-shelving`：持久化执行中任务的搁置状态，并提供执行中列表的折叠展示与切换操作。

### 修改能力

- 无。

## 影响

- 后端任务模型、生命周期服务与 Wails 绑定需要提供原子化的搁置状态切换和排序更新。
- 前端任务类型、API 包装、任务树和应用状态管理需要展示折叠区并刷新返回的完整任务列表。
- 需要更新 Go 与前端测试，以及 Wails 生成的绑定类型。
