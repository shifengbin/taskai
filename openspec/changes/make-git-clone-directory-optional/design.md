## Context

Git 仓库克隆是只读的系统生命周期命令。命令链通过引用的逐行追加参数配置克隆目录，当前设置层要求且仅接受一行 `dir=<相对目录>`；执行层将该目录与任务工作目录拼接，再将每个 Git 信息克隆到 `<克隆根目录>/<项目名称>`。

前端保存命令链时会去除空白行，因此未填写参数会以空数组提交。现有实现会在设置保存和执行前拒绝该数组，使用户即使希望克隆到任务工作目录下也必须手动填写 `dir=.`。

## Goals / Non-Goals

**Goals:**

- 让 Git 克隆命令的追加参数可留空，且将空参数稳定地解释为任务工作目录。
- 保留现有显式 `dir=<相对目录>` 配置和安全校验。
- 使界面、README 和错误处理清楚区分默认目录与自定义目录。
- 确保已有已保存的命令链无需迁移即可继续执行。

**Non-Goals:**

- 不允许绝对路径、父级目录或多个 Git 克隆参数。
- 不改变每个项目以其名称作为目标子目录、已有目标跳过或 Git 分支处理逻辑。
- 不新增按单个 Git 信息指定不同克隆目录的配置。

## Decisions

### 1. 将空参数数组定义为任务工作目录默认值

设置层在规范化 Git 克隆参数时接受零个非空参数；目录解析函数对此返回 `.`。执行层继续以任务工作目录为基准拼接路径，因此每个项目的最终目标为 `<任务工作目录>/<项目名称>`。

选择空数组而非在保存时转换成 `dir=.`：前者保留“用户未配置自定义目录”的语义，前端再次编辑时输入框也保持为空；后者会在不必要时写入显式配置并让用户误以为参数仍必填。显式 `dir=.` 继续有效，兼容已存在的链。

### 2. 显式参数规则保持严格不变

只要存在非空参数，系统仍要求恰好一条 `dir=<相对目录>`。空目录、未知键、多个参数、绝对路径以及经清理后跳出任务目录的路径均继续拒绝。这样放宽的是“是否需要配置目录”，而非目录边界安全策略。

另一种方案是允许 `dir=` 也表示默认目录；不采用该方案，因为它会掩盖输入错误，并与“空参数表示默认值”的语义重复。

### 3. 使用说明描述最终克隆位置

系统命令说明和 README 均表述为：参数可留空，默认克隆到 `<任务工作目录>/<项目名称>`；填写 `dir=<相对目录>` 时克隆到 `<任务工作目录>/<dir>/<项目名称>`。命令链编辑器可继续复用现有追加参数输入框，无需新增控件。

## Risks / Trade-offs

- [空数组可能来自旧链或外部调用] → 统一在设置规范化和运行时目录解析边界处理，结果始终为任务工作目录。
- [放宽校验导致路径逃逸] → 仅放行零参数；显式参数仍使用现有相对路径和父目录校验，执行前继续验证最终路径。
- [用户误以为仓库会直接覆盖任务目录] → 文档明确项目名称仍是目标子目录，多个仓库不会相互覆盖。

## Migration Plan

1. 更新参数规范化和目录解析逻辑，使空数组默认返回 `.`。
2. 保持已有 `dir=<相对目录>` 快照原样保存和执行，不进行数据迁移。
3. 更新系统说明、README 与前后端回归测试。
4. 若需回滚，已有显式 `dir` 配置不受影响；仅空参数的新命令链会在旧版本中恢复为校验错误。
