## Context

任务模板由设置中的 `TaskTemplates` 和 `ActiveTaskTemplateID` 管理。生命周期命令已经提供创建工作目录、指定仓库克隆、清单生成和 Git 仓库克隆；预置 `iterations-ai` 的初始化应在状态进入执行中前完成。Git 远程分支检查若未指定工作目录，会继承桌面应用进程的当前目录；该目录可能在应用运行期间被删除。

新安装可通过默认设置获得预置内容，但已保存设置的命令链切片通常不是 `nil`，既有归一化不会追加新的默认链。若在每次加载时无条件补齐，用户删除预置链后会在下次启动时重新出现，违反“可以删除”的要求。进行中的 `fix-lifecycle-chain-persistence` 变更也正在收紧普通设置保存与生命周期配置的字段所有权。

## Goals / Non-Goals

**Goals:**

- 为新安装和升级后的既有设置提供一致的默认分支模板及两条仓库操作预置链。
- 默认激活模板而不覆盖用户已经选择的其他模板。
- 让预置的 `beforeStart` 链通过适用范围校验，并保持其命令顺序和参数精确可见。
- 预置一次后允许用户按现有命令链删除规则删除链，且后续加载不重建。
- 不为两条预置链设置默认钩子映射。

**Non-Goals:**

- 不改变指定仓库克隆、清单生成或 Git 仓库克隆的参数格式、Git 凭据和分支检出策略。
- 不将“更新仓库”链扩展为 `git pull`、fetch、合并或覆盖已有工作树；其 Git 仓库克隆步骤继续仅克隆缺失目标。
- 不将普通设置保存改造成通用并发控制；生命周期字段持久化保护继续由现有独立变更负责。

## Decisions

### 1. 使用稳定预置标识和一次性版本迁移

为默认分支模板和两条命令链分配稳定的预置 ID，并在设置中持久化预置迁移版本。新安装直接写入最新版本和完整预置；版本 1 以下的旧数据补齐缺失预置，版本 2 将仍保持版本 1 内置结构的 `iterations-ai` 从 `postStart` 调整为 `beforeStart`，版本 3 补回版本 2 状态中异常缺失的默认分支模板。迁移完成后不再根据 ID 或名称自动重建内容，因此用户修改或删除预置链会永久保留其选择。

迁移在存储层读取、归一化后的最新数据上执行，并在同一原子保存中记录版本和预置，避免前端旧快照或普通设置保存覆盖生命周期配置。若用户已有当前模板选择，迁移不改变它；仅在没有当前模板时激活新增的“默认分支”模板。

备选方案是在每次生命周期归一化中调用默认链工厂。该方案实现较少，但用户删除后会被恢复，故不采用。仅修改 `Settings.Default` 则无法将预置交付给已有用户，也不采用。

### 2. 预置链是普通可删除链，而非受保护系统对象

两条预置链使用普通 `LifecycleCommandChain` 数据模型，只是创建时采用稳定 ID、名称、范围、命令引用和参数。它们不增加“内置”标记，也不加入固定链归一化；删除时继续遵循现有保护：被未执行或执行中任务引用的链不可删除，未被该类任务引用时可删除。

这样用户能自由修改、复制和删除仓库工作流，同时仍避免将正在运行任务指向不存在的链。备选方案是把它们做成固定链并每次归一化恢复，但这会与已确认的可删除要求冲突。

### 3. 默认分支模板使用空的必填字符串字段

预置模板名称为“默认分支”，其中唯一字段为 `branch`：显示名称“默认分支”、类型 `string`、`required=true`、默认值 `""`，且不注入环境变量。新安装和没有当前模板的既有设置将它设为活动模板；任务表单已有的必填字符串校验会阻止空白值保存。

空默认值使用户明确提供要检出的分支，而不把 `main`、`master` 或任意仓库默认分支误写为用户指定值。指定仓库克隆继续通过现有 `branch` 字段解析路径取得该值。

### 4. 扩展所需系统命令并固定两条链的范围

“创建任务工作目录”和“Git 仓库克隆”系统命令保留 `beforeStart`、`postStart` 范围。原有创建目录默认链仍只声明 `beforeStart`，故默认启动行为不变；两条预置链以外的 Git 克隆选择保持用户手动配置。

`iterations-ai` 仅适用于 `beforeStart`，命令顺序为：

1. 创建任务工作目录；
2. 克隆指定 Git 仓库，参数 `repository=git@gitlab.jiandan100.cn:webdev/iterations-ai.git`；
3. 生成清单文件，无追加参数；
4. Git 仓库克隆，参数 `dir=workspaces`。

“更新仓库”仅适用于 `updateTask`，命令顺序为：

1. 生成清单文件，无追加参数；
2. Git 仓库克隆，参数 `dir=workspaces`。

两条链都不写入 `LifecycleDefaultChains`。`iterations-ai` 在状态提交前创建或复用任务工作目录，随后指定仓库克隆可将仓库直接置于目录根部。Git 远程检查、远程分支克隆和默认分支克隆均使用目标父目录作为显式工作目录；本地分支创建仍在克隆后的目标目录执行。

## Risks / Trade-offs

- [指定仓库克隆后的后续步骤失败，重试从链首开始时根目录已经非空] → 保持既有严格的非空目录拒绝语义；用户须清理任务目录后重试，避免自动覆盖 Git 工作树。
- [“更新仓库”名称被理解为拉取远程更新] → 在命令链说明中明确其只重新生成清单并克隆缺失的 Git 信息，已有目标按 Git 仓库克隆现有语义跳过。
- [升级用户已选择自定义模板] → 仅在当前模板为空时激活预置模板，绝不改写已有选择。
- [预置迁移与生命周期持久化修复同时改动设置保存] → 实现时基于最新持久化设置应用迁移，并与 `fix-lifecycle-chain-persistence` 的字段所有权规则一并回归验证。
- [开始前链完成事件先于开始请求响应到达] → 前端在已收到执行中事件时拒绝旧的未执行开始结果覆盖，避免执行中标签为空。

## Migration Plan

1. 为默认设置和持久化设置增加预置版本，首次新建数据直接使用最新版本。
2. 加载旧数据时，在验证现有模板、命令和链后执行一次性补齐；只在当前模板为空时选中默认分支模板，且不改写默认链映射。
3. 保存迁移后的完整状态；后续加载检测到版本已更新，不重新插入用户已删除的预置链。
4. 若需回滚，保留版本字段和用户数据，仅停止创建新预置；既有链继续作为普通链可读取、编辑或删除。
