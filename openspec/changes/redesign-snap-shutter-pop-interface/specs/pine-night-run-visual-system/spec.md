## MODIFIED Requirements

### Requirement: 松林夜跑双模式视觉令牌
系统 SHALL 将现有 `colorScheme` 的亮色与暗色模式分别渲染为快门波普（Snap）视觉系统。亮色模式必须以近白画布 `#F1F5F4`、纯白表面、墨黑 `#10212B` 正文与描边建立明快层级；暗色模式必须以深夜画布 `#0B151A`、深层表面 `#16242B`/`#1F3038` 和高亮正文建立清晰的暗色层级。两种模式都必须以珊瑚 `#FF5A4E`（亮）/`#FF7A6E`（暗）为品牌与强调色、以钴蓝 `#1E66F5`（亮）/`#5C8CFF`（暗）为主要操作与结构/选中色，并将琥珀与紫罗兰限制在警告、信息、终端关键字或少量辅助提示，不得把高饱和色均匀铺满正文容器。

#### Scenario: 在亮色模式启动工作台
- **WHEN** 已保存的 `colorScheme` 为亮色且应用完成加载
- **THEN** 工作台必须显示近白画布、纯白表面、墨黑正文与描边、钴蓝主操作色、珊瑚品牌色和小面积琥珀/紫罗兰辅助提示

#### Scenario: 在暗色模式启动工作台
- **WHEN** 已保存的 `colorScheme` 为暗色且应用完成加载
- **THEN** 工作台必须显示深夜画布、深层表面、高亮正文和与亮色模式明显不同的暗色层级

#### Scenario: 验证关键文字可读性
- **WHEN** 在任一颜色模式查看正文、辅助正文、按钮文字、状态标签或表单标签
- **THEN** 这些文字与其实际背景的对比度必须不低于 4.5:1（大号或粗体 UI 不低于 3:1），且珊瑚填充上的文字必须为粗体大号或改用墨色以满足该阈值

### Requirement: 工作台与任务树保持跑道式层级
系统 SHALL 在不改变现有工作台布局和操作位置的前提下，使用 2–2.5px 实色描边、`Npx Npx 0` 错位硬投影、6–9px 圆角和 hover 抬起位移表现快门波普的新粗野层级。顶栏、任务树、状态标签、任务行、终端子项、详情区、空状态、分隔条及拖拽反馈必须使用同一视觉语言。每个未选中的任务行 MUST 以其用户定义的任务颜色渲染约 4% 不透明度的极浅背景，并继续以该颜色的左边框作为主要颜色标记。

#### Scenario: 查看未选中的任务项
- **WHEN** 用户在任一亮色或暗色模式中查看未选中的任务项
- **THEN** 任务项必须显示与左侧任务色条相同色相的极浅背景（约为该任务色的 4% 不透明度）、粗描边与硬投影卡片，且标题、描述、图标和操作控件保持清晰可辨

#### Scenario: 选择任务
- **WHEN** 用户在任务树中选择一个任务
- **THEN** 选中任务必须获得可见的快门波普选择态（钴蓝描边或填充），同时任务标题、描述、操作按钮和用户定义的任务颜色仍保持可辨认，且不得显示易被误解为新建任务状态的装饰性尾标

#### Scenario: 拖拽调整任务顺序
- **WHEN** 用户拖拽任务并悬停在有效插入位置
- **THEN** 插入指示器与拖拽预览必须使用快门波普主色或描边清晰标示目标，且不改变原有拖拽判定或排序行为

#### Scenario: 未选择任务或终端
- **WHEN** 用户未选择任务和终端
- **THEN** 详情区必须显示与快门波普主题一致、易读的引导空状态，且创建任务入口保持可见

### Requirement: 终端与实时状态的视觉连续性
系统 SHALL 让终端标题栏、终端背景、前景文字、光标、选择区和实时状态点适配快门波普视觉系统。终端背景必须叠加半色网点底纹，并通过 xterm 主题注入提示符珊瑚、成功信息钴蓝、关键字与光标紫罗兰的配色；无论工作台处于亮色或暗色模式，亮色模式终端背景必须使用快门波普浅次表面 + 半色网点，暗色模式必须使用比亮色更深的夜色次表面 + 半色网点；若亮色模式下输出可读性不足，亮色终端可回退为深色表面。终端标题栏不得出现影响终端图标或标题阅读的额外横杠装饰。终端的输入输出、尺寸调整、焦点、关闭、剪贴板和实时事件行为不得因视觉改造而变化。

#### Scenario: 在任意模式查看活动终端
- **WHEN** 用户在亮色或暗色模式选择一个活动终端
- **THEN** 终端必须使用高对比前景与背景、半色网点底纹和快门波普配色的高亮，且终端标题不与图标或额外横杠装饰重叠

#### Scenario: 在暗色模式查看活动终端
- **WHEN** 用户在暗色模式选择一个活动终端
- **THEN** 终端必须使用比亮色模式更深的背景和高对比前景，并保持终端标题、关闭操作和实时状态点可见

#### Scenario: 终端出现工作中或未读状态
- **WHEN** 终端实时状态为工作中或未读
- **THEN** 状态点必须使用快门波普主题一致的静态或脉冲提示（working=钴蓝、unread=琥珀、error=红、idle=muted），且其现有无障碍状态标签保持不变

### Requirement: 覆盖层与表单控件的一致视觉
系统 SHALL 为任务编辑、额外信息管理和编辑、模板编辑、设置、状态帮助、菜单项编辑、结束确认、退出确认、菜单、Popover、Snackbar、Alert、Accordion、Tab、Chip、TextField、Checkbox 和 Switch 提供一致的快门波普视觉外壳与状态样式：粗描边、硬投影、可见焦点与清晰的操作层级。该外壳不得改变任何覆盖层的打开、关闭、提交、校验或删除逻辑。

#### Scenario: 打开新建任务对话框
- **WHEN** 用户打开新建任务对话框
- **THEN** 对话框必须显示快门波普标题带、粗描边表单表面、可见焦点和区分取消与创建操作的按钮层级

#### Scenario: 填写内容很长的新建或编辑任务
- **WHEN** 任务模板字段、额外信息或生命周期命令链使任务表单内容超过可用视口高度
- **THEN** 对话框内容区必须在弹窗内部纵向滚动，标题和取消、创建或保存操作必须始终保持可见且可操作

#### Scenario: 打开设置与管理对话框
- **WHEN** 用户打开设置、额外信息或模板管理对话框并切换其中的既有标签或折叠区
- **THEN** 所有标签、折叠区、表单、帮助内容和操作栏必须保持一致主题且原有内容与切换行为不变

#### Scenario: 显示错误或危险操作
- **WHEN** 系统显示错误提示、删除操作或失败状态
- **THEN** 它必须使用可识别的语义错误表现和文字信息，不得只依赖颜色传达含义

### Requirement: 可访问的运动与交互反馈
系统 SHALL 为启动、任务开始、拖拽落点、执行状态、按钮悬停和对话框进场提供克制的快门波普动效与可见焦点状态，包括 hover/选中时的 `translate(-1px,-1px)` 抬起与硬投影加大。系统 MUST 在用户启用减少动态效果偏好时禁用抬起与进场等非必要动画，并保留等价的静态描边与投影反馈。系统 MUST 提供基于钴蓝的可见焦点环，且在亮暗两种模式与任务自定义颜色之上均可辨认。

#### Scenario: 默认动态效果偏好
- **WHEN** 用户未启用减少动态效果偏好并触发可动画的视觉状态
- **THEN** 动画必须在 120 至 350 毫秒内完成或为低干扰状态脉冲，交互元素在悬停/选中时产生抬起位移与投影变化，且不得引起布局重排

#### Scenario: 减少动态效果偏好
- **WHEN** 用户的系统启用 `prefers-reduced-motion: reduce`
- **THEN** 抬起、入场和脉冲等非必要动画必须被关闭或立即稳定，焦点、选中、执行和拖拽状态仍必须可辨认

### Requirement: 业务行为与语义保持不变
系统 SHALL 将本变更限制为视觉呈现。任务、终端、设置、生命周期、额外信息和退出流程的 API 调用、状态迁移、数据结构、快捷键、控件标签、键盘操作和业务结果必须保持不变。

#### Scenario: 完成一次既有任务操作
- **WHEN** 用户在新视觉中创建、编辑、开始、结束、排序或操作一个任务
- **THEN** 操作必须调用原有行为并产生与视觉改造前相同的任务和终端业务结果

#### Scenario: 使用键盘操作控件
- **WHEN** 用户通过键盘聚焦并操作既有按钮、表单字段、标签、菜单或对话框
- **THEN** 现有控件语义和键盘行为必须保持不变，且焦点指示必须在当前模式下可见

## ADDED Requirements

### Requirement: 快门波普图标系统
系统 SHALL 使用与 `design-preview` 同源的 Lucide 粗描边图标取代 Material `*Outlined` 细线图标，统一描边宽度约 2.25，并按原控件尺寸渲染。系统 SHALL 将品牌标记重绘为快门波普版（实色珊瑚方块 + 墨色粗描边 + 白色粗描边勾选/快门图形）。图标替换不得改变控件的无障碍标签、触发行为或所在位置。

#### Scenario: 查看工具栏与操作图标
- **WHEN** 用户查看顶栏、任务行、终端子项、设置或任何既有操作按钮中的图标
- **THEN** 图标必须为粗描边几何风格、描边宽度一致，并继承当前主题的墨色或语义色

#### Scenario: 查看品牌标记
- **WHEN** 用户查看顶栏或启动屏中的品牌标记
- **THEN** 标记必须为快门波普风格的实色珊瑚粗描边方块，并保持其原有品牌识别语义与引用方式

### Requirement: 快门波普字体系统
系统 SHALL 在标题使用 Hanken Grotesk、在正文与 UI 使用 Plus Jakarta Sans、在终端使用 JetBrains Mono，且三套字体必须以 woff2 离线自托管，不得在运行时请求外部 CDN。中文字形必须通过系统 Noto Sans SC 等回退呈现。系统 MUST 修正既有 Nunito `@font-face` 对未提供字重的错误声明。

#### Scenario: 离线运行应用
- **WHEN** 应用在无网络环境下启动并渲染任意界面
- **THEN** 标题、正文与终端文字必须以快门波普的三套自托管字体正确呈现，不得出现回退到系统默认衬线/无衬线字体的明显差异，也不得发起外部字体网络请求

#### Scenario: 渲染中文内容
- **WHEN** 界面渲染任务工作台、未执行、执行中等中文文本
- **THEN** 中文必须通过系统 CJK 字体清晰呈现，与拉丁字母的几何无衬线风格协调

### Requirement: 快门波普组件基础
系统 SHALL 在 Radix 无样式无障碍原语 + Tailwind CSS + lucide-react 之上渲染快门波普界面，并以 Tailwind 配置与 `:root`/`.dark` CSS 变量承载亮/暗令牌，替代既有基于 MUI 的 `createAppTheme`。系统 MUST 在本变更完成后不再于运行时依赖 `@mui/material`、`@mui/icons-material` 或 `@emotion/*`。组件迁移 MUST 保留既有控件的无障碍语义、键盘行为、焦点管理与触发逻辑。

#### Scenario: 应用不再依赖 MUI
- **WHEN** 本变更完成并构建应用产物
- **THEN** 运行时代码不得引用 `@mui/material`、`@mui/icons-material` 或 `@emotion/*`，且界面由 Radix 原语与 Tailwind 样式渲染

#### Scenario: 既有控件保持无障碍与键盘行为
- **WHEN** 用户通过键盘或辅助技术操作对话框、标签页、菜单、折叠区、开关、复选框或任何迁移后的控件
- **THEN** 控件必须保留焦点管理、键盘导航与既有 ARIA 语义，其打开、关闭、提交、校验或删除行为与迁移前一致
