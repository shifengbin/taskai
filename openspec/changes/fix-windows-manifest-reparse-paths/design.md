## Context

清单文件命令会在任务工作目录内逐级创建输出目录、以临时文件写入 YAML，并以目录句柄完成原子替换。Unix 实现只禁止最终工作目录和后续句柄相对路径经过符号链接；Windows 实现却以 `OBJ_DONT_REPARSE` 打开完整绝对工作目录。Windows 会因此拒绝完整路径中任一重解析点，返回 `STATUS_REPARSE_POINT_ENCOUNTERED`。

任务工作目录创建使用普通文件系统路径解析并允许工作区根目录位于联接点、挂载文件夹或同步目录下。因此同一任务可先创建目录、再在生成清单时失败。现有规格要求的是任务工作目录及输出路径安全，并未要求其上级路径不含重解析点。

## Goals / Non-Goals

**Goals:**

- 允许 Windows 解析任务工作目录的上级重解析点。
- 验证最终任务工作目录是实际目录且不是重解析点，然后仅用其已验证的目录句柄处理输出。
- 继续拒绝输出子目录和清单目标的重解析点，保留原子写入和失败语义。
- 通过 Windows 专属回归测试覆盖合法祖先联接点和不安全最终路径。

**Non-Goals:**

- 不允许任务工作目录自身、输出目录或输出文件成为重解析点。
- 不改变工作区根目录设置、其他生命周期命令或 Unix 实现。
- 不支持向任务工作目录外写入，也不改变清单内容和参数格式。

## Decisions

### 单独验证最终工作目录，而非禁止完整路径重解析

Windows 实现将为任务工作目录使用单独的打开流程：允许系统解析完整路径中的祖先组件，但在最终组件处以不跟随重解析点的方式取得句柄，并检查它是目录且不带重解析点属性。验证成功后，后续所有目录创建、临时文件写入和重命名都以该目录句柄为根。

这与安全需求直接对应：上级路径的解析不会使输出越过已取得的最终工作目录句柄，而最终目录本身不能被链接替换为外部位置。继续对完整绝对路径设置 `OBJ_DONT_REPARSE` 会错误拒绝合法工作区；仅以字符串规范化或 `filepath.EvalSymlinks` 判断则无法提供句柄级锚定，也不采用。

### 保持子路径和目标的句柄相对拒绝策略

已验证工作目录以下的每个输出目录组件继续使用相对目录句柄打开或创建，并拒绝重解析点。清单目标继续以“打开重解析点本身并检查属性”的方式验证，临时文件也继续在已验证目录句柄内创建。

这样自定义 `dir`、已存在目标和并发路径替换均不能将写入重定向到工作目录之外。放宽所有重解析点或改用普通路径 API 虽能避免当前失败，但会破坏现有边界保护，因此不采用。

### 明确 Windows 回归测试边界

Windows 专属测试将创建一个作为工作区上级目录的目录联接点，并验证清单成功写入其下的实际任务目录；还将覆盖最终任务目录或输出路径为重解析点时的拒绝行为。测试使用 Windows 可创建的目录联接点，避免依赖创建符号链接所需的开发者模式或管理员权限。

现有跨平台清单测试继续覆盖 YAML 内容、原子替换和普通文件目标；新增测试只验证 Windows API 的路径解析差异。

## Risks / Trade-offs

- [上级重解析点指向意外位置] → 最终目录在打开后立即验证，所有后续操作以该目录句柄为根，不再依赖可变的完整路径字符串。
- [Windows 对不同重解析点类型的打开行为存在差异] → 使用目录联接点进行回归测试，并将最终组件的非目录或无法安全打开情形统一视为不可用或不安全。
- [错误信息过于底层] → 对不安全最终目录返回领域错误，避免把 `STATUS_REPARSE_POINT_ENCOUNTERED` 暴露为合法上级路径的失败原因。

## Migration Plan

无需迁移配置或数据。发布更新后，曾在 Windows 上因上级重解析点失败的生命周期命令可以直接重试；回退到旧版本会恢复旧的严格拒绝行为，但不会影响已经生成的清单文件。
