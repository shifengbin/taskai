## ADDED Requirements

### Requirement: 按真实进程结果分类自然终端结束

系统 MUST 在终端输出流结束后取得进程的真实退出结果，并在终端退出事件中使用 `normal`、`unexpected` 或既有受控关闭原因进行分类。没有受控关闭原因时，退出码为 `0` MUST 分类为 `normal`；非零退出码、信号终止、无法取得有效进程状态或等待失败 MUST 分类为 `unexpected`。存在用户关闭、任务结束或应用关闭原因时，系统 MUST 保留该受控原因，且不得被进程退出码覆盖。退出码可用时，退出事件 MUST 携带该值。

#### Scenario: Unix 或 Windows 终端以零退出码自然结束
- **WHEN** 终端进程自然结束，且平台会话报告退出码为 `0`
- **THEN** 系统发布退出码为 `0`、退出原因为 `normal` 的终端退出事件

#### Scenario: 终端以非零退出码自然结束
- **WHEN** 终端进程自然结束，且平台会话报告非零退出码
- **THEN** 系统发布携带该退出码、退出原因为 `unexpected` 的终端退出事件

#### Scenario: 终端由信号终止或无法取得退出结果
- **WHEN** 终端进程由信号终止，或会话等待无法返回有效进程状态
- **THEN** 系统发布退出原因为 `unexpected` 的终端退出事件，且不得伪造退出码

#### Scenario: 用户主动关闭覆盖进程终止结果
- **WHEN** 用户关闭终端后，进程因该关闭返回信号终止或非零退出码
- **THEN** 系统发布退出原因为 `closed` 的终端退出事件，而不将其标记为 `unexpected`

### Requirement: 正常和受控结束自动清理终端

系统 MUST 在收到 `normal`、`closed`、`task-ended` 或 `application-shutdown` 终端退出事件时，移除对应实时状态记录、前端终端条目和前端终端会话。`normal` 结束 MUST NOT 将终端或任务实时状态标记为异常。

#### Scenario: 正常结束自动移除终端标签
- **WHEN** 前端收到退出原因为 `normal` 的终端退出事件
- **THEN** 对应终端从终端列表移除，xterm 会话被释放，任务实时状态按剩余终端重新聚合

#### Scenario: 正常结束不显示异常状态
- **WHEN** 某任务仅有一个以退出码 `0` 正常结束的终端
- **THEN** 该任务不保留终端级或任务级异常状态点

### Requirement: 异常退出保留可关闭的诊断快照

系统 MUST 在收到 `unexpected` 终端退出事件时保留对应终端条目与其只读输出快照，并将该终端投影为实时异常状态。快照 MUST 保留到用户手动关闭该终端、所属任务结束或前端应用卸载。用户成功关闭已退出的异常终端后，系统 MUST 移除其终端条目、输出快照和实时异常状态。

#### Scenario: 非零退出保留故障终端
- **WHEN** 前端收到退出原因为 `unexpected` 且退出码为 `1` 的终端退出事件
- **THEN** 终端条目保持可选择且显示为已退出，任务聚合状态包含异常，用户可查看该终端的只读输出快照

#### Scenario: 用户关闭异常快照
- **WHEN** 用户关闭一个已异常退出的终端
- **THEN** 系统移除该终端的前端条目和快照，并发布移除后的实时状态，使该终端不再参与任务状态聚合

#### Scenario: 异常终端所在任务结束
- **WHEN** 用户结束包含异常终端快照的任务
- **THEN** 系统释放该任务的所有终端快照和实时状态，且不影响其他任务的终端
