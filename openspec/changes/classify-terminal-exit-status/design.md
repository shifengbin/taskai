## Context

终端管理器的读取协程在输出流结束后调用 `Session.Wait()`，但忽略其返回值；退出原因仅记录用户主动关闭、任务结束和应用关闭。未记录原因的自然结束一律归为 `unexpected`。应用层据此将异常终端标记为实时错误，前端则将所有退出终端标记为 `exited` 并释放 xterm 会话。

因此，正常退出与异常退出在前端都留下标签，而异常标签又不保留可复查的输出。退出状态和终端会话均是运行时数据，不能写入任务持久化数据。共享终端契约还必须同时适配 Unix PTY 和 Windows ConPTY。

## Goals / Non-Goals

**Goals:**

- 根据真实进程退出结果区分自然正常结束和自然异常结束。
- 让正常自然结束、用户关闭、任务结束和应用关闭都自动释放前端终端条目与实时状态。
- 将异常终端变为不可输入的只读输出快照，保留到用户关闭、任务结束或前端卸载。
- 保持异常终端的实时错误状态；用户关闭该快照后清除相应实时状态。
- 用同一共享契约覆盖 Unix 与 Windows 的退出结果采集。

**Non-Goals:**

- 不持久化终端输出、退出状态或终端历史，不在应用重启后恢复快照。
- 不改变任务生命周期状态或把命令的非零退出转为任务结束失败。
- 不增加新的 Wails 绑定、设置项或第三方依赖。
- 不将已被用户或系统主动中止的进程误判为异常。

## Decisions

### 将退出结果提升为终端会话契约

`Session.Wait` 返回结构化的退出结果和仅表示等待基础设施失败的错误。结果包含可用的进程退出码；Unix 后端从 `exec.Cmd.ProcessState` 取得它，Windows 后端从 `os.Process.Wait` 返回的 `ProcessState` 取得它。Unix 的非零 `exec.ExitError` 代表进程已结束而非等待失败，必须转换为退出结果而不能丢弃。

当进程由信号终止、未取得有效进程状态或等待基础设施失败时，退出码视为不可用，并按异常结束处理。退出事件继续使用可选退出码字段，避免把平台内部的哨兵值当作用户可读退出码。

备选方案是在管理器中解析 `error` 文本。该方法无法覆盖 Windows，且依赖错误文案；不采用。备选方案是只在 Unix 实现中读取 `ProcessState`，会破坏共享契约的跨平台一致性；不采用。

### 显式终止原因优先于自然退出结果

管理器在用户关闭、任务结束和应用关闭前已记录受控退出原因。结束收尾时，若存在该原因则保留它；仅在没有受控原因的自然结束中，根据退出结果分类：退出码 `0` 为 `normal`，其余情况为 `unexpected`。

这样即使关闭操作最终导致进程返回信号或非零码，也不会把用户或系统的受控关闭显示为异常。

### 以退出原因驱动应用层与前端清理

应用层继续将 `unexpected` 映射为实时错误；`normal` 与全部受控结束通过现有实时状态移除机制清除终端投影。`CloseTerminal` 在终端管理器成功关闭或确认已关闭后也执行同一移除操作，使已退出异常快照被用户关闭时不会遗留任务级错误。

前端终端事件带上退出原因和可选退出码。正常或受控结束会移除对应终端记录；异常结束保留记录并标记为已退出。这样前端不自行推断退出码，也不会把任务级实时状态直接重置为 `idle`。

### 异常终端保留冻结的只读 xterm 快照

前端会话注册表在异常退出时保留已解析的 xterm 会话与最多 1000 行的既有滚屏，标记该会话不可写、不可粘贴、不可执行快捷键，也不再向后端发送尺寸更新。终端视图显示该快照但不提供活动终端的输入操作。用户手动关闭、所属任务结束或前端卸载时才销毁会话。

正常和受控结束仍立即销毁会话，保持既有资源释放行为。备选方案是把原始输出写进 React 状态后重放，但会破坏 ANSI 状态且造成无界内存增长；不采用。备选方案是继续释放异常会话，只保留树条目，无法满足复查失败输出的目标；不采用。

## Risks / Trade-offs

- [异常快照占用前端资源] → 继续使用 1000 行滚屏上限，并在手动关闭、任务结束和卸载时释放。
- [退出事件与实时状态事件先后不同] → 使用现有实时事件版本号收敛任务状态，前端只按后端事件投影。
- [PTY 在进程结束前先报告读取错误] → 读取协程仍在结束收尾处等待进程并以最终退出结果分类；读取错误本身不覆盖受控退出原因。
- [Windows 与 Unix 语义不一致] → 两端都实现同一退出结果契约，并分别增加平台后端测试。
- [保留快照后触发无效输入或调整大小] → 在会话注册表和终端视图两层禁用交互与后端调用。

## Migration Plan

无需数据迁移。发布后，新建终端按新规则处理退出；历史运行时终端在应用重启时仍自然释放。回滚只需恢复退出分类与会话释放策略，不影响任务数据或设置。
