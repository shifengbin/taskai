## Why

终端进程自然结束时，系统没有读取退出码，而是将所有未预设原因的结束都视为异常。正常结束的终端因此长期显示为异常；真正失败的终端又会释放其前端输出，用户无法复查失败位置。

## What Changes

- 在 Windows 和 Unix PTY 会话中采集进程退出结果，区分正常结束、非零退出、信号终止和等待失败。
- 将退出码为 `0` 的自然结束标记为正常结束，并自动移除其终端条目、实时状态记录和前端会话。
- 将非零退出、信号终止或无法取得有效退出结果的自然结束标记为异常，并携带可用的退出码。
- 对异常退出保留只读、有限滚屏的终端输出快照，直到用户手动关闭该终端；正常结束及受控关闭继续及时释放资源。
- 让用户关闭保留的异常快照后，同步清除对应实时异常状态，避免任务状态与可见终端不一致。

## Capabilities

### New Capabilities

- `terminal-exit-status-classification`: 根据进程真实退出结果分类终端结束，并驱动正常自动清理与异常保留行为。

### Modified Capabilities

- `terminal-output-retention`: 将异常退出的只读输出快照纳入终端会话保留与释放规则。

## Impact

- 后端：`internal/terminal` 的跨平台会话契约、Unix/Windows 后端和终端事件；`app.go` 的实时状态投影与手动关闭处理。
- 前端：终端事件类型、终端列表状态归约、xterm 会话释放策略，以及只读异常快照的交互限制。
- 测试：终端管理器、平台后端、应用实时状态和前端状态/会话测试。
- 不涉及任务持久化、Wails 公开绑定签名或新增第三方依赖。
