## Context

任务实体目前只保存标题、描述、颜色、附加信息与生命周期命令链。设置保存了生命周期命令、命令链和默认链；所有数据由同一个 `tasks.json` 文件持久化。生命周期命令链在执行前将 `realtime.TaskResource` 序列化为标准输入 JSON，自定义命令则额外接收 `TASKAI_TASK_ID` 环境变量。

本次变更引入可全局选择的任务模板。模板不是任务快照：设置中当前选择的模板始终决定新建和编辑任务的字段，以及 HTTP 和生命周期命令链对外输出的字段。任务只独立保存按键索引的实际值，以避免模板调整时丢失历史数据。

## Goals / Non-Goals

**Goals:**

- 在设置中维护多个具名任务模板，并选择一个当前使用模板。
- 让模板字段在任务描述与颜色之间输入，支持字符串、布尔、必填和默认值。
- 让当前模板字段以原生 JSON 基元形式出现在任务 HTTP 列表、详情和生命周期命令链标准输入中。
- 仅将显式标记的字段转换为自定义生命周期 Shell 命令环境变量。
- 兼容没有模板和没有任务模板值的既有数据，并保留模板变更前的历史值。

**Non-Goals:**

- 不为每个任务绑定或快照模板定义，也不提供历史模板字段的界面。
- 不通过 HTTP 接口编辑模板或任务模板值。
- 不向普通终端、任务菜单命令、前后置脚本或内置生命周期命令注入模板环境变量。
- 不将模板字段作为密码或其他敏感信息的存储方案。

## Decisions

### 1. 模板定义位于设置，任务仅保存值映射

新增 `TaskTemplate` 与 `TaskTemplateField`。模板保存稳定 ID、唯一的非空名称和有序字段；字段保存 `key`、显示名称、输入类型（`string` 或 `bool`）、必填标记、类型匹配的默认值与环境变量注入标记。`Settings` 保存 `TaskTemplates` 和可为空的 `ActiveTaskTemplateID`。

`Task` 增加 `TemplateFields map[string]any`，其值只允许字符串或布尔值。模板变更时不扫描或重写全部任务：删除模板、删除字段或变更字段键后，旧键和值继续持久化，但不属于当前模板的键不参与表单、HTTP、标准输入和环境变量生成。字段重新以相同键加入后，可恢复历史值。

这是对“任务快照模板”的选择性放弃。快照可以保持历史界面稳定，但与“按设置中的最新模板显示新建和编辑任务”的需求冲突；纯粹从设置即时读取且不保存值又无法可靠编辑和执行命令。因此选择全局定义加任务值映射。

### 2. 在保存边界验证定义和值

模板名称在设置中唯一。字段键使用 ASCII 字母开头、后续为字母、数字或下划线的格式，并在同一模板内按大小写不敏感方式唯一。键转换为大写后不得对应 `TASKAI_TASK_ID`、`TASKAI_TERMINAL_ID`、`TASKAI_STATUS_API`、`TASKAI_EXEC_COMMAND` 或 `TASKAI_EXEC_ARGUMENTS`，以避免覆盖应用运行时变量及 PowerShell 启动变量。

字段默认值和任务当前字段值必须与字段类型匹配。必填字符串去除首尾空白后必须非空；必填布尔字段必须为 `true`。模板中已有任务值的字段不得直接更改输入类型，避免同一键在既有任务中出现无法解释的值类型；需要改变类型时以新键新增字段并保留旧键为历史值。

新建任务按当前模板初始化所有字段默认值。编辑旧任务时，当前模板中缺失的键在表单中使用默认值；已存在值（包括空字符串）不被新的默认值覆盖。保存时仅合并当前模板字段，其他历史键保持不变。

### 3. 前端在设置与任务表单中使用同一模板定义

设置弹窗增加任务模板管理区：可新增、编辑、删除模板，编辑字段顺序和字段属性，并选择当前使用模板。删除当前模板时，活动模板选择清空；无活动模板时任务表单不显示模板字段区。

任务对话框在“任务描述”之后、“任务颜色”之前渲染当前模板的有序字段。字符串使用文本输入，布尔使用复选框；必填布尔字段以勾选为保存条件。前端提供即时提示，后端仍作为最终校验者。

### 4. 通过同一资源模型提供 HTTP 与命令链 JSON

`realtime.TaskResource` 新增非省略的 `templateFields` 对象。构建任务 HTTP 列表、任务详情和生命周期命令链输入时，均根据当前设置中的活动模板筛选任务值；无活动模板或任务没有可见值时输出 `{}`。值保持字符串或 JSON 布尔值，不包含字段显示名称、必填标记、模板 ID 或其他设置元数据。

命令链标准输入继续由 `lifecycle.BuildCommandInput` 构建，因此与 HTTP 资源使用相同的 `templateFields` 语义。生命周期运行开始时从同一次已加载的设置和任务快照构建输入及环境变量，保证同一次链中每条自定义命令看到一致的数据。

### 5. 环境变量仅服务自定义生命周期 Shell 命令

根据当前模板按字段定义顺序生成环境变量。标记注入的字符串字段直接使用其值；布尔字段使用 `true` 或 `false`。即使可选字符串为空，也传入 `TASKAI_<KEY大写>=`，使命令可区分“字段可用但为空”和“字段未被模板声明”。

这些变量追加到生命周期 `CommandChainRequest.Environment`，并只被 `LifecycleCommandKindCustom` 传给 Shell。创建和删除工作目录直接调用 Go 实现，Git 克隆使用独立 Git 执行器，因此保持现有行为且不伪造环境变量支持。

## Risks / Trade-offs

- [当前模板调整会改变历史任务的对外字段] → 这是全局最新模板语义的预期行为；仍保留历史值，以便同键字段恢复时再次可用。
- [环境变量可能暴露字段值给子进程] → 仅由用户显式勾选字段启用，不将其用于敏感信息，并校验保留变量名。
- [HTTP 列表响应增大] → 仅返回当前模板的原始键值，不返回定义元数据；这是支持外部扩展批量读取的必要开销。
- [字段类型变化造成既有值歧义] → 当任何任务已保存该键时拒绝修改输入类型，要求使用新键完成迁移。
- [旧客户端不了解新增响应字段] → 新字段为附加字段，既有客户端可忽略；无模板时始终返回空对象，便于客户端稳定处理。

## Migration Plan

1. 扩展设置和任务 JSON 模型，并在加载时将缺失的模板集合、活动模板 ID 和任务值映射归一化为空集合、空 ID 和空对象。
2. 保存设置时验证模板及活动模板引用；保存任务时合并当前可见字段，保留未知历史键。
3. 扩展 Wails 绑定、前端类型与 API 包装，再实现设置管理和任务表单。
4. 扩展任务资源和命令链环境构建，并用单元及集成测试覆盖 HTTP、标准输入和环境变量。
5. 旧版本会忽略新增 JSON 字段；若需回滚，旧任务核心字段、附加信息和生命周期链保持可读。

## Open Questions

无。模板全局生效、历史值保留、HTTP 范围、必填布尔语义和默认值策略均已确认。
