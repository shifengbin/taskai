## ADDED Requirements

### Requirement: 使用可记忆的个人访问令牌连接私有 GitLab
系统 MUST 在额外信息管理的 Git 分类中提供“从 GitLab 导入”入口，并要求用户输入 GitLab 地址、用户名和个人访问令牌。系统 MUST 只接受包含主机的 HTTP 或 HTTPS 地址，MUST 保留私有部署子路径，MUST 使用令牌查询当前用户并校验返回用户名与输入用户名一致。系统 MUST 允许 HTTP 地址，但 MUST 在发送请求前明确提示访问令牌将通过未加密连接传输。系统 MUST 明确提示三项连接信息会以未加密形式保存在本机。项目读取接口 MUST 不直接保存连接；前端 MUST 仅在确认完整项目响应仍属于当前弹窗请求后，通过专用保存接口把经过裁剪的地址、用户名和原始访问令牌写入本地配置，并仅在保存成功后展示项目。下次打开弹窗时 MUST 自动回填三项内容。

#### Scenario: 使用 HTTPS 私有地址连接
- **WHEN** 用户输入有效的 HTTPS GitLab 私有部署地址、匹配的用户名和具有读取 API 权限的个人访问令牌
- **THEN** 系统验证令牌身份、完整读取该用户可访问的项目，并在成功后明文保存三项连接输入

#### Scenario: 过期项目响应不保存连接
- **WHEN** 用户在项目读取期间关闭弹窗，随后较早请求的完整项目响应才返回
- **THEN** 系统忽略该响应，不展示项目且不保存该请求的地址、用户名或访问令牌

#### Scenario: 使用 HTTP 私有地址连接
- **WHEN** 用户输入有效的 HTTP GitLab 地址
- **THEN** 系统在连接前显示访问令牌将被明文传输的警告，并仍允许用户继续连接

#### Scenario: 令牌用户与输入用户名不一致
- **WHEN** GitLab 当前用户接口返回的用户名与用户输入用户名不一致
- **THEN** 系统停止读取项目并提示令牌对应用户不一致，且错误中不包含访问令牌

#### Scenario: 再次打开时恢复成功连接
- **WHEN** 用户成功读取项目后关闭 GitLab 导入弹窗并再次打开，或重启应用后再次打开
- **THEN** GitLab 地址、用户名和访问令牌自动恢复为上一次成功连接使用的值，仓库地址格式仍默认为 SSH

#### Scenario: 失败连接不覆盖已保存默认值
- **WHEN** 用户修改连接输入后遇到认证、网络、分页、已有信息读取或本地保存失败
- **THEN** 当前弹窗保留本次输入供重试，但专用本地配置仍保持上一次成功连接的三项值

### Requirement: 完整获取认证用户可访问的全部项目
系统 MUST 通过 GitLab 项目接口获取认证用户可访问的全部 public、internal 和 private 项目，且 MUST NOT 将查询限制为仅成员项目。系统 MUST 使用严格连续的分页读取全部结果，并仅在所有分页均成功后向用户展示项目；任一页请求、响应状态、跳页、顶层 `null` 或数据解析失败时，系统 MUST 丢弃本次全部项目结果，不得展示部分列表。系统 MUST 返回项目 ID、项目名、完整路径、SSH 地址、HTTPS 地址、归档状态和可见性供选择界面使用。

#### Scenario: 获取多页可访问项目
- **WHEN** GitLab 将用户可访问的项目分为多页返回，其中包含 public、internal 和 private 项目
- **THEN** 系统读取全部页并在完成后一次展示所有项目，且查询不使用仅成员项目过滤

#### Scenario: 后续分页失败
- **WHEN** 第一页项目读取成功但任一后续页连接失败、返回错误状态或包含无效数据
- **THEN** 系统提示项目读取失败并丢弃已读取页面，不展示残缺项目列表

#### Scenario: 展示归档项目
- **WHEN** 完整项目结果中包含归档项目
- **THEN** 系统显示该项目及“已归档”标记，并允许用户主动选择它

### Requirement: 模糊筛选并选择要导入的项目
系统 MUST 在项目首次加载后保持全部项目未选择，并 MUST 提供忽略大小写的模糊筛选，同时匹配项目名称和 `namespace/project` 完整路径。系统 MUST 以 GitLab 项目 ID 保存选择状态，使筛选条件变化不清除筛选范围外的选择。系统 MUST 提供“全选当前结果”和“取消选择当前结果”操作，两者 MUST 仅影响当前筛选结果中的可选项目。系统 MUST 显示当前结果数量、项目总数和全部筛选范围下的已选择数量，并 MUST 在没有选择项目时禁用导入操作。

#### Scenario: 按完整路径模糊筛选
- **WHEN** 用户输入不同大小写的部分群组名或项目名
- **THEN** 系统显示名称或完整路径包含该内容的项目，并隐藏其他项目

#### Scenario: 全选仅作用于当前结果
- **WHEN** 用户筛选出一组项目并点击“全选当前结果”
- **THEN** 系统选择当前结果中所有可导入项目，且不改变筛选结果之外的选择状态

#### Scenario: 取消选择仅作用于当前结果
- **WHEN** 用户在多个筛选条件下选择了项目，再对当前结果点击“取消选择当前结果”
- **THEN** 系统只取消当前结果中的选择，其他筛选范围内已经选择的项目保持不变

#### Scenario: 筛选变化保留选择
- **WHEN** 用户选择项目后修改或清空模糊筛选条件
- **THEN** 已选项目仍保持选择，导入按钮显示全部已选项目数量

### Requirement: 统一选择 SSH 或 HTTPS 仓库地址
系统 MUST 为整个导入列表提供一个仓库地址格式下拉选项，默认值 MUST 为 SSH。切换地址格式 MUST 同时更新全部项目的地址预览和最终导入地址，且 MUST 不改变项目选择状态。系统 MUST 使用 GitLab 返回的 SSH 或 HTTPS clone 地址，不得把个人访问令牌拼入仓库地址。

#### Scenario: 默认使用 SSH 地址
- **WHEN** 项目列表首次显示
- **THEN** 地址格式为 SSH，所有项目预览和导入候选值均使用 GitLab 返回的 SSH 地址

#### Scenario: 统一切换为 HTTPS
- **WHEN** 用户把地址格式切换为 HTTPS
- **THEN** 全部项目预览和最终导入地址切换为 HTTPS，已有项目选择保持不变，地址中不包含个人访问令牌

### Requirement: 识别并跳过已经导入的 GitLab 项目
系统 MUST 以 GitLab 返回的 SSH/HTTP clone endpoint 与项目完整路径识别重复项目，并 MUST 将匹配任一 endpoint 的标准 URL、结尾 `.git` 和路径分隔写法视为同一身份。系统 MUST 允许私有部署的 HTTP clone 地址包含相对路径前缀，并允许 HTTP 与 SSH 使用不同主机或端口，只要求每个 clone 地址的仓库路径以 `path_with_namespace` 结尾。系统 MUST 在选择列表中标记已经存在于 Git 分类的信息并禁止选择，且 MUST 在保存前基于最新持久化数据再次检查重复。没有共享 clone endpoint 的不同 GitLab 项目 MUST NOT 被视为重复。保存前新发现的重复项目 MUST 被正常跳过并计入结果，不得导致其他有效选择失败。

#### Scenario: 已有 SSH 地址匹配 HTTPS 候选项目
- **WHEN** Git 分类已有 `git@gitlab.example.com:team/api.git`，本次项目的 HTTPS 地址为 `https://gitlab.example.com/team/api.git`
- **THEN** 系统将该项目标记为“已导入”、禁止选择，并从当前结果全选范围中排除

#### Scenario: 不同主机的相同路径可分别导入
- **WHEN** Git 分类已有 `git@gitlab-a.example.com:team/api.git`，本次项目来自 `gitlab-b.example.com` 的 `team/api`
- **THEN** 系统不把本次项目标记为重复并允许选择导入

#### Scenario: 保存前出现新的重复项目
- **WHEN** 项目列表加载后、批量保存前，同一 GitLab 项目已经通过其他操作加入 Git 分类
- **THEN** 系统跳过该项目、继续保存其他有效选择，并在结果中增加跳过数量

### Requirement: 原子批量写入内置 Git 分类
系统 MUST 使用当前内置 Git 模板把全部非重复选择批量创建为可复用信息。每条信息的 `name` MUST 为 GitLab 项目名称，`repository` MUST 为统一地址格式对应的 clone 地址；模板新增固定字段 MUST 使用当前默认值。系统 MUST 在一次受控存储操作中完成加载、校验、追加和文件替换。除正常重复跳过外，任一项目校验失败或持久化失败时 MUST 不写入任何本批项目。成功结果 MUST 返回导入数量和重复跳过数量，并使前端刷新和展开 Git 分类、清理项目选择临时状态并关闭导入弹窗；专用本地默认连接 MUST 保持不变。

#### Scenario: 批量导入多个项目
- **WHEN** 用户选择多个有效且未导入的项目并执行导入
- **THEN** 系统一次保存全部项目，每条信息使用项目名和所选格式的仓库地址，并提示成功导入数量

#### Scenario: 应用 Git 模板新增字段默认值
- **WHEN** 当前内置 Git 模板包含用户新增且设有默认值的固定字段
- **THEN** 每条批量导入信息都保存该字段的当前默认值

#### Scenario: 批量校验失败不部分写入
- **WHEN** 所选项目中任一非重复项目不满足 Git 信息校验
- **THEN** 系统拒绝本次批量导入且不写入任何所选项目，前端保留选择供用户重试

#### Scenario: 批量保存失败不部分写入
- **WHEN** 全部项目校验成功但最终数据文件替换失败
- **THEN** 系统报告保存失败且既有数据和本批项目前状态保持不变，前端保留选择供用户重试

### Requirement: 提供可重试且不泄露凭据的失败反馈
系统 MUST 区分并反馈无效地址、连接超时、证书不受信任、认证失败、权限不足、API 不存在、请求频率限制、用户名不匹配、分页失败和批量保存失败。连接或获取失败 MUST 保留连接表单输入并允许重试，导入失败 MUST 保留项目列表、筛选条件、地址格式和选择并允许重试。除专用默认连接读取接口外，任何日志、用户可见错误和返回数据 MUST NOT 包含个人访问令牌、认证请求头或包含敏感数据的响应正文。

系统 MUST 拒绝把携带令牌的 HTTPS 请求重定向到 HTTP。项目读取期间系统 MUST 冻结三项连接输入但允许取消；用户关闭弹窗后，系统 MUST 忽略晚到结果且不得保存该请求的默认连接。默认连接保存期间系统 MUST 禁止关闭弹窗。批量导入写入期间系统 MUST 禁止关闭弹窗，并 MUST 冻结连接输入、项目读取、筛选、地址格式、单项选择和当前结果批量选择操作，在操作完成后再解锁或清理临时状态并关闭。

#### Scenario: 认证失败后重试
- **WHEN** GitLab 返回认证失败
- **THEN** 系统显示认证错误、保留本次连接输入供用户修正，且提示和日志中不包含访问令牌，也不覆盖上一次成功保存的默认连接

#### Scenario: 请求频率受限
- **WHEN** GitLab 返回请求频率限制响应
- **THEN** 系统显示可识别的频率限制错误并允许用户稍后重试，不展示任何部分项目

#### Scenario: 导入失败后重试
- **WHEN** 用户已经选择项目但批量导入失败
- **THEN** 项目列表、筛选条件、地址格式和选择状态保持不变，用户可以再次执行导入

#### Scenario: 导入期间尝试修改选择状态
- **WHEN** 批量导入写入尚未完成，用户尝试修改连接、筛选、地址格式或项目选择
- **THEN** 所有相关控件保持禁用且状态不变；若写入失败，原状态完整恢复为可操作并允许重试
