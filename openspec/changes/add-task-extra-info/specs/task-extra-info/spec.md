## ADDED Requirements

### Requirement: 独立维护额外信息分类和模板
系统 MUST 在设置功能之外提供独立的额外信息管理入口，供用户创建、查看和删除分类，并在分类下创建、查看、修改和删除可复用的额外信息模板。分类 MUST 使用唯一且非空的名称。模板 MUST 保存已存在分类的 `catalogue`、信息展示名称、一个或多个固定字段及零个或多个参数定义；每个固定字段 MUST 保存键、显示名称和静态值，每个参数定义 MUST 保存参数键、显示名称和必填标记。

#### Scenario: 创建分类并在其中创建带多个字段和参数的模板
- **WHEN** 用户新建 `git` 分类，并在额外信息管理中选择该分类保存一个包含展示名称、多个固定字段以及多个参数定义的有效模板
- **THEN** 系统持久化该模板，并在后续创建或编辑任务时将其作为可选信息提供

#### Scenario: 模板只能选择已有分类
- **WHEN** 用户新建或编辑模板时选择一个不存在的分类
- **THEN** 系统拒绝保存该模板，并提示必须选择已创建的分类

#### Scenario: 空分类可以删除
- **WHEN** 用户删除一个不包含任何信息模板的分类
- **THEN** 系统删除该分类，且不修改任何已有任务保存的附加信息

#### Scenario: 包含模板的分类不可删除
- **WHEN** 用户尝试删除一个仍包含一个或多个信息模板的分类
- **THEN** 系统拒绝删除并提示先删除该分类下的全部信息模板

#### Scenario: 管理入口不属于设置
- **WHEN** 用户查看顶部工具栏
- **THEN** 系统在设置按钮旁展示额外信息管理入口，且不在设置弹窗中提供额外信息管理标签

#### Scenario: 删除模板不改变任务快照
- **WHEN** 用户删除已经被一个或多个任务选用的模板
- **THEN** 系统从可选模板中移除该模板，且不修改任何已有任务保存的附加信息

### Requirement: 校验模板字段与参数定义
系统 MUST 拒绝保存未选择已有分类、缺少信息展示名称、未包含固定字段或包含不完整固定字段的模板。每个固定字段的键、显示名称和静态值 MUST 非空。同一 `catalogue` 内的信息展示名称 MUST 唯一；同一模板内的全部固定字段键和参数键 MUST 唯一，且不得彼此冲突。

#### Scenario: 保存重复展示名称被拒绝
- **WHEN** 用户在同一 `catalogue` 中保存与现有模板展示名称相同的模板
- **THEN** 系统拒绝保存并提示展示名称重复

#### Scenario: 保存冲突字段键被拒绝
- **WHEN** 用户保存一个固定字段键与另一固定字段键或参数键相同，或保存重复参数键的模板
- **THEN** 系统拒绝保存并说明字段键冲突

### Requirement: 创建和编辑任务时保存附加信息快照
系统 MUST 在创建和编辑任务时提供分类选择器，以当前分类筛选可勾选模板，并允许一个任务选择多个信息。切换分类 MUST 保留先前在其他分类勾选的信息。系统 MUST 在表单上方集中展示全部已选信息，每个信息使用紧凑方形标签并提供 `x` 移除按钮。选中模板后，系统 MUST 展示其固定字段和参数输入；必填参数去除首尾空白后为空时，系统 MUST 阻止保存。保存成功时，任务 MUST 记录模板分类、固定字段、参数定义和参数实际值的独立快照。

#### Scenario: 创建任务并选择多个 Git 仓库
- **WHEN** 用户创建任务时选择两个 `catalogue` 为 `git` 的仓库模板，并为各自的必填 `branch` 参数填写值
- **THEN** 系统创建任务并保存两个仓库及其各自的分支参数快照

#### Scenario: 跨分类选择保持不变
- **WHEN** 用户先在 `git` 分类勾选一个信息，再切换到另一分类并勾选信息
- **THEN** 两个信息均保留为已选状态，并在表单上方分别显示可通过 `x` 移除的方形标签

#### Scenario: 编辑任务修改附加信息
- **WHEN** 用户编辑已有任务并移除一个附加信息、添加一个当前模板以及修改保留信息的参数值
- **THEN** 系统保存更新后的任务快照，且不修改任何模板定义

#### Scenario: 编辑已删除模板的历史快照
- **WHEN** 用户编辑包含已删除模板快照的任务
- **THEN** 系统展示该快照，并允许用户修改其参数值或将其移除

### Requirement: 任务详情按目录输出附加信息
系统 MUST 在 `GET /api/v1/tasks/{taskId}` 的成功响应中包含 `extraInfo` 对象。系统 MUST 以每条任务附加信息的 `catalogue` 作为对象键，并将同一 `catalogue` 的信息聚合为数组。每个数组元素 MUST 将每个固定字段键映射为静态值，并将每个参数键映射为该任务保存的参数值。

#### Scenario: 返回按 Git 目录聚合的信息
- **WHEN** 客户端查询一个包含两个 Git 仓库附加信息的任务详情
- **THEN** 响应的 `extraInfo.git` 为包含两个对象的数组，且每个对象都包含仓库键和值及其分支键和值

#### Scenario: 接口不返回展示元数据
- **WHEN** 客户端查询包含附加信息的任务详情
- **THEN** `extraInfo` 中不包含信息展示名称、固定字段显示名称、参数显示名称或独立的 `catalogue` 字段

#### Scenario: 查询未附加信息的任务
- **WHEN** 客户端查询未选择任何附加信息的任务详情
- **THEN** 响应包含空对象 `"extraInfo": {}`

#### Scenario: 返回未填写的可选参数
- **WHEN** 客户端查询包含未填写可选参数的任务详情
- **THEN** 响应包含该参数键，且其值为空字符串

### Requirement: 保持旧数据和既有任务接口兼容
系统 MUST 能够读取没有分类、额外信息模板或任务附加信息字段的既有数据文件。缺失分类集合且存在旧模板时，系统 MUST 从模板已有的 `catalogue` 去重生成分类；没有模板时使用空分类集合。系统 MUST 将旧单键、键显示名称和静态值的模板及任务快照兼容为包含一个固定字段的数据。系统 MUST 保持 `GET /api/v1/tasks` 的响应字段和筛选行为不变。

#### Scenario: 读取旧数据文件
- **WHEN** 应用加载不含额外信息字段的既有数据文件
- **THEN** 系统正常加载任务和设置，并允许用户开始管理附加信息

#### Scenario: 读取旧单键值模板
- **WHEN** 应用加载使用旧版单一信息键和静态值保存的额外信息模板或任务快照
- **THEN** 系统将其作为包含一个固定字段的兼容数据读取，且任务详情继续返回该键和值

#### Scenario: 查询任务列表
- **WHEN** 客户端请求 `GET /api/v1/tasks`
- **THEN** 系统按既有规则返回任务列表，且列表元素不增加 `extraInfo` 字段
