## ADDED Requirements

### Requirement: 应用启动时跨平台检测代理命令

系统 MUST 在每次应用启动并读取持久化设置后，分别按当前操作系统的可执行命令查找规则检测 `codex` 和 `claude`。Linux、macOS 与 Windows MUST 使用相同的候选命令和菜单补充语义；Windows 检测 MUST 接受系统命令查找规则解析出的 `.exe`、`.cmd` 等可执行命令形式。单个命令未找到或检测失败 MUST 仅将该命令视为不可用，不得阻止应用启动或影响另一个命令的检测。

#### Scenario: 两个代理命令均可用

- **WHEN** 应用启动时当前命令环境可以分别解析 `codex` 和 `claude`
- **THEN** 系统将两个命令都判定为可用，并继续补充各自的任务菜单设置

#### Scenario: 仅有一个代理命令可用

- **WHEN** 应用启动时只能解析 `codex`，不能解析 `claude`
- **THEN** 系统仅补充 `codex` 的任务菜单设置，且应用仍正常完成启动

#### Scenario: Windows 解析命令包装文件

- **WHEN** Windows 的命令查找规则将 `codex` 或 `claude` 解析为 `.cmd` 等命令包装文件
- **THEN** 系统将该代理命令判定为可用，且不得因其不是 `.exe` 而跳过对应菜单设置

### Requirement: 自动补充代理任务菜单设置

系统 MUST 为检测到的代理命令补充具有稳定标识的任务菜单命令项。`codex` 项的名称和启动命令 MUST 为 `codex`，参数 MUST 仅包含 `--yolo`；`claude` 项的名称和启动命令 MUST 为 `claude`，参数 MUST 仅包含 `--dangerously-skip-permissions`。两个命令项 MUST 启用显示终端，并按 `codex`、`claude` 的顺序追加到当前任务菜单设置末尾。系统 MUST 持久化发生的补充，使右键菜单、任务操作下拉菜单和菜单设置读取同一结果。

#### Scenario: 首次检测到 Codex

- **WHEN** 应用启动时检测到 `codex`，且设置中不存在 Codex 自动菜单项
- **THEN** 系统在现有菜单项之后追加名称为 `codex`、命令为 `codex`、参数为 `--yolo` 且显示终端的菜单设置并持久化

#### Scenario: 首次同时检测到两个命令

- **WHEN** 应用启动时同时检测到 `codex` 和 `claude`，且两个自动菜单项均不存在
- **THEN** 系统在保留所有现有菜单项及其顺序后，依次追加 `codex` 和 `claude` 自动菜单项并持久化一次完整设置

#### Scenario: 未检测到命令

- **WHEN** 应用启动时未检测到某个代理命令
- **THEN** 系统不为该命令新增自动菜单项，也不删除或修改任何已有菜单设置

#### Scenario: 启动同步与设置访问并发

- **WHEN** 前端在启动菜单同步尚未完成时请求读取或保存设置
- **THEN** 系统等待同步完成，并基于仓储中的最新完整设置返回或保存，不暴露旧菜单也不覆盖并发设置

### Requirement: 重复启动幂等且保留现有设置

系统 MUST 依据自动菜单项的稳定标识、已记录的删除选择和命令型菜单的精确启动命令判断是否需要补充。设置中已经存在相同稳定标识时，系统 MUST 保留该菜单项的已保存内容和位置，不得再次添加、重置或移动该项。除新追加的自动菜单项外，系统 MUST 保留所有系统菜单项和用户自定义菜单项的内容与顺序。

#### Scenario: 重复启动不产生重复项

- **WHEN** 设置中已经存在 Codex 和 Claude 自动菜单项，且应用再次启动并检测到两个命令
- **THEN** 系统不新增重复项、不改变菜单顺序，且无需仅因检测结果再次写入设置

#### Scenario: 保留用户修改的自动项

- **WHEN** 用户已经修改或移动具有 Codex 自动菜单稳定标识的菜单项，随后应用再次检测到 `codex`
- **THEN** 系统保留该菜单项的已保存内容和位置，不用默认值覆盖用户设置

#### Scenario: 保留同名但命令不同的用户自定义项

- **WHEN** 用户已有名称与代理相同、但启动命令不是精确 `codex` 或 `claude` 的自定义菜单项
- **THEN** 系统不修改或删除该自定义项，并继续按自动稳定标识、删除选择和精确启动命令判断是否需要补充

#### Scenario: 已有精确命令配置

- **WHEN** 用户已有命令型菜单的启动命令精确为 `codex` 或 `claude`，但菜单稳定标识、名称或参数与自动默认项不同
- **THEN** 系统认为对应命令已经配置，不追加自动项，并保留用户菜单内容和位置

### Requirement: 删除自动项后不再补充

系统 MUST 持久化用户删除 Codex 或 Claude 自动菜单项的选择。自动项被用户删除后，即使后续启动仍检测到对应命令，系统 MUST 不再自动添加该项。删除普通用户自定义菜单 MUST NOT 产生自动项删除记录。

#### Scenario: 删除 Codex 自动项后重启

- **WHEN** 用户从设置中删除具有 Codex 自动稳定标识的菜单项并保存，随后在仍可检测到 `codex` 的环境中重启应用
- **THEN** 系统不再自动添加 Codex 菜单项，并保留其他自动项和用户自定义菜单

#### Scenario: 删除普通自定义项

- **WHEN** 用户删除一个普通自定义命令菜单，且该菜单不使用自动代理稳定标识
- **THEN** 系统不把此次删除记录为 Codex 或 Claude 自动项删除选择

### Requirement: 自动菜单通过任务内嵌终端执行

自动补充的代理菜单项 MUST 复用现有显示终端任务菜单命令行为，在当前任务的任务操作目录中创建内嵌终端，并按菜单设置中的命令和参数启动代理。所有平台 MUST 保持参数边界；Windows 上通过 `.cmd` 等命令包装形式安装的代理 MUST 能在内嵌终端中启动。系统 MUST 保持已有任务状态、任务目录校验、终端环境变量和终端退出状态行为。

#### Scenario: 从执行中任务启动 Codex

- **WHEN** 用户在执行中任务的右键菜单或任务操作下拉菜单中选择 `codex`
- **THEN** 系统在该任务的操作目录创建内嵌终端，并以单独参数 `--yolo` 启动 `codex`

#### Scenario: 从执行中任务启动 Claude

- **WHEN** 用户在执行中任务的右键菜单或任务操作下拉菜单中选择 `claude`
- **THEN** 系统在该任务的操作目录创建内嵌终端，并以单独参数 `--dangerously-skip-permissions` 启动 `claude`

#### Scenario: Windows 命令包装文件可以启动

- **WHEN** Windows 上自动检测到的代理命令由 `.cmd` 等命令包装文件提供，且用户选择对应自动菜单项
- **THEN** 系统通过已配置 Shell 的命令执行语义在 ConPTY 内启动代理，不显示额外的后台控制台窗口

#### Scenario: fish 配置 Shell 可以启动

- **WHEN** Unix 平台配置的终端 Shell 为 fish，且用户选择任一自动代理菜单项
- **THEN** 系统使用 fish 的参数语义启动命令，并保持代理参数为独立参数
