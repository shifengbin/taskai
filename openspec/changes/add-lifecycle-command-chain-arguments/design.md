## Context

生命周期命令现有 `arguments` 字段保存命令的固定参数，命令链中的 `LifecycleCommandReference.arguments` 则保存按链追加的参数。运行时应用先复制命令固定参数，再按顺序追加引用参数。设置界面没有区分这两层含义：命令编辑器将前者简单标为“参数”，命令链编辑器始终为每个引用显示“链级参数”输入框。

本次变更只调整命令链追加参数的编辑能力。用户已确认，当一个命令关闭该能力时，已经保存的命令链及其追加参数必须保持不变并继续参与执行；关闭后仅不再显示输入框。

## Goals / Non-Goals

**Goals:**

- 让命令明确声明能否在命令链中配置追加参数。
- 在界面中明确区分固定参数和追加参数，并按命令能力显示后者的输入框。
- 保留旧配置和已保存链的追加参数，确保开关变更不改变历史链的执行结果。
- 为新字段提供可区分“旧数据缺失”与“用户显式关闭”的迁移语义。

**Non-Goals:**

- 不改变固定参数与链级追加参数的执行顺序。
- 不清理、拒绝或改写已保存链引用中的追加参数。
- 不为任务菜单命令、前后置脚本或普通终端命令增加同类开关。
- 不改变命令链的钩子范围、排序、复制或执行时序。

## Decisions

### 1. 使用参数模式枚举持久化，而非直接新增布尔值

为 `LifecycleCommand` 增加链级参数模式，取值为“允许”或“禁止”。前端将其表现为“允许在命令链中追加参数”的复选框。

直接新增布尔字段无法区分旧 JSON 中字段缺失与用户明确保存 `false`，会在迁移时误将旧命令判为禁止。枚举零值代表旧数据，规范化时转换为“允许”；新建命令的界面草稿则显式初始化为“禁止”，要求用户主动选择允许。这样保留旧版本“所有命令均可编辑链级参数”的行为，同时满足新增命令需要选择能力的交互。

替代方案是使用布尔指针区分缺失值。它会把可空类型传播到 Go、Wails 绑定和 TypeScript，且每个消费者都需处理空值；枚举的归一化边界更清晰。

### 2. 固定参数与追加参数继续独立保存，并无条件按既有顺序执行

`LifecycleCommand.arguments` 保持为固定参数，在命令编辑器中改标为“固定参数”。`LifecycleCommandReference.arguments` 继续作为链级追加参数。应用层仍按以下顺序构造调用：

```text
可执行命令 + 命令固定参数 + 命令链已保存的追加参数
```

参数模式不参与运行时拼接，也不作为 `normalizeLifecycleCommandReference` 的校验条件。否则，先保存带追加参数的链、再关闭命令能力时，设置加载或保存会拒绝该链，与“关闭不影响已保存的链”的要求冲突。

### 3. 参数模式只控制链编辑器的可编辑入口

命令编辑弹窗为自定义命令提供复选框。链编辑器根据当前命令模式决定是否渲染对应引用的“追加参数”多行输入框：允许时显示并编辑引用参数；禁止时完全不显示输入框。

禁止状态下，链草稿仍保留该引用原有的 `arguments` 数组，保存整条链时也原样提交。重新允许后，输入框重新出现并展示这些保留值。由此开关不会隐式丢失数据，也不会使历史执行不可见于运行结果。

系统命令同样具有固定模式：创建和删除任务工作目录禁止链级追加参数；Git 仓库克隆允许，因为其 `dir=<相对目录>` 由链引用配置。系统命令仍保持只读。

### 4. 在设置规范化边界完成兼容迁移

`NormalizeLifecycle` 在读取或保存设置时把缺失的参数模式归一化为“允许”，并拒绝未知枚举值。随后写回快照，使迁移只发生一次。历史链引用的参数不修改。

命令复制和链复制继续深复制原有数组；命令链的保存、加载和执行不因参数模式重排或清空引用参数。Wails 生成绑定与前端类型都使用归一化后的非空模式值。

## Risks / Trade-offs

- [关闭后历史追加参数在链编辑器中不可见] → 这是用户要求的“不显示参数框”结果；草稿和执行均保留数据，重新开启后可再次查看和修改。
- [外部调用绕过前端为禁止命令写入追加参数] → 后端保留这些值以满足历史链兼容；该模式是编辑器能力而非执行权限，不将其作为安全边界。
- [旧 JSON 被误认为显式禁止] → 使用可归一化的模式枚举，将缺失值固定迁移为允许，并用持久化测试覆盖。
- [Git 克隆参数框意外消失] → 系统 Git 克隆命令固定为允许追加参数，回归测试验证其 `dir` 参数仍可保存和执行。

## Migration Plan

1. 扩展生命周期命令模型、前端类型与 Wails 绑定，定义链级参数模式。
2. 在设置规范化中将缺失模式迁移为“允许”，并为三个系统命令写入固定模式；不触碰 `LifecycleCommandReference.arguments`。
3. 将命令编辑器初始化为明确的禁止状态，允许用户勾选；链编辑器按模式显隐追加参数框，同时保留隐藏引用的草稿值。
4. 先运行设置、存储、应用和前端的针对性测试，再运行项目规定的完整构建脚本。
5. 回滚到旧程序时新增模式字段会被旧版本忽略，旧版本仍会执行已保存的固定和追加参数。

## Open Questions

无。固定参数、链级追加参数、历史链保留和关闭后的界面行为均已确认。
