# 任务额外信息仅使用既有信息与空分类过滤设计

## 背景

额外信息管理中的信息可以定义自己的动态参数，任务选择信息后应只填写该信息及模板带入的参数值。当前任务编辑器仍允许新增、删除和修改参数定义，因而能产生不属于信息的数据。

同时，额外信息管理会为每个模板渲染信息分类，即使该分类当前没有任何信息，增加了无效列表项。

## 方案比较

1. 任务仅保留参数值控件，参数定义在信息管理中维护；信息列表仅渲染有实际信息的分类。采用此方案。
2. 只隐藏“新增动态参数”按钮，保留键、显示名称和类型编辑。仍可在任务中修改信息以外的数据。
3. 删除任务中所有动态参数区。会使任务无法填写模板和信息参数的值。

## 设计

### 任务额外信息

`TaskExtraInfoSnapshotFields` 只展示每条参数的值控件：文本参数使用现有文本输入，复选框参数使用现有复选框。参数键、显示名称、类型和必填定义均不再提供编辑界面，也不显示参数删除或“新增动态参数”操作。

参数定义继续在额外信息管理的信息编辑器中维护。创建或编辑任务不会再生成额外的任务级参数。历史任务不做迁移或特殊兼容处理。

### 信息分类列表

额外信息管理按模板遍历时，仅保留 `templateInfos.length > 0` 的分类。对于实际有信息、但被当前搜索条件筛空的分类，仍显示分类及“未找到匹配的信息”，保持搜索反馈完整。

## 验证

前端测试覆盖：

1. 任务选择信息后可填写带入参数的值，但不存在新增、删除或定义编辑控件。
2. 创建任务请求只包含信息带入的参数。
3. 信息管理隐藏实际没有信息的模板分类，同时保留搜索无匹配的非空分类。

完成后运行前端全量测试、Go 全量测试和 `scripts/build-linux.sh`。
