# GitLab 项目批量导入设计

## 背景

额外信息管理目前通过内置 Git 模板逐条保存项目名称和仓库地址。前端调用 `SaveExtraInfo` 后，存储层会为单条信息加载并替换完整 JSON 数据文件；直接循环该接口既会重复读写，也会在中途失败时留下部分导入结果。应用当前没有 GitLab 客户端，也没有 GitLab 默认连接配置。

本变更跨越 GitLab HTTP 通信、Wails 绑定、额外信息持久化和前端选择交互。目标实例可能部署在子路径上，可能使用 HTTP，并可能返回大量分页项目。用户明确接受把地址、用户名和访问令牌明文保存在本机；令牌仍不能进入日志或用户可见错误。

## 目标与非目标

**Goals:**

- 通过 GitLab 官方 REST API 读取认证用户可访问的全部项目，并严格处理身份校验和分页完整性。
- 在额外信息管理中提供可预测的筛选、选择、地址格式切换和重复项目反馈。
- 使用一次存储锁、一次数据加载和一次文件替换完成批量导入；除正常重复跳过外，失败时不留下部分结果。
- 保持现有 Git 信息结构、项目名称和生命周期克隆目录语义不变。
- 让网络错误、认证错误、权限错误和保存错误可区分且可重试，同时避免泄露令牌。
- 成功读取项目后明文记住 GitLab 地址、用户名和访问令牌，并在下次打开时自动回填。

**Non-Goals:**

- 不支持 GitHub、GitLab.com 专属流程、群组限定导入或仅成员项目模式。
- 不加密 GitLab 默认连接配置，不提供后台同步或定期刷新。
- 不模拟用户名密码网页登录，不创建或管理个人访问令牌。
- 不验证所选仓库能否通过本机 SSH 密钥或 Git 凭据管理器实际克隆。
- 不自动导入 GitLab 分支、主题、描述或其他项目元数据。

## 技术决策

### 1. 在 Go 后端使用标准库实现独立 GitLab 客户端

新增独立的 GitLab 集成组件，由 Wails 应用层接收 GitLab 地址、用户名和个人访问令牌并调用。客户端使用 `net/http`，先请求当前用户，再请求项目列表；不引入 GitLab SDK 或依赖用户安装 `glab`。前端不直接请求 GitLab，避免 WebView CORS 差异并集中处理分页、超时和错误分类。

连接地址仅允许 `http` 和 `https`，必须包含主机，不得包含 userinfo、查询参数或片段；地址中的部署子路径予以保留。HTTP 地址允许连接，但前端必须在发送令牌前持续显示明文传输警告。HTTPS 使用操作系统信任链，不提供跳过证书校验选项。

令牌使用 `PRIVATE-TOKEN` 请求头。HTTP 客户端只允许同一主机内的重定向，防止令牌被带到其他主机；分页只读取 GitLab 返回的数字页信息并基于原始地址构造下一页，不跟随响应提供的外部分页地址。

另一种方案是前端直接调用 REST API，但私有实例不一定允许跨域请求，且会扩大令牌在 WebView 中的使用范围。调用 `glab` 则要求额外安装和登录状态，无法作为桌面应用的稳定前提。

### 2. 先校验令牌身份，再完整读取全部可访问项目

客户端先调用当前用户接口，并以忽略大小写的方式比较返回用户名和输入用户名。不一致时停止，不继续读取项目。用户名用于防止误用其他账号的令牌；令牌本身仍是唯一认证凭据。

项目请求使用每页最大数量，并且不传 `membership=true`，以取得认证用户可访问的 public、internal 和 private 项目。客户端循环读取所有页，将结果暂存在内存中；任何一页请求、状态码、响应大小或解码失败时，丢弃全部暂存结果。页码必须单调递增，以避免异常响应造成无限循环。

返回给前端的项目模型只包含选择所需字段：项目 ID、项目名、完整路径、SSH 地址、HTTPS 地址、归档状态和可见性。访问令牌不得出现在返回模型或包装后的错误中。

### 3. 使用两阶段弹窗和基于项目 ID 的稳定选择状态

GitLab 导入弹窗先显示连接表单，获取成功后显示项目选择区。项目初始全部不选；归档项目保留在列表中并显示标记。前端在完整结果上本地执行忽略大小写的子串匹配，匹配项目名或完整路径。

选择状态保存为项目 ID 集合，与当前筛选结果分离。“全选当前结果”只向集合加入当前可见且未导入的项目，“取消选择当前结果”只移除当前可见项目；改变筛选条件不得清除其他选择。已导入项目显示但禁用，不参与全选和选择数量。

仓库地址格式使用弹窗级统一下拉框，默认 SSH。切换为 HTTPS 时只改变预览和最终导入所选字段，不改变选择集合。导入按钮显示全部筛选条件下的选择总数，选择为空时禁用。

### 4. 使用仓库身份规范化完成跨地址格式去重

重复身份由 GitLab 返回的 clone endpoint 与项目完整路径共同确定，而不是强制 SSH 与 HTTPS 完整 URL 归一化后完全相同。规范化器支持标准 HTTP/HTTPS/SSH URL 和 `git@host:namespace/project.git` 形式，统一主机大小写、路径首尾分隔符和 `.git` 后缀；每个项目同时保留 SSH 与 HTTP endpoint 身份。私有部署相对路径和 HTTP/SSH 独立主机或端口分别保留，没有共享 endpoint 的不同项目保持不同身份。

应用层在展示项目前读取现有 Git 信息并标记已经导入的项目。存储层在持有变更锁并加载最新数据后再次执行相同去重，避免列表读取后数据变化造成重复。保存时新发现的重复项目作为正常跳过并计数，不使整批失败。

不为 Git 信息增加 GitLab 项目 ID 或来源字段，避免数据迁移并保持手工录入信息兼容。代价是去重依赖可解析的标准 clone 地址；无法解析的既有地址不参与自动去重。

### 5. 在存储层提供原子批量导入操作

批量导入方法在一次 `mutationMu` 临界区内加载最新数据，定位当前内置 Git 模板，校验全部所选项目和地址格式，并使用现有额外信息构造规则在内存中生成信息。模板后来新增的固定字段继续使用模板默认值，既有 `name` 和 `repository` 字段分别写入 GitLab 项目名和所选 clone 地址。

全部非重复项目构造成功后才把它们追加到数据并调用一次现有临时文件替换保存。构造或保存失败返回错误且不产生可见的部分导入；成功返回导入数量、重复跳过数量和保存后的信息。前端据此显示结果、刷新并展开 Git 分类，然后清理项目、筛选和选择临时状态并关闭弹窗；已保存的默认连接保持不变。

循环调用现有单条 `SaveExtraInfo` 无法满足原子性，因此不采用。把批量事务放在前端也无法防止并发状态变化或中途磁盘错误。

### 6. 保持项目名语义，并增加完整路径辅助展示

导入后的 `name` 继续使用 GitLab 项目名，保证 Git 克隆生命周期命令仍创建 `<任务工作目录>/<项目名称>`。为区分不同群组的同名项目，额外信息管理列表和任务选择器在 Git 信息名称下方显示从仓库地址提取的完整路径。该路径只用于展示，不新增持久化字段；无法提取时继续只显示名称。

把 `namespace/project` 直接写入 `name` 会改变克隆目录并引入路径分隔符，因此不采用。

### 7. 对外提供可重试且脱敏的错误语义

GitLab 客户端把地址无效、连接超时、证书不受信任、认证失败、权限不足、API 不存在、请求频率受限、用户名不匹配和分页失败包装为可区分的中文错误。错误只包含 GitLab 主机、请求阶段和安全的状态信息，不包含请求头、令牌或完整响应正文。

获取失败保留连接表单输入并允许重试，但不展示部分项目且不覆盖上次成功配置。读取期间冻结连接输入但允许取消；晚到响应不得展示项目或保存连接。导入期间冻结连接、读取、筛选、地址格式和选择操作并禁止关闭，失败后完整保留状态供重试。成功连接后明文记住地址、用户名和令牌，关闭或导入成功只清理项目临时状态，下次打开重新回填默认连接。HTTP 警告属于连接状态提示，不被视为错误或阻断条件。

### 8. 使用专用本地字段记住默认连接

项目读取 Wails 方法不直接保存连接。前端确认完整响应仍属于当前弹窗请求后，才调用专用保存方法把裁剪后的地址、用户名和原始令牌写入现有 TaskAI 数据文件；保存期间禁止关闭弹窗。该字段不进入通用 Settings，弹窗只通过专用方法读取，保存方法不回传令牌。保存失败不展示项目，也不覆盖旧值；认证、网络、分页、已有信息读取或晚到响应同样保留旧值。

弹窗每次打开都重新读取默认连接并回填，关闭时清理项目、筛选、选择和本次未保存输入。仓库地址格式不持久化，仍默认 SSH。界面明确提示连接信息将以未加密形式保存在本机；不引入密钥环或加密层。

## 风险与取舍

- [GitLab 项目数量很大，完整加载耗时和占用内存] → 使用最大分页大小、请求超时和分页循环保护；只保留列表所需字段，并在完成所有分页前显示加载状态。
- [HTTP 私有部署会明文传输令牌] → 在连接表单明确持续警告；该兼容行为由用户确认保留。
- [本地数据文件包含明文令牌] → 沿用仅本机用户可读写的数据文件和专用接口，界面明确提示，不记录到日志或错误。
- [既有手工仓库地址格式无法解析] → 不对该信息做自动去重，仍允许用户在导入前查看项目；规范化器覆盖 GitLab 返回的标准 SSH 和 HTTPS 格式。
- [同名项目在 Git 信息中仍使用相同名称] → 在管理列表和任务选择器显示完整路径，同时保持生命周期克隆目录兼容。
- [GitLab 在分页期间项目权限发生变化] → 任一页失败时舍弃全部结果；导入阶段只保存已经完整取得且仍通过本地校验的选择。
- [前端提交的数据与获取结果不一致] → 后端重新校验项目字段、地址格式、Git 模板和重复身份；桌面应用不建立额外服务器端会话缓存。

## 实施与回滚

1. 新增 GitLab 客户端、错误分类和单元测试，并为默认连接配置增加向后兼容的可选持久化字段。
2. 新增存储层批量导入及去重测试，再通过 Wails 应用层暴露查询和导入方法。
3. 重新生成 Wails 绑定并实现前端连接、选择和辅助路径展示。
4. 完成后端、前端和 `wails dev` 集成测试，再使用项目构建脚本编译并打开应用验证。
5. 回滚时移除导入入口、GitLab 调用代码和默认连接字段；旧版本会忽略未知字段，已经导入的信息仍是普通 Git 信息，无需迁移或删除。
