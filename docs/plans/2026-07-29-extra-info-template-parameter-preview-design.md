# 新建信息的模板参数只读预览设计

## 背景

模板可定义动态参数，但创建信息时草稿只包含固定字段和信息级动态参数。用户无法在保存前核对该信息将从模板带入哪些参数，只能在创建任务后看到。

模板参数属于分类定义，信息级动态参数属于单条信息。两者在创建任务时才合并，因此不能将模板参数混入可编辑的信息级参数列表。

## 方案比较

1. 在信息编辑器中单独只读预览模板参数，并保留可编辑的信息级参数区域。采用此方案。
2. 将模板参数复制到信息草稿并禁用编辑。会使信息保存旧模板定义，模板后续修改后数据容易不一致。
3. 仅以文本摘要显示参数数量。无法满足查看参数键、显示名称、默认值与必填状态的需求。

## 交互与数据流

新增信息选择模板后，编辑器在“动态参数”区域先显示“模板参数”小节。每条参数展示：

1. 参数键。
2. 显示名称。
3. 默认值；文本参数默认值为空，复选框显示 `true` 或 `false`。
4. 必填状态；复选框参数不显示必填状态。

该小节仅依据当前选择的 `ExtraInfoTemplate.parameters` 渲染，不写入 `ExtraInfo.parameters`，也不提供输入、删除或新增操作。切换模板时，预览随所选模板更新。

“信息参数”小节继续保存至 `ExtraInfo.parameters`，可以新增、修改和删除。创建任务时继续由既有逻辑按“模板参数 + 信息参数”合并，保持所有后端接口和保存数据不变。

编辑已保存信息时通过其 `templateId` 查找模板并显示同一预览；模板已被删除时隐藏该小节，避免展示过期定义。

## 验证

前端回归测试覆盖：

1. 选择带文本和复选框参数的模板后，能展示键、显示名称、默认值和适用的必填状态。
2. 模板预览中没有可编辑输入、删除按钮或必填切换控件。
3. 信息级新增动态参数仍可创建和编辑，并且保存请求仅包含信息级参数。

完成后运行前端全量测试、Go 全量测试和 `scripts/build-linux.sh`。
