# Nebula UI 重构设计

## 目标

参考 `design-preview/index.html` 中的“03 · Nebula”方案，将 TaskAI 工作台统一为冷蓝、青色和紫色的指挥中枢视觉。变更只修改界面表现，不改变任务、终端、生命周期、设置、额外信息、快捷输入和退出流程的行为。

## 现有结构

保留当前工作台信息架构和交互节点：

```text
顶部操作栏 52px
└── 主体区域
    ├── 任务与终端侧栏
    │   ├── 状态 Tabs
    │   ├── 任务卡片
    │   └── 终端子项
    ├── 可拖拽分隔条
    └── 任务详情或活动终端
```

侧栏标题使用 40px，终端标题栏使用 40px。保留当前最小窗口宽度、侧栏拖拽宽度、任务卡 60px 高度、滚动容器和所有操作按钮占位。

## 视觉系统

### 颜色令牌

亮色主题使用 `#EDF1FB` 画布、白色半透明表面、`#0E1730` 正文、`#5A6588` 辅助文字、`#0BA5BE` 主色和 `#7C3AED` 辅助色。暗色主题使用 `#070A16` 画布、深蓝半透明表面、`#E8ECFF` 正文、`#8A93C2` 辅助文字、`#2DE2E6` 主色和 `#B06BFF` 辅助色。

状态色固定为：运行中工程绿、空闲蓝灰、未读紫色、异常红色。状态点继续保留工作中和未读脉冲，`prefers-reduced-motion: reduce` 时变为稳定静态提示。

表面使用低透明度冷蓝层和轻微模糊。参考中的大块径向光晕收敛为低干扰的整体背景层，避免产生独立的装饰性光斑。

### 字体与图标

- 正文使用 Sora，标题、品牌、Tabs 和元数据标签使用 Chakra Petch。
- 终端输出、路径、快捷输入预览和状态元信息使用 JetBrains Mono。
- 三套字体以本地资源随前端打包，不依赖运行时网络请求。
- 图标继续使用 `lucide-react`，统一细几何描边；保留现有图标语义、ARIA 标签、Tooltip 和键盘焦点。

### 几何与状态

- 任务卡使用 10px 圆角、细边框、任务色内嵌标记和约 4% 同色背景；未选中状态不显示外部阴影。
- 任务悬停和选中使用不改变尺寸的轻微抬升、边框高亮和低强度光晕。
- 终端子项使用 8px 圆角和次级玻璃表面，活动终端使用青色边框。
- Tabs 使用青色底部指示线，避免 Snap 主题的实心色块。
- Dialog、Popover、Dropdown、Tooltip、Toast、Alert、Accordion、Checkbox、Switch、Input 和 Chip 使用相同的半透明表面、细边框、8-10px 圆角和可见焦点环。

## 组件映射

### 顶栏与侧栏

顶栏保留信息管理、设置和退出入口，保留现有品牌标记语义，不加入参考中的 `LIVE` 指示。侧栏保留任务状态筛选、展开/收起、创建任务、完成任务批量选择和删除入口。拖拽分隔条继续可用，只替换颜色和悬停反馈。

### 任务树

保留任务选择、展开、拖拽排序、执行、结束、重试、搁置、批量选择和右键菜单。任务标题、描述、生命周期进度、状态点和上下文按钮的位置不变；只替换卡片表面、圆角、任务色条、选中态和上下文控件的显示风格。

### 终端与详情

保留 xterm 会话、输入输出、尺寸调整、文件拖入、剪贴板、快捷输入、关闭终端和实时状态。仅替换标题栏、终端背景、光标、选区、ANSI 调色板、快捷输入 Popover 和详情内容表面。

### 覆盖层

任务编辑、设置、额外信息、模板、命令链、快捷输入、状态帮助、结束确认、退出确认和菜单继续使用现有 Radix 原语与打开/关闭/提交逻辑，只统一 Nebula 外壳和滚动区域样式。

## 实现边界

主要修改范围：

- `frontend/src/style.css`、`frontend/src/App.css`
- Tailwind 字体、颜色、圆角和阴影令牌
- `frontend/src/components/ui/` 的基础视觉类
- 必要的字体入口与本地字体依赖
- `frontend/src/terminal-session.ts` 的 xterm 主题颜色

尽量不改 `App.tsx`、`TaskTree.tsx` 和 `TerminalView.tsx` 的状态、回调、API 调用和 DOM 语义；只有在视觉样式无法通过现有类名表达时，才增加不承载业务的样式类或布局属性。不得修改 Go/Wails API、数据结构、持久化格式、生命周期命令链和终端会话注册逻辑。

## 验证

1. 运行前端测试，覆盖任务树、终端、状态点、弹窗和基础 UI 组件。
2. 运行 `npm run build`，确认 TypeScript、Tailwind 和 Vite 构建通过。
3. 检查亮色和暗色下的顶栏、任务树、详情、终端、Popover、菜单和所有 Dialog。
4. 确认 Portal 内容没有残留旧 Snap 色值、粗描边和硬阴影。
5. 回归任务执行、结束、重试、拖拽排序、终端输入输出、快捷输入、设置保存和弹窗关闭行为。
6. 检查减少动态效果偏好下，抬升、脉冲和过渡被限制但状态仍清晰。
7. 按项目要求运行 Go 测试和最终编译脚本。
