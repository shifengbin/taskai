# 启动失败的未执行任务安全删除实施计划

## 目标

允许用户放弃并删除 `pending + beforeStart + failed` 的任务。若 TaskAI 在该次启动中确实新建了任务工作目录，删除时一并安全清理；若没有创建目录、创建失败或复用了既有目录，则只删除任务记录，绝不根据路径存在性推断并删除目录。

## 实现范围

- 在 `LifecycleExecution` 中持久化开始前工作区根目录、任务目录、随机所有权令牌和 `unknown`、`not-created`、`created` 三态归属。
- 在工作区根目录的私有元数据区保存侧车凭据，并在任务目录自身保存所有权标记；删除前同时校验任务 ID、路径边界、令牌、目录标记和文件系统身份。
- Unix 使用扩展属性并校验目录权限；macOS 额外校验扩展 ACL；Windows 使用备用数据流和仅当前用户可访问的受保护 DACL。
- 创建目录前探测所有权标记能力；不支持时在创建前失败，不降级到仅凭路径或目录身份的删除方案。
- 使用不覆盖已有目标的原子重命名发布新目录；创建中断时可凭 staging 和侧车信息恢复，目标被其他进程占用时只回收本次 staging。目录清理先把凭据迁移为可恢复的清理提交标记，避免目录删除与凭据删除之间退出后永久阻断重试。
- 生命周期服务统一执行删除资格校验、条件目录清理和最新任务快照保存；全部任务写操作共享互斥锁，桌面进程在解析或迁移最终数据目录前先获取稳定启动协调目录的实例锁。
- 前端集中使用与后端一致的删除资格谓词，并在确认框中区分普通任务的记录删除和启动失败任务的条件目录清理。

## 实施结果

1. 在 `.worktrees/allow-deleting-failed-pending-tasks` 的 `worktree/allow-deleting-failed-pending-tasks` 分支完成隔离开发，并在交付前合入最新 `main`。
2. 模型和存储保持旧数据兼容；缺少新字段的历史失败记录归一化为 `unknown`，继续禁止删除。
3. `not-created` 任务删除时不调用任务目录删除；只有可验证为本次创建的目录才进入隔离、复核和递归删除流程。
4. 清理失败、目录被替换、同名重建、符号链接越界或最终持久化失败时保留任务记录及失败信息，允许用户重试。
5. 开始前失败任务仍保留重试入口，只有在“未执行”选择模式中额外开放删除；运行中的命令链和其他失败钩子继续不可删除。

## 自动化验证

- 后端：运行 `go test -race ./...`，覆盖模型归一化、创建与复用识别、路径和身份校验、崩溃恢复、并发保存、实例锁以及生命周期删除编排。
- 前端：运行 `cd frontend && npm test -- --run`，16 个测试文件共 315 项通过；运行 `npm run build` 验证 TypeScript 和生产构建。
- 平台：交叉编译 Windows 主程序和平台实现，并在禁用 CGO 的 Darwin 目标上验证主程序与平台降级实现可编译。
- OpenSpec：运行 `openspec validate allow-deleting-failed-pending-tasks --strict`，确保提案、设计、规格和任务清单一致。
- 发行构建：使用 `scripts/build-linux.sh amd64` 生成 Linux 可执行程序；合并主分支后再次运行同一脚本验证集成结果。

## Wails 集成测试

1. 使用 `wails dev -tags webkit2_41` 启动应用，不设置禁用终端颜色的环境变量，并根据输出取得调试地址。
2. 用 MCP Chrome DevTools 打开调试地址，配置一条“创建任务工作目录后执行 `false`”的 `beforeStart` 命令链。
3. 创建并启动任务，确认任务保持 `pending`，界面显示第 `2/2` 步失败、错误信息和重试入口；进入未执行任务的选择模式，确认该任务可勾选。
4. 打开删除确认框，确认文案明确说明：记录删除不可撤销，且只清理由 TaskAI 本次实际新建的启动失败任务目录。
5. 确认删除后，任务记录从列表消失，并检查 TaskAI 新建的对应目录不存在。
6. 预先创建同名目录及测试文件，让创建命令复用该目录后再触发失败；删除任务后检查预存目录和测试文件仍存在。
7. 补充验证普通未执行和已完成任务仍只删除记录、运行中的链不可选择，以及人为制造清理错误时任务和失败信息均保留。
8. 测试完成后关闭 `wails dev`，确保没有遗留调试进程。
