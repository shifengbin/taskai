# HTTP 接口说明弹窗设计

## 目标

将“实时状态”设置中的 HTTP 接口使用说明由连续段落改为可快速扫描的结构化文档，同时完整保留服务启用、接口调用、状态规则和限制说明。

## 范围

- 仅调整“HTTP 状态接口使用说明”弹窗。
- 不调整前后置脚本的 `?` 说明、HTTP 服务实现或接口契约。
- 不新增接口、鉴权或外部依赖。

## 信息架构

弹窗保持单页，按用户完成配置和调用的顺序分为以下区块：

1. **服务与设置**：突出回环监听、无需鉴权、独立启用服务与 HTTP 状态管理自动启用的关系；使用两步说明配置路径。
2. **终端环境变量**：说明仅 HTTP 状态管理模式中新建的普通终端和显示终端的自定义命令会注入变量，并独立显示变量代码块。
3. **查询接口**：将终端状态、按生命周期筛选任务列表、单任务详情拆分为独立条目，显示 HTTP 方法、路径、用途和 `status` 取值。
4. **状态更新**：分别列出任务与终端更新接口，集中展示 JSON 请求体与可复制的 `curl` 示例。
5. **状态与错误规则**：以紧凑的说明行列出状态值、终端更新后的任务汇总优先级、常见错误码和已运行终端的配置限制。

## 视觉与可访问性

- 使用已有 MUI `Paper`、`Chip`、`Alert`、`Typography` 与等宽代码块，不引入新设计系统或字体。
- 方法使用语义色彩区分 `GET` 与 `PUT`，但所有信息仍保留文本标签，避免仅依赖颜色。
- 每一组均使用标题和短说明，避免大段连贯文字；代码块水平可滚动。
- 在窄窗口中让接口项自然垂直排列，避免路径与说明重叠。

## 验证

前端测试验证弹窗呈现“服务与设置”“查询接口”“状态更新”等主要分组，以及任务列表、任务详情和终端更新接口路径。继续运行完整前端测试与生产构建以确保 TypeScript 和 MUI 样式通过。
