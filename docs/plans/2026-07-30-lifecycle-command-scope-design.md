# 生命周期命令适用范围设计

## 目标

为生命周期命令与命令链分别保存可多选的钩子适用范围，使用户只能在适用的钩子、默认值和新建任务中选择有效链；未执行任务编辑时可调整其已保存的选择，执行中和已完成任务仅展示既有选择。

## 数据规则

- 自定义命令必须至少选择一个钩子范围。
- 命令链必须至少选择一个钩子范围，且链内每个命令的范围必须覆盖该链的全部范围。
- 系统“创建任务工作目录”命令固定仅适用于 `beforeStart`；系统“删除任务工作目录”命令固定仅适用于 `postEnd`。
- 默认链和新建任务的某个钩子选择器，只显示包含该钩子的链。
- 未执行任务编辑时可保存新的链选择，且后端必须校验所选链覆盖对应钩子；该保存不触发 `updateTask`。
- 执行中和已完成任务编辑时保留已保存的链选择并只读展示；后端拒绝其修改链选择。

## 迁移与一致性

- 没有范围字段的旧自定义命令和旧命令链迁移为五个钩子均适用，以保留既有可用性。
- 系统内置命令和初始创建/删除目录链在规范化时使用固定范围。
- 规范化会移除范围不匹配的默认链；无法覆盖任一钩子的旧链保留为不可选配置，供用户调整后再次使用。
- 前端筛选只提升体验，仓库与应用绑定必须重复验证范围，避免 API 调用写入无效配置。

## 交互

- 命令编辑弹窗使用五个钩子复选框；系统命令只读显示其固定范围。
- 链编辑弹窗先选择范围，再仅展示能够覆盖该范围的命令；修改范围导致已有命令不兼容时，保留原选择并阻止保存、提示用户调整。
- 默认链下拉框与新建任务下拉框按当前钩子筛选；编辑未执行任务时选择器可用，编辑执行中或已完成任务时显示禁用选择器。

## 验证

- Go 测试覆盖范围规范化、迁移、链保存与默认链拒绝无效范围。
- 前端和应用绑定测试覆盖命令/链范围选择、命令筛选、默认链筛选、新建任务筛选，以及未执行可编辑、执行中/已完成只读的状态边界。
