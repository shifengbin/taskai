# 终端回到底部按钮实施记录

## 目标

当用户向上滚动查看终端历史时，在终端内容区右下角显示“回到底部”按钮；点击后回到最新输出。该行为同时适用于活动终端和异常退出的只读快照，并且不得改变终端实时状态的画面比较基线。

## 实现

### 终端会话滚动状态

`TerminalSessionRegistry` 继续持有 xterm 会话，并新增当前可见视图的滚动位置订阅与 `scrollToBottom()` 公共方法：

- 使用活动缓冲区的 `viewportY >= baseY` 判断当前是否位于底部。
- 会话附着和尺寸适配完成后立即同步一次状态。
- 监听 xterm `onScroll`，只在“位于底部”布尔值真实变化时通知 React，避免高频输出重复更新状态。
- 切换、分离或释放会话时释放滚动监听并清空回调，旧会话事件不得更新已卸载视图。
- 滚动监听不调用 `captureTerminalDisplay()`、`resetDisplay()` 或实时活动回调；画面活动继续从 `baseY` 捕获底部终端页。

### 终端视图按钮

`TerminalView` 保存当前会话是否位于底部的局部状态，并在离开底部时渲染现有 `IconButton`：

- 按钮位于终端内容区右下角，不占用 xterm 网格空间。
- 使用 Nebula 主题的背景、边框、阴影和强调色，图标使用 `ArrowDown`。
- `aria-label` 和 `title` 均为“回到底部”。
- 点击后只滚动当前会话；活动终端恢复输入焦点，异常退出快照仍保持只读。
- 用户手动滚回底部、点击按钮回底或切换到位于底部的其他终端后，按钮自动隐藏。

## 测试先行

实施遵循测试先行：

1. 会话层先新增 3 个失败用例，分别证明初始状态未通知、缺少 `scrollToBottom()` 和监听未释放；旧实现下 3 项失败、47 项既有测试通过。
2. 完成最小会话实现后，`terminal-session.test.ts` 的 50 项测试全部通过。
3. 视图层先新增 4 个失败用例，覆盖显示、隐藏、点击、切换和异常快照；旧视图下 4 项失败、35 项既有测试通过。
4. 完成按钮实现后，两个相关测试文件共 89 项全部通过。
5. 代码审查发现相同滚动状态可能重复通知，随后新增失败断言，确认旧实现会重复回调；加入状态去重后相关 89 项测试再次通过。

## 代码审查

审查覆盖滚动监听生命周期、会话隔离、异常快照只读行为、实时状态基线和按钮可访问性。审查没有发现 Critical 问题，并修正以下 Important 问题：

- xterm 在高频输出期间可能连续发布相同滚动位置，原实现会重复调用 React 状态回调。
- 修正后每次订阅强制发送初始值，后续仅在底部状态变化时通知；`scrollToBottom()` 的 xterm 事件与主动同步两条路径也只产生一次通知。
- 测试桩的监听释放现在真实移除回调，并验证 detach、切换和 dispose 后旧事件保持静默。

## 集成验证

使用隔离的 `XDG_CONFIG_HOME` 运行 `wails dev -tags webkit2_41`，从输出取得 `http://localhost:34115`，通过 chrome-devtools 完成以下真实交互：

- 创建任务和多个终端，生成长滚屏输出。
- 终端位于底部时按钮隐藏，按 `Shift+PageUp` 离开底部后按钮显示。
- 连续输出期间保持用户历史视口和按钮可见。
- 多次 `Shift+PageDown` 手动回到底部后按钮隐藏。
- 点击按钮回到最新输出、隐藏按钮并恢复活动终端焦点。
- 在多个终端之间切换时，各会话保留独立滚动位置和按钮状态。
- 调整浏览器窗口尺寸后按钮继续位于终端内容区右下角。
- 终端在历史视口异常退出后继续显示按钮；点击后回到退出提示所在底部，快照保持只读。

控制台仅出现仓库既有的 `/favicon.ico` 404 和表单字段提示，与本功能无关。集成测试结束后已关闭浏览器调试页和 `wails dev`。
