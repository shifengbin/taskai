# 额外信息默认模板选择设计

## 背景

额外信息管理中的“新增模板”位于分类模板折叠区域内部，模板收起时无法直接创建。分类模板默认展开，也占用信息列表的首屏空间。新增信息时始终要求手动选择模板，即使系统只有一个模板，或用户刚刚连续在同一分类中添加信息。

## 目标

1. 分类模板在当前应用首次打开管理界面时默认收起。
2. “新增模板”始终位于分类模板折叠区域外部，可在模板列表收起时直接使用。
3. 新增信息在只有一个模板时自动选择该模板。
4. 存在多个模板时，下一次新增信息自动选择本次应用运行期间最后一次成功新增信息的模板。
5. 不将默认模板写入本地存储；应用重启后不保留该选择。

## 方案

### 模板区域

将分类模板 `Accordion` 与“新增模板”按钮置于同一个外层横向布局中。折叠面板只负责展示和隐藏模板列表，创建按钮作为同级控件保持可见。模板面板改为受控折叠状态，初始值为收起；用户在当前会话中手动展开后保留该状态。

### 新增信息的模板决策

新增信息不再一律清空模板选择，而是按下列优先级决定默认模板：

1. 模板数量恰好为一个时，直接创建该模板的信息草稿。
2. 模板数量超过一个且内存中的“最后新增模板 ID”仍存在时，直接创建该模板的信息草稿。
3. 其他情况保持无选择状态，继续展示“选择模板”下拉框。

编辑已有信息仍直接克隆该信息，不受默认模板逻辑影响。用户在下拉框中切换模板、取消信息编辑或编辑旧信息均不会更新“最后新增模板 ID”。只有新增信息保存成功后，才记录保存结果的 `templateId`。

### 边界情况

若上次使用的模板已被删除，自动选择逻辑会忽略该 ID；多模板场景回退到手动选择。模板列表从一个变为多个后，原先的单模板默认不被视为“上次新增”，除非确实保存过一条新信息。

## 验证

前端测试覆盖：

1. 分类模板初始收起，且收起时“新增模板”按钮仍可打开模板编辑器。
2. 只有一个模板时新增信息直接显示该模板固定字段，不展示模板下拉框。
3. 多个模板时首次仍手动选择；成功新增后，再次新增自动进入刚保存信息的模板。
4. 删除上次使用模板后，新增信息安全回退到手动选择。
