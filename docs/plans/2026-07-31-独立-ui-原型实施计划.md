# 独立 UI 原型实施计划

> **实施提示：** 按任务逐项执行，并在完成前运行全部验证。

**目标：** 在不接入任务工作台前端的前提下，交付五套可交互、可离线打开并支持亮暗主题的单页 UI 原型。

**架构：** 原型位于独立 `ui-prototypes/` 目录，每个 HTML 文件内嵌样式和脚本。五页复用同一类任务工作台信息层级，但各自定义颜色、字体、间距与组件轮廓，避免让视觉差异被业务数据差异干扰。

**技术栈：** 语义化 HTML、CSS 自定义属性、原生 JavaScript、Node.js 静态校验脚本。

---

### 任务 1：建立原型静态校验

**文件：**
- 新建：`ui-prototypes/validate-prototypes.mjs`
- 测试：`ui-prototypes/validate-prototypes.mjs`

**步骤 1：编写预期断言**

校验脚本枚举五个页面，要求每页包含文档标题、`data-theme`、主题切换按钮、任务状态标签、任务列表和终端区，并确认不引用项目的 `frontend/src`。

**步骤 2：运行校验，确认页面不存在时失败**

运行：`node ui-prototypes/validate-prototypes.mjs`

预期：退出码非零并报告缺少原型文件。

### 任务 2：实现白墙与编辑部原型

**文件：**
- 新建：`ui-prototypes/01-whitewall.html`
- 新建：`ui-prototypes/02-editorial.html`

**步骤 1：实现共同交互基线**

各页以独立脚本实现亮暗主题切换、任务状态切换、任务选择，以及“概览/终端”视图切换；使用同一组代表性任务与终端数据。

**步骤 2：落实各自视觉语言**

白墙采用严格栅格和单色强调；编辑部采用纸感中性色、衬线标题与编辑排版。两页不得引入渐变背景、大面积阴影或项目依赖。

**步骤 3：运行静态校验**

运行：`node ui-prototypes/validate-prototypes.mjs`

预期：已实现页面通过；未实现的页面仍被报告缺失。

### 任务 3：实现控制室、夜航与庭院原型

**文件：**
- 新建：`ui-prototypes/03-control-room.html`
- 新建：`ui-prototypes/04-night-watch.html`
- 新建：`ui-prototypes/05-courtyard.html`

**步骤 1：实现控制室**

使用雾蓝灰底色、信息密集的元数据带和等宽标签，优先展示状态与生命周期。

**步骤 2：实现夜航**

以终端作为右侧主要视觉区域，使用冷青状态强调，并为亮色主题提供雾蓝对应关系。

**步骤 3：实现庭院**

使用岩灰与低饱和自然色，扩大列表留白并降低强调元素数量。

**步骤 4：运行静态校验**

运行：`node ui-prototypes/validate-prototypes.mjs`

预期：五页全部通过。

### 任务 4：增加入口与离线使用说明

**文件：**
- 新建：`ui-prototypes/index.html`
- 新建：`ui-prototypes/README.md`

**步骤 1：建立方案入口页**

入口页仅链接五份独立 HTML，标明每套的中文名称与一句视觉定位，不加载项目资源。

**步骤 2：编写中文使用说明**

说明浏览器直接打开入口页或任一方案页即可预览；注明原型不进入应用构建和发布流程。

**文件：**

**步骤 1：运行结构校验**
