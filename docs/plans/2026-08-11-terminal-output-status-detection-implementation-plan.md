# 终端画面变化状态判定实施记录

## 目标

将“根据终端输出变化”的实时状态判定改为比较 xterm 解析后的可见终端画面，避免仅移动光标、设置后续颜色、标题或响铃等无可见结果的控制序列产生工作中或未读状态。

## 实现

- `TerminalSessionRegistry` 在每个解析批次读取活动缓冲区的当前可见网格，并与上次快照比较。
- 快照比较字符（包含空格和其他空白单元格）、宽度、前景色、背景色与可见文本样式，不比较光标状态。
- 只有快照不同才通过新的 Wails 方法上报；前端只在 `output-change` 方式下调用，后端继续使用既有方式校验和 1.5 秒静默计时。
- 原始 PTY 事件不再直接改变实时状态；异常退出时由前端写入的只读快照提示也不会作为活动上报。

## 覆盖

- 普通文字、空格覆盖、空白单元格背景或样式、同字符改色会触发活动。
- 无画面差异、光标控制、未使用的颜色或样式设置不会触发活动。
- 标题变化和 HTTP 方式不会接受画面活动上报。
- 初始化、尺寸适配、外观更新和销毁会重建或清理快照基线，避免界面操作误报。

## 验证

- `go test -race ./...`
- `cd frontend && npm test -- --run && npm run build`
- `./scripts/build-linux.sh`
- 启动 `build/bin/taskai`，不设置 `NO_COLOR` 等禁用终端颜色的环境变量。
