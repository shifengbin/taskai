# Git 同步状态设计

## 目标

当仓库工作区干净且本地与选定远程分支没有提交差异时，将该仓库的“同步远程”按钮置灰。任务没有工作目录时，不显示 Git 标签。

## 判定方式

仓库服务在已有的远程分支查询中读取远程分支提交号，并额外读取本地跟踪分支和当前提交：

1. 当前本地分支必须跟踪选定的远程分支。
2. 本地跟踪分支的提交号必须与远程查询到的提交号一致，避免本地远程引用陈旧时误判。
3. 当前提交与本地跟踪分支之间的领先和落后提交数都必须为零。

满足以上条件时返回 `synchronized: true`。工作区有未提交改动、缺少上游分支、远程分支不存在或无法读取远程状态时，均不会标记为已同步。

该方案复用仓库列表原本就会执行的 `git ls-remote`，不执行额外的 `fetch`，因此不会增加扫描时的网络请求。

## 界面

Git 仓库卡片继续使用既有的一个主按钮。`action` 为 `sync` 且 `synchronized` 为真时，按钮文字保持“同步远程”，但禁用点击并以控件的禁用样式显示。其他提交、发布和同步状态保持不变。

任务没有工作目录，或虽保存了预期路径但目录尚未实际创建时，详情中的“Git”标签及其内容不渲染，也不会发起仓库查询；“项目信息”仍会显示。任务详情标签由当前任务驱动：从已选中 Git 标签的任务切换到这类任务时，立即切回“项目信息”，不能保留已移除的 Git 标签状态。

## 错误处理

远程仓库不可访问时继续显示既有配置或读取错误提示，并保持同步按钮可点击，以便用户在修复配置后重试。无法可靠判断同步状态时保守地视为未同步，避免隐藏实际需要的同步操作。

## 验证

后端测试覆盖完全同步、本地领先或落后、远程已变化、缺少上游分支等状态。前端测试覆盖同步按钮禁用、无工作目录任务不显示 Git 标签，以及从 Git 标签切换到该任务后仍显示项目信息。随后执行 Go、前端、OpenSpec 与 Wails 集成验证。
