# 终端光标显示异常修复实施记录

## 目标

修复终端输出更新期间光标消失、闪烁频率异常以及按左右方向键后光标不显示的问题。问题同时出现在 Windows 和 Linux，根因是前端为抑制重绘中间态而向 xterm 追加 `ESC[?25l`，该序列会持久修改 xterm 的光标隐藏状态，延迟恢复又可能被后续输出竞态跳过。

## 实现

### 输出渲染同步

- 保留终端会话级 32 毫秒静默合批、64 毫秒截止冲刷、1MB 缓冲上限和输出顺序。
- 删除应用层合成 `ESC[?25l` / `ESC[?25h` 以及光标恢复定时器，不再篡改终端程序的光标可见性、闪烁选项或光标样式。
- 对包含高频重绘特征的输出，在本地 xterm 中使用 `ESC[?2026h` / `ESC[?2026l` 同步输出模式缓存渲染行；同步状态跨越截止冲刷，在静默后统一解除。
- 记录同步状态所有权：程序自身已启用或接管同步输出时，注册器不强制解除；xterm 安全超时解除后，后续重绘可重新建立注册器同步状态。
- 在终端切换、异常退出、分离和销毁时冲刷或取消未决回调，并解除注册器自己建立的同步状态。

### 测试

- 扩展终端会话测试桩，验证同步状态进入、持续、释放、超时重建和生命周期清理。
- 增加真实 xterm parser 测试，覆盖重绘后普通输出、字符输入、左右方向键以及程序主动隐藏光标。
- 使用真实浏览器挂载 xterm，采样 `.xterm-cursor` 的可见性、位置和 CSS 闪烁周期；高频重绘压力采样仅观察到 3 个位置，动画周期均为 `1s`。

## 代码审查

审查重点覆盖同步状态所有权、截止冲刷与静默定时器竞态、终端程序自身 `?2026` 控制序列、`?25` 光标控制序列兼容性以及退出/分离/销毁路径。审查后补充了程序接管同步模式的回归用例，确保注册器不会误关闭程序自己的同步状态。
