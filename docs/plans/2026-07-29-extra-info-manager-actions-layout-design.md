# 额外信息管理操作栏布局设计

## 背景

分类模板区的“新增模板”与信息区的“新增信息”分处不同区域，两个同级创建动作在视觉上断开。模板和信息编辑弹窗均使用 `sm` 宽度，当固定字段或动态参数较多时，横向空间不足，表单显得拥挤。

## 方案比较

1. 在分类模板区域保留“新增模板”，仅调整信息区域位置：改动最小，但两个创建动作仍然分散。
2. 将两个创建动作放入统一操作栏：清楚表达“模板”和“信息”是管理界面的主要操作，并保留分类折叠区域的浏览职责。采用此方案。
3. 使用悬浮操作按钮：节省垂直空间，但不适合桌面工作台的高频、成对操作，也会弱化按钮标签。

## 设计

### 管理操作栏

在“额外信息管理”弹窗内容顶部设置一条操作栏：左侧展示简短的“管理操作”标签，右侧并列“新增模板”和“新增信息”按钮。两个按钮使用一致的 `small` 尺寸和包含式样式；当系统还没有模板时，“新增信息”保持禁用。

分类模板 `Accordion` 仍默认收起，并移动到操作栏之后，只展示分类模板的说明、列表、编辑和删除操作。信息标题和说明保留在搜索框上方，但不再携带创建按钮。

### 编辑弹窗

“新增/编辑模板”与“新增/编辑信息”弹窗从 `sm` 扩展为 `md`，保留 `fullWidth`。MUI 在窄屏会自动把对话框限制在可用视口宽度，因此无需引入额外断点逻辑。表单中的已有响应式网格不变，较宽的桌面空间可自然容纳更多输入项。

## 非目标

不调整模板、信息的保存逻辑、默认模板选择策略、表单字段结构或后端接口。

## 验证

前端测试覆盖：

1. 管理操作栏内的“新增模板”和“新增信息”并列显示。
2. 两个编辑弹窗均使用 `md` 最大宽度。
3. 无模板时“新增信息”仍不可用。

完成后运行前端全量测试、Go 全量测试和 `scripts/build-linux.sh`。
