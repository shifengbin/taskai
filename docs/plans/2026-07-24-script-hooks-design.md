# 前后置脚本语义重命名设计

## 目标

将新功能中的“命令钩子”统一改为“前置脚本”和“后置脚本”。脚本是菜单主命令生命周期中的独立可执行脚本，而不是另一条普通菜单命令。

## 配置模型

自定义菜单项直接保存 `beforeScript` 和 `afterScript`。每项脚本包含 `script` 与 `arguments`：`script` 是脚本路径或当前 Shell `PATH` 中的可执行脚本，`arguments` 的每个非空行保持为独立参数。功能尚未发布，因此不读取、不兼容也不迁移 `beforeHook`、`afterHook` 或 `command` 字段。

主菜单项仍使用 `command` 与 `arguments` 表示要执行的主命令；钩子标准输入 JSON 中的 `command` 与 `arguments` 也继续表示该主命令，避免混淆脚本自身配置和主命令上下文。

## 执行与错误

应用层将前置脚本同步执行成功后再启动主命令；主命令实际退出后启动后置脚本。后置脚本的启动边界继续与任务结束标记使用同一临界区，任务进入结束流程后不会新启动后置脚本。错误事件改为脚本命名，前端仅显示“执行前置脚本”或“执行后置脚本”的用户可见提示。

## 界面与文档

菜单项编辑器的第二个 Tab 命名为“前后置脚本”，输入框使用“前置脚本”“后置脚本”及其逐行参数；“？”帮助说明脚本路径或可执行脚本、标准输入 JSON 和参数边界。README、OpenSpec proposal、design、specs 与任务清单均采用相同术语。

## 验证

先让 Go 设置与执行测试、前端可访问标签测试因旧字段或旧文案失败，再完成重命名。最后由 `scripts/build-linux.sh amd64` 重新生成 Wails 绑定并生产构建，配合 Go、前端和 OpenSpec 验证。
