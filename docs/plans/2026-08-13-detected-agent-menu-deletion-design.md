# 自动代理菜单删除记忆设计

## 背景

应用启动时会为可用的 `codex`、`claude` 命令补充自动任务菜单。用户希望删除自动项后不再补充，并且已有启动命令完全相同的自定义菜单时不要追加重复入口。

## 行为

- 启动合并时，命令型菜单的 `command` 字段精确为 `codex` 或 `claude`，即视为对应命令已经配置，不再追加自动项；名称、参数和菜单 ID 不参与该判断。
- 用户通过设置保存删除 `auto.agent.codex` 或 `auto.agent.claude` 时，仓储记录对应稳定 ID。以后即使命令仍可检测，也不再自动补充。
- 删除普通自定义菜单不产生删除记录。
- 删除记录不自动清除。用户需要恢复时，可通过现有“新增菜单项”手动添加对应命令。

## 数据设计

在仓储根数据中增加可选字段 `dismissedAgentTaskMenuItemIds`。该字段不属于公开 `Settings`，因此不会进入 Wails 绑定或设置表单，也不会被前端保存的设置快照覆盖。

`SaveSettings` 在仓储变更锁内比较保存前后的菜单项：只有原设置包含自动稳定 ID、而新设置不再包含该 ID 时，才将其追加到删除记录。记录去重并仅接受两个已知自动 ID。

启动原子合并在同一仓储锁内读取菜单、删除记录和检测结果。候选项按以下顺序判断：

1. 对应命令未检测到：跳过。
2. 自动稳定 ID 已被记录删除：跳过。
3. 已有相同稳定 ID：跳过并保留现有内容。
4. 已有命令型菜单的 `command` 精确匹配：跳过。
5. 其余情况追加默认自动项。

## 兼容与错误处理

旧数据没有删除记录时按空列表处理。仓储加载时规范化未知或重复记录，避免损坏数据扩大影响。设置保存失败时，菜单变更和删除记录都不落盘，保持原子性。

## 验证

- 设置单元测试覆盖精确命令去重、不同命令不误判和删除记录抑制。
- 仓储测试覆盖自动项删除后持久化、重启不恢复、自定义项删除不记录以及失败保存原子性。
- 应用和前端测试覆盖删除自动项的保存请求；浏览器集成测试删除 `codex` 后重启，确认 `codex` 不恢复、`claude` 保持且无重复项。
