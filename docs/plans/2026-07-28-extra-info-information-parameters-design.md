# 信息级动态参数与分类稳定展示设计

## 背景

现有信息只能保存模板固定字段，任务选择信息后只会生成模板动态参数。因此，用户无法为某一条信息配置专属的动态参数和默认值。额外信息管理的搜索还会移除不匹配的分类分组，模板定义区在内容较多时会挤压操作控件。

## 已确认的交互

- 创建或编辑信息时，除模板固定字段外，可新增、编辑、删除信息专属动态参数。
- 每个信息级参数保存参数键、显示名称、默认值和必填标记；参数属于该信息，不写回模板。
- 创建任务选择信息时，信息级参数自动带入任务动态参数区域并显示默认值；任务仅编辑值。
- 任务内新增的参数仍只属于任务，可编辑定义和值。
- 分类模板定义区整体可折叠，默认展开；信息分组仍按模板展示，Git 信息分组默认展开。
- 搜索仅按信息名称模糊匹配信息行，模板定义和分类标题始终展示；命中分类自动展开。

## 数据与校验

`task.ExtraInfo` 增加 `Parameters []ExtraInfoParameter`。使用现有带值参数结构可避免再引入一套相近 DTO，并让 JSON、Wails 与任务快照的传输格式一致。

保存信息时，固定字段及信息级参数均会被规范化。信息级参数键不得与模板固定字段、模板动态参数或同一信息其他参数重复。已有 JSON 未出现 `parameters` 时会被规范化为空切片，兼容已保存的信息。

任务快照来源分三类：模板参数、信息级参数、任务级新增参数。前两类的键、显示名称、必填标记由其来源固定，任务只能变更值；第三类维持当前可编辑定义的行为。创建快照使用信息内的默认值，编辑已有任务继续以历史快照为准。

## 界面布局

模板定义区替换为独立 `Accordion`，通过响应式 CSS Grid 承载模板详情和操作：窄屏单列，宽屏将内容与按钮区域分列，按钮区自动换行。信息分组 `Accordion` 不会随搜索被移除；每个组显示匹配的信息或“未找到匹配的信息”状态。搜索时匹配组会加入展开集合。

信息编辑弹窗增加“动态参数”分区，参数行使用现有模板参数的堆叠式响应布局，避免多输入控件挤压。任务参数渲染根据模板与信息参数键判断来源：两者隐藏键/显示名称编辑与删除控件，任务新增参数保留这些控件。

## 测试策略

先为领域和服务写失败测试，验证信息参数默认值复制、来源定义不可伪造以及冲突拒绝；再补充仓储兼容测试。前端测试覆盖信息保存参数、任务选择自动展示默认值、模板定义折叠和搜索保留分类标题。最后运行全量 Go 测试、Vitest、前端构建、OpenSpec 严格校验与项目 Linux 构建脚本。
