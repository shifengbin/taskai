# 活动任务模板删除保护设计

## 背景

任务此前只保存模板字段值，不保存所用模板的 ID。删除模板时，设置保存逻辑无法识别仍在未执行或执行中任务中的模板引用，导致模板定义可被移除，任务字段也随之无法在编辑界面解析。

## 目标

未执行和执行中的任务引用某个任务模板时，禁止删除该模板。已完成任务不阻止删除。保护必须由后端强制执行，前端只负责提前说明不可操作状态。

## 设计

`task.Task` 新增可持久化的 `TaskTemplateID`。创建或通过模板字段编辑任务时，服务将当前模板 ID 与字段值一同写入任务；后续模板删除校验据此精确检查未执行和执行中的任务。

保存设置时，后端比较旧模板列表与新模板列表。若被移除模板的 ID 被任一未执行或执行中任务引用，整次设置保存失败且不写入数据。已完成任务的引用不参与阻止条件。

旧任务没有模板 ID，无法安全推断其字段属于哪个模板。只要存在未执行或执行中的旧任务且含模板字段，后端拒绝删除任何任务模板；前端同样禁用删除按钮并说明需要先结束这些旧任务。此策略避免把无法归属的活动数据暴露给误删风险。

## 前端行为

设置中的任务模板列表根据任务状态和 `TaskTemplateID` 计算受保护模板。受保护模板的删除按钮禁用，并通过提示说明对应的活动任务状态；存在旧字段但没有模板 ID 时，所有模板删除按钮禁用。后端错误仍会显示，以覆盖并发或旧客户端提交。

## 验证

后端测试覆盖未执行、执行中、已完成和旧任务场景，以及失败保存的原子性。前端测试覆盖受保护模板删除控件禁用、已完成引用不阻止删除和旧任务保护提示。完整 Go、Vitest、前端构建与 Linux 打包构建作为收尾验证。
